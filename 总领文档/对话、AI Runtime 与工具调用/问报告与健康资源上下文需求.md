# 问报告与健康资源上下文需求

## 一、模块目标

支持用户在聊天中选择医疗报告、病例、检查、处方等健康资源，将其作为上下文发送给 AI，实现“问报告”和健康数据辅助对话。

## 二、问报告与健康资源上下文模块结构

## 三、功能模块

### 3.1 健康资源选择

#### 需求说明

用户在聊天中打开问报告选择器，按成员加载完整医疗数据，选择最多一定数量的健康资源附加到待发送消息。

#### 基础要求

- 选择器按 memberID 加载数据。
- 支持初始 completeData，避免重复请求。
- 用户选择顺序稳定，用于 refIndex 和卡片顺序。
- 选择数量受 `HealthResourceSendValidator.maxRefs` 限制。

#### 验收标准

- 已选资源在重新打开选择器时保持选中。
- 超过数量限制时不允许继续追加。
- 搜索和分类 tab 不破坏选择顺序。

#### 技术细节与设计代码位置

- `ChatAskReportSheetViewModel.swift`
- `ChatSelectableHealthSource.swift`
- `HealthResourceSendValidator.swift`

### 3.2 Timeline 映射与搜索

#### 需求说明

成员完整医疗数据需要映射成可搜索、可分组、可预览的 timeline 行，便于用户快速找到报告或病例。

#### 基础要求

- 支持病例组和 leaf 资源。
- 搜索匹配标题、副标题、摘要、badge 和归一化搜索文本。
- 分组父项匹配时保留完整子项；子项匹配时保留匹配子项。

#### 验收标准

- 搜索关键词能命中报告标题、摘要和标签。
- 病例组展示不会丢失子资源。
- 加载失败显示错误状态。

#### 技术细节与设计代码位置

- `ChatAskReportTimelineMapper.swift`
- `ChatAskReportTimelineView.swift`
- `ChatAskReportSheetViewModel.filterRow`

### 3.3 健康资源上下文注入

#### 需求说明

选中的健康资源需要转成 `HealthResourceRef`，在发送时进入聊天上下文，供 AI 回答时引用。

#### 基础要求

- 发送前去重已有 refs。
- 资源引用必须包含稳定 id 和类型信息。
- 上下文构建应限制内容大小，避免超过模型上下文。

#### 验收标准

- 追加选择后编辑区出现资源预览。
- 发送时 AI 能获得相关健康资源摘要。
- 删除预览后不会继续发送该资源。

#### 技术细节与设计代码位置

- `ChatAskReportTimelineMapper.makeHealthResourceRef(from:)`
- `HealthResourceAIContextBuilder.swift`
- `HealthResourceContextResolver.swift`
- `ChatOutboundContextAssembler.swift`

### 3.4 资源预览与工具读取

#### 需求说明

聊天中应能预览选中的健康资源，并允许工具在需要时读取更详细的资源内容。

#### 基础要求

- 预览加载和聊天发送解耦。
- 资源读取应走医疗查询 API 或统一服务。
- 工具读取健康资源需要遵守工具授权和审计规则。

#### 验收标准

- 点击健康资源卡片可打开预览。
- 资源不存在或加载失败有明确提示。
- 工具读取结果能映射为模型可理解的 JSON 或文本。

#### 技术细节与设计代码位置

- `ChatHealthResourcePreviewLoader.swift`
- `ChatHealthResourcePreviewViewModel.swift`
- `HealthResourceToolJSON.swift`
- `DefaultHealthResourceToolService.swift`

## 四、整体业务流程

```text
聊天输入区点击问报告
  -> ChatAskReportSheetViewModel.load()
  -> MemberCompleteDataFetcher 拉取成员完整数据
  -> ChatAskReportTimelineMapper 映射 timeline
  -> 用户选择资源
  -> refsToAppend 去重并生成 HealthResourceRef
  -> 编辑区展示健康资源预览
  -> SendChatMessageUseCase 接收 healthResourceRefs
  -> ChatOutboundContextAssembler 构建上下文
  -> AI Runtime 生成回答
```

## 五、状态模型

| 状态 | 含义 |
| --- | --- |
| idle | 未加载 |
| loading | 正在拉取成员数据 |
| loaded | 已映射 timeline |
| failed | 拉取或映射失败 |
| selected | 用户已选择资源 |
| atCapacity | 超过可追加数量 |

## 六、数据与持久化

问报告选择本身主要是 UI 状态；真正的医疗数据归属医疗档案/成员模块。聊天消息持久化时只保存资源引用和必要摘要，不应复制完整医疗档案。

## 七、错误模型

| 错误 | 恢复 |
| --- | --- |
| 成员数据加载失败 | 显示失败并允许重试 |
| 资源已删除 | 从选择中移除并提示 |
| 超过数量限制 | 阻止追加 |
| 上下文过大 | 摘要截断或要求减少资源 |

## 八、与其他模块的接口边界

- 上游：聊天输入区、消息发送。
- 下游：成员完整数据获取、医疗查询 API、健康资源工具。
- 本专题不负责医疗数据本身的创建、编辑和归档。

## 十、测试策略

## 十一、当前实现、缺口与演进

当前问报告有较完整的选择、搜索、timeline 和引用构造。后续应明确每类健康资源进入模型上下文的字段白名单，避免把无关或敏感字段送入模型。

## 十二、整体验收标准

- [ ] 用户可按成员选择健康资源。
- [ ] 搜索、分类和选择顺序稳定。
- [ ] 资源引用可进入聊天发送。
- [ ] 上下文大小可控。
- [ ] 工具读取健康资源有权限和审计边界。
