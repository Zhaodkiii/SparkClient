>
> 边界约定：

## 一、模块目标

本模块负责把已加载到 `ChatStateStore` / `ChatDetailViewModel` 中的线程投影与消息窗口，渲染成用户可浏览、可操作的会话列表与会话详情时间线；并在流式更新、加载更旧消息、键盘升降和富内容高度变化时保持视口稳定。

当前实现形态是 **SwiftUI 线程列表 + UIKit `UICollectionView` 消息宿主 + SwiftUI 消息行 / 气泡 / 卡片**：

```text
ChatConversationListPage（线程列表）
        ↓ MainNavigationLink / navigationDestination
ChatView（会话详情壳）
        ↓ ChatConversationMessageListContainer
ConversationMessageListRepresentable
        ↓
ConversationMessageListViewController（Diffable + 锚定）
        ↓ UIHostingController
ChatConversationMessageRow
        ↓
ChatMessageBubbleContentView → ChatMessageTimelineProjector
        ↓
ChatMessageBlock.render(context:) → MessageCards / 富块视图
```

目标边界：

- 负责线程列表搜索、空态、创建/删除/置顶/外观编辑入口，以及进入会话详情的导航。
- 负责消息列表 Diff、加载更多行、贴底跟随、顶部插入锚定、高度变化保视口、长按气泡菜单与消息级瞬时 UI 状态。
- 负责把 `ChatMessageBlock` 映射为具体卡片 UI（文本、推理、工具、健康可视化、结构化医疗卡、采集卡等）。
- 不负责 Core Data 查询、同步游标、Outbox、AI 推理网关、ToolHub 执行器本体；这些由读模型 / 发送管线 / Runtime / ToolHub 专题覆盖。
- Composer（`HanlinChatInputView` 等）仅作为详情页壳层协作入口，发送编排细节不在本文展开。

### 2.3 目录职责与依赖方向

- Presentation 只消费 Domain 消息/块模型与 ViewModel 已投影的数据；不直接创建 Core Data 对象。
- 线程列表经 `ChatListViewModel` → UseCase / `ChatSyncSupervisor`；消息窗口参数 `ChatMessageWindow` 供详情加载使用，实际 fetch 在读模型侧。
- 消息列表宿主是 UIKit；行内容是 SwiftUI，经 `UIHostingController` 嵌入。依赖方向：`ChatView` → Representable → ViewController → Row → Bubble → Block render。
- MessageCards 只负责展示与本地交互回调；落库/保存业务由 `ChatDetailViewModel` 或 Task / 医疗相关 UseCase 完成。
- `ChatMessageUIStateStore` 是会话页瞬时状态，不是持久化事实源；`CardActionSnapshot` 仅用 `UserDefaults` 按 thread 缓存部分卡片动作结果。
- Guest（`Presentation/Guest`）不进入本目录树的 CollectionView / MessageCards 主路径。

## 三、线程列表页

### 需求说明

提供已登录用户的会话线程入口：展示标题、最新预览、时间、置顶标记与自定义图标；支持搜索、下拉刷新、创建新会话、编辑外观、置顶与删除，并导航进入 `ChatView`。

### 基础要求与业务规则

- 列表数据来自 `ChatStateStore.threadItems`（`ChatThreadListItem`）；页面通过 `listViewModel.search(text:)` 做本地标题/预览过滤，不发起服务端搜索。
- 首次进入调用 `loadForListIfNeeded()`；本地为空时生命周期内最多一次 `refreshThreadsIfLocalEmpty` 远端兜底，并展示 syncing 空态。
- 创建会话前必须 `detailViewModel.hasAvailableChatModel()`；失败则 alert 并引导打开 API Keys 设置。
- 创建成功后请求推送授权（`pushAdapter.requestAuthorizationIfNotDetermined`）、`loadMessagesIfNeeded`，再 `pendingThreadNavigation` 进入详情。
- 置顶、删除、外观更新经 `ChatListViewModel` 调 UseCase 后 `reloadThreads` 或 `tryPatchThreadList` 局部刷新。
- 未登录时 ViewModel 不加载列表；不得展示其他账号线程。

### 验收标准

- [ ] 空列表、同步中、有数据三种空态/内容态可区分。
- [ ] 搜索只过滤当前内存列表，清空搜索后恢复全量。
- [ ] 无可用模型时不能创建线程；有模型时可创建并自动进入详情。
- [ ] 置顶/取消置顶、删除、编辑标题图标颜色后列表立即反映。
- [ ] 点击行进入对应 `threadID` 的 `ChatView`。

### 技术细节与设计代码位置

- 入口：`Presentation/ChatConversationListPage.swift`。
- 编排：`ChatListViewModel`（`loadForListIfNeeded`、`refreshThreads`、`createThread`、`deleteThread`、`toggleThreadPinned`、`updateThreadAppearance`、`search`、`tryPatchThreadList`）。
- 外观编辑：`ChatThreadAppearanceEditSheet`；图标渲染：`threadIcon` / `ChatThreadAppearanceResources`。
- 时间格式：今天 `HH:mm`、昨天本地化文案、更早 `MM-dd`。
- 交互：`contextMenu` + 左滑置顶/编辑 + 右滑全滑删除；列表滚动交互式收键盘。

## 四、会话消息窗口与滚动锚定

### 需求说明

会话详情用高性能列表展示当前消息窗口：支持增量 Diff、顶部加载更旧消息、流式贴底跟随、键盘与气泡高度变化时保持视口，避免整表 SwiftUI `List` 在流式场景下抖动。

### 基础要求与业务规则

- 宿主为 `ConversationMessageListViewController` + Diffable `UUID`（`clientMessageID`）；内容 cell 托管 `ChatConversationMessageRow`。
- 窗口参数：`ChatMessageWindow.initialNewestLimit = 6`，`loadOlderPageSize = 10`；`newestFetchLimit` 不得小于内存已有条数。
- `ConversationUpdateBuilder.plan`：首帧 `reloadAll`；ID 序列不变 → `minor`（变更行 reload）；尾部对齐 → prepend；头部对齐 → append；否则 structural。
- 贴底阈值 `ScrollAnchorPolicy.pinnedDistanceThreshold = 80pt`；`shouldFollowStream` = 未拖拽且贴底。
- `hasMore` 时在快照顶部插入 load-more 占位 UUID；`willDisplay` 触发 `ConversationListCommand.loadMore`。
- 软删消息（`uiStateStore.isDeleted`）在 hosted 行过滤，不进入可见行。
- `ChatLoadCoordinator` 对 DB 通知刷新做 120ms throttle（挂在详情 ViewModel 侧，非 VC 内实现）。

### 验收标准

- [ ] 打开会话默认展示最新窗口并可贴底。
- [ ] 流式输出时，用户贴底则跟随；用户上滑阅读历史则不强制打断。
- [ ] 顶部加载更旧消息后，视口相对原第一条可见消息保持稳定。
- [ ] 推理块展开、工具结果出现导致行高变化时，贴底/锚点策略仍有效。
- [ ] 键盘弹出时视口准备贴底，不遮挡最新消息。

### 技术细节与设计代码位置

- SwiftUI 桥接：`ChatView` → `ChatConversationMessageListContainer` → `ConversationMessageListRepresentable`。
- Apply：`ConversationMessageListViewController.apply(threadID:payload:)`，payload 含 messages / hasMore / loadingMore / `lockBottomViewport` / `scrollToBottomRequestGeneration` / `forceFullListRediff`。
- 命令：`.loadMore` → `detailViewModel.loadMoreMessages`；`.captureOpenFiles` → 详情 `fileImporter`。
- 切线程：`resetForNewThread()`；下拉刷新经 `ConversationMessageListRefreshCoordinator.refreshMessageList`（`loadMessagesIfNeeded` + `layoutNonce++`）。
- 布局：Compositional Layout，`estimated(140)`，`interGroupSpacing = 12`。

## 五、消息行与气泡内容

### 需求说明

每条消息渲染为左（assistant/system）或右（user）对齐气泡；气泡内按时间线节点顺序展示块内容，并支持长按菜单与选中文本。

### 基础要求与业务规则

- 用户气泡带 accent 背景；助手/系统气泡左对齐，最大宽度扣除对侧边距。
- `ChatMessageBubbleContentView` 为纯渲染组件：通过入参与回调协作，不直接持有全局业务 Store（除 `MemberContextStore` 观察）。
- `ChatMessageTimelineProjector`：按 `orderKey`/`createdAt` 排序；tool 与 toolPresentation 归并；用户侧连续 `healthResourceReference` 合并为 group 节点。
- 翻译结果由 UIState 注入：投影前剔除旧 `translatedText` 块再追加当前译文。
- `showActions` / `actionButtonsHStack` 仍存在于 Bubble，但当前 `body` **未挂载**操作栏；操作入口以长按菜单为准（当前实现）。
- 行宽经 `GeometryReader` preference 测量，驱动 `bubbleMaxWidth`。

### 验收标准

- [ ] user / assistant 对齐与最大宽度符合设计。
- [ ] 多块消息按投影顺序展示，工具块与其展示子块不重复错位。
- [ ] 用户连续健康资料引用显示为分组卡，不逐条重复单卡。
- [ ] 长按出现自定义菜单；选中文本可进入全屏选择页。

### 技术细节与设计代码位置

- 行：`ConversationList/ChatConversationMessageRow.swift`。
- 气泡：`ChatView/Components/ChatMessageBubbleContentView.swift`（含 `ChatMessageTimelineNode` / `ChatMessageTimelineProjector`）。
- 渲染上下文：`ChatRenderContext.swift`。
- 菜单 / 选文：`ChatBubbleMenuView.swift`、`ChatTextSelectionView.swift`。
- 失败重试：`shouldUseUnifiedRetryFlow`（内联错误 clientMessageID 或非用户消息）。

## 六、消息块渲染与富内容卡片

### 需求说明

将 Domain 中 26 种 `ChatMessageBlockKind` / `ChatMessageBlockPayload` 映射为可交互的 UI；对 pending/streaming 富块显示占位文案，避免空白闪烁。

### 基础要求与业务规则

- 入口：`ChatMessageBlock.render(context:)`。
- `status == .pending`，或 `streaming` 且 kind 不是 `text` / `deepThought` / `tool` 时，显示 `ChatPendingPresentationBlockView`（按 kind 本地化标题）。
- `medicalDisclaimerCard` 在 `deliveryState == .sending` 时渲染 `EmptyView`，发送结束后再显示。
- 用户消息中的单条 `healthResourceReference` 在块级 render 返回 `EmptyView`（由 Timeline group 统一渲染）。
- 结构化健康卡支持分组成员、保存；抽取失败时显示失败卡（`blockStatus == .failed` 或 `blob.extractionFailed`）。
- 营养 / 任务 / 知识卡保存态由 context 中的 ID 集合驱动按钮 loading。
- 工具块经 `ChatToolBlockStreamedPresentationView`；是否展示结果区由 `shouldShowToolResultContent` 根据发送中后续块或 toolContent 判定。

### 验收标准

- [ ] 下表每种已实现 kind 均有对应视图，未知/空文本不崩溃。
- [ ] pending 富块显示明确进度文案。
- [ ] 医疗免责声明不在流式发送中途抢先露出。
- [ ] 健康可视化卡带 HealthKit 数据来源说明（适用卡片）。
- [ ] 卡片动作（保存、选成员、打开采集、工具预览）回调到达 `ChatDetailViewModel` 或导航目标。

## 七、气泡菜单与消息级动作

### 需求说明

长按气泡提供复制、选中文本、删除，以及对助手消息的朗读、翻译、存知识库，避免系统 `contextMenu` 与自定义预览不一致。

### 基础要求与业务规则

- 长按时长 0.45s，重触感反馈后弹出 `ChatBubbleMenuView`（透明全屏 cover）。
- 菜单预览气泡与真实内容一致，但 `showActions=false` 且 `allowsHitTesting=false`。
- 删除仅 `uiStateStore.markDeleted`（UI 软删），不是 Core Data tombstone。
- 翻译 / 存知识 / 任务确认等经 `ChatMessageActionState` actor 互斥，避免并发重复提交。
- 助手可选中文本页额外提供「存知识库」。

### 验收标准

- [ ] 用户与助手菜单能力符合角色差异（朗读/翻译/存知识仅助手）。
- [ ] 复制写入系统剪贴板；无文本时不提供选中文本。
- [ ] 删除后行立即从列表消失；进程内有效，不等同于服务端删除。
- [ ] 翻译进行中有互斥，不重复触发。

### 技术细节与设计代码位置

- `ChatConversationMessageRow.makeBubbleMenuConfig`、`ChatBubbleMenuView`。
- 动作用例：`ChatView/Domain/ChatMessageActionUseCase.swift`。

## 八、UI 瞬时状态与卡片动作快照

### 需求说明

集中管理消息级 UI 状态，减少 View 散落 `@State`；并对部分卡片动作结果按线程做轻量本地恢复。

### 基础要求与业务规则

- `ChatMessageUIStateStore` 持有：软删、译文、翻译中、mathMode、知识卡生成/保存、消息保存、任务卡 loading/ignored/created。
- `CardActionSnapshot` 序列化 saved knowledge / saved message / ignored&created task IDs；`ChatView` 用 `UserDefaults` 键 `chat.view.card_action_snapshot.<threadID>` 读写。
- 快照不是消息正文源，不能替代 Core Data；账号切换时应随页面生命周期清理或覆盖（`forceReload` 路径存在）。
- `ChatSpeechHelper` 负责朗读态，与 UIStateStore 分离。

### 验收标准

- [ ] 同线程再次进入可恢复已保存知识卡/任务卡相关标记（快照覆盖范围内）。
- [ ] 软删、翻译态不写回消息实体。
- [ ] ActionState 保证同类动作互斥。

### 技术细节与设计代码位置

- `ChatView/State/ChatMessageUIStateStore.swift`
- `ChatView.swift`：`restoreCardActionSnapshotIfNeeded` / `persistCardActionSnapshot`
- `Presentation/ChatSpeechHelper.swift`

## 九、整体业务流程

```text
进入聊天 Tab / 会话列表
  ↓
ChatConversationListPage.task → loadForListIfNeeded
  ↓（可选空列表远端兜底）
展示 threadItems / 搜索过滤
  ↓
点击线程或创建线程（模型门控）
  ↓
ChatView(threadID)
  ↓
loadMessagesIfNeeded → StateStore 消息窗口
  ↓
ConversationMessageListRepresentable.apply payload
  ↓
Diffable 快照 + 锚定策略
  ↓
ChatConversationMessageRow → Bubble → TimelineProjector → Block.render
  ↓
用户长按 / 卡片动作 / 加载更多 / 流式更新
  ↓
UIState 更新或 ViewModel 业务回调 → 再次 apply
```

### 成功路径

1. 列表有数据，点进会话，最新消息贴底可见。
2. 助手流式输出，贴底用户看到文本与后续卡片依次出现。
3. 上滑加载更旧消息后继续阅读，位置不跳飞。
4. 卡片保存/采集/工具预览按回调完成并有 loading 反馈。

### 失败、重试和恢复

- 列表刷新失败：`notificationClient.error`，保留本地列表。
- 无可用模型创建失败：alert + API Keys sheet，不创建空线程。
- 助手错误/状态卡：`ChatAssistantStatusCardView` + `onRetry`（统一重试流）。
- 结构化健康抽取失败：失败卡展示，不阻断同消息其他块。
- 健康资料不可用：`onHealthResourceUnavailableTap` 通知用户。

### 取消、并发和幂等

- 用户拖拽中不跟随流式贴底；取消拖拽后按是否仍贴底决定。
- 消息级动作经 ActionState 互斥。
- 列表 Diff 以 `clientMessageID` 为稳定 identity；块级 revision 合并属读模型/写入侧，UI 只消费最新消息快照。
- UI 软删与持久化 tombstone 分离，避免误当作同步删除。

## 十、状态模型

| 状态 | 进入条件 | 用户可见结果 | 退出条件 |
| --- | --- | --- | --- |
| 列表初始加载 | 首次 `loadForListIfNeeded` | loading / 随后内容或空态 | `hasFinishedInitialLocalLoad` |
| 空列表远端兜底 | 本地空且未尝试过 | Progress + syncing 文案 | 刷新结束 |
| 列表有数据 | `threadItems` 非空 | 行列表 | 删除至空 / 账号切换 |
| 会话消息冷启动 | 进入 `ChatView` | 最新窗口，可贴底 | 加载完成 |
| 加载更旧中 | load-more 触发 | 顶部占位 / loadingMore | 页到达或无更多 |
| 流式贴底跟随 | sending + 贴底 | 自动滚到底 | 用户上滑或结束 |
| 行高变化保视口 | 推理/卡片高度变化 | 视口锁定或锚点恢复 | 布局完成 |
| 气泡菜单打开 | 长按 | 自定义菜单 + 预览 | 关闭 cover |
| UI 软删 | 菜单删除 | 行消失 | 仅进程内；重载窗口可能再出现（若未持久化删除） |
| 卡片动作 loading | 保存/确认中 | 按钮 loading | 成功/失败结束 |

## 十一、数据与持久化

| 数据 | 所有者 | 存储位置 | 生命周期 | 清理时机 |
| --- | --- | --- | --- | --- |

| 消息窗口 | 读模型 / DetailVM | Core Data → 内存 | 当前线程 | 切线程 / 重置 |

| CardActionSnapshot | `ChatView` | UserDefaults 按 thread | 设备本地 | 未确认账号级统一清理 |

## 十二、错误模型

| 错误类别 | 触发条件 | 是否重试 | 用户反馈 | 清理动作 |
| --- | --- | --- | --- | --- |
| 列表远端刷新失败 | `refreshThreadListIncremental` 抛错 | 可手动下拉 | toast/error 通知 | 保留本地 |
| 无可用聊天模型 | 创建线程门控失败 | 去设置后重试 | alert + API Keys sheet | 不创建线程 |
| 助手发送/生成失败 | delivery / status 卡 | 是（重试回调） | 状态卡文案 + Retry | 由发送管线处理 |

| 健康资料不可用 | 引用失效 | 否 | unavailable tap 提示 | 无 |
| 卡片保存失败 | ViewModel 动作失败 | 视实现 | 通知（推断） | 清除 saving ID |
| Hosting / Diff 异常 | 未确认专项处理 | — | — | 当前未确认独立错误面 |

## 十六、当前实现、缺口与演进

### 当前实现

- SwiftUI 线程列表 + UIKit Diffable 消息宿主已落地。
- 26 种消息块均有渲染分支；健康资料用户侧分组、pending 占位、长按菜单已实现。

### 当前缺口

- 消息列表 / 卡片 / 锚定策略缺少自动化测试。

- 索引文档仍把「UI 状态」主要归在读模型专题，需与本专题交叉链接（见下节更新）。

### 建议演进

- 为 Diff / 锚定 / TimelineProjector 补单测，作为回归护栏。
- 明确消息删除：仅 UI 隐藏 vs 写 tombstone + 同步，并统一菜单文案。
- 收敛操作入口：要么恢复气泡下操作栏，要么从 API 移除死代码 `showActions`。
- 若启用 math mode，从菜单或设置显式接线，避免死 API。
