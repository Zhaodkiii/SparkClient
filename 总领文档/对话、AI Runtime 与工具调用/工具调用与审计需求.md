# 工具调用与审计需求

## 一、模块目标

本模块负责把模型（或调试命令）发出的 `tool_call` 变成可执行、可授权、可落库、可审计的客户端副作用。它是聊天助手「能做事」的执行面：读健康数据、插卡片、问用户、检索知识、联网搜索等，都经同一套 ToolHub 入口完成。

本模块覆盖：

- `SparkToolName` 工具目录、Schema、本地化提示与 Composer / AI Settings 白名单过滤。
- `ToolHub` 注册、路由、参数解析、执行分发与调试斜杠命令（`/tool`、`/audit_tools`）。
- Apple Health 敏感结果外传前的 Consent（允许 / 拒绝 / 始终允许）。
- 全局人机交互队列：授权、追问、选成员、健康资料候选、工具详情预览。
- `ToolSideEffect` → `MessageRunActor` 串行写入消息块（营养卡、睡眠/运动可视化、知识卡、任务卡等）。
- 进程内工具审计事件写入与调试读取。

本模块不覆盖：

- 场景模型解析、本地/远端推理网关、流式事件与工具能力硬降级（见 `AI Runtime 推理编排需求.md`）。
- 消息线程读模型、Core Data 投影与气泡渲染细则（见 `对话线程与消息读模型需求.md`）。
- 发送、附件、OCR、outbox 同步（见 `消息发送、附件与同步管线需求.md`）。
- 问报告资料选择器与 timeline 注入产品细节（见 `问报告与健康资源上下文需求.md`；本模块只固定问报告相关三个工具执行契约）。
- AI Settings 页的工具开关 UI 与服务端工具目录同步（见 `总领文档/AI 设置与本地模型/`）。

当前实现范围以 iOS `SparkClient` 代码为准。工单向需求见 `需求文档/对话/工具调用需求文档.md`，与本文冲突时以**当前可编译代码**为准，工单仅作待办增量。

### 目录职责与依赖方向

```text
SendChatMessageUseCase
  → ChatOrchestrator
      → AIRuntimeService（推理，见姊妹文档）
      → ToolHub.executeToolCall / runIfNeeded
          → Executors
          → AppleHealthToolConsentPolicy + ToolInteractionCoordinator（Consent）
          → ToolAuditStore
          → ToolSideEffect[] → MessageRunActor.apply
  → ChatView.sheet(ToolInteractionPresentationSheet)
```

- `Core/AIRuntime/ToolHub`：工具定义与执行内核；可依赖 Health / Knowledge / Search 等基础设施，**不**直接写消息 Core Data。
- `Features/Chat/Application`：副作用落库与发送编排；是 ToolHub 与消息读模型之间的唯一串行管道。
- `Features/Chat/Presentation/ToolInteraction`：仅人机交互 UI；不落库、不执行工具业务。
- 当前未单独拆 Domain 包：工具契约集中在 `ToolingModels.swift`，执行器以 `ToolHub` extension 文件存在。

### ToolHub 不承担 capability 决策（CHAT-000009）

能力选择（是否启用 tools / 知识库 / 联网、工具白名单、小任务历史替换）属于 **Capability 层**，由 `ChatCapabilityStrategy` 在 `SendChatMessageUseCase` 内算出 `ChatOrchestratorInferenceOptions` 后交给 `ChatOrchestrator`。

**ToolHub 边界：**

- 只接收已过滤的 `allowedToolNames` 与工具定义，负责执行、Consent、审计与产出 `ToolSideEffect`。
- **不得**引用 `ChatComposerRuntimeFlags`、`ChatOrchestratorInferenceOptions`、`SmallTask`、`ChatCapabilityStrategy` 等 capability 策略类型（由 `AIRuntimeArchitectureGateTests.testToolHubDoesNotReferenceCapabilityPolicyTypes` 门禁固化）。

副作用落库与 UI 展示见 `ToolSideEffectBlockMapper` / `MessageRunActor` / `ToolInteractionCoordinator`；回归测试见 `ToolSideEffectPipelineTests.swift` 与 `ChatOrchestratorDebugToolSideEffectTests.swift`。

### ToolHub 文件拆分（CHAT-000010）

`ToolHub` 仍为单一类型与单一 DI 对象；物理文件按职责拆分 extension，便于后续继续瘦身：

| 文件 | 职责 |
| --- | --- |
| `ToolHub.swift` | 类型声明、依赖注入、`shortID` |
| `ToolHub+Schema.swift` | `toolDefinitions` / `toolProperties` / `toolRequiredFields` / 本地化 helper |
| `ToolHub+Routing.swift` | `runIfNeeded` / `executeToolCall` / `execute` / 参数解析 |
| `ToolHub+Consent.swift` | Apple Health 模型外传 Consent |
| `ToolHub+Audit.swift` | 审计查询与写入 |
| `ToolHub+Shared.swift` | 执行器共享 helper（不变） |
| `Executors/*` | 单工具业务实现（不变） |

调试 slash 命令早退路径（`ChatOrchestrator` → `runIfNeeded` 命中）现已与模型 tool loop 一致：`result.sideEffects` 经 `MessageRunActor.apply(.toolSideEffect)` 落库。

## 三、工具目录与 Schema

### 需求说明

维护一份与服务端、本地化文案、AI Settings 白名单一致的工具目录，使模型只看到合法、可描述、可过滤的 OpenAI 兼容 tools schema。

### 基础要求与业务规则

- 工具名以 `SparkToolName` 穷举枚举为准；`rawValue` 必须与服务端 `SparkService/ai_config/models.py` 的 `SparkToolName` 一致。
- 新增工具必须同步：
  1. `ToolingModels.swift` 枚举与 `dataCategory` / `declaredSensitivity` / `egressPolicy`
  2. `ToolHub.toolProperties` / `toolRequiredFields` / `execute`（无 `default`，编译期强制补全）
  3. `Executors/` 实现或并入 `ToolHubExternalConnector`
  4. `ToolPrompts.strings`（`tool.summary.*` / `tool.param.*`）与 `Localizable.strings` 的 `ai_settings.tools.*`
  5. 按需更新 Onboarding / Composer 默认白名单
- 每个工具声明 `ToolDataCategory`、`ToolDataSensitivity`、`ToolEgressPolicy`；**声明策略不等于运行时 Consent**（见第五章）。
- `toolDefinitions()` 生成全量 `AIRuntimeToolDefinition`；聊天路径再由 Orchestrator 按 Composer 开关与 `allowedToolNames` 过滤。

主要工具分组（当前实现）：

| 分组 | 代表工具 |
| --- | --- |
| 健康读取 / 卡片 | `fetch_step_details`、`fetch_energy_details`、`fetch_nutrition_details`、`fetch_sleep_details`、`fetch_workout_details`、`make_nutrition_data`、`show_medical_risk_notice`、`generate_structured_health_card` |
| 问报告 | `list_member_health_sources`、`get_health_resource_reference`、`get_health_resource_context` |
| 知识 | `search_knowledge_bag`、`create_knowledge_document` |
| 成员 | `get_current_member`、`request_member_selection`、`find_member`、`switch_member`、`query_member_profile` |
| 记忆 | `save_memory`、`retrieve_memory`、`update_memory` |
| UI / 系统 | `ask_user_question`、`show_custom_message_card`、`generate_chat_title`、`create_canvas`、`edit_canvas`、`query_tasks_by_member`、`generate_task` |
| 外部连接器 | `search_online`、`read_web_page`、`search_arxiv_papers`、`extract_remote_file_content`、位置/天气/日历等 |

### 验收标准

- 新增 `SparkToolName` case 后，未补 `toolProperties` / `execute` 会导致编译失败。
- Composer 关闭知识/联网后，对应工具不会进入本轮 `tools` 列表。
- 工具摘要与参数说明可随语言环境切换（`ToolPrompts.strings`）。

### 技术细节与设计代码位置

Schema 编码（发给模型的 OpenAI 兼容形态）：

```text
AIRuntimeToolDefinition
  name / summary / properties / required
    → Gateway 编码为 tools[].type=function + function.{name,description,parameters}
AIRuntimeToolProperty
  type / description / enum / format / properties / required / items
    → 支持嵌套 object 与 array；与 ToolHub.toolProperties 一一对应
```

`ChatOrchestrator.filteredToolDefinitions` 过滤顺序：

1. `useTools == false` → 空列表，`toolChoice=.none`
2. `useKnowledgeBag == false` → 去掉 `search_knowledge_bag`、`create_knowledge_document`
3. `useWebSearch == false` → 去掉 `search_online`、`read_web_page`、`search_arxiv_papers`、`extract_remote_file_content`
4. `allowedToolNames != nil` → 仅保留交集（工具名 trim + lowercased 比较）

UI 分组 `SparkToolGroup`（健康 / 成员 / 位置 / 记忆 / 知识 / 系统）用于 AI Settings 展示，与 `dataCategory` 不完全等同（例如联网工具挂在 knowledge 组）。

白名单存储约定：

| API | 行为 |
| --- | --- |
| `SparkToolName.selectedSet(fromStoredToolNames:)` | 含 `__spark_tools_none__` → 空集；交集为空 → **默认全选** |
| `SparkToolName.storageValues(forSelectedToolNames:)` | 空集 → 存 sentinel；否则存排序后的 rawValue |

必填参数（`toolRequiredFields`，节选）：

| `create_knowledge_document` | `title`, `content` |
| `ask_user_question` / `list_member_health_sources` / `get_current_member` 等 | `[]`（可空） |

## 四、注册与执行内核

### 需求说明

提供统一执行入口：调试斜杠命令与模型 `tool_call` 共用同一套 `execute` 分发，产出 `ToolExecutionResult`（文本回灌 + 可选副作用 + 等待用户标记）。

### 基础要求与业务规则

入口：

| API | 触发 | 行为 |
| --- | --- | --- |
| `runIfNeeded` | 用户输入以 `/tool` / `/audit_tools` 开头 | 命中则执行并 `shouldBypassModel`；未命中返回 `.none` 进入推理 |
| `executeToolCall` | Orchestrator 收到模型 tool_calls | 解析 arguments JSON → `execute` → Consent → 填 toolCallID / 参数 → `appendAudit` |

`ToolExecutionResult` 关键字段：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `toolName` | `String` | 执行的工具名（通常为 `SparkToolName.rawValue`） |
| `outputText` | `String` | 回灌给模型（或 bypass 时直接展示）的文本 |
| `sensitive` | `Bool` | 是否含敏感数据（Consent 判定输入之一） |
| `shouldBypassModel` | `Bool` | 调试命令或拒绝外传等场景跳过模型 |
| `isAwaitingUserInput` | `Bool` | 需要用户交互；Orchestrator 锁工具 |
| `resolvedMemberID` | `Int?` | 工具切换成员后更新循环上下文 |
| `toolCallID` | `String?` | 模型本轮 tool_call id |
| `anchorToolCallID` | `String?` | 展示块锚定 id；默认由 Hub 用 `pendingToolCallID` 填充 |
| `arguments` | `[String: String]?` | 归一化调用参数，供详情 Sheet |
| `sideEffects` | `[ToolSideEffect]` | 需落库的 UI 副作用列表 |

调试命令：

- `/tool list`：列出工具（内部名 `tool_list`）。
- `/tool <name> <args>`：显式执行；受 `allowedToolNames` 约束。
- `/audit_tools`：最近 20 条审计摘要，bypass 模型。

失败、重试与恢复：

- 未知工具名：`outputText = "未识别工具：…"`，不抛异常。
- 执行器内业务失败以 `outputText` 文案表达。
- 工具层**无通用自动重试**；消息级重试由 `RetryFailedMessageUseCase` 负责整轮助手生成。
- `executeToolCall` **内部不接收取消令牌**；取消仅在 Orchestrator 轮次/每个 call 前检查。

### 验收标准

- 模型同一条 assistant 消息中的多个 tool_calls 全部串行执行并逐个回灌 `role: .tool`。
- `/tool` 命中后不进入模型推理，气泡 kind 为 tool。
- 执行后必有审计事件（含调试路径）。

### 技术细节与设计代码位置

`ToolHub` 构造依赖（组合根注入，执行器经这些能力访问业务）：

| 依赖 | 用途 |
| --- | --- |
| `chatRepository` | 读会话/消息辅助 |
| `auditStore` | 审计写入 |
| `medicalQueryAPI` / `healthResourceToolService` | 问报告与医疗查询 |
| `aiSettingsRepository` / `aiConfigCenter` / `runtimeService` | 配置与二次 AI 抽取 |
| `taskService` | 小任务读写 |
| Memory / Knowledge UseCases | 记忆与知识包 |
| `typedMedicalDocumentExtractor` | 结构化健康卡抽取 |
| `sideEffectSink`（`MessageRunActor`） | 异步副作用 |
| `healthTool` | HealthKit |
| `toolInteractionCoordinator?` | Consent / 追问 / 选成员 |
| `webSearchGateway` | 联网搜索 |
| `canvasStore: [String: String]` | 进程内画布（标题→正文） |

`executeToolCall` 管道：

```text
name + arguments(String)
  → parseArguments → ToolInvocation
  → ToolExecutionContext(member/thread/assistant/provider/model/…)
  → execute(switch SparkToolName | tool_list | 未识别)
  → applyModelEgressConsentIfNeeded
  → withToolCallID / withAnchorToolCallID / withInvocationArgumentsIfMissing
  → appendAudit
  → ToolExecutionResult
```

`parseArguments` 规则：

1. 空串 → `[:]`
2. 以 `{` 开头 → `JSONSerialization` 对象 → `flattenJSONObject`（嵌套 `a.b`；数组整段 JSON 字符串；`NSNumber`/`Bool` 转字符串）
3. 否则按空格切分 `key=value`
4. 仍为空 → 把整段填入 `query` / `content` / `title`(前 20 字) / `raw_text`（调试兜底）

`ToolHubResult`：`.none` | `.executed(ToolExecutionResult)`。

调用链：

```text
ChatOrchestrator.generateReply
  → toolHub.runIfNeeded（可选 bypass）
  → 或 toolHub.executeToolCall
      → execute(switch SparkToolName)
      → applyModelEgressConsentIfNeeded
      → appendAudit
```

## 五、编排边界与多轮 tool_call

### 需求说明

固定 ChatOrchestrator 与 ToolHub 的契约：编排层管循环与锁工具，ToolHub 管执行与授权，MessageRunActor 管落库。

### 基础要求与业务规则

- 最多 `maxToolRounds = 30`；超限回退兜底文案，`finishReason: "length"`。
- 同轮多个 tool_calls **串行**；任一 `isAwaitingUserInput` 则：清空 tools、`toolChoice=.none`、追加 system「禁止继续调工具」，并 `break` 本轮 call 循环后继续下一轮纯文本回复。
- 同步副作用在 `executeToolCall` 返回后立即 `messageRunActor.apply(.toolSideEffect…)`。
- 流式 UI：执行前 `emitToolPartial`（调用中），执行后再次 emit（参数 + 输出）。
- 深度细节与推理降级见 `AI Runtime 推理编排需求.md`；本文不重复网关实现。

### 验收标准

- 等待用户输入后，本轮不再向模型暴露 tools。

## 六、授权与 Consent

### 需求说明

在敏感健康工具结果离开设备、进入第三方模型上下文前，向用户征求明确授权，并支持「始终允许」跨启动记忆。

### 基础要求与业务规则

**当前实现策略**（`AppleHealthToolConsentPolicy`）同时满足才弹窗：

1. `result.sensitive == true`
2. 工具名为五类 Apple Health 读取工具之一：`fetch_step_details` / `fetch_energy_details` / `fetch_nutrition_details` / `fetch_sleep_details` / `fetch_workout_details`
3. `providerCompany` 不是 `LOCAL`
4. `ToolConsentPermissionStore` 中该工具尚未「始终允许」

用户决策：

| 决策 | 行为 |
| --- | --- |
| 允许一次 | 原结果回灌模型 |
| 始终允许 | `rememberAllowed` 写入 UserDefaults，原结果回灌 |
| 拒绝 / 取消 / conflict / 无 Coordinator | 替换为 blocked hint，`sensitive=false`，`shouldBypassModel=true`，**敏感原文不进模型** |

声明漂移（当前缺口）：

- `SparkToolName.egressPolicy` 对 member / memory / 多数 health 工具声明为 `requireConsent`，但运行时 **仅**上述五类 Health 读工具走 Consent。文档与设置文案不得把声明策略写成已实现的运行时行为。

持久化：

- Key：`spark.tool_consent.allowed_tools.v1`
- 仅写「允许集合」；**当前无撤销 UI / API**（推断：需清 UserDefaults 或后续补 revoke）。

### 验收标准

- 云端模型首次拿到敏感步数等结果前必须出现授权 Sheet。
- 拒绝后模型只收到 blocked 提示，不包含健康明细。
- 「始终允许」后同工具再次调用不再弹窗。
- 本地 `LOCAL` provider 不弹外传授权。

### 技术细节与设计代码位置

Consent 展示载荷由 `ConsentPayloadBuilder.makeSharePrompt` 组装：

| 类型 | 字段 | 说明 |

| `ExternalToolDataSharePayloadBlock` | `id`, `toolAPIName`, `friendlyTitle`, `argumentsText`, `resultText`, `fullResultCharCount` | 单工具参数/结果块；Codable 兼容旧键 `argumentsDisplay`/`resultDisplay` |

`modelEgressDeniedResult`：`outputText = PromptLocalizer().consentBlockedHint(reason:)`，`sensitive=false`，`shouldBypassModel=true`，**清空副作用语义由拒绝路径不返回原 result 保证**。

## 七、人机交互队列

### 需求说明

工具执行过程中需要用户介入时，使用全局 FIFO Sheet，不把交互状态写入消息流；交互完成后通过 Continuation 恢复工具执行。

| Snapshot | 用途 | 恢复结果 |

| `.member` | 成员选择 | `memberID` |

- 同时触发多个交互时按 FIFO 逐个展示，不叠多个业务 Sheet。

## 九、审计

### 需求说明

记录每次工具执行的摘要事件，供调试命令与诊断使用；明确当前存储边界，避免把「审计」误解为合规级落盘日志。

### 基础要求与业务规则

`ToolAuditEvent` 字段：`id`、`toolName`、`memberID`、`inputSummary`（参数描述前 200 字）、`outputSummary`（输出前 200 字）、`status`、`createdAt`。

写入时机：`executeToolCall` 与 `runIfNeeded` 成功走出 `execute` 后的 `appendAudit`。

状态判定（当前实现）：

```text
outputText 含「失败」（大小写不敏感）→ .failed
否则 → .success
```

- 枚举存在 `.denied`，但 **appendAudit 从未写入 denied**（拒绝 Consent 仍可能记为 success，因 blocked hint 不含「失败」）。
- 存储：`actor ToolAuditStore` 内存数组；`recent(limit:)` 按时间倒序。
- 读取：`/audit_tools` → `recent(20)` 文本摘要，`shouldBypassModel=true`。
- **无**按会话过滤、无上限裁剪、无导出、无进程外持久化、无 clear API。

### 验收标准

- 任意工具执行后 `/audit_tools` 能看到近期条目。
- App 重启后审计记录消失（当前实现预期行为）。
- 不得把内存审计当作合规审计完成项。

### 技术细节与设计代码位置

`ToolAuditEvent` 字段级契约：

| 字段 | 类型 | 写入规则 |
| --- | --- | --- |
| `id` | `UUID` | 默认 `UUID()` |
| `toolName` | `String` | `invocation.name`（非规范化展示名） |
| `memberID` | `Int?` | `context.memberID` |
| `inputSummary` | `String` | `arguments.description` 前 200 字符 |
| `outputSummary` | `String` | `outputText` 前 200 字符 |
| `status` | `ToolAuditStatus` | 见启发式 |
| `createdAt` | `Date` | 默认 `Date()` |

`ToolAuditStore`：

- `append`：无上限追加（进程内可能无限增长，当前缺口）。
- `recent(limit:)`：按 `createdAt` 降序，`prefix(max(1, limit))`。

`/audit_tools` 输出行格式：`[日期时间] toolName - status.rawValue`。

- `SparkClient/Projects/Core/AIRuntime/ToolHub/Audit/ToolAuditStore.swift`

## 十三、整体业务流程

```text
用户发送 / 重生成
  ↓
SendChatMessageUseCase → MessageRunActor 占位助手消息
  ↓
ChatOrchestrator.generateReply
  ↓
前置：cancellation + runIfNeeded（/tool|/audit_tools）
  ↓ 未命中
组包历史 + filteredToolDefinitions
  ↓
推理轮（≤30）
  ↓ 有 tool_calls
串行 executeToolCall
  → Executor 业务
  →（可选）Consent Sheet
  → appendAudit
  → apply sideEffects → MessageRunActor
  → 回灌 role:.tool
  → 若 awaitingUser → 锁工具并进入下一轮纯文本
  ↓ 无 tool_calls
汇总文本 / blocks → finalize 助手消息
```

### 成功路径

1. 模型发出合法 tool_call → 执行成功 → 文本回灌 → 副作用落库 → 继续推理或结束。
2. 调试 `/tool` → bypass 模型 → 直接 tool 气泡。
3. 敏感 Health 读 + 云端模型 → 用户允许 → 原结果进模型。

### 失败、重试和恢复

| 场景 | 行为 |
| --- | --- |
| 执行器业务失败 | `outputText` 描述失败；审计可能标 failed（依赖文案含「失败」） |
| Consent 拒绝 | blocked hint 回灌；敏感数据不出设备 |
| 工具轮次耗尽 | 兜底文案 |
| 消息级失败 | `RetryFailedMessageUseCase` 整轮重跑，不单重试某一个 tool_call |
| 结构化卡超时 | pending → failed 块 |

### 取消、并发和幂等

- 取消：Orchestrator 边界检查；单次 execute / 后台 Task 取消不完整。
- 并发：同轮 tool_calls 串行；副作用 Actor 串行；交互 Sheet FIFO。
- 幂等：稳定 block ID + revision；医疗风险卡合并策略；无工具级执行幂等 ID。

## 十四、状态模型

| 状态 | 进入条件 | 用户可见结果 | 退出条件 |
| --- | --- | --- | --- |
| 工具调用中 | 收到 tool_call，execute 未完成 | 气泡显示工具名/参数 partial | 执行返回 |
| 等待授权 | Health 敏感外传需 Consent | Consent Sheet | 允许/拒绝/取消 |
| 等待用户输入 | 追问/选成员/候选确认 | 对应 Sheet | 提交或取消；锁工具一轮 |
| 副作用落库中 | apply toolSideEffect | 卡片逐渐出现 | Actor upsert 完成 |
| 结构化卡 pending | 异步抽取开始 | pending 块 | ready / failed |
| 审计已记录 | appendAudit | 仅 `/audit_tools` 可见 | 进程结束清空 |
| 工具锁定 | `isAwaitingUserInput` | 模型不得再调工具 | 下一轮纯文本完成 |

## 十六、错误模型

| 错误类别 | 触发条件 | 是否重试 | 用户反馈 | 清理动作 |
| --- | --- | --- | --- | --- |
| 工具业务失败 | Executor 逻辑/数据源错误 | 否（工具层） | 工具输出文案 / 失败块 | 审计 failed（启发式） |
| Consent 拒绝 | 用户拒绝外传 | 否 | blocked hint | 敏感结果丢弃 |
| 交互 conflict | Sheet 队列冲突 | 否 | 按拒绝处理 | 无 |
| 取消生成 | 用户停止 | 否 | 停止流式 | 边界取消；后台 Task 可能残留 |
| 轮次耗尽 | >30 轮 tool | 否 | 兜底文案 | 结束本轮 |
| 结构化卡超时 | 抽取超时 | 否 | failed 块 | pending 升级为 failed |
| 白名单拦截 | `/tool` 不在允许列表 | 否 | 转入正常推理（`.none`） | 无 |
| 空解释器路径 | 旧 attachment 解释 | — | 无附件 | 富 UI 改走 sideEffect |

### 18.10 调用时序：Consent（示例）

```text
executeToolCall(fetch_step_details)
  → Executor 返回 sensitive=true + 健康明细
  → applyModelEgressConsentIfNeeded
      → AppleHealthToolConsentPolicy.requiresConsent == true
      → coordinator.requestConsentDecision(...)
          → ConsentPayloadBuilder.makeSharePrompt
          → enqueue .consent → ChatView Sheet
          → 用户 completeConsent(allowed:rememberTool:)
      → 若 allowed && rememberTool → rememberAllowed
      → 若拒绝 → modelEgressDeniedResult（不回传明细）
  → appendAudit(结果文本)
  → Orchestrator 回灌 outputText
```

### 18.11 调用时序：同轮多 tool_call + 副作用

```text
response.toolCalls = [A, B]
loopMessages += assistant(toolCalls:[A,B])
for A:
  emitToolPartial(调用中)
  resultA = executeToolCall(A)
  emitToolPartial(参数+输出)
  for e in resultA.sideEffects: apply(.toolSideEffect)
  loopMessages += tool(A)
  if awaiting: lock tools; break
for B: …（若未 break）
下一轮 generateTextStream(tools: locked?)
```

## 二十一、当前实现、缺口与演进

### 当前实现

- 完整 `SparkToolName` 穷举 Schema 与执行路由。
- 模型多轮 tool_call + 同步副作用落库。
- Apple Health 五类读工具云端外传 Consent +「始终允许」。
- 交互队列（授权/追问/成员/候选/预览）。
- 结构化健康卡异步管道。
- 联网搜索/读页真实网关；调试斜杠与内存审计。

### 当前缺口

1. 审计仅内存；`denied` 未写入；状态靠「失败」文案启发式。
2. `egressPolicy` 声明宽于运行时 Consent。
3. 位置/天气/日历等外部工具仍占位。
4. 工具执行中与后台抽取 Task 取消不完整。
5. 无工具级重试与执行幂等 ID。
6. Consent 无撤销入口；审计无按会话/导出。
7. 相关单测过时或缺失。
8. Orchestrator 调用 `executeToolCall` 时 `endpoint`/`privacyPolicyURL` 未传入（Consent UI 信息不完整）。

### 建议演进

1. 审计写入区分 success / failed / denied；可选按 `threadID` 索引与上限环形缓冲。
2. 对齐声明 `egressPolicy` 与运行时策略，或缩小声明范围避免误导。
3. 为 `executeToolCall` 传入取消令牌；结构化卡 Task 可取消。
4. 补齐外部连接器真实实现或从 Schema 中隐藏未就绪工具。
5. 提供「撤销始终允许」设置项。
6. 以 Mapper / Consent / Orchestrator 契约测替换过时解释器测。
7. 编排层补齐 Consent 所需的 endpoint / privacyPolicyURL。
