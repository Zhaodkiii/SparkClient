# 知识库、记忆与科普内容需求

## 一、模块目标

本文是 `SparkClient` 中“知识库、记忆与科普内容”专项文档，记录当前代码已经存在的三条内容链路及其边界：

1. `Knowledge`：账号隔离的本地知识文档、文件/网页导入、Markdown 切块、Embedding 向量索引和 Chat 检索。
2. `Memory`：账号隔离的长期记忆档案、偏好控制和 AI ToolHub 读写。
3. `PopularScience`：不要求登录的服务端科普内容列表、详情、缓存、Markdown 阅读、阅读统计和分享。

三者不能混用：科普文章不会自动导入本地知识库；长期记忆不是知识文档；知识库检索与记忆召回分别通过不同的 AI 工具完成。

本文以当前文件系统和代码为事实来源。`当前实现`、`当前缺口`、`建议演进`和`推断`分别表示不同确定性，不把原有需求稿中的规划误写成已落地能力。

当前实现是 SwiftUI + `@MainActor` ViewModel + UseCase/Repository 协议 + Core Data/HTTP 适配器的模块化分层架构。Knowledge 和 Memory 是本地持久化功能，PopularScience 是公开远端内容功能并带文件缓存；三者均在 iOS App 组合根中装配，不是独立进程或微服务。

## 三、知识库模块

### 3.1 本地文档管理

#### 需求说明

用户可以创建、编辑、查看、搜索和删除个人知识文档。文档包含标题、正文、摘要、来源、作用域、绑定模型、切块数量和向量索引状态。

#### 基础要求与业务规则

- 文档使用 `UUID` 标识，并按当前会话 `ownerAccountID` 隔离。
- `scope` 支持 `personal` 和 `agentBound`；`agentBound` 的 `boundModelID` 由领域模型保留。
- `source` 区分用户创建和 Tool/自动化流程创建。
- 文档正文更新时会重建文本切块并清除旧向量状态；仅元数据变化时保留现有索引。
- 删除文档时先删除其切块，再删除文档实体。
- 新建文档默认未完成向量索引，但创建时会先生成文本切块。

#### 主流程

```text
KnowledgeLibraryView / Editor
  → KnowledgeLibraryViewModel
  → Create/Update/DeleteKnowledgeDocumentUseCase
  → KnowledgeRepository
  → CoreDataKnowledgeRepository
  → KnowledgeDocumentEntity + KnowledgeChunkEntity
  → 刷新列表或详情状态
```

#### 失败、重试和恢复

- 未登录时仓库无法取得账号 ID，操作失败并由 ViewModel 转为 `errorMessage`。
- Core Data 读取/写入失败时不产生远端补偿；用户可通过页面重新触发加载或保存。
- 列表首次加载使用 `hasLoaded` 防重复请求；会话切换时通过 `resetForSessionSwitch()` 清空内存状态。
- 当前未确认删除操作是否有回收站或跨设备恢复能力。

#### 验收标准

- 新建、编辑、删除后的列表和详情与 Core Data 一致。
- 账号 A 的文档不能被账号 B 的列表、详情或检索返回。
- 正文为空、标题清理和更新失败时，用户能看到明确错误，不出现静默成功。
- 删除后对应切块不再参与检索。

#### 技术细节与设计代码位置

- 入口：`SparkClient/Projects/Features/Knowledge/Presentation/KnowledgeLibraryView.swift`、`KnowledgeDocumentDetailView.swift`。
- ViewModel：`SparkClient/Projects/Features/Knowledge/Presentation/KnowledgeLibraryViewModel.swift`、`KnowledgeDocumentEditorViewModel.swift`。
- 用例：`SparkClient/Projects/Features/Knowledge/Application/KnowledgeUseCases.swift`。
- 协议与模型：`SparkClient/Projects/Features/Knowledge/Domain/KnowledgeRepository.swift`、`KnowledgeModels.swift`。
- 持久化：`SparkClient/Projects/Features/Knowledge/Infrastructure/CoreDataKnowledgeRepository.swift`；实体定义在 `SparkClient/Projects/App/Resources/SparkClient.xcdatamodeld/SparkClient.xcdatamodel/contents`。

### 3.2 文件、网页和 OCR 导入

#### 需求说明

编辑器支持将本地纯文本/Markdown/PDF 文本或网页内容导入正文，也支持通过 OCR 将图片文字追加到编辑内容。

#### 基础要求与业务规则

- 文件支持 `txt`、`text`、`md`、`markdown` 和 PDF；无扩展名文件按 UTF-8 文本尝试。
- PDF 逐页提取文字；无可提取文字时返回 `pdfNoText`。
- 网页通过 `URLSession` 获取 HTML，再用 `NSAttributedString` 转换为纯文本。
- 不支持的扩展名返回 `unsupportedType`；文件访问使用 security-scoped resource 生命周期。
- OCR 复用 `OCROrchestrator` 的 `medicalDefault` 选项。

#### 主流程

```text
文件选择 / 网页 URL / 图片
  → ImportKnowledgeFromFileUseCase / ImportKnowledgeFromWebUseCase / OCRKnowledgeImageUseCase
  → UTF-8/PDF/HTML/OCR 文本
  → 编辑器草稿
  → 用户确认保存
  → KnowledgeRepository 创建或更新文档
```

#### 失败、重试和恢复

- 文件无法读取、UTF-8 解码失败、PDF 无文本、URL 无效、HTTP 非 2xx 和空响应均有专用错误分支。
- 网页导入使用 `URLSession.shared`，当前未发现离线网页缓存或断点恢复。
- OCR 失败由编辑器显示错误；当前未发现自动重试策略。

#### 验收标准

- 支持类型可以生成可编辑正文，不支持类型不会写入半成品文档。
- PDF 多页文字按顺序合并，空 PDF 有明确提示。
- 网页导入不把 HTML 标签直接写入正文。
- 取消或失败不会覆盖已有编辑草稿。

#### 技术细节与设计代码位置

- `SparkClient/Projects/Features/Knowledge/Application/KnowledgeImportUseCases.swift`。
- `SparkClient/Projects/Features/Knowledge/Application/KnowledgeTextProcessingUseCases.swift`。
- `SparkClient/Projects/Features/Knowledge/Presentation/KnowledgeDocumentEditorViewModel.swift`。

### 3.3 切块、Embedding 与知识库检索

#### 需求说明

知识文档被切分为检索最小单元。存在向量索引时优先进行 Embedding 语义检索；查询 Embedding 不可用或尚未建立向量时回退到本地词法打分。

#### 基础要求与业务规则

- `KnowledgeChunk` 保存所属文档、序号、正文和可选向量。
- Embedding 构建按 10 个文本块批量请求，返回数量必须与块数量一致。
- 建立索引前解析当前 AI 配置中的模型、API Key 和 Embeddings URL。
- 向量写入前删除旧切块，完成后更新 `isEmbeddingIndexed`、`chunkCount` 和 `lastEmbeddingModelName`。
- 检索查询为空直接返回空结果；知识库工具默认取 5 条，通用用例默认上限为 8 条。

#### 主流程

```text
搜索 query
  → SearchKnowledgeUseCase
  → 是否存在当前账号的 vectorData？
      ├─ 是 → 解析 AI Embedding 配置 → OpenAICompatibleEmbeddingClient → 余弦相似度 Top-K
      └─ 否/Embedding 失败 → CoreDataKnowledgeRepository 词法检索
  → KnowledgeSearchResult
  → ToolHub 知识卡或搜索页状态
```

#### 失败、重试和恢复

- 文档不存在、正文为空、向量数量不匹配会终止构建，不写入不完整索引。
- 查询 Embedding 失败会回退词法检索，保证 `search_knowledge_bag` 仍可用。
- 建索引过程中的网络失败不会自动继续批次；用户可再次执行重建。
- 当前未发现向量模型版本迁移、维度变更检测或全库批量重建调度。

#### 验收标准

- 文档内容修改后旧向量不被错误复用。
- 向量检索结果按相似度排序，未建索引或 Embedding 服务不可用时仍能返回词法结果。
- 不同账号的切块不会进入同一检索结果。
- Embedding 返回块数不一致时，文档不会被标记为已完成索引。

#### 技术细节与设计代码位置

- 切块与向量编码：`SparkClient/Projects/Features/Knowledge/Domain/KnowledgeChunking.swift`、`KnowledgeVectorCoding.swift`、`KnowledgeEmbeddingSimilarity.swift`。
- 用例：`SparkClient/Projects/Features/Knowledge/Application/BuildKnowledgeEmbeddingsUseCase.swift`、`KnowledgeUseCases.swift`。
- HTTP：`SparkClient/Projects/Features/Knowledge/Infrastructure/OpenAICompatibleEmbeddingClient.swift`。
- 仓库：`SparkClient/Projects/Features/Knowledge/Infrastructure/CoreDataKnowledgeRepository.swift`。
- AI 工具入口：`SparkClient/Projects/Core/AIRuntime/ToolHub/Executors/ToolHubSearchKnowledgeBag.swift`。

## 四、长期记忆模块

### 4.1 记忆档案与账号隔离

#### 需求说明

长期记忆保存用户可被 AI 跨对话召回的短文本记录，支持标题、正文、置顶、编辑、删除和全文关键词检索。

#### 基础要求与业务规则

- `MemoryRecordEntity` 使用 `ownerAccountID` 隔离数据，查询、更新、删除都带账号条件。
- 正文去除首尾空白后不得为空；无标题时从正文生成标题，标题最多 40 个字符。
- 归档列表按置顶优先、更新时间倒序排列。
- `MemoryPreferences` 使用按账号拼接的 UserDefaults Key 保存，包含启用、允许 Tool 写入、允许跨线程召回和最大召回数。
- 最大召回数限制在 1 到 20 之间，默认值为 5。

#### 主流程

```text
记忆设置/归档页或 AI Tool
  → Save/Load/Update/Delete/RetrieveMemoryUseCase
  → MemoryRepository
  → CoreDataMemoryRepository + MemorySearchEngine
  → 账号级记录/偏好 → 归档 UI 或 Chat Runtime 上下文
```

#### 失败、重试和恢复

- 未登录保存、更新、删除或保存偏好返回 `notSignedIn`。
- 空正文返回 `emptyContent`。
- 关闭记忆或禁止跨线程召回时，召回用例直接返回空结果；关闭 Tool 写入时，ToolHub 在写入前拦截。
- 当前未发现远端同步、回收站或自动合并重复记忆机制。

#### 验收标准

- 账号切换后旧账号记忆不出现在新账号归档或召回中。
- 置顶、搜索、编辑和删除结果可在重新读取后保持。
- 关闭跨线程召回确实阻止 `retrieve_memory` 返回数据。
- 关闭 Tool 写入不会阻止用户在归档页面手动管理记忆，除非上层另有明确限制。

#### 技术细节与设计代码位置

- 模型与协议：`SparkClient/Projects/Features/Memory/Domain/MemoryModels.swift`、`MemoryRepository.swift`。
- 用例：`SparkClient/Projects/Features/Memory/Application/MemoryUseCases.swift`。
- 检索：`SparkClient/Projects/Features/Memory/Domain/MemorySearchEngine.swift`。
- 持久化和偏好：`SparkClient/Projects/Features/Memory/Infrastructure/CoreDataMemoryRepository.swift`。
- ToolHub：`SparkClient/Projects/Core/AIRuntime/ToolHub/Executors/ToolHubSaveMemory.swift`、`ToolHubRetrieveMemory.swift`、`ToolHubUpdateMemory.swift`。

## 五、科普内容模块

### 5.1 列表、详情和 Markdown 阅读

#### 需求说明

科普模块从 SparkService 公开内容 API 获取已发布文章，提供一级 Tab、分页列表、分类筛选、详情 Markdown 阅读、空态/错误态和离线缓存兜底。

#### 基础要求与业务规则

- `PopularScience` 与本地 `Knowledge` 保持独立；当前主 Tab 已在 Chat 后、Settings 前展示科普入口。
- 列表支持 locale、分页、分类、标签、关键词和推荐筛选；实际页面 ViewModel 当前重点使用分类和分页。
- 详情可按文章 ID 或 slug 加载；正文由现有 `Core/Markdown/Markdown.swift` 渲染。
- 公开内容 API 的网络策略 `requiresAuth: false`，列表/详情使用 ETag 和默认幂等重试。
- 当前代码中详情页的标题、摘要、封面 UI 部分被注释，正文和参考文献区仍展示；这属于已存在但未完全呈现的 UI 缺口。

#### 主流程

```text
PopularScience Tab
  → PopularScienceHomeViewModel
  → LoadPopularScienceArticlesUseCase
  → RemotePopularScienceRepository
  → PopularScienceRemoteAPI
  → GET /api/v1/content/articles/
  → DTO 映射 + JSON 缓存
  → 文章列表

点击文章
  → PopularScienceArticleDetailViewModel
  → GET /api/v1/content/articles/{id}/ 或 {slug}/
  → Markdown(article.content) + 参考文献
```

#### 失败、重试和恢复

- 远端列表、详情和分类失败时优先读取对应 JSON 缓存；没有缓存才向 UI 抛出错误。
- 标签接口当前失败后不做缓存回退，直接抛错；需由上层决定是否影响页面。
- 文章详情打开只上报一次 view；页面消失或 App 进入后台时结束阅读并上报时长。
- 统计接口关闭重试且标记为非幂等，避免重复计数；统计失败不会阻塞正文阅读。
- 缓存写入和读取错误当前被 `try?` 忽略，无法向用户区分缓存损坏与无缓存。

#### 验收标准

- 未登录用户可以浏览公开文章；列表分页和下拉刷新不重复追加同一页。
- 远端不可用但存在缓存时可以进入列表/详情并显示离线提示。
- Markdown 正文、参考文献和分享入口与服务端详情数据一致。
- 文章打开、离开和后台切换不会重复发送同一阅读会话的 view 统计。

#### 技术细节与设计代码位置

- 主 Tab/路由：`SparkClient/Projects/App/Sources/App/MainTabCoordinatorView.swift`、`AppRouteStore.swift`。
- 页面与状态：`SparkClient/Projects/Features/PopularScience/Presentation/PopularScienceHomeView.swift`、`PopularScienceHomeViewModel.swift`、`PopularScienceArticleDetailView.swift`、`PopularScienceArticleDetailViewModel.swift`。
- 领域模型：`SparkClient/Projects/Features/PopularScience/Domain/PopularScienceModels.swift`。
- API/仓库/缓存：`SparkClient/Projects/Features/PopularScience/Infrastructure/PopularScienceRemoteAPI.swift`、`RemotePopularScienceRepository.swift`、`PopularScienceCacheStore.swift`。
- Markdown：`SparkClient/Projects/Core/Markdown/Markdown.swift`。

### 5.2 分享、阅读统计与服务端边界

#### 需求说明

客户端只负责消费内容和上报阅读行为；文章创建、编辑、发布、下架、版本和权限属于 SparkService 内容系统及后台管理端，不属于 iOS 客户端。

#### 基础要求与业务规则

- 分享优先使用详情已有 `shareURL`，没有时调用 `GET /api/v1/content/articles/{id}/share-link/`。
- 阅读打开调用 `POST /api/v1/content/articles/{id}/view/`。
- 阅读时长调用 `POST /api/v1/content/articles/{id}/reading-duration/`，包含秒数和可选 session ID。
- 服务端内容接口、客户端 API DTO 和 Domain 模型必须保持字段兼容，尤其是 `content_format`、`locale`、`slug`、引用和分享 URL。

#### 主流程

```text
详情加载成功
  ├─ reportView(articleID)
  ├─ 用户点击分享 → shareURL 优先，否则请求 share-link → 系统分享面板
  └─ 页面消失/进入后台 → 计算 duration → reportReadingDuration
```

#### 失败、重试和恢复

- 分享 URL 非法返回 `PopularScienceError.invalidShareURL`，不打开分享面板。
- 分享接口是只读幂等请求，可使用 ETag；统计接口禁用重试，失败只记录为统计失败。
- 当前未发现客户端对统计事件做本地持久化队列，因此进程被杀或网络断开时事件可能丢失。

#### 验收标准

- 客户端不出现文章发布、下架、版本回滚等后台权限入口。
- 分享失败不会影响用户继续阅读。
- 统计请求不会阻塞详情页面关闭，也不会因为普通网络重试重复计数。

#### 技术细节与设计代码位置

- 客户端接口：`SparkClient/Projects/Features/PopularScience/Infrastructure/PopularScienceRemoteAPI.swift`。
- 服务端内容模块：`SparkService/content/models.py`、`serializers.py`、`services.py`、`views.py`、`urls.py`。
- 服务端后台权限与文章状态入口：`SparkService/backoffice/rbac.py`、`SparkService/content/`。

## 六、整体业务流程

### 6.1 AI 使用本地知识与长期记忆

```text
ChatOrchestrator 决定启用工具
  → ToolHub 选择 search_knowledge_bag / retrieve_memory / save_memory / update_memory
  → 对应 UseCase
  → 账号隔离的 Core Data 仓库
  → 工具结果映射为文本或知识卡
  → Chat Runtime 消费结果
```

知识库工具返回知识卡时支持用户后续保存；`create_knowledge_document` 当前生成的是消息内草稿卡片，不直接写入知识库，必须由用户确认保存。

### 6.2 科普内容阅读

```text
RootTab.popularScience
  → 列表请求
  → 远端成功：映射并写 JSON 缓存
  → 远端失败：读取匹配 locale/筛选/页码的缓存
  → 详情请求
  → Markdown 渲染
  → 统计/分享副作用异步执行
```

## 七、状态模型

| 状态类别 | 知识库 | 长期记忆 | 科普内容 |
| --- | --- | --- | --- |
| 未开始 | `hasLoaded == false` | 归档未加载 | `phase == .idle` |
| 加载中 | `isLoading == true` | 由页面/用例调用期体现 | `phase == .loading` 或 `isLoadingNextPage` |
| 成功 | 文档/检索结果非空或空列表 | 记录列表/空列表 | `phase == .loaded` |
| 空数据 | 空文档、空检索结果 | 无记忆 | 服务端无文章或无匹配筛选 |
| 失败 | `errorMessage` | `LocalizedError` 转 Tool/UI 文案 | `phase == .failed`，或缓存也不存在时抛错 |
| 取消/离开 | 当前未见统一取消状态 | 当前未见统一取消状态 | 离开/后台结束阅读计时 |
| 未登录 | 仓库要求账号 ID | 读偏好默认值，写操作 `notSignedIn` | API 明确不要求登录 |
| 数据归属 | Core Data 文档/切块按账号 | Core Data 记录和 UserDefaults 偏好按账号 | 公开远端数据，缓存按 locale/文章/筛选键 |

## 八、数据与持久化

| 数据 | 存储 | 生命周期 | 敏感性与边界 |
| --- | --- | --- | --- |
| 知识文档正文/切块/向量 | Core Data `KnowledgeDocumentEntity`、`KnowledgeChunkEntity` | 随账号长期保存 | 可能含用户健康资料，不能跨账号检索 |
| 记忆正文/偏好 | Core Data `MemoryRecordEntity` + UserDefaults | 随账号长期保存 | 属于敏感个性化信息，ToolHub 返回结果标记为 sensitive |
| 科普列表/详情/分类 | Caches 目录 JSON | 可清理、可从服务端重建 | 公开内容，不是用户知识库数据 |
| ETag/网络缓存 | 通用 `DeviceCache`/网络层及科普文件缓存 | 由缓存策略控制 | 不承担数据事实源职责 |

当前未确认 Core Data 是否启用 CloudKit 或跨设备同步；模型实体的 `syncable` 属性存在，但本文不将其等同于已经完成的同步流程。

## 九、错误模型

| 场景 | 当前错误/处理 | 恢复方式 |
| --- | --- | --- |
| 知识库未登录 | 仓库要求当前账号 ID | 登录或切换有效会话 |
| 文档导入失败 | `unsupportedType`、`readFailed`、`pdfNoText` | 更换文件/URL后重试 |
| Embedding 配置/网络失败 | 构建失败；查询阶段回退词法检索 | 修正 AI 配置后重建索引 |
| 记忆正文为空 | `emptyContent` | 输入非空内容 |
| 记忆未授权 Tool 写入/召回 | ToolHub 前置拦截或用例返回空 | 在记忆设置中启用对应开关 |
| 科普远端失败 | 优先 JSON 缓存，无缓存则页面失败 | 重试；服务恢复后刷新 |
| 分享 URL 非法 | `invalidShareURL` | 重新获取或关闭分享 |
| 阅读统计失败 | 不阻塞页面；统计请求不自动重试 | 当前无本地补偿队列 |

## 十、与其他模块的接口边界

### 本模块负责

- 本地 Knowledge 文档和切块的生命周期、检索和索引。
- Memory 记录、账号级偏好和召回策略。
- PopularScience 公开内容的客户端消费、缓存和阅读副作用。
- 为 AI Runtime/ToolHub 提供稳定的 UseCase 入口。

### 本模块不负责

- AI 模型选择、API Key 管理和通用对话编排。
- 科普文章后台编辑、发布、下架、版本回滚和内容审核。
- 医疗事实源、成员权限或服务端文章内容的权威性校验。
- Knowledge 与 PopularScience 的自动导入或跨账号共享。

### 上游与下游

| 方向 | 模块 | 交接内容 |
| --- | --- | --- |
| 上游 | `ChatOrchestrator`、`ToolHub`、主 Tab 和编辑页面 | 查询、文档草稿、记忆操作、文章 ID/slug |
| 下游 | Core Data、AI Embedding API、SparkService Content API、Markdown 渲染器 | 文档/切块、向量、文章 DTO、Markdown 正文 |
| 横向 | 会话快照、AI 配置、网络层、日志 | 账号 ID、Embedding 配置、ETag/重试、错误日志 |

## 十二、测试策略

### 当前实现

已核对 `SparkClient/SparkClient/Tests`，当前未发现名称或路径明确对应 `Knowledge`、`Memory`、`PopularScience` 的专项测试。仓库虽有网络、AI、聊天等其他测试，但不能替代本专项验收证据。

### 当前缺口

- Knowledge：账号隔离、正文修改清索引、删除切块、向量数量不匹配、Embedding 失败回退词法、文件/PDF/网页导入边界。
- Memory：账号切换、偏好开关、空正文、置顶排序、更新匹配和删除全部记录。
- PopularScience：分页去重、ETag/缓存回退、按 ID/slug 双索引、统计去重、非法分享 URL和缓存损坏。
- 跨模块：ToolHub schema 与 UseCase 参数一致性、敏感结果标记、会话切换清理。

### 建议验收顺序

1. 先补 Repository 层内存替身测试，验证账号隔离和错误边界。
2. 再补 Knowledge 的切块、向量相似度和检索回退测试。
3. 补 PopularScience CacheStore/RemoteRepository 测试，再补 ViewModel 分页和生命周期测试。
4. 最后补 ToolHub 集成测试，验证工具开关、结果映射和副作用。

## 十三、当前实现、缺口与演进

### 当前实现

- 三个 Feature 目录、Domain/Application/Infrastructure/Presentation 分层和 App 组合根已经存在。
- Knowledge 和 Memory 均按账号 ID过滤 Core Data 数据。
- Knowledge 支持本地词法检索，并可选使用 OpenAI 兼容 Embedding 做余弦相似度检索。
- PopularScience 已接入公开内容 API、ETag、JSON 缓存、Markdown、分享和阅读统计。

### 当前缺口

- 本专项没有独立测试证据，不能宣称上述边界已被自动化验证。
- 科普详情页标题/摘要/封面等展示代码当前部分注释，实际 UI 与原需求稿目标不完全一致。
- PopularScience 标签列表缺少与分类相同的缓存回退。
- 阅读统计没有本地持久化补偿队列，进程终止可能丢失事件。
- Knowledge Embedding 没有确认的模型版本/维度迁移机制，也未发现全库批量重建入口。
- ToolHub 生成知识文档当前先产生知识卡草稿，不能直接视为已保存文档。

### 建议演进

- 为三类 Repository 提供可控的测试替身和统一测试夹具；收益是可以验证账号隔离和失败恢复，代价是需要维护协议与测试数据构造器。
- 为 Embedding 索引增加模型名、维度和索引版本校验；收益是避免旧向量误用于新模型，代价是需要一次迁移/重建策略。
- 为阅读统计增加轻量本地事件队列和去重键；收益是减少离线丢失与重复统计，代价是增加生命周期清理和隐私审计复杂度。
- 将科普详情页注释掉的元信息展示纳入明确版本验收；收益是客户端能力与服务端内容字段一致，代价是需要重新处理图片失败、长标题和无摘要状态。

## 十四、整体验收标准

- [ ] Knowledge、Memory、PopularScience 三个边界在代码和文档中保持独立。
- [ ] Knowledge 文档、切块和向量均按当前账号过滤。
- [ ] Knowledge Embedding 失败时检索仍可回退词法路径。
- [ ] 文件、网页、PDF 和 OCR 导入失败不会写入半成品内容。
- [ ] Memory 的保存、召回、更新、删除和偏好开关均按账号生效。
- [ ] 禁止 Tool 写入或跨线程召回时，ToolHub 不产生越权副作用。
- [ ] 科普列表和详情不要求登录，并在无网络时按匹配缓存兜底。
- [ ] 科普正文使用统一 Markdown 组件，分享、点击量和阅读时长请求边界清楚。
- [ ] 科普统计失败不阻塞用户阅读，且当前已明确未实现本地补偿。
- [ ] 为高风险的账号隔离、索引回退、缓存回退和 Tool 权限补充自动化测试。
