### 0.1 端到端状态流

```text
对话 Tab（院内名医默认）
-> 搜索 / 科室筛选
-> 医生卡
   -> 当前成员有最近绑定 thread：打开并续聊
   -> 无最近绑定 thread：POST conversations(agent_id, member_id)
-> ChatView
   -> 服务端 system 医生身份卡
   -> 点击身份卡：轻量医生详情
   -> 右上角新建对话：同 agent_id + 当时 member_id 新建医院会话
```

`GET /api/v1/hospital-care/conversations/?member_id=...` 仅用于找出每位医生智能体最近可续聊会话和卡片 CTA，不作为患者端的历史会话页面数据源。

## 1. 落地结论

医院 Demo 采用“新增独立医院 Tab + 改造对话 Tab 根页面”的方式落地：

```text
底部主导航（医院 Demo dashboard 模式）
├── 健康：保留现有家庭健康首页
├── 医院：新增医院服务首页
├── 对话：替换为院内医生智能体 + 最近医院会话列表
└── 设置：保留现有设置
```

关键决定：

1. 新增 `RootTab.hospital`，不把医院首页塞进现有 `healthHome` 的 pager 或样式开关。
2. 医院 Tab 首页只承担医院服务入口，不复制家庭健康档案首页。
3. 对话 Tab 在医院 Demo 中使用新的 `HospitalConversationListPage`；现有 `ChatConversationListPage` 保留给普通产品模式。
4. 新对话列表进入时不自动复用、不自动新建 ChatThread，必须由患者选择院内医生智能体后主动发起。
5. 登录账号下当前选中的 Member 就是当前患者；医院首页、挂号和对话列表共用同一个 MemberContext。
6. 真正进入聊天后继续复用现有 ChatView、ChatThread、ChatMessage、MessageBlock、同步和 AI Runtime。

## 3. 新主 Tab 需求

### 3.1 目标顺序

```text
健康        医院        对话        设置
heart       cross       messages    gear
```

- 医院 Tab 位于健康与对话之间，成为医院服务的稳定入口。
- 标签文案使用“医院”，不使用含义过宽的“服务”或可能被误解为医生问诊的“就医”。
- 图标建议使用医院建筑或医疗十字语义；最终 SF Symbol 在实现前做 iOS 版本可用性确认。
- iOS 26 使用系统 Tab/Liquid Glass；旧系统使用现有 TabView，不自行绘制假 TabBar。

### 3.2 RootTab 目标设计

- 新增目标值：`hospital = 10`。
- 选择 10 是因为现有 rawValue 已使用 0、2、3、4、5、7、8、9；不得重排旧值，否则会破坏已持久化的 selectedTab。
- 医院 Demo 模式的 visibleTabs：`healthHome / hospital / chat / settings`。
- 普通产品模式默认不显示 hospital，直到服务端提供有效医院配置或 Demo 开关生效。
- 从医院模式切回普通模式时，如上次选中 hospital，`ensureSelectedTabIsVisible` 回退 healthHome。

### 3.3 AppRoute 目标

| 目标路由 | rootTab | 是否根目的地 | 参数 |
| --- | --- | --- | --- |
| `hospitalHome` | hospital | 是 | 无 |
| `hospitalDepartment` | hospital | 否 | departmentID |
| `hospitalAgentDirectory` | hospital | 否 | departmentID 可选 |
| `hospitalAgentDetail` | hospital | 否 | agentID |
| `hospitalRegistration` | hospital | 否 | hospitalID、memberID、可选 doctorID |
| `hospitalChatThread` | chat | 否 | threadID、来源 hospital |

`hospitalChatThread` 只新增路由来源语义，不新增聊天数据模型。它仍构建现有 ChatView，但关闭/返回行为按来源回到医生智能体详情、院内对话列表或医院首页，不能复用 `automaticChatThread` 固定回健康首页的逻辑。

### 3.4 深链与通知

- 医院通知进入具体 thread 时使用 hospitalChatThread；服务端仍只传稳定 threadID 和医院上下文标识。
- 医生智能体分享链接进入 agent detail；登录和成员准备完成后再继续路由。
- 挂号跳转返回只恢复医院 Tab，不根据外部返回自动判定挂号成功。
- 账号切换继续调用现有 resetRouteGraph；设备级 selectedTab 保留，但必须重新校验 hospital 是否对新账号可见。

## 4. 新医院首页需求

### 4.1 页面目标

医院首页不是功能宫格堆叠页，而是围绕“我现在该去哪里、找谁、下一步做什么”组织：

```text
医院官方身份
-> 当前患者
-> 四个首要动作
-> 常用科室
-> 院内医生智能体
-> 就医服务和公告
```

### 4.2 首屏内容

1. 顶部医院身份：Logo、官方名称、服务状态；Demo 环境显示明确 Demo 标识。
2. 当前患者：直接读取当前 selectedMember；点击调用既有成员切换。
3. 首要动作：预约挂号、AI 导诊、报告解读、线上问诊。
4. AI 导诊是主按钮；它先做科室/风险引导，再推荐医生智能体，不直接创建无归属普通对话。
5. 未接真实 HIS 时，预约挂号显示“演示”或“前往医院挂号”，不显示虚假号源状态。

### 4.3 下半屏内容

- 常用科室：横向 4 个以内，进入 department detail 或过滤后的 agent directory。
- 院内医生智能体：最多显示 2 张推荐卡，提供“去问 AI 助手”；医生与 AI 身份同时可见。
- 就医服务：医院导航、门诊流程、报告查询、用药清单；无能力时隐藏或明确未开通。
- 医院公告：只显示一条重要公告，更多内容进入列表，不占据首屏。

### 4.4 患者切换

```text
点击当前患者
-> 复用 MemberProfileBindingMenu / 既有成员选择 Sheet
-> 现有 selectMember UseCase 更新 selectedMemberID
-> 医院首页、推荐、挂号上下文和对话列表并行刷新
-> 旧患者的历史会话不改绑
```

如果当前没有成员，页面只显示“添加就诊人”主动作；挂号、导诊、报告解读和问医生全部禁用，不能创建 memberID=nil 的医院会话。

## 5. 新院内对话列表需求

### 5.1 页面结构

```text
对话
├── 当前患者 + 切换
├── 搜索医生、科室或会话
├── 院内医生智能体（推荐横向列表 / 查看全部）
├── 状态筛选：全部、AI 服务中、医生已加入、已结束
└── 最近咨询
```

### 5.2 与普通对话列表的区别

| 行为 | 当前普通列表 | 新医院列表 |
| --- | --- | --- |
| 进入 Tab | 自动复用/创建并进入聊天 | 始终停留在列表 |
| 新建按钮 | 创建普通模型会话 | 不提供通用加号；从医生智能体发起 |
| 顶部内容 | 知识库入口 | 当前患者、医院智能体入口 |
| 列表范围 | 账号下全部 Thread | 当前 memberID + 当前医院的绑定 Thread |
| 列表头像 | 自定义会话图标 | 医生头像 + AI/真人状态 |
| 编辑外观 | 允许 | 医院会话标题和医生身份不可任意改写 |
| 删除 | 软删普通 Thread | 医疗历史默认不在列表直接删除；按服务端留存策略归档 |
| 置顶 | 用户置顶 | 可继续复用，但不能替代医院风险或医生关注状态 |

### 5.3 会话卡片

每张卡片必须展示：

- 医生头像、医生姓名、科室。
- 智能体名称或“真人医生已加入”。
- 当前患者姓名，避免家庭成员之间看错会话。
- 最新消息发言者前缀：AI 助手、医生姓名、我、系统。
- 服务状态：AI 服务中、待医生回复、医生已加入、已结束。
- 最新时间、未读数；中高风险提示使用独立行动标签。

禁止把医生后台“重点患者”标记展示给患者；该字段只影响医生工作台排序。

### 5.4 搜索和筛选

- 搜索范围：医生姓名、科室、智能体名称、现有 thread title、最新消息摘要。
- 当前患者是强制过滤条件，不提供隐蔽的跨成员混合列表。
- 切换患者后清空搜索与筛选，重新加载对应医院会话。
- 服务端分页和本地缓存并存时，搜索结果需注明“仅已加载”或调用服务端搜索，不能假装全量。

### 5.5 空态

```text
尚无院内咨询
选择医院医生 AI 助手，先描述你的不适或健康问题。
[浏览院内医生]
```

- 当前科室无智能体：提供返回全部科室。
- 医院停用：历史会话可读，隐藏发起咨询动作。
- 离线：展示已缓存历史；无法加载医生目录时给出重试。
- 当前成员无权限：返回成员选择，不显示其他成员数据。

## 7. 数据来源和状态

| 页面字段 | 来源 | 本地策略 |
| --- | --- | --- |

页面状态统一覆盖：loading、ready、refreshing、empty、partialFailure、offlineCache、unauthorized、hospitalSuspended、memberMissing。

## 9. 验收标准

1. 医院 Demo 模式冷启动默认进入医院 Tab；普通模式仍进入健康首页。
2. 新 hospital rawValue 不改变旧版已保存 Tab 的恢复结果。
3. 医院首页所有患者数据来自当前 MemberContext，切换患者与现有切换成员结果一致。
4. 对话 Tab 首次进入不会自动新建或自动打开会话。
5. 新对话只能从已发布医生智能体发起，并绑定当前 memberID。
6. 会话列表不会混入其他家庭成员或普通模型会话。
7. AI、真人医生、患者和系统消息在列表预览中均有文字身份。
8. 旧 ChatView、同步、知识库、记忆和 AI Runtime 没有平行实现。
9. 医院不可用或离线时，历史消息可读且不会显示虚假挂号成功。
10. iPhone 320pt 宽度、动态字体、深色模式和 VoiceOver 下核心动作可用。

## 10. 风险与待确认项

- 医院 Demo 开关由编译配置、远端配置还是账号医院绑定决定，需在 P0 冻结；客户端不得自行猜医院。

- classic 模式若也显示医院 Tab 会达到 6 个主入口；Demo 应固定 dashboard，正式产品再决定是否重组营养/运动入口。

## 11. 知识库自动同步确认结果

本节记录第 21–37 题确认结果，并覆盖旧文档中“患者侧不下载医院知识”的早期描述。

| 决策项 | 最终确认 |
| --- | --- |
| 同步触发 | 进入医生智能体会话后启动；不等待同步完成才展示 ChatView |
| 同步 UI | 完全静默，不显示进度、完成、文件数、向量数或错误提示 |
| Manifest 来源 | `conversation context` 直接返回当前智能体知识库 Manifest |
| 数据拉取 | 客户端按 `knowledge_base_id` 逐库拉取正文、切块、向量和墓碑 |
| 授权口径 | 医院知识库按公开患者科普资料处理；不使用 thread grant 或短期 sync grant |
| 内容红线 | 公开同步库不得包含内部诊疗规范、病历、处方、患者信息或受限资料 |
| 增量协议 | 复用现有 opaque `cursor/revision`；首次完整拉取，后续增量拉取 |
| cursor 作用域 | `account + hospital + agent + knowledge_base` |
| Manifest 缓存 | 先使用缓存 Manifest 和缓存检索，再后台静默刷新 |
| 向量可用 | 仅 `vector_status=current` 且向量对应当前正文 revision 时参与语义检索 |
| 向量不可用 | `not_built/stale` 或 revision 不一致时，仅关键词/全文检索；不得使用旧向量 |

| 知识库删除 | 增量 tombstone 到达后执行同样清理，不等待 TTL |
| 智能体下架 | 历史会话可读，禁止继续咨询，不再同步知识库 |
| 成员权限撤回 | 禁止发送和联网拉取，但演示版允许展示设备已有缓存；正式上线前必须重新评审 |

### 13.1 医院、科室和医生智能体

### 13.2 会话接口与 Manifest 扩展

| 状态 | Method | Path | iOS 用途 |
| --- | --- | --- | --- |
| 已有 | GET | `/api/v1/hospital-care/conversations/?member_id={member_id}` | 找当前成员在每个智能体下的最近会话，只用于 CTA/续聊，不渲染历史列表 |
| 已有 | POST | `/api/v1/hospital-care/conversations/` | 以 `agent_id + member_id` 创建医院会话 |
| 目标扩展 | GET | `/api/v1/hospital-care/conversations/{thread_id}/context/` | 返回现有上下文并增加 `knowledge_manifest` |

目标 `knowledge_manifest` 最小字段：

```text
knowledge_manifest
├── schema_version: integer
├── hospital_id: uuid
├── agent_id: uuid
├── manifest_revision: integer
├── updated_at: datetime
└── knowledge_bases[]
    ├── knowledge_base_id: uuid
    ├── profile_id: uuid
    ├── name: string
    ├── revision: integer
    ├── vector_status: not_built | current | stale
    ├── indexed_revision: integer | null
    ├── embedding_binding_id: integer | null
    ├── embedding_model: string | null
    ├── embedding_dimension: integer | null
    ├── content_hash: string
    ├── is_deleted: boolean
    └── updated_at: datetime
```

规则：

1. Manifest 只列当前智能体 `ClinicalAgentKnowledgeBinding.status=active` 且知识库未删除的绑定。
2. Manifest 表达**最新绑定状态**，不是会话创建时快照；解除绑定后下一次刷新必须消失。
3. `manifest_revision` 在绑定增加、解除、排序、知识库删除或可同步策略变化时递增。
4. `revision` 是正文版本；`indexed_revision` 是当前向量对应的正文版本。两者不相等时客户端禁止使用向量。
5. 会话上下文失败时，iOS 可打开本地会话并尝试按原 thread 在线发送，但暂停 Manifest 刷新，绝不降级为普通 AI 对话。

### 13.3 按知识库 ID 的公开只读增量同步

目标接口：

```text
GET /api/v1/hospital-care/knowledge-bases/{knowledge_base_id}/sync/pull/
    ?cursor={opaque_cursor}
    &limit={1...200}
```

授权口径：继续使用 App 正常登录态，但不校验 thread、member 或短期 grant；医院知识库 ID 对所有登录患者可读。该接口只允许读取，不提供 push/create/update/delete。

目标响应：

```text
knowledge_base_id: uuid
revision: integer
vector_status: not_built | current | stale
indexed_revision: integer | null
embedding_model: string | null
embedding_dimension: integer | null
cursor: opaque string | null
has_more: boolean
documents[]
├── id: uuid
├── title: string
├── content: string
├── excerpt: string
├── revision: integer
├── content_hash: string
├── is_deleted: boolean
├── deleted_at: datetime | null
├── server_updated_at: datetime
└── chunks[]
    ├── id: uuid
    ├── document_id: uuid
    ├── document_revision: integer
    ├── chunk_index: integer
    ├── content: string
    ├── content_hash: string
    ├── vector: number[] | null
    ├── embedding_binding_id: integer | null
    └── updated_at: datetime
```

同步语义：

- 无 cursor 表示完整快照；有 cursor 表示只返回该知识库在 cursor 之后的文档/切块变化和 tombstone。
- cursor 是 opaque token，iOS 不解析；只有整页在同一 Core Data 事务内成功落地后才能推进。
- 服务端必须保证正文、chunk、vector、`document_revision` 属于同一发布版本。
- `is_deleted=true` 必须携带足够 ID 供客户端删除正文、切块和向量。
- 分页任一页失败时，本轮视为失败，并执行已确认的“清空当前 agent scope”策略。
- 公开接口的数据红线必须在服务端发布流程落实，不能依赖 iOS 隐藏敏感字段。

## 14. iOS 缓存与持久化设计

### 14.1 两类缓存必须分开

| 缓存 | 生命周期 | 内容 | 失败策略 |
| --- | --- | --- | --- |
| 医院目录内存缓存 | 当前进程/账号 | 医院、科室、医生智能体、轻量详情 | stale-while-revalidate；失败保留旧缓存 |
| 医院知识持久缓存 | Core Data/账号 | Manifest 引用、正文、切块、向量、cursor | 同步失败清空当前 agent scope |

医院目录缓存参考成员健康数据现有缓存习惯，但需要独立 key：`accountID + resourceType + hospitalID + query`。同一请求 single-flight，防止页面重入、搜索和返回前台造成重复请求。

### 14.2 医院知识作用域

cursor 与检索作用域固定为：

```text
account_id + hospital_id + agent_id + knowledge_base_id
```

不得把 memberID 加入知识 cursor：医院资料是公开内容，不随患者成员改变。不得只按 knowledgeBaseID：同一知识库在多个智能体中的绑定、解除和本地清理必须互不影响。

推荐在现有 Knowledge Core Data 基础上增加“医院使用范围索引”，而不是复制第二套正文/切块/向量算法：

```text
HospitalKnowledgeScope
├── ownerAccountID
├── hospitalID
├── agentID
├── knowledgeBaseID
├── manifestRevision
├── knowledgeRevision
├── cursor
├── vectorStatus
├── indexedRevision
├── embeddingModel
├── lastManifestRefreshAt
└── lastSyncSucceededAt
```

医院作用域只读：不创建 Outbox，不允许编辑、上传、删除或 push。患者个人知识库 Tab 的查询必须排除医院 scope；普通 AI 对话的本地检索也必须排除医院 scope。

### 14.3 Manifest 缓存优先

```text
进入医生智能体 ChatView
-> 读取 account+hospital+agent 的缓存 Manifest
-> 有缓存：立即允许该 scope 本地检索
-> 无缓存：本地检索暂不可用，但 ChatView 和在线发送立即可用
-> 后台请求 conversation context
-> 比较最新 Manifest
   -> 绑定未变：逐库按 cursor 增量 pull
   -> 新增绑定：无 cursor 完整 pull
   -> 解除绑定：立即移除 scope 并清理该 agent 的对应本地检索数据
   -> revision 变化：立即停用旧向量，再增量 pull
   -> 知识库删除：按 tombstone 清理
```

这是产品确认的“缓存 Manifest 先用”方案，因此存在短暂使用旧绑定/旧内容的窗口。客户端不能声称资料已是最新；该风险在正式医疗上线前需要重新评审。

### 14.4 原子落地与失败清空

每一页的 Manifest/正文/切块/向量合并必须在同一后台 Core Data 事务完成。只有事务保存成功才写新 cursor。任一网络、解码、校验、向量维度或数据库错误均执行：

1. 取消当前 `account+hospital+agent` 的其余同步任务。
2. 清理该 agent 作用域下所有医院知识关联、正文可见范围、切块、向量、Manifest 和 cursor。
3. 若底层正文被其他 agent scope 共享，只移除当前 agent 引用；无其他引用后才物理删除共享数据。
4. 不清理个人知识库，不清理其他医院/智能体，不清理聊天消息。
5. 不显示同步错误；记录脱敏日志和指标。
6. 下次进入该会话时没有 cursor，重新完整同步。

## 15. 本地检索规则

| 状态 | 本地检索行为 | 在线咨询 |
| --- | --- | --- |
| Manifest/正文/切块/向量版本一致 | 关键词 + 向量混合检索 | 正常 |
| `vector_status=not_built` | 关键词/全文检索 | 正常 |
| `vector_status=stale` | 关键词/全文检索，旧向量禁用 | 正常 |
| `indexed_revision != revision` | 关键词/全文检索，旧向量禁用 | 正常 |
| 向量为空或维度不匹配 | 关键词/全文检索 | 正常 |
| 没有本地缓存 | 不执行本地检索 | 正常，由服务端按 thread/agent 处理 |
| 同步失败并已清空 | 不执行本地检索；下次进入重试 | 正常 |

检索请求必须显式携带当前 agent scope，不能调用“搜索账号下全部 KnowledgeDocument”的旧入口。返回结果只允许来自当前 Manifest 中仍关联的知识库。

服务端手动生成的向量直接同步给 iOS；iOS 不为医院资料重新调用 Embedding 模型。正文变化而服务端向量尚未重建时，iOS 使用已同步切块做关键词/全文检索。

## 16. 异常边界矩阵

| 场景 | 页面/缓存行为 | 发送行为 | 知识同步行为 |
| --- | --- | --- | --- |
| 医院列表为空/失败 | 自动切普通对话；院内名医显示重试 | 普通对话正常 | 不启动 |
| 医生目录失败、有缓存 | 展示离线缓存目录 | 继续咨询可打开缓存会话；开始咨询需联网校验 | 进入已有会话后按正常规则尝试 |
| 医生目录失败、无缓存 | 显示重试 | 不可开始医院咨询 | 不启动 |
| context 失败、有会话缓存 | 打开缓存医生身份和消息 | 允许尝试原 thread 在线发送；按服务端结果收敛 | 暂停 Manifest 刷新 |
| 普通网络发送失败 | 复用现有 ChatView 失败/重试 | 不转普通 AI，不新建无绑定 thread | 与消息失败隔离 |
| `AGENT_NOT_PUBLISHED` | 已有缓存会话只读；返回名医列表后不再展示该智能体 | 禁止发送/新建 | 停止并清理 agent scope |
| `HOSPITAL_INACTIVE/HOSPITAL_NOT_FOUND` | 医院目录不可用；已有缓存会话只读 | 禁止发送 | 停止 |
| `CONVERSATION_ENDED` | 保留历史页面，输入框禁用 | 禁止发送 | 不影响已落缓存；不再主动同步 |
| `MEMBER_ACCESS_DENIED` | 演示版展示设备已有缓存，不再联网拉消息 | 禁止发送 | 停止联网同步；不主动清缓存 |
| Manifest 请求失败 | 继续使用缓存 Manifest；无缓存则无本地检索 | 在线咨询正常 | 下次进入静默重试 |
| 知识 pull 任一页失败 | 清空当前 agent scope | 在线咨询正常 | cursor 归零，下次完整同步 |
| 知识库 404/删除 | 从当前 agent scope 移除并清缓存 | 在线咨询正常 | 不再重试该库，等待新 Manifest |
| vector stale/not built | 无 UI 提示，关键词降级 | 在线咨询正常 | 不在 iOS 自动生成向量 |
| Token 失效 | 复用现有统一刷新；刷新失败进入登录状态 | 不旁路鉴权 | 暂停全部同步 |
| 退出/切换账号 | 清空医院目录内存缓存，取消任务 | 使用新账号上下文 | 医院知识按 ownerAccount 隔离，不串账号 |

`MEMBER_ACCESS_DENIED` 后仍展示设备缓存是当前演示版明确选择，存在医疗隐私泄露风险。它不能标记为生产可接受；正式上线前必须改为清理缓存或由服务端提供合规的历史查看授权。

- `HospitalKnowledgeSyncCoordinator`：按 agent single-flight，取消、分页、原子提交、失败清空。
- 现有 Knowledge Repository：继续负责正文、切块、向量编码和词法/向量检索；查询必须增加 hospital agent scope。
- 现有 ChatView：只触发同步生命周期，不观察或渲染同步进度。

## 18. 实施顺序与验收

### P0 服务端契约冻结

1. 为 conversation context 增加 `knowledge_manifest`。
2. 增加按 `knowledge_base_id` 的公开只读 pull，包含正文、切块、向量、tombstone、cursor。
3. 补测试：公开读取红线、分页稳定性、revision 一致性、解绑/删除 tombstone、向量 stale。

### P1 医院目录内存缓存

1. 医院列表第一项选择。
2. account scope 缓存、立即展示、后台静默刷新。
3. 医院失败切普通对话；智能体目录缓存与重试。

### P2 Manifest 与只读同步

1. 新增 Manifest DTO、KB pull DTO、复合 scope cursor。
2. 接入 ChatView 进入/退出生命周期和 agent single-flight。
3. 验证医院知识不产生 Outbox、不出现在个人知识库。

### P3 本地检索与清理

1. 当前 agent scope 检索过滤。
2. vector revision 校验与关键词降级。
3. 解绑、删除、下架、失败清空和账号切换测试。

### 验收清单

1. 进入会话首屏和发送消息不等待知识同步。
2. 全程不显示同步进度、向量状态或同步错误。
3. 首次进入完整同步，后续使用独立 cursor 增量同步。
4. 当前 agent 不能检索未绑定知识库；个人知识库和普通 AI 对话不消费医院缓存。
5. 向量只在正文 revision 一致时使用；其他情况稳定降级关键词。
6. 同步任一页失败后，当前 agent scope 已清空，其他 agent 和个人知识不受影响。
7. 解除关联/删除后，下一次 Manifest/pull 清理本地引用、正文可见范围、切块和向量。
8. 智能体下架后历史可读、输入禁用、同步停止。
9. context 失败不会把医院会话转成普通 AI 对话。
10. 医院列表失败不阻断普通对话。
11. App 重启、切账号、快速切换会话和重复进入时没有 cursor 串用、重复页或并发覆盖。
12. 日志只记录 scope 哈希、数量、revision、错误码和 request ID，不记录正文、向量或患者消息。
