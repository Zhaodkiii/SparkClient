# 首页医疗数据缓存需求

> 关联文档：[首页医疗接口.md](./首页医疗接口.md)（负责 complete-data 拉取与首页卡片投影）。本文只覆盖 **客户端侧内存缓存**：持有、注入、字段级回写、跨页复用、失效与边界。

## 一、模块目标

首页医疗数据缓存负责把当前选中成员的 `/complete-data/` 聚合快照保存在首页进程内，并作为病历、体检、检查、用药等列表页与聊天「问报告」场景的首屏数据源，避免进入子页时再次全量拉取。

该模块需要统一处理：

- 缓存载体：`HomeDashboard.medical.completeData`（内存态）。
- 缓存注入：列表页、家庭药箱、聊天详情通过首页持有的快照直出。
- 字段级回写：列表局部刷新、增删改、明细懒加载后只 patch 对应字段。
- 特殊字段保留：`familyMedicineBoxes` 不由首页 complete-data 默认返回，刷新时需保留既有内存值。
- 失效与重建：成员切换、强制刷新、删除成员后重建；登出后随 `HomeViewModel` 生命周期释放。
- 账号/成员边界：缓存只对应当前选中成员；切换成员必须换新快照，不得串用。

业务价值：

1. 降低首页到医疗列表的重复网络请求。
2. 让列表页首屏可立即渲染。
3. 让聊天健康资源选择器优先命中本地快照。
4. 用字段级回写保持缓存新鲜，而不必每次重拉整个 complete-data。

**模块边界**

| 负责 | 不负责 |
| --- | --- |
| 首页内存中的 `completeData` 持有与 patch | 服务端 complete-data 聚合实现 |
| 列表页/药箱回写首页缓存 | 成员列表持久化（属 `MemberContextStore`） |
| 向 Chat / 列表页注入当前快照 | Disk / UserDefaults 持久化 complete-data（当前未实现） |
| `familyMedicineBoxes` 跨刷新保留 | 用药执行中心 9 天窗口缓存（`MedicationExecutionRecordCache`，独立机制） |
| 成员模块维护页的独立 `moduleSetupCache` 协作说明 | 把成员维护缓存与首页缓存自动双向同步（当前未打通） |

### 2.3 目录职责与依赖方向

```text
UI 列表 / Chat
    ↓ 读注入的 completeData；变更时回调
HomeMedicalRouteSupport（接线）
    ↓ updateMedicalCompleteData(transform)
HomeViewModel.dashboard.medical.completeData  ← 唯一首页医疗缓存根
    ↑ 全量重建
LoadHomeMedicalOverviewUseCase → MedicalQueryAPI.fetchMemberCompleteData
```

- **当前实现**：没有独立 Cache Store / Repository；缓存即 `HomeViewModel` 发布的 `HomeDashboard`。
- **当前未单独分层**：无 DiskCache、无 ETag 命中层、无按成员多槽 LRU。
- 依赖方向：Presentation 持有缓存；Application 只负责首拉/切换时全量写入；列表与 Chat 不得各自再持有一份“权威”完整快照（Chat 仅镜像，变更以首页为准同步）。

## 三、内存快照持有与注入

### 需求说明

首页加载成功后，必须把当前成员的 `RemoteMemberCompleteData` 放进 `HomeMedicalOverview.completeData`，并在进入医疗列表、家庭药箱、聊天相关入口时注入同一份引用视图（值类型拷贝/赋值），使下游首屏无需再请求 complete-data。

### 基础要求与业务规则

- 缓存位置固定为 `HomeViewModel.dashboard?.medical.completeData`。
- 注入入口：
  - 医疗列表：`HomeMedicalRouteSupport.medicalListView` 传入 `homeViewModel.dashboard?.medical.completeData`。
  - 家庭药箱：`familyMedicineCabinetView` 传入 `memberCompleteData`。
  - 聊天：`ChatView` 用 `initialCompleteData` / `onChange(of: homeViewModel.dashboard?.medical.completeData)` 同步到 `ChatDetailViewModel`。
- 成员 ID 必须一致才可复用：问报告选择器仅在 `initialCompleteData?.memberId == memberID` 时命中。
- 缓存为进程内内存态；进程杀死、登出或 `dashboard` 清空后不保留。
- `LoadHomeMedicalOverviewUseCase` 注释写明「无本地聚合快照」：即没有离线磁盘快照可读。

### 验收标准

- 首页 complete-data 成功后，进入病历/体检/检查/用药列表首屏不请求 complete-data。
- 聊天问报告在首页已有同成员快照时，可直接 `applyCompleteData`。
- 首页无 complete-data（失败降级为 `nil`）时，下游不得假装有缓存成功态。
- 切换选中成员后，列表注入的数据必须是新成员快照，不得继续展示旧成员列表。

### 技术细节与设计代码位置

- 领域字段：`HomeDashboard.swift` 中 `HomeMedicalOverview.completeData`。
- 全量写入：`LoadHomeMedicalOverviewUseCase.execute` → `HomeViewModel.load` 组装 `HomeDashboard`。
- 注入接线：`HomeMedicalRouteSupport.swift`。
- Chat 同步：`ChatView.swift`（`updateCachedMemberCompleteData`）、`ChatDetailViewModel.updateCachedMemberCompleteData`。
- 问报告命中：`ChatAskReportSheetViewModel` 构造时按 `memberId` 过滤。

## 四、字段级回写（列表局部刷新与变更）

### 需求说明

列表页下拉刷新、增删改、明细懒加载成功后，只回写 `completeData` 中对应字段，保持其它字段不变，避免再次进入页面重复请求或丢失其它模块数据。

### 基础要求与业务规则

统一回写 API：

```swift
HomeViewModel.updateMedicalCompleteData { completeData in
    // 仅修改目标字段
}
```

当前已接线的字段回写：

| 回调 | 回写字段 | 典型触发 |
| --- | --- | --- |
| `onMedicalCasesUpdated` | `medicalCases` | 病历列表刷新/增删改 |
| `onHealthExamReportsUpdated` | `healthExamReports` | 体检列表刷新、明细懒加载、删除 |
| `onExaminationReportsUpdated` | `examinationReports` | 检查列表刷新、明细懒加载、时间线补丁 |
| `onMedicationPlansUpdated` | `medicationPlans` | 用药计划变更（并可能触发提醒重建） |
| `onPrescriptionsUpdated` | `prescriptions` | 处方变更 |
| `onMedicineBoxesUpdated` | `medicineBoxes` | 个人药箱列表刷新/变更 |
| `onMemberCompleteDataChanged`（家庭药箱） | `familyMedicineBoxes` | 家庭药箱加载/变更 |

业务规则：

1. **只 patch 目标字段**，不得整体替换为“半成品”结构体导致其它字段被 `nil` 覆盖。
2. **归档列表默认不回写活跃缓存**：例如体检/检查在 `archiveMode != .active` 时把 `onReportsUpdated` 置 `nil`，避免归档数据污染首页活跃列表缓存。
3. **下拉刷新策略**：只请求当前资源列表接口（如 `listExaminationReportsWithAttachments`），不重拉 complete-data。
4. **明细懒加载也回写**：`MedExamDetailLazyLoadViewModel` 在明细加载成功后通过 `onReportsUpdated` 回写整表（含已补齐 `medExamDetails` 的条目）。
5. **前置条件**：`dashboard` 或 `completeData` 为 `nil` 时，`updateMedicalCompleteData` 直接 return，不创建空壳缓存。

### 验收标准

- 检查/体检下拉刷新成功后，再次进入同列表仍看到刷新后的数据，且不必重拉 complete-data。
- 刷新失败时保留原缓存，不把列表清空写回首页。
- 归档模式操作不得覆盖活跃态 `completeData` 对应字段。
- 用药计划变更回写后，若存在 `reminderEnabled`，应触发提醒重建（接线在 `HomeMedicalRouteSupport`）。

### 技术细节与设计代码位置

- Patch API：`HomeViewModel.updateMedicalCompleteData`。
- 回调组装：`HomeMedicalRouteSupport.medicalListView`。
- 列表刷新注释与实现：
  - `ExaminationReportsListPage.refreshReports`
  - `HealthExamReportsListPage.refreshReports`
  - `MedicineBoxListPage.refreshMedicineBoxes`
  - `MedicalCasesListPage.refreshCases`
- 明细回写：`MedExamDetailLazyLoadViewModel`（`onReportsUpdated?(reports)`）。
- 检查报告时间线局部补丁：`MedicalCaseTimelineRow.patchCompleteDataCacheIfPossible`。

## 五、家庭药箱字段保留与懒写入

### 需求说明

服务端首页 `/complete-data/` **默认不返回** `familyMedicineBoxes`。该字段只在用户进入家庭药箱并加载成功后写入首页缓存；之后首页全量刷新同一成员时，必须保留内存中已有的家庭药箱列表，避免页面空白。

### 基础要求与业务规则

- DTO 注释约定：`familyMedicineBoxes` 为按需懒加载字段。
- 家庭药箱页加载成功后：`completeData.familyMedicineBoxes = boxes`，经 `onMemberCompleteDataChanged` 回写首页。
- `HomeViewModel.load` 在写入新 complete-data 时：
  - 若新旧 `memberId` 相同；
  - 且旧缓存存在 `familyMedicineBoxes`；
  - 则把旧值拷到新快照上。
- 刷新失败时家庭药箱页保留原缓存，不回写空结果（见 `FamilyMedicineCabinetPage` 注释）。
- 切换到其他成员后，不得把旧成员的 `familyMedicineBoxes` 带入新成员快照（依赖 `memberId` 相等判断）。

### 验收标准

- 进入家庭药箱并加载成功后，返回首页再强制刷新同成员，家庭药箱数据仍可从缓存读出。
- 切换成员后，家庭药箱缓存不串成员。
- 家庭药箱刷新失败不把首页 `familyMedicineBoxes` 清空。

### 技术细节与设计代码位置

- 保留逻辑：`HomeViewModel.load` 中 `previousComplete.familyMedicineBoxes` 合并段。
- 回写：`HomeMedicalRouteSupport.familyMedicineCabinetView` → `updateMedicalCompleteData`。
- 页面：`FamilyMedicineCabinetPage` / `FamilyMedicineCabinetViewModel`。
- DTO：`MedicalSyncAPI.RemoteMemberCompleteData.familyMedicineBoxes`。

## 六、缓存失效、重建与并发

### 需求说明

缓存必须在成员上下文变化或用户主动刷新时正确失效/重建，并防止首屏重复请求。

### 基础要求与业务规则

| 事件 | 缓存行为 |
| --- | --- |
| 首屏 `loadInitialIfNeeded` | `dashboard == nil` 才加载；`isInitialLoadInFlight` 防重入 |
| `forceReload` / `refresh` | 重新拉取成员列表 + complete-data，整表替换（保留同成员家庭药箱） |
| `selectMember` | `load(syncRemote: false)` 重建当前成员医疗缓存 |
| `switchMemberAndLoad` | `load(syncRemote: true)` 重建 |
| `deleteMember`（删当前选中） | 清空选中后 `load(syncRemote: true)` 重建 |
| `reloadMembers` | 只更新成员列表，**保留**既有 `dashboard.medical` |
| complete-data 请求失败 | 用例返回 `completeData = nil` + 空卡片；首页成员区仍可展示 |
| 成员列表失败 | 抛错；上层保留既有 dashboard（不静默清空） |
| 登出 / ViewModel 释放 | 内存缓存随对象释放；当前无显式磁盘清理 |

关于 `syncRemote` / `refreshRemoteSnapshot`：

- `HomeViewModel` 注释写「false 优先使用本地缓存」。
- **当前实现**：`LoadHomeMedicalOverviewUseCase` 仍会请求 `listMembers` + `fetchMemberCompleteData`，`refreshRemoteSnapshot` 仅写入日志，**未改变请求策略**。因此“本地缓存优先”属于接口预留，不是当前磁盘/内存命中逻辑。

### 验收标准

- Coordinator 预加载与 `HomeView.task` 并发时，不会打出两次完整首屏加载。
- 成员列表失败时，已有 dashboard 不被清空成空成功态。
- 删除当前成员后，医疗缓存对应到新的选中成员或空态。
- `reloadMembers` 不会误清医疗 complete-data。

### 技术细节与设计代码位置

- 防重入与加载：`HomeViewModel.loadInitialIfNeeded` / `forceReload` / `load`。
- 成员切换：`selectMember`、`switchMemberAndLoad`。
- 成员删除：`deleteMember`。
- 仅成员刷新：`reloadMembers`。
- 用例：`LoadHomeMedicalOverviewUseCase`（`refreshRemoteSnapshot` 未驱动分支）。

## 七、旁路缓存与相关但不相同的机制

### 需求说明

项目中存在多处 “completeData / 记录缓存” 命名，必须区分权威源，避免误把旁路缓存当成首页医疗缓存。

### 基础要求与业务规则

| 机制 | 所有者 | 与首页缓存关系 |
| --- | --- | --- |
| `HomeDashboard.medical.completeData` | `HomeViewModel` | **权威首页医疗缓存** |
| `MemberSetupFlowViewModel.moduleSetupCache` | 成员模块维护流程 | 独立预加载/patch；**当前未确认**自动回写首页 dashboard |
| `ChatDetailViewModel.cachedMemberCompleteData` | 聊天详情 | 镜像首页；随 `onChange` 同步 |
| `MedicationExecutionRecordCache` | 用药执行中心 | 按日期窗口缓存用药记录，**不是** complete-data |

### 验收标准

- 文档与实现讨论中不得把 `MedicationExecutionRecordCache` 描述成首页医疗缓存。
- 成员维护页的 `patchCompleteData` 只改 `moduleSetupCache`，除非另有显式同步代码（当前未找到回写 `HomeViewModel` 的路径）。

### 技术细节与设计代码位置

- `MemberSetupFlowViewModel.patchCompleteData` / `moduleSetupCache`。
- `MedicationExecutionRecordCache.swift`。
- Chat 镜像：`ChatDetailViewModel.updateCachedMemberCompleteData`。

## 八、整体业务流程

```text
首页 load / 切换成员
  ↓
LoadHomeMedicalOverviewUseCase
  → listMembers
  → fetchMemberCompleteData(selectedMemberID)
  ↓
组装 HomeMedicalOverview(cards + completeData)
  ↓
HomeViewModel 写入 dashboard
  （同成员时合并保留 familyMedicineBoxes）
  ↓
同步 MemberContextStore / 可选加载 module settings
  ↓
用户进入医疗列表 / 家庭药箱 / 聊天
  ↓
注入 dashboard.medical.completeData
  ↓
子页首屏直出
  ↓
下拉刷新或本地变更成功
  ↓
回调 → updateMedicalCompleteData { 单字段赋值 }
  ↓
dashboard 发布 → 列表/Chat 观察者看到更新
```

### 成功路径

1. 首页拿到 complete-data → 卡片有统计 → 列表首屏零 complete-data 请求。
2. 列表局部刷新 → 仅对应字段更新 → 再次进入仍命中新数据。
3. 家庭药箱懒写入 → 首页全量刷新同成员仍保留药箱列表。

### 失败、重试和恢复

- complete-data 失败：`completeData = nil`，卡片空统计；用户可下拉首页 `refresh` 重试。
- 列表刷新失败：Toast + 日志；不回写失败结果；保留旧缓存。
- `updateMedicalCompleteData` 在无缓存时静默忽略：需先有成功的首页快照才能回写。

### 取消、并发和幂等

- 首屏 `isInitialLoadInFlight` 防止并发双载。
- 字段回写是同步主线程赋值，后写覆盖先写；同字段连续回写以最后一次为准。
- 归档模式切断回写回调，避免与活跃缓存交叉污染。
- 当前未确认：列表页是否对 in-flight 刷新做取消；从已读代码看多为新 Task 覆盖展示，失败则保留旧 UI。

## 九、状态模型

| 状态 | 进入条件 | 用户可见结果 | 退出条件 |
| --- | --- | --- | --- |
| 无缓存 | 未登录 / 未加载 / complete-data 失败 | 医疗卡片空或错误提示；列表无直出数据 | 加载成功 |
| 加载中 | `isLoading` / `isLoadingMedical` | 首页 loading | 成功或失败 |
| 有完整快照 | fetch complete-data 成功 | 卡片有 count；列表可直出 | 切换成员 / 强制刷新 / 删除成员 |
| 字段已脏写 | 列表回写成功 | 再次进入列表看到新数据；卡片 count **不一定**更新 | 全量 reload 重算卡片 |
| 家庭药箱已懒填充 | 家庭药箱加载成功 | 药箱页可直出 | 切换成员或进程结束 |
| 旁路维护缓存 | 打开成员模块维护 | 维护页使用 `moduleSetupCache` | 关闭流程 |

**重要缺口（当前实现）**：`updateMedicalCompleteData` 只改 `completeData`，**不会重算** `HomeMedicalOverview.cards`。因此列表增删后返回首页，卡片数量可能仍是旧值，直到下次全量 `load`。

## 十、数据与持久化

| 数据 | 所有者 | 存储位置 | 生命周期 | 清理时机 |
| --- | --- | --- | --- | --- |
| `completeData` 全量快照 | `HomeViewModel` | 内存（`dashboard`） | 当前登录会话 + 当前选中成员 | 切换成员覆盖、强制刷新、登出释放 |
| `cards` 投影 | `HomeViewModel` | 内存 | 与全量 load 绑定 | 全量 load 重算 |
| `familyMedicineBoxes` | 首页缓存字段 | 内存 | 同成员跨 refresh 保留 | 切换成员丢失旧值 |
| 选中成员 ID | `SelectedMemberIDPersisting` | 本地持久化 | 账号级 | 账号切换/显式清理 |
| 成员列表 | `MemberContextStore` | 内存 + 其自身持久化策略 | 账号级 | 成员变更/登出 |
| `moduleSetupCache` | `MemberSetupFlowViewModel` | 内存 | 维护流程期间 | 流程结束 |
| Chat 镜像缓存 | `ChatDetailViewModel` | 内存 | 跟随首页 onChange | 会话切换/释放 |
| 用药执行窗口记录 | `MedicationExecutionRecordCache` | 内存（页面态） | 执行中心会话 | 离开页面/窗口失效 |

敏感数据说明：complete-data 含病例、用药、检查等健康信息，仅内存持有降低落盘风险；但也意味着冷启动必重新拉取。

## 十一、错误模型

| 错误类别 | 触发条件 | 是否重试 | 用户反馈 | 清理动作 |
| --- | --- | --- | --- | --- |
| 成员列表失败 | `listMembers` 抛错 | 用户可手动刷新 | Toast / 保留旧 dashboard | 不清空已有缓存 |
| complete-data 失败 | `fetchMemberCompleteData` 失败 | 可首页刷新 | 卡片空态；成员区仍在 | `completeData = nil` |
| 列表单资源刷新失败 | 各 `list*` 失败 | 列表内可再下拉 | Toast | 不回写 |
| 无缓存却回写 | `dashboard`/`completeData` 为 nil | 否 | 无 | 忽略 patch |
| 成员 ID 不匹配 | Chat 注入不同成员快照 | 否 | 问报告自行再拉 | 丢弃 initialCompleteData |
| 401/会话失效 | 网络层鉴权失败 | 走全局会话清理 | 依网络模块 | 推断：dashboard 随登出释放（首页层未单独处理） |

## 十二、与其他模块的接口边界

### 本模块负责

- 首页内存 complete-data 的持有、注入、字段 patch、同成员家庭药箱保留。

### 本模块不负责

- complete-data HTTP 契约与服务端聚合（见 [首页医疗接口.md](./首页医疗接口.md)）。
- 成员 CRUD 与选中持久化（`MemberContext`）。
- 各医疗资源的表单/识别上传业务。
- 用药执行中心窗口缓存。

### 上游调用方

- `HomeView` / Coordinator 触发 load。
- 医疗列表、家庭药箱、Chat 读取与回写。

### 下游依赖

- `LoadHomeMedicalOverviewUseCase` + `SparkMedicalQueryAPI`。
- `MemberContextStore`（成员上下文，非医疗明细）。
- `NotificationClient` / `Logger`。

### 输入和输出契约

| 方向 | 模型 |
| --- | --- |
| 输入（全量） | `RemoteMemberCompleteData`（API） |
| 输入（回写） | 单字段数组/可选列表（cases、reports、plans…） |
| 输出（注入） | `completeData: RemoteMemberCompleteData?` |
| 输出（首页 UI） | `cards: [MedicalCard]`（仅全量 load 时更新） |

## 十五、当前实现、缺口与演进

### 当前实现

- 首页以内存 `completeData` 作为跨页权威医疗快照。
- 列表通过回调做字段级回写；家庭药箱懒写入并在同成员 refresh 时保留。
- Chat 镜像首页缓存，降低问报告重复请求。
- 首屏加载有防重入锁。

### 当前缺口

1. **卡片与 completeData 不同步**：回写不重算 `cards`。
2. **`syncRemote: false` 未真正跳过网络**：用例仍拉 complete-data。
3. **无磁盘持久化**：冷启动必全量请求（可能是有意设计）。
4. **成员维护 `moduleSetupCache` 与首页缓存未打通**。
5. **无缓存专项自动化测试**。
6. **多成员并行缓存**：当前只缓存选中成员一份；切回旧成员需重新拉取。

### 建议演进

1. 在 `updateMedicalCompleteData` 末尾按同一套 `makeMedicalCards` 规则重算 `cards`，或提供显式 `recomputeCards()`。
2. 若需要真正的 `syncRemote: false`，应在用例中命中内存快照并跳过 complete-data；或删除误导性参数。
3. 评估是否将选中成员 complete-data 做短时内存多槽（LRU），降低来回切换成本。
4. 明确成员维护结束时是否要把关键字段 merge 回首页缓存。
5. 为回写与家庭药箱保留补单元测试。

## 十六、整体验收标准

- [ ] 首页成功加载后，医疗列表首屏可直接消费 `completeData`，不再请求 complete-data。
- [ ] 列表局部刷新/增删改只回写对应字段，失败不污染缓存。
- [ ] 归档模式不覆盖活跃态缓存字段。
- [ ] 同成员全量刷新保留已懒加载的 `familyMedicineBoxes`；跨成员不串数据。
- [ ] Chat 仅在同 `memberId` 时命中首页缓存。
- [ ] 成员切换、删除、强制刷新后缓存与选中成员一致。
- [ ] 成员列表失败不静默清空已有 dashboard。
- [ ] 文档与实现区分首页缓存、成员维护旁路缓存、用药执行窗口缓存。
- [ ] 已知缺口（卡片不同步、`syncRemote` 未生效、缺测试）已显式记录，不当作已交付能力。
