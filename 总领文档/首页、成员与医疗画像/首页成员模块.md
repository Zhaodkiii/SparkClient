# 首页成员模块

> 范围：成员切换与选中持久化、成员级健康模块（`medical` / `nutrition` / 预留 `daily_health`）开通状态、首页分区显隐、公共成员添加/维护引导流，以及 `member-module-settings` 接口契约。  
> 相关文档：[首页医疗接口](./首页医疗接口.md)、[首页医疗数据缓存](./首页医疗数据缓存.md)。  
> 本模块**不**重新定义邀请分享票据协议、complete-data 聚合算法，或病历/体检等内容本体。

# 一、模块目标

首页成员模块负责回答五类问题：

1. 用户如何在首页成员条上切换当前成员，选中如何按账号持久化。
2. 当前选中成员开通了哪些健康能力模块（医疗、饮食等）。
3. 首页是否应展示医疗分区、饮食分区，或仅展示「去维护模块」入口。
4. 公共「添加成员 / 维护模块」页面有哪些步骤、按钮与落库时机。
5. 模块配置与小节进度如何写入服务端并回读。

当前实现的核心约定：

- **默认不开通**：没有对应 `isEnabled == true` 的模块配置时，首页不展示该分区。
- **分区显隐只看 `isEnabled`**：`isCompleted` 只影响维护态文案与完成徽章，不决定首页是否显示分区。
- **首页二次拉取配置**：即使 `complete-data` 已含 `memberModuleSettings`，`HomeViewModel` 仍在医疗加载成功后单独调用 `listMemberModuleSettings`（与 [首页医疗接口](./首页医疗接口.md) §3.5 一致，属已知缺口）。
- **新建成员默认开通医疗**：创建成功后写 `medical` enabled/incomplete，并跳过模块选择页直接结束。
- **`syncRemote` 当前未分流缓存**：`LoadHomeMedicalOverviewUseCase.refreshRemoteSnapshot` 只进日志，`selectMember(false)` 与 `switchMemberAndLoad(true)` 都会打远端（见 §3）。

# 三、成员切换

## 3.1 需求说明

已登录首页需要：

- 展示当前账号可访问成员列表（chips）。
- 允许用户切换当前成员，并驱动 complete-data、医疗卡片与模块分区同步到该成员。
- 冷启动恢复上次选中成员（按账号隔离）。
- 支持推送/用药提醒等场景强制切到指定成员并强刷。

## 3.2 基础要求与业务规则

### 3.2.1 首页成员条 UI（`HomeView.memberSelectorBar`）

| 元素 | 行为 |
| --- | --- |
| 待邀请铃铛 | `pendingInviteCount > 0` → `activeSheet = .pendingInvites` |
| 横向 chips | 数据源：`viewModel.dashboard?.members`；选中态胶囊高亮 |
| 未选中 chip 点击 | `viewModel.selectMember(member.id)` + light haptic |
| 已选中 chip 点击 | `confirmationDialog`：查看详情 / 分享（需 `canShare`）/ 取消 |
| 查看详情 | `activeFullScreenCover = .memberDetail(memberID:)` |
| 分享 | `activeSheet = .share(member)` |
| `+` | `activeSheet = .addMember(.create())` |
| 动画 | `.animation(.spring(0.3, 0.7), value: selectedMemberID)` |

成员条**不**调用 `switchMemberAndLoad`。

### 3.2.2 `selectMember` vs `switchMemberAndLoad`

| API | 实现 | 调用方 |
| --- | --- | --- |
| `selectMember(_ memberID: Int?)` | 写 `selectedMemberID` → `memberContextStore.select` → `Task { await load(syncRemote: false) }`（**不等待**） | 成员条、新建 `onCreatedMemberCompleted`、维护 sheet `onMemberCreated` |
| `switchMemberAndLoad(_ memberID: Int)` | 同上但 `await load(syncRemote: true)` | **主要** `HomeLaunchIntentConsumer`（用药提醒 / 健康资源变更等） |

两者成功后都会：`LoadHomeMedicalOverviewUseCase` → 更新 dashboard / Context → `loadCurrentMemberModuleSettings()`。

### 3.2.3 选中持久化

| 层 | 路径 | 规则 |
| --- | --- | --- |
| Protocol | `SelectedMemberIDPersisting` | `load/save/clear(for accountID:)` |
| 实现 | `UserDefaultsSelectedMemberIDStore` | Key：`memberContext.selectedMemberID.<accountID>` |
| Store | `MemberContextStore.select` / `update` | 有 `activeAccountID` 才 `persistSelection` |
| 冷启动解析 | `LoadHomeMedicalOverviewUseCase` | 优先级：**本次传入 `selectedMemberID`** → **持久化** → **排序后首位** |
| 成员排序 | 同 UseCase | `isPrimary` 优先，再按 `updatedAt` |
| 登出 | `clearSessionPersistenceAndReset()` | 清持久化；仅 `resetInMemoryContext()` 只清内存 |

`HomeViewModel` 不直接读写 UserDefaults。

### 3.2.4 切换后刷新链

```text
selectMember / switchMemberAndLoad
  → load(syncRemote:)
    → listMembers + fetchMemberCompleteData(resolvedSelectedID)
    → dashboard / selectedMemberID / memberContextStore.update
    → loadCurrentMemberModuleSettings
         GET …/resources/?kind=member-module-settings&member_id=…
  →（load 末尾）fetchPendingInvitesIfNeeded
```

家庭药箱兼容：同 `memberId` 时保留上一份 `familyMedicineBoxes` 内存补丁（见医疗接口/缓存文档）。

### 3.2.5 与 `reloadMembers` 差异

| | `load` / select / switch | `reloadMembers` |
| --- | --- | --- |
| 触发 | 用户切成员、`refresh`、删除后整页加载等 | `membersDidChange`（增删改后局部刷新） |
| 成员列表 | 经 medical overview `listMembers` | 仅 `loadMembersUseCase` |
| complete-data / 卡片 | **重建** `dashboard.medical` | **保留旧** medical |
| module settings | **会**重拉 | **不会** |
| 选中解析 | 入参 > 持久化 > first | 当前 ID 仍在列表则保留，否则 first |

### 3.2.6 `syncRemote` 真相

- 参数名暗示「是否刷新远端快照」。
- **当前实现**：`refreshRemoteSnapshot` 仅写入日志字符串，**不**跳过网络请求。
- 因此文档不得把 `selectMember(false)` 写成「只读缓存」；应记为**意图未落地 / 已知缺口**。

### 3.2.7 失败语义

| 场景 | 行为 |
| --- | --- |
| `listMembers` / 医疗主路径抛错 | `notificationClient.error`；early return；**不**刷新 settings；保留旧 dashboard |
| settings list 失败 | `currentMemberModuleSettings = []`；warning；**无 toast** → 易露出维护卡 |
| 无 selectedMemberID | settings 清空；无维护卡 |

`SelectMemberUseCase` 在 MemberContext 装配存在，但首页切换路径**未**使用。

## 3.3 验收标准

- [ ] 点击未选中 chip 后，选中态、医疗卡片、模块分区均对应该成员。
- [ ] 杀进程重进后，同账号应恢复上次选中（若该成员仍存在）。
- [ ] 切到另一账号不得读到上一账号的选中 ID。
- [ ] 推送切成员走 `switchMemberAndLoad` 时必须 await 完整 load。
- [ ] `reloadMembers` 后若未再 `load`，医疗快照与 settings 可变陈旧——行为需与产品预期一致或补刷新。
- [ ] 不得将 `syncRemote:false` 误验收为「离线缓存命中」。

## 3.4 技术细节与设计代码位置

- UI：`HomeView.swift`（`memberSelectorBar`）
- VM：`HomeViewModel.selectMember` / `switchMemberAndLoad` / `reloadMembers` / `load`
- 持久化：`SelectedMemberIDPersisting.swift`、`MemberContextStore.swift`
- 解析：`LoadHomeMedicalOverviewUseCase.swift`
- 推送入口：`HomeLaunchIntentConsumer.swift`

# 四、模块配置加载与首页分区显隐

## 4.1 需求说明

确定当前成员后，根据模块配置决定医疗区、饮食区或维护入口是否渲染。

## 4.2 基础要求与业务规则

- 触发：`load` 成功更新 Context 之后 → `loadCurrentMemberModuleSettings()`。
- 未选中成员：`currentMemberModuleSettings = []`；维护分区不展示。
- `isModuleEnabled`：同 `moduleCode` 任一条 `isEnabled == true` 即展示。
- `shouldShowModuleMaintenanceSection`：`selectedMemberID != nil && !medical && !nutrition`。
- **默认不开通**；`isCompleted` **不参与**显隐。
- settings 失败：清空 + warning，无 toast。
- 医疗主路径失败：early return，**不**刷新 settings。
- `reloadMembers()`：**不**重载 settings。

## 4.3 验收标准

- [ ] 仅 `medical`/`nutrition` 且 `is_enabled=true` 时展示对应分区。
- [ ] 双未开通且已选中成员时必须展示维护入口。
- [ ] 切换成员后分区不得串用上一成员 settings。

## 4.4 技术细节与设计代码位置

- `HomeViewModel.shouldShowMedicalSection` / `shouldShowNutritionSection` / `shouldShowModuleMaintenanceSection`
- `HomeView.swift` 条件渲染与维护卡 → `HomeSheet.memberModuleSetup`

# 六、成员模块配置读写接口

## 6.1 需求说明

模块开通状态以成员为粒度持久化，供首页、详情、维护流、Onboarding 共用。

## 6.2 基础要求与业务规则

| 操作 | Method | Path | Query / Body |
| --- | --- | --- | --- |
| List | GET | `/api/v1/medical/resources/` | `kind=member-module-settings` + `member_id` + 可选 `module_code` |
| Create | POST | `/api/v1/medical/resources/` | `kind=member-module-settings` + SavePayload |
| Update | PATCH | `/api/v1/medical/resources/{id}/` | `kind=member-module-settings` + SavePayload |

Upsert（`saveModuleSetting`）：先 list(moduleCode) 取 first → update 或 create。

`saveSectionProgress`：合并 progressMap；`isEnabled=true`；宽松 `isCompleted`。

`markModuleSelected`：`isEnabled=true`，保留原 `isCompleted`。

## 6.3 验收标准

- [ ] list 必带 kind + member_id。
- [ ] 同成员同 module_code 重复保存应更新而非堆多条（客户端 upsert）。
- [ ] section_progress 可 round-trip。

## 6.4 技术细节与设计代码位置

- `MemberModuleSetupUseCase`
- `MedicalQueryAPI.list/create/updateMemberModuleSetting`
- `MemberModuleSectionProgressCodec`

# 七、公共成员添加与维护页面细节

## 7.1 需求说明

提供统一的成员建档与模块维护体验：创建基本信息、默认开通医疗、维护时勾选/完善医疗与饮食模块。邀请接受、分享绑定、简单编辑仍可走 `AddFamilyMemberView` 传统表单；**create + homeDependencies** 时整页替换为 `MemberSetupFlowView`。

## 7.2 入口装配矩阵

| 入口 | Sheet / Cover | 实际页面 | mode |
| --- | --- | --- | --- |
| 首页 `+` | `HomeSheet.addMember(.create)` | `AddFamilyMemberView` → **`MemberSetupFlowView(.create)`**（有 homeDependencies） | create |
| 首页维护卡 | `HomeSheet.memberModuleSetup(member)` | `MemberSetupFlowView(.maintain)`；`onMemberCreated` → `selectMember` + `refresh()` | maintain |
| 已选 chip → 详情 | `HomeFullScreenCover.memberDetail` | `MemberDetailView`（内嵌 maintain VM，**不**经模块选择页） | maintain 子集 |

| Onboarding | fullScreenCover | `MemberSetupFlowView` create/maintain | 同左 |

首页维护回调（代码事实）：

```text
onMemberCreated: { member in
  viewModel.selectMember(member.id)
  Task { await viewModel.refresh() }
}
```

新建成功回调通常仅 `selectMember(member.id)`（内部已会 `load`）。

## 7.3 Create 流程（`MemberSetupFlowView`）

```text
[根] MemberNameBirthStepView
      底栏：下一步（姓名非空 canAdvanceFromBasicInfo）
      工具栏：关闭 dismiss
   └─ .birthDate → MemberBirthDateStepView
         底栏：下一步 | 跳过（均可进 relationship；未改 DatePicker 时 birthDate 可能仍 nil）
      └─ .relationship → MemberRelationshipGenderStepView
            底栏：创建（loading=isSavingMember||isPersistingModules）| 上一步
            onNext:
              createMember()
              → enableDefaultMedicalModuleForCreatedMember()
                   save medical isEnabled=true, isCompleted=false, summary=""
              → onMemberCreated?(member)
              → dismiss()
            ※ 成功路径不进入 .modules（默认开通医疗后直接结束）
```

说明：

- Navigation destination 仍注册 `.modules` / medicalSummary / nutritionSummary，但 **create 成功路径不可达**（历史/维护共用栈）。
- `.task`：`preloadModuleSetupCacheIfNeeded`；`loadExistingModuleSettingsIfNeeded` 在 create 模式因 mode 直接 return。
- Alert：`alertMessage`；title 使用 `common.ok`（实现细节）。

## 7.4 Maintain 流程（首页 Sheet）

```text
init(maintain member):
  createdMember = member
  draft 回填姓名/生日/关系/性别
  navigationPath = [.modules]   // 根 NameBirth 仍在栈底，其上 push modules

[modules] MemberModuleSetupView
  加载中：ProgressView「正在读取已开通模块」；整页 disabled（isLoadingExistingModules）
  顶部 Hero + 基本信息卡片（若有 createdMember）
  行：可见模块 MemberModuleToggleRow
      点击 → openModuleSummary（进 medicalSummary/nutritionSummary，不是直接 sheet）
      ※ FlowView 传入的 onOpenModule={ openSheet } 在选择页主路径上被汇总页路径覆盖使用
  底栏：
      完成（canFinish）→ completeModuleSetup
      暂不完善 → 同 completeModuleSetup（Done=Skip 同路径）
  completeModuleSetup:
      finish() → 对 selectedModules 可见项 saveModuleSetting(isEnabled:true, isCompleted:…)
      → onMemberCreated?(member) → dismiss()

回填 loadExistingModuleSettingsIfNeeded:
  优先旁路 complete-data.memberModuleSettings
  否则 list API
  isEnabled → selectedModules
  isEnabled && isCompleted → completedModules
失败：Alert「模块配置加载失败…」
```

`canFinish`：至少一个可见 selected，且非 `isPersistingModules` / `isLoadingExistingModules`。

**当前缺口**：`finish()` **从不写 `isEnabled=false`**，无 delete；无法在维护流关闭已开通模块。

## 7.5 医疗 / 饮食汇总与 Sheet

```text
模块选择 / 详情入口
  → medicalSummary / nutritionSummary
     Medical:
       Header 进度；「一键完整流程」；小节卡片
       进页约 0.4s 可自动 openFullFlow() → sheet .medical(.full)
       底栏：完成 finishModule | 暂不填写 skipModule(=markModuleSelected 持久化 enabled)
       小节 → openMedicalSheet(section entryMode)
     Nutrition:
       无自动 full；小节列表（basic_info）
       底栏同构：完成 / 暂不填写
Sheet 完成回调:
  full → markModuleCompleted（多数仅本地 Set）
  section → markSectionCompleted → saveSectionProgress + 旁路 patch
```

`markModuleCompleted(_:summaryText:)`：**多数调用只改本地 `completedModules` Set**，真正写服务端依赖 `saveSectionProgress` / `finish` / 显式 `saveModuleSetting`。

Lifestyle：`daily_health` 汇总打开 `MemberLifestyleSetupSheet` 占位，不在可见勾选列表。

## 7.6 旁路 complete-data 缓存

- `MemberModuleSetupCacheContext` 在维护流预加载 / 强制刷新 complete-data。
- `MemberModuleSetupCompleteDataPatcher.upsertModuleSetting` 等只改旁路缓存。
- **不直接回写** `HomeViewModel.dashboard.medical.completeData`；返回首页依赖 `selectMember` + `refresh`/`load`。

## 7.7 MemberDetail 入口差异

```text
模块总览行
  医疗 → openMedicalModuleSummary（push summary + preload cache）
  饮食 → openNutritionModuleSummary
状态文案 fallback：settings 缺失但已有医疗/饮食数据时，详情可显示「已开通」
动作：已开通→「去维护」；否则「去开通」
完成后：refresh cache + detail.reload + membersDidChange
※ 不经过 MemberModuleSetupView，也不关 HomeSheet
```

与首页差异：首页 settings 失败 = 未开通（可能出维护卡）；详情可有数据 fallback 为已开通。

# 八、整体业务流程

## 8.1 首页首屏（成员 + 模块）

```text
HomeView.task
  ↓
loadInitialIfNeeded / load
  ↓
listMembers + complete-data（解析 selected：入参>持久化>首位）
  ↓
MemberContextStore.update（含持久化）
  ↓
loadCurrentMemberModuleSettings
  ↓
按 isEnabled 渲染医疗 / 饮食 / 维护入口
```

## 8.2 用户切换成员

```text
点击未选中 chip
  ↓
selectMember(id) → Context.select（持久化）
  ↓
load(syncRemote:false)  // 当前仍打远端
  ↓
新成员 complete-data + settings → UI 刷新
```

## 8.3 维护流开通

见 §7.4–7.5；返回后 `selectMember` + `refresh` → 再次 settings。

## 8.4 失败、重试和恢复

| 场景 | 行为 |
| --- | --- |
| 首页 settings 失败 | 清空；无 toast |
| 医疗 load 失败 | toast；settings 不更新 |
| 维护流 load/save 失败 | Alert |
| 详情 settings 失败 | 可 fallback「已开通」 |

无自动重试；用户刷新首页或重进维护流。

## 8.5 取消、并发和幂等

- `isPersistingModules` 防 finish / 默认开通重入。
- Upsert 先 list 再写；跨页面无锁。
- `selectMember` 用 `Task{}` 不 await，快速连点可能并发多个 `load`（依赖 load 内部 generation/状态；以代码为准做回归）。

# 九、状态模型

| 状态 | 进入条件 | 用户可见结果 | 退出条件 |
| --- | --- | --- | --- |
| 无选中成员 | `selectedMemberID == nil` | 无维护卡；settings 空 | 选中成员 |
| 切换加载中 | `isLoading` / `isLoadingMedical` | 可能保留旧卡片直至成功 | load 结束 |
| 未开通 | 无 enabled medical/nutrition | 隐藏两区；有选中则维护卡 | 开通并刷新 |
| 仅医疗 / 仅饮食 / 双开通 | 对应 enabled | 分区显示 | 切换成员或关闭（客户端无关闭） |
| 开通未完善 | enabled && !completed | 分区仍显示 | 完成引导 |
| 首页 settings 降级 | list 抛错 | 等同未开通 | 下次成功 |
| 维护加载中 / 持久化中 | Flow VM flags | Progress / 按钮禁用 | 成功或 Alert |

# 十、数据与持久化

| 数据 | 所有者 | 存储位置 | 生命周期 | 清理时机 |
| --- | --- | --- | --- | --- |
| `selectedMemberID` 持久化 | SelectedMemberIDStore | UserDefaults 按 accountID | 跨启动 | 登出 clear |
| `currentMemberModuleSettings` | HomeViewModel | 内存 | 当前会话/成员 | 切成员、失败清空 |
| 服务端 module settings | 后端 | DB | 账号+成员 | 服务端删除（客户端无 delete） |

| 维护旁路 complete-data | CacheContext | 内存 | Sheet 生命周期 | dismiss |
| Member 列表 | Context / dashboard | 内存 + 远端 | — | 登出 |

# 十五、当前实现、缺口与演进

## 15.1 当前实现

- 成员条切换 + 账号级选中持久化 + 推送强切。
- 首页二次 list settings 控制三区显隐。
- create 默认开通 medical；maintain 模块选择与医疗/饮食引导。
- 旁路 complete-data patch；详情模块入口。

## 15.2 当前缺口

1. `refreshRemoteSnapshot` 未实现缓存分支。  
2. 首页成员条不调用 `switchMemberAndLoad`。  
3. `reloadMembers` 不刷新 settings/complete-data。  
4. settings 失败无 toast，易误显维护入口。  
5. 首页不复用 complete-data 内 settings（重复请求）。  
6. 无法关闭模块（无 isEnabled=false / delete）。  
7. `markModuleCompleted` 名实不符。  
8. UseCase 宽松完成 vs 汇总页严格完成不一致。  
9. 模块选择页 Done=Skip 同 `finish()`。  
10. 维护旁路缓存与首页 dashboard 不同步。  
11. `SelectMemberUseCase` 未用于首页切换。  
12. MemberDetail fallback 与首页失败语义分裂。  
13. create 成功路径跳过 `.modules`（路由仍注册）。  
14. `daily_health` 仅占位。  
15. 无专项自动化测试。

## 15.3 建议演进

- 落地 `syncRemote` 真缓存分支，或删除误导参数并统一强刷语义。  
- 首页优先消费 complete-data.settings，失败再 list。  
- `reloadMembers` 后按需刷新 settings，或强制跟随 `load`。  
- 明确关闭模块产品语义后补 API。  
- 维护成功回调直接 patch `currentMemberModuleSettings`。  
- 统一详情与首页的「settings 失败」展示策略。  
- 补齐切换 / 分区 / upsert 单测。
