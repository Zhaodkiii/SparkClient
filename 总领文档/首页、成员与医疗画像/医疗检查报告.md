# 医疗检查报告需求

> 所属模块：`总领文档/首页、成员与医疗画像/`  
> 关联文档：[首页医疗接口.md](./首页医疗接口.md)、[首页医疗数据缓存.md](./首页医疗数据缓存.md)、[体检报告.md](./体检报告.md)（对照）  
> 边界说明：本文只覆盖 **医疗检查报告（Examination Report）**——检验 / 影像 / 病理。**不覆盖**体检报告（`HealthExamReport`）。  
> **UI/模型/加载细节**：见下文「二点五」（三类报告页面、卡片、字段表、数据加载时序）。

## 一、模块目标

医疗检查报告模块负责在已登录、已选中成员的前提下，为用户提供检查类医疗档案的完整闭环能力：

1. 从首页「检查」卡片进入列表，首屏直接消费 `complete-data.examinationReports`。
2. 按分类筛选与时间线分组浏览报告摘要与附件。
3. 按需懒加载 `MedExamDetail` 细项，并回写首页缓存。
4. 手工新建、拍照/文件上传 + OCR 识别入库。
5. 详情查看、编辑、删除、归档/取消归档、公开分享。
6. 与病历（`medicalRecord`）关联、附件绑定，以及病历时间线中的交叉补丁。

**业务价值**

- 把「一次完整检查」从首页概览落到可检索、可编辑、可归档的档案。
- 与体检报告共享明细懒加载基础设施，但资源 kind、`business_type`、UI 分类规则均独立。
- 列表局部刷新只打 `examination-reports`，避免重拉整个 complete-data。

**适用范围**

| 覆盖 | 不覆盖 |
| --- | --- |
| `kind=examination-reports` 列表/详情 CRUD | `kind=health-exam-reports` 体检报告 |
| `kind=med-exam-details` 且 `business_type=examination_report` | 通用医疗报告 `RemoteMedicalReport` |
| 首页卡片 `.medicalReports` → 路由 `.examinationReports` | 用药计划 / 药箱 |
| OCR 文档类型 `.medicalReport` | OCR 流水线内部实现细节（属医疗文档上传模块） |

**当前实现范围（代码已验证）**

- 列表、分类时间线、明细懒加载、下拉刷新单字段回写。
- 手工新建（`ExamReportFormView` + `MedicalRecordFormSubmissionService`）。
- 详情编辑/删除/归档/分享、服务端明细替换写。
- 归档列表入口（`archiveMode=.archived`，不回写首页活跃缓存）。
- 病历时间线中的检查项局部补丁。

## 二点五、页面设计、三类卡片、公共组件、数据模型与数据加载

> 本节按当前 iOS 代码还原实验室 / 影像 / 病理的 UI 与模型字段，供 HarmonyOS / 跨端对齐。能力流程仍见后文第三～九节。

### 2.5.1 三类报告总览（同一套报告头，三种展示语义）

检查报告**没有三套独立后端资源**。后端只有：

| 层 | 资源 / 类型 | 说明 |
| --- | --- | --- |
| 报告头 | `kind=examination-reports` → `RemoteExaminationReport` / `WithAttachments` | 一份检查报告一条 |
| 细项 | `kind=med-exam-details` → `RemoteMedExamDetail` | `business_type=examination_report`（兼容 `examination`） |
| 客户端分类 | `ExaminationReportCategory` | `laboratory` / `imaging` / `pathology`，用于筛选、时间线、卡片与详情分型 |

分类如何决定（`ExaminationReportCategory.category(for:)`）：

1. 优先匹配 `category` / `subCategory` 标准字面：`laboratory|lab|实验室检查|检验|化验` → 实验室；`imaging|image|影像|影像学检查` → 影像；`pathology|病理|病理检查` → 病理。
2. 否则在 `category/subCategory/itemName/findings/impression/extra.summary|abstract` 拼接文本中做关键词命中（影像含 CT/MR/超声等；病理含「病理」等）。
3. **兜底：实验室**。

| 分类 | 图标 SF Symbol | 色 | 列表卡片内容侧重 | 明细详情页 |
| --- | --- | --- | --- | --- |
| 实验室 `.laboratory` | `testtube.2` | systemBlue | 项数/正常/异常三格 + 异常要点折叠 | 完整表：`LaboratoryReportDetailPage`；单行导航当前走影像卡片页（见下「实现注意」） |
| 影像 `.imaging` | `camera.fill` | systemIndigo | 科室/医生 + 印象；所见临时隐藏 | `ImagingReportDetailPage`（模态/部位/结果/诊断） |
| 病理 `.pathology` | `doc.text.magnifyingglass` | systemOrange | 大类/亚类 + 所见/印象 + 最多 5 条细项预览 | `PathologyReportDetailPage`（结果 + 病理诊断） |

**实现注意（代码已验证，跨端须知情）：**

- `ExaminationReportCategoryDetailPage` 中 **实验室单条子项** 与影像一样路由到 `ImagingReportDetailPage`（实验室分支被注释）；**完整检验宽表**仍由摘要页「查看完整检验表」进入 `LaboratoryReportDetailPage`。
- 列表卡片点「查看详情」进入的是 **报告总览** `ExaminationReportDetailHostPage` → `ExaminationReportSummaryDetailPage`，不是直接进三类明细页。

### 2.5.7 数据加载细节（完整时序）

#### 阶段 0：首页聚合（本模块前置）

1. `LoadHomeMedicalOverviewUseCase`：`listMembers` → `fetchMemberCompleteData`。
2. `examinationReports` 进入 `HomeDashboard.medical.completeData`（**不含**或空 `medExamDetails`）。

#### 阶段 2：按卡片懒加载明细

触发：`ExaminationReportCategorySection` 内每个 `LabReportCard.task { onLoadDetails(id) }`。

```text
loadDetailsIfNeeded(reportID)
  guard 下标存在
  guard medExamDetails == nil          // 已是 [] 也不再请求
  guard !loadingIDs.contains(id)
  loadingIDs.insert
  GET resources/?kind=med-exam-details
       &member_id=&business_type=examination_report&business_id=

失败：仅 logger.warning，不 toast，保持 nil 以便重试
```

并发：同 ID 由 `loadingIDs` 去重；不同 ID 可并行。

#### 阶段 3：下拉刷新（单资源）

```text
失败：toast source=home.examination_reports.refresh；保留旧 reports
```

注意：刷新结果通常再次使 `medExamDetails` 缺失，需重新懒加载（建议演进：按 id 合并旧明细）。

#### 阶段 4：详情内补拉

`ExaminationReportDetailPage.task`（server 模式）：若明细仍缺，再调 `listMedExamDetails` + `filterMedExamRows`（accepted 同协议）。

- 首屏不注入 complete-data；`.task` 调 `refreshReports` 拉 `archived=true`。
- `onReportsUpdated == nil`，不污染首页活跃数组。

## 三、列表首屏与首页缓存消费

### 需求说明

用户从首页「检查」卡片进入后，应立即看到当前成员的检查报告摘要列表，无需等待 complete-data 二次请求。列表数据来源是首页已持有的 `RemoteMemberCompleteData.examinationReports`。

### 基础要求与业务规则

- 首页卡片 kind `.medicalReports` 映射路由 `.examinationReports`（命名历史：卡片叫 medicalReports，资源 kind 为 examination-reports）。

- 归档列表传入 `onReportsUpdated: nil`，避免把归档集写回首页活跃缓存。

- [ ] 归档页操作不污染首页 `examinationReports`。
- [ ] `memberID == 0` 时无新增/上传入口，刷新无请求。

## 十、整体业务流程

```text
首页检查卡片
  ↓
HomeMedicalRouteSupport.medicalListView(.examinationReports)
  ↓
注入 completeData.examinationReports → ExaminationReportsListPage
  ↓
本地筛选 / 时间线分组渲染
  ↓
（可选）展开卡片 → MedExamDetailLazyLoadViewModel.loadDetailsIfNeeded
  ↓ listMedExamDetails(business_type=examination_report)
  ↓ onReportsUpdated → HomeViewModel.patch examinationReports
  ↓
（可选）下拉刷新 → listExaminationReportsWithAttachments → replaceReports → patch
  ↓
（可选）手工新建 / OCR 上传 → 写 API → prepend/刷新列表 → patch
  ↓
进入详情 → 查看 / 编辑 / 删除 / 归档 / 分享
  ↓ Mutation / Archive / Share API
  ↓ 回调 upsert/remove → patch 首页缓存
```

### 成功路径

1. 有成员 + complete-data → 列表直出 → 用户浏览/筛选。
2. 懒加载成功 → 缓存带明细 → 再次进入零请求。
3. 刷新成功 → 列表与首页 count 同步。
4. 写操作成功 → 列表即时更新并 patch。

### 失败、重试和恢复

| 场景 | 行为 |
| --- | --- |
| 列表刷新失败 | toast + 保留旧列表；不清空缓存 |
| 明细懒加载失败 | 仅日志；摘要保留；可再次触发（仍为 nil 时） |
| 更新报告失败 | 详情 alert / notification；不乐观覆盖 |
| 删除失败 | 不调用 `onDeleted`；列表保留 |
| 无网络 | 依赖网络模块错误映射；用户可见 toast/alert |

### 取消、并发和幂等

- 明细加载：同 ID `loadingIDs` 防并发重复。
- 更新明细：先删后建，非差分 patch；并发编辑可能互相覆盖（当前无版本号乐观锁，**缺口**）。
- 归档列表刷新与活跃回写隔离（`onReportsUpdated == nil`）。

## 十一、状态模型

| 状态 | 进入条件 | 用户可见结果 | 退出条件 |
| --- | --- | --- | --- |
| 列表空（活跃） | 无报告 | `ExaminationReportsEmptyStateView` | 新建/上传/刷新有数据 |
| 列表空（归档） | 无归档报告 | 归档空文案 | 归档操作或刷新 |
| 明细未加载 | `medExamDetails == nil` | 卡片可点加载 | 加载成功/失败结束 loading |
| 明细加载中 | `loadingIDs` 含 id | Progress | 请求结束 |
| 明细已缓存 | `medExamDetails != nil` | 展示细项 | 刷新替换整表可能重置为无明细（取决于接口是否带回） |
| 详情删除中 | `isDeleting` | 菜单禁用 | 成功 dismiss / 失败恢复 |
| 归档切换中 | `isUpdatingArchiveState` | 菜单禁用 | 成功回调 / 失败 |
| 本地草稿 | `mode == .localDraft` | 有限操作集 | 确认入库或丢弃 |

## 十二、数据与持久化

> 字段级模型定义见上文「2.5.6 数据模型详解」。本节只描述归属与生命周期。

| 数据 | 所有者 | 存储位置 | 生命周期 | 清理时机 |
| --- | --- | --- | --- | --- |
| `examinationReports` 摘要数组 | `HomeViewModel` | 内存 `completeData` | 当前选中成员会话 | 切成员 / 强制 load / 登出释放 |
| 列表页 `reports` | `MedExamDetailLazyLoadViewModel` | 内存 | 页面生命周期 | 离开页面；与首页通过闭包同步 |
| `RemoteMedExamDetail` | 同上 | 嵌在报告 `medExamDetails` | 懒加载后随缓存 | 刷新整表可能丢明细直至再加载 |
| 选中分类 / 搜索词 | 列表 `@State` / VM | 内存 | 当次页面 | 离开页面 |
| 识别草稿 | 上传模块 | 流程内内存（及模块自有持久化，若有） | OCR 会话 | 确认入库或取消 |
| 领域 `ExaminationReport` | 映射层 | 未作为列表主存 | — | — |
| Disk 持久化检查列表 | — | **当前未实现** | — | — |

**敏感字段**：`findings` / `impression` / 明细结果 / 附件 URL —— 按医疗隐私处理；分享走服务端 share ticket，不在客户端落明文长期盘。

**三类细项字段使用差异**：实验室重 `resultValue/unit/referenceRange/flag`；影像重 `modality/bodyPart/diagnosis`；病理重 `diagnosis` + 所见印象头字段；详见「2.5.6 D / 2.5.8」。

## 十三、错误模型

| 错误类别 | 触发条件 | 是否重试 | 用户反馈 | 清理动作 |
| --- | --- | --- | --- | --- |
| 刷新 HTTP/业务错 | `listExaminationReportsWithAttachments` 失败 | 用户再次下拉 | toast `home.examination_reports.refresh` | 无，保留旧数据 |
| 明细加载失败 | `listMedExamDetails` 失败 | 可再次展开触发 | 无 toast（仅日志） | 无 |
| 权限不足 / 403 | 成员无访问权 | 否 | 网络错误文案 | 不写缓存 |
| 404 报告不存在 | retrieve/update/delete | 否 | alert/toast | 删除场景可本地 remove（若已确认） |
| 更新明细部分失败 | 删旧成功建新失败 | 需人工重试 | 错误提示 | **可能留下无明细中间态（风险）** |
| 分享失败 | `createShare` | 可重试 | `shareErrorMessage` | 无 |
| memberID 缺失 | complete-data 空 | 否 | 无刷新/无新增 | 跳过请求 |

## 十四、与其他模块的接口边界

### 本模块负责

- 检查报告列表/详情 UX、分类时间线、明细懒加载触发。

## 十七、当前实现、缺口与演进

### 当前实现

- 列表 + 分类时间线 + 搜索筛选。
- complete-data 首屏 + 下拉单资源刷新 + 字段级回写。
- 明细懒加载（检查/体检共享 VM）。
- 手工新建、详情编辑/删除/归档/分享。
- 与病历时间线交叉补丁。
- 归档列表独立入口。

### 当前缺口

- 无 Disk 级检查列表缓存；杀进程后依赖重新 complete-data。
- 更新明细无事务/版本号，部分失败可致中间态。
- 除时间线外自动化测试覆盖薄。
- 列表页内仍有注释掉的旧 `ExaminationReportCategorySection` 调用痕迹（不影响当前 Section 路径）。
- 领域模型 `ExaminationReport` 与 UI 主路径 Remote DTO 双轨，文档以 Remote 为准。
- **`ExaminationReportCategoryDetailPage`：实验室单行与影像共用 `ImagingReportDetailPage`**（完整表仍走 `LaboratoryReportDetailPage`）；跨端若要严格三分页需产品确认是否修正。
- 影像卡片 `findings` / 细项预览当前注释隐藏。
- 下拉刷新后明细通常需重新懒加载（未做按 id 合并保留）。

### 建议演进

1. 为 Mutation 增加「明细替换」服务端单一接口或客户端补偿重试。
2. 刷新接口若可带已加载明细则减少闪烁；否则刷新后按 id 合并保留旧明细。
3. 补齐懒加载与 patch 的单测，作为跨端（HarmonyOS）对标基线。
4. HarmonyOS 落地主路径时严格复用：kind、`business_type`、四类卡片映射、单字段 patch 语义。
