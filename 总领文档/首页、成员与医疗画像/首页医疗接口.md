# 一、模块目标

首页医疗接口模块负责为首页“成员切换 + 医疗卡片概览 + 医疗列表页首屏数据”提供统一的数据入口。当前实现不是在首页并发请求多个医疗资源列表，而是采用“两段式加载”：

1. 先请求成员列表，确定当前账号可访问的成员集合与默认选中成员。
2. 再针对当前选中成员请求一次 `/api/v1/medical/members/{memberID}/complete-data/`，用单个聚合快照驱动首页医疗卡片和后续列表页首屏。

该模块的核心价值是减少首页首屏请求扇出、统一成员上下文、复用已加载的 complete-data 缓存，并让病历、体检、检查、用药等列表页在首屏无需再次全量拉取。

## 2.3 目录职责与依赖方向

- `Features/Home/Presentation` 是首页医疗入口，负责触发加载、切换成员、展示错误和把列表页局部刷新结果回写到首页缓存。

# 三、首页医疗能力拆解

## 3.1 首页医疗首屏聚合加载

### 需求说明

首页在已登录前提下需要快速得到：

- 当前账号可访问的成员列表。
- 当前成员的医疗卡片统计。
- 当前成员的 complete-data 快照，供医疗列表页首屏直出。

当前实现位于 `LoadHomeMedicalOverviewUseCase.execute(...)`，由 `HomeViewModel.load(syncRemote:)` 调用。

### 基础要求与业务规则

- 首先调用 `medicalQueryAPI.listMembers()` 拉取成员列表，失败时直接抛错，首页不降级为空成员数组。
- 成员列表按 `isPrimary` 优先、`updatedAt` 次序排序。
- 当前选中成员优先级为：本次传入的 `selectedMemberID` > 本地持久化 `SelectedMemberIDPersisting` > 排序后的第一个成员。
- 若存在当前成员，则继续调用 `medicalQueryAPI.fetchMemberCompleteData(memberID:)`。
- `fetchMemberCompleteData` 失败时不会让首页整体失败，而是以 `nil` complete-data 生成空卡片统计。
- 首页医疗卡片当前只汇总 4 类：病例、体检报告、检查报告、用药计划。

### 验收标准

- 已登录且有成员时，首页必须能确定一个有效的当前成员 ID。
- `listMembers()` 失败时，首页不应把成员区错误展示为空列表成功态。
- `complete-data` 请求失败时，首页仍可展示成员区，但医疗卡片数量为 0 或保留空态。
- 生成的卡片数量固定为 4 个，且统计字段来自同一份 complete-data 快照。

### 技术细节与设计代码位置

- 加载编排：`SparkClient/SparkClient/Projects/Features/Home/Application/LoadHomeMedicalOverviewUseCase.swift`
- 首页入口：`SparkClient/SparkClient/Projects/Features/Home/Presentation/HomeViewModel.swift`
- 聚合模型：`SparkClient/SparkClient/Projects/Features/Home/Domain/HomeDashboard.swift`

## 3.2 成员列表与成员上下文接口

### 需求说明

首页医疗能力依赖成员上下文。成员不仅用于 UI 选择，还决定 complete-data 请求的 `memberID`、模块配置加载和后续列表页的数据范围。

### 基础要求与业务规则

- 成员列表接口由 `SparkMedicalQueryAPI.listMembers()` 提供，底层仍走医疗资源 `.members`。
- `DefaultMembersRepository.loadMembers()` 失败时会吞掉异常并返回空数组；这条路径主要用于成员列表局部刷新，而不是首页首屏主加载。
- `MemberContextStore` 负责：
  - 保存当前账号的成员列表与 `selectedMemberID`。
  - 通过 `SelectedMemberIDPersisting` 按账号隔离持久化选中成员。
  - 在成员新增、编辑、删除后发送 `membersDidChange`，驱动首页仅刷新成员列表。
- `HomeViewModel.selectMember(_:)` 切换成员后会先更新上下文，再以 `syncRemote: false` 重新加载首页。
- `HomeViewModel.switchMemberAndLoad(_:)` 用于显式强刷成员，切换后以 `syncRemote: true` 重新拉取。

### 验收标准

- 登录账号切换后，旧账号的成员选择不能污染新账号。
- 成员创建、修改、删除后，首页成员条必须可通过 `membersDidChange` 触发刷新。
- 当前选中成员被删除后，首页必须清空当前选中，再重新加载。

### 技术细节与设计代码位置

- 成员实体：`SparkClient/SparkClient/Projects/Core/Domain/Entities/Member.swift`
- 成员上下文：`SparkClient/SparkClient/Projects/Features/MemberContext/Presentation/MemberContextStore.swift`
- 成员读取仓库：`SparkClient/SparkClient/Projects/Features/MemberContext/Infrastructure/DefaultMembersRepository.swift`
- 成员加载用例：`SparkClient/SparkClient/Projects/Features/MemberContext/Application/LoadMembersUseCase.swift`

## 3.3 Complete-data 聚合接口

### 需求说明

complete-data 是首页医疗接口的核心。它承担首页卡片统计、成员医疗维护页预加载、医疗列表页首屏直出、聊天健康资料卡片本地命中等多处消费。

### 基础要求与业务规则

- 接口路径：`GET /api/v1/medical/members/{memberID}/complete-data/`
- 当前客户端为该接口配置了 `etagTTL: 86400`，说明它被视为高复用聚合快照。
- `RemoteMemberCompleteData` 当前已确认包含：
  - `member`
  - `memberMedicalProfile`
  - `memberModuleSettings`
  - `nutritionGoalState`
  - `medicalCases`
  - `healthExamReports`
  - `examinationReports`
  - `medicineBoxes`
  - `familyMedicineBoxes`
  - `prescriptions`
  - `medicationPlans`
  - `todayMedicationRecords`
  - `medicationSummary`
  - `symptoms`
  - `visits`
  - `surgeries`
  - `followUps`
- 其中 `familyMedicineBoxes` 不会在首页首次加载或切换成员时主动返回，只有进入家庭药箱模块成功加载后才回写到首页缓存。
- 首页当前只直接消费 complete-data 里的病例、体检、检查、用药计划和部分用药汇总字段，但 DTO 已为更多医疗场景预留。

### 验收标准

- 当前成员存在时，首页必须优先尝试走 complete-data，而不是并发拉取多个资源列表。
- 列表页首屏进入时，如果首页已有 complete-data，则应直接使用这份快照构造 UI。
- 进入家庭药箱后补拉的数据必须只回写 `familyMedicineBoxes`，不能无意覆盖其他 complete-data 字段。

### 技术细节与设计代码位置

- complete-data 接口：`SparkClient/SparkClient/Projects/Core/Networking/API/Medical/MedicalQueryAPI.swift`
- complete-data DTO：`SparkClient/SparkClient/Projects/Core/Networking/API/Medical/MedicalSyncAPI.swift`
- 首页对家庭药箱缓存补丁：`SparkClient/SparkClient/Projects/Features/Home/Presentation/HomeViewModel.swift`

## 3.4 医疗列表页首屏复用与局部刷新

### 需求说明

首页医疗卡片点击后会进入病历、体检、检查、用药等列表页。列表页首屏不重新全量拉 complete-data，而是直接消费首页缓存；用户下拉刷新时，仅刷新当前资源类别并回写对应字段。

### 基础要求与业务规则

- `HomeMedicalRouteSupport.medicalListView(...)` 把 `homeViewModel.dashboard?.medical.completeData` 注入 `HomeMedicalListView`。
- `HomeMedicalListView` 按路由拆分到：
  - `MedicalCasesListPage`
  - `HealthExamReportsListPage`
  - `ExaminationReportsListPage`
  - `MedicationExecutionCenterPage`
- 列表页的更新回调只 patch 对应字段，例如：
  - `medicalCases`
  - `healthExamReports`
  - `examinationReports`
  - `medicationPlans`
  - `prescriptions`
  - `medicineBoxes`
- `ExaminationReportsListPage.refreshReports()` 已明确采用按资源刷新策略：下拉刷新只调用 `listExaminationReportsWithAttachments(memberID:archived:)`，并只回写首页 `completeData.examinationReports`。

### 验收标准

- 从首页进入医疗列表页时，若 complete-data 已存在，首屏应无需再次请求 complete-data。
- 列表页下拉刷新后，首页缓存中仅对应资源字段发生变化。
- 列表页返回首页后，再次进入同一列表，应优先命中首页已回写的缓存。

### 技术细节与设计代码位置

- 路由注入：`SparkClient/SparkClient/Projects/Features/Home/Presentation/HomeMedicalRouteSupport.swift`
- 列表总入口：`SparkClient/SparkClient/Projects/Features/Home/Presentation/HomeMedicalListsView.swift`
- 检查报告局部刷新示例：`SparkClient/SparkClient/Projects/Features/Home/Presentation/MedicalLists/ExaminationReports/ExaminationReportsListPage.swift`
- 首页缓存 patch：`SparkClient/SparkClient/Projects/Features/Home/Presentation/HomeViewModel.swift`

## 3.5 首页成员模块配置接口

> 详细分析见专项文档：[首页成员模块.md](./首页成员模块.md)。本节仅保留与首页医疗加载链路的衔接说明。

### 需求说明

首页不仅展示医疗卡片，还会根据当前成员的模块配置决定是否展示医疗分区、饮食健康分区或模块维护入口。

### 基础要求与业务规则

- `HomeViewModel.load(syncRemote:)` 在首页医疗加载成功后，会继续调用 `loadCurrentMemberModuleSettings()`。
- `loadCurrentMemberModuleSettings()` 通过 `MemberModuleSetupUseCase.loadModuleSettings(memberID:)` 拉取当前成员全部模块配置。
- `MemberModuleSetupUseCase.loadModuleSettings` 底层调用 `medicalQueryAPI.listMemberModuleSettings(memberID:)`。
- 当前首页判断是否显示模块区时，只看当前选中成员对应模块配置中是否存在 `isEnabled == true`；`isCompleted` 不参与分区显隐。
- **默认不开通**：无 enabled 配置时不展示对应分区；医疗与饮食均未开通且已选中成员时展示模块维护入口。
- `memberModuleSettings` 同时也可能被 complete-data 聚合返回；但首页这里仍保留了单独加载逻辑（已知重复请求缺口，详见成员模块专项文档）。

### 验收标准

- 没有选中成员时，模块配置列表必须为空。
- 有成员但未启用任何首页模块时，应显示模块维护入口，而不是错误地展示空医疗区。
- 当前成员切换后，模块配置必须重新按新成员加载。

### 技术细节与设计代码位置

- 专项文档：`总领文档/首页、成员与医疗画像/首页成员模块.md`
- 首页模块配置刷新：`SparkClient/SparkClient/Projects/Features/Home/Presentation/HomeViewModel.swift`
- 模块配置用例：`SparkClient/SparkClient/Projects/Features/Home/Application/MemberModuleSetupUseCase.swift`
- 模块配置查询 API：`SparkClient/SparkClient/Projects/Core/Networking/API/Medical/MedicalQueryAPI.swift`

```text
用户进入首页
  ↓

  ↓

  ↓
```

# 五、状态模型

## 5.1 首页加载状态

- 未开始：`dashboard == nil`，首页尚未完成首屏加载。
- 全局加载中：`isLoading == true`。
- 医疗分片加载中：`isLoadingMedical == true`，此时首页可能已有成员区但医疗区尚未刷新完。
- 成功：`dashboard` 已生成，且 `selectedMemberID` 与 `memberContextStore` 已同步。
- 部分成功：成员列表成功，但 complete-data 拉取失败，此时首页仍可展示成员区，医疗卡片退化为空统计。
- 失败：`listMembers()` 抛错，`HomeViewModel.load(syncRemote:)` 直接走错误提示并终止首页刷新。

## 5.2 成员切换状态

- 已持久化选择命中：优先使用账号级持久化成员 ID。
- 当前成员仍可用：直接刷新该成员 complete-data。
- 当前成员失效：回退到排序后的第一位成员。
- 成员被删除：先清空 `selectedMemberID`，再重新加载首页。

## 5.3 列表页缓存状态

- 首页已有 complete-data：列表页首屏直接命中缓存。
- 首页无 complete-data：列表页是否会自行补请求，需按各子页面分别核验；本页只确认其首屏支持消费 complete-data。
- 局部刷新后：通过 `updateMedicalCompleteData` 只回写当前资源字段。

# 六、数据与持久化

## 6.1 持久化数据

- 当前选中成员 ID 通过 `SelectedMemberIDPersisting` 按 `accountID` 隔离存储。
- current member module settings 当前仅保存在 `HomeViewModel.currentMemberModuleSettings` 内存态。
- 首页 complete-data 当前保存在 `HomeDashboard.medical.completeData` 内存态，用于当前任务周期内复用。

## 6.2 聚合数据边界

- 成员基础信息和绑定能力来自成员列表接口，不以 complete-data 作为唯一来源。
- 医疗卡片统计来自 complete-data 投影，而不是各列表页本地重新聚合。
- 家庭药箱数据是后续按需补丁数据，不属于首页首屏接口的稳定返回。

# 七、错误模型

## 7.1 已确认错误处理

- `listMembers()` 失败：
  - 首页首屏主路径会抛错，`HomeViewModel` 通过 `notificationClient.error(...)` 提示。
  - 成员局部刷新路径 `DefaultMembersRepository` 会吞错并返回空数组。
- `fetchMemberCompleteData(memberID:)` 失败：
  - `LoadHomeMedicalOverviewUseCase` 中使用 `try?` 吞掉错误，退化为 `completeData = nil`。
- 列表页按资源刷新失败：
  - 例如检查报告列表页会 toast 错误并记录日志，但不清空现有列表。

## 7.2 风险与恢复

- 首页首屏主加载与成员局部刷新对 `listMembers()` 的失败语义不一致，可能造成同一接口在不同链路上的用户体验差异。
- complete-data 被静默降级为 `nil`，有利于首页可用性，但会隐藏聚合接口长期失败的问题，需要依赖日志排查。
- 当前未确认首页是否对 complete-data 的 401、403、404 做了细分处理；从已读代码看，首页层只消费通用 `localizedDescription`。

# 八、与其他模块的接口边界

## 8.1 本模块负责什么

- 首页医疗首屏数据聚合。
- 当前成员选择与首页医疗数据联动。
- 首页到医疗列表页的 complete-data 复用。
- 成员模块配置对首页显示分区的控制。

## 8.2 本模块不负责什么

- 病历、体检、检查、处方、用药等写接口的业务规则本身。
- 文件上传、OCR 识别、附件绑定等医疗录入流程。
- 成员邀请、分享、绑定权限完整闭环。
- complete-data 服务端聚合逻辑本身。

## 8.3 上下游依赖

- 上游调用方：
  - 首页页面与首页协调逻辑
  - 首页医疗卡片导航
- 下游依赖：
  - `SparkMedicalQueryAPI`
  - `MemberContextStore`
  - `MemberModuleSetupUseCase`
  - 各医疗列表页

## 8.4 输入输出模型

- 输入：
  - `UserSession`
  - `selectedMemberID`
  - 本地持久化的成员选择
- 输出：
  - `HomeMedicalLoadResult`
  - `HomeDashboard`
  - `RemoteMemberCompleteData`
  - 当前成员模块配置数组

# 十一、当前实现、缺口与演进

## 11.1 当前实现结论

- 当前首页医疗接口方案已经形成清晰的“双段式聚合 + 列表页局部刷新”架构。
- 首页主链路避免了首屏并发拉取多个资源列表，接口收敛方向是对的。
- complete-data 在首页、列表页、成员模块维护、聊天健康资料场景之间已经具备复用价值。

## 11.2 已确认缺口

- 首页首屏主加载与成员局部刷新对成员列表失败的处理不一致。
- complete-data 已经内含 `memberModuleSettings`，但首页仍单独再次请求模块配置，存在重复读取。
- `refreshRemoteSnapshot` 参数已传入 `LoadHomeMedicalOverviewUseCase.execute(...)`，但当前实现里没有看到它直接改变成员列表或 complete-data 请求策略，更多像保留参数。
- 首页当前只统计 4 类卡片，complete-data 中的症状、就诊、手术、随访等资源尚未映射到首页概览。

## 11.3 演进建议

1. 统一成员列表失败语义。
2. 评估是否以 complete-data 中的 `memberModuleSettings` 替代二次模块配置请求，减少一次网络往返。
3. 为首页医疗聚合补充单元测试和状态测试，尤其是降级分支。
4. 如果后续首页继续扩展医疗卡片，需要先明确“卡片概览层”和“完整医疗档案层”的边界，避免首页重新退回多接口拼装。

# 十二、整体验收标准

1. 已登录用户进入首页后，系统能确定当前账号可访问的成员列表与一个有效的当前成员。
2. 首页医疗卡片统计基于当前成员的 complete-data 生成，而不是四散的独立列表请求。
3. 成员切换后，首页会刷新当前成员的医疗概览，并同步更新成员上下文与模块配置。
4. 医疗列表页首屏可以直接消费首页 complete-data，减少重复请求。
5. 列表页下拉刷新只更新当前资源类别，并能把刷新结果回写到首页缓存。
6. 成员删除、成员切换、complete-data 失败等关键路径不会把首页错误渲染成“空成功态”。
