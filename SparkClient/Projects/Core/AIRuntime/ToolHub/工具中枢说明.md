# ToolHub 模块说明

Core 层**工具运行时**模块。负责工具注册与执行分发、授权持久化、调用审计；各工具的具体逻辑在 `Executors/` 中实现。需要用户介入的弹窗由 [`ToolInteraction`](../../../Features/Chat/Presentation/ToolInteraction/工具交互说明.md) 模块负责展示。

## 模块职责

| 层级 | 职责 |
| --- | --- |
| `ToolHub.swift` | 解析 `SparkToolName`，路由到对应 Executor，写审计，处理 consent 与副作用 |
| `ToolHub+Shared.swift` | 日期/成员解析、健康数据诊断、任务载荷构建等跨工具复用逻辑 |
| `ToolHubTaskModels.swift` | `TaskQueryToolPayload`、`ToolQuestionAnswerPayload` 等 Encodable 载荷 |
| `Models/` | 工具名枚举、执行结果、副作用、上下文、数据分类与出口策略 |
| `Consent/` | 外部工具/健康数据共享的授权状态与弹窗展示模型 |
| `Audit/` | 工具调用记录（进程内 actor，调试命令 `/audit_tools` 可读） |
| `Executors/` | 单工具（或同类工具组）执行实现，一文件一职责 |

## 扩展指南

新增一种工具时：

1. 在 `Models/ToolingModels.swift` 增加 `SparkToolName` case 与相关 payload/副作用类型（同步服务端 `SparkToolName` 与 `ToolPrompts.strings`）。
2. 在 `Executors/` 新建 `ToolHubXxx.swift` 实现执行逻辑（或并入 `ToolHubExternalConnector.swift` 若属外部能力）。
3. 在 `ToolHub.swift` 的 `toolProperties` / `toolRequiredFields` / `execute` 注册路由。
4. 若需用户授权或交互，对接 `ToolInteractionCoordinator` 并在 `ToolInteraction` 模块增加 Sheet。
5. 若产出 UI block，通过 `ToolSideEffect` → `MessageRunActor` 落库。
