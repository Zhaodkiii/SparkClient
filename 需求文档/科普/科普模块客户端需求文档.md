# 一、背景与目标

## 1.1 业务背景

SparkService 后台管理系统规划了统一文档系统，用于发布健康科普、就医指南、报告解读、用药说明、App 使用帮助等内容。SparkClient 需要在 App 内提供一个稳定入口，让用户可以浏览服务端发布的科普内容，并在详情页内阅读 Markdown 文档。

当前客户端已有 `Knowledge` 本地知识库模块，但它主要面向用户本地创建和 Chat 工具检索，不适合作为服务端运营内容入口。因此新增“科普”模块需要保持独立，不复用为本地知识库 Tab。

## 1.2 建设目标

1. 在 RootTab 中新增“科普”Tab，视觉顺序放在 Chat 之后、Settings 之前。
2. 科普模块从服务端内容系统加载已发布文档列表。
3. 点击列表项进入文档详情，使用客户端现有 `Markdown` 组件渲染正文。
4. 支持下拉刷新、分页加载、空态、错误态、离线缓存兜底。
5. 支持分类、标签、语言、推荐/置顶等服务端字段展示。
6. 支持 App 内分享，分享服务端生成或客户端拼接的可打开链接。
7. 支持点击量上报和阅读时长上报。
8. 模块保持独立目录、独立 ViewModel、独立 Repository，不与本地 `Knowledge` 模块混用。
9. 保持现有 Tab raw value 兼容，避免升级后历史 Tab 顺序或选中态错乱。

## 1.3 非目标范围

一期不包含：

1. 不在客户端提供文档编辑、发布、下架能力。
2. 不做点赞、收藏、评论、分享数统计。
3. 不实现推送通知展示入口。
4. 不做复杂全文搜索，一期可预留搜索入口，优先服务端列表和分类筛选。
5. 不把科普文档导入本地 `Knowledge` 知识库。
6. 不在客户端校验医疗参考文献完整性，该能力由服务端发布前校验。

# 二、RootTab 与主导航需求

## 2.1 RootTab 枚举调整

当前代码位置：

```text
SparkClient/Projects/App/Sources/App/AppRouteStore.swift
```

当前枚举：

```swift
enum RootTab: Int, Hashable {
    case home = 0
    /// 历史版本曾为「健康」Tab；保留 raw value 以免升级后 Tab 顺序错乱。
    case knowledge = 2
    case chat = 3
    case settings = 4
}
```

建议调整为：

```swift
enum RootTab: Int, Hashable {
    case home = 0
    /// 历史版本曾为「健康」Tab；保留 raw value 以免升级后 Tab 顺序错乱。
    case knowledge = 2
    case chat = 3
    case settings = 4
    /// 新增科普 Tab。为不改动 settings 历史 raw value，这里使用新的 raw value。
    case popularScience = 5
}
```

### 设计说明

1. `settings` 保持 raw value `4`，避免历史版本升级后持久化选择值错乱。
2. `popularScience` 使用新的 raw value `5`。
3. Tab 视觉顺序由 `TabView` 内声明顺序决定，不依赖 raw value 大小。
4. 科普 Tab 放在 Chat 之后、Settings 之前。
5. 如果当前版本暂时关闭 `knowledge` Tab，保持其 enum case 不删除，只是不在 `TabView` 中展示。

# 三、页面与交互需求

## 3.1 科普首页 `PopularScienceHomeView`

### 页面入口

RootTab：科普。

### 页面目标

展示服务端已发布科普文档列表，让用户快速进入阅读。

### 页面元素

| 区域 | 内容 |
| --- | --- |
| 顶部标题 | 科普 |
| 顶部筛选 | 分类横向滚动、推荐/最新切换，搜索入口可二期 |
| 列表 | 标题、摘要、封面、分类、标签、发布时间、预计阅读时间 |
| 推荐/置顶 | 服务端返回 `is_top`、`is_recommended` 时优先展示 |
| 加载态 | 首次进入显示骨架屏或 ProgressView |
| 空态 | 无内容时展示“暂无科普内容” |
| 错误态 | 网络失败时提供重试按钮 |
| 离线态 | 有缓存时展示缓存列表，并提示“内容可能不是最新” |

### 触发规则

1. 首次进入 Tab：`viewModel.loadIfNeeded()`。
2. 下拉刷新：`viewModel.refresh()`。
3. 滚动到底部：`viewModel.loadNextPageIfNeeded(currentItem:)`。
4. 点击文档：进入 `PopularScienceArticleDetailView(articleID:)`。
5. 点击分类：更新筛选条件并刷新列表。
6. 点击分享：对列表项可选展示分享按钮，默认详情页提供分享。

### 列表排序

默认排序由服务端控制，客户端建议传参：

```text
ordering=-is_top,-is_recommended,-published_at
```

如果服务端暂不支持复杂排序，客户端只按返回顺序展示。

## 3.2 文档详情页 `PopularScienceArticleDetailView`

### 页面目标

展示完整 Markdown 文档，支持分享、阅读时长上报和来源声明。

### 页面元素

| 区域 | 内容 |
| --- | --- |
| 标题区 | 标题、摘要、分类、发布时间、预计阅读时间 |
| 封面图 | 有则展示，无则隐藏 |
| Markdown 正文 | 使用 `Core/Markdown/Markdown.swift` 渲染 |
| 参考来源 | 展示 `source_url` 和 `references_json` 中的来源信息 |
| 声明 | 医疗健康内容展示“内容仅供参考，不能替代医生诊疗建议” |
| 底部操作 | 分享按钮 |

### Markdown 渲染要求

1. 使用现有 `Markdown(article.content, baseURL: ..., imageBaseURL: ...)`。
2. 支持标题、段落、列表、引用、代码块、表格、图片、链接。
3. 外链点击优先使用系统浏览器或 App 内 Safari 视图，避免在 Markdown 内直接执行不可信内容。
4. 图片 URL 只加载 HTTPS。
5. 加载失败的图片展示占位。

### 阅读时长上报

1. 页面打开成功后上报一次点击量：`POST /api/v1/content/articles/{id}/view/`。
2. 进入详情页时记录 `enteredAt`。
3. 页面消失、App 进入后台、用户切换 Tab 时计算本次停留秒数。
4. 停留不足 3 秒不计入有效阅读。
5. 单次上报建议最大截断为 30 分钟，避免后台驻留造成异常。
6. 上报失败不阻塞用户阅读，可写入本地待重试队列或直接丢弃，二期再做可靠队列。

## 3.3 分享需求

### 分享入口

1. 详情页导航栏右侧显示分享按钮。
2. 列表项可在二期增加长按菜单分享。

### 分享内容

分享文本建议：

```text
{title}
{summary}
{share_url}
```

### 分享链接来源

优先级：

1. 服务端详情接口直接返回 `share_url`。
2. 调用 `GET /api/v1/content/articles/{id}/share-link/`。
3. 客户端根据配置域名和 `locale + slug` 拼接。

### Deep Link / Universal Link

分享链接打开规则：

1. 已安装 App：优先跳转到 `popularScienceArticle(id:)` 或 `popularScienceArticle(slug:locale:)`。
2. 未安装 App：展示 Web 落地页。
3. 链接参数至少包含 `id` 或 `slug + locale`。

# 四、服务端接口需求

## 4.1 接口列表

| 方法 | 路径 | 说明 | 客户端用途 |
| --- | --- | --- | --- |
| `GET` | `/api/v1/content/articles/?locale=zh-CN&page=1&page_size=20` | 已发布文档列表 | 科普首页列表 |
| `GET` | `/api/v1/content/articles/{slug}/?locale=zh-CN` | 根据 slug 获取详情 | 分享链接/深链详情 |
| `GET` | `/api/v1/content/articles/{id}/` | 根据 ID 获取详情 | App 内列表点击详情，若服务端支持 |
| `GET` | `/api/v1/content/categories/` | 分类列表/分类树 | 首页分类筛选 |
| `GET` | `/api/v1/content/tags/` | 标签列表 | 二期标签筛选 |
| `POST` | `/api/v1/content/articles/{id}/view/` | 点击量/详情打开上报 | 详情打开时调用 |
| `POST` | `/api/v1/content/articles/{id}/reading-duration/` | 阅读时长上报 | 详情退出或后台时调用 |
| `GET` | `/api/v1/content/articles/{id}/share-link/` | 获取分享链接 | 分享按钮 |

## 4.2 列表请求参数

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `locale` | `String` | 是 | 当前 App 语言，默认 `zh-CN` |
| `page` | `Int` | 否 | 页码，默认 1 |
| `page_size` | `Int` | 否 | 每页数量，建议 20 |
| `category_id` | `Int` | 否 | 分类筛选 |
| `tag_id` | `Int` | 否 | 标签筛选，二期 |

## 4.3 接口逐项设计

### 4.3.1 获取文章列表

| 项目 | 说明 |
| --- | --- |
| 客户端方法 | `PopularScienceRemoteAPI.listArticles(locale:page:pageSize:categoryID:tagID:query:recommendedOnly:)` |
| HTTP | `GET /api/v1/content/articles/` |
| 鉴权 | 默认 `requiresAuth=false`；若服务端后续要求登录则改为 `true` |
| ETag | `allowETag=true` |
| 串行键 | `popular_science.articles.list` |
| 队列优先级 | `.normal` |
| 重试 | `.default` |
| 解码 | `APIResponseDecoder.decodeWrappedData(PopularSciencePageDTO<PopularScienceArticleSummaryDTO>.self, from:)` |

请求参数：

| 参数 | 来源 | 说明 |
| --- | --- | --- |
| `locale` | `PopularScienceListFilter.locale` | 当前 App 语言 |
| `page` | ViewModel 分页状态 | 从 1 开始 |
| `page_size` | 固定或配置 | 一期建议 20 |
| `category_id` | 筛选条件 | 为空时不传 |
| `tag_id` | 筛选条件 | 二期 |
| `q` | 搜索框 | 二期 |
| `is_recommended` | 推荐筛选 | 为空时不传 |

客户端处理：

1. 成功后 DTO 映射为 `PopularSciencePage<PopularScienceArticleSummary>`。
2. 第一页成功后写入列表缓存。
3. 第一页为空时进入 `.empty`。
4. 非第一页为空时设置 `hasNext=false`。
5. 网络失败且第一页有缓存时展示缓存列表。

### 4.3.2 根据 ID 获取文章详情

| 项目 | 说明 |
| --- | --- |
| 客户端方法 | `PopularScienceRemoteAPI.loadArticle(id:locale:)` |
| HTTP | `GET /api/v1/content/articles/{id}/` |
| 鉴权 | 默认 `requiresAuth=false` |
| ETag | `allowETag=true` |
| 串行键 | `popular_science.article.detail.{id}` |
| 队列优先级 | `.normal` |
| 重试 | `.default` |
| 解码 | `APIResponseDecoder.decodeWrappedData(PopularScienceArticleDetailDTO.self, from:)` |

请求参数：

| 参数 | 来源 | 说明 |
| --- | --- | --- |
| `locale` | 当前 App 语言 | 服务端支持多语言详情时传；不支持可忽略 |

客户端处理：

1. 成功后写入详情缓存 `article:{locale}:{id}`。
2. 详情 `content_format != markdown` 时仍进入详情页，但提示正文格式暂不支持；一期服务端应固定返回 `markdown`。
3. 404/410 展示“内容不存在或已下架”。

### 4.3.6 上报点击量

| 项目 | 说明 |
| --- | --- |
| 客户端方法 | `PopularScienceRemoteAPI.reportView(articleID:)` |
| HTTP | `POST /api/v1/content/articles/{id}/view/` |
| 鉴权 | 默认 `requiresAuth=false`；若服务端要绑定用户可改 `true` |
| ETag | `allowETag=false` |
| 串行键 | `popular_science.article.view.{id}` |
| 队列优先级 | `.low` |
| 重试 | 建议关闭自动重试，避免重复计数 |
| 请求体 | 无，或 `{ "client_platform": "ios" }` |

客户端处理：

1. 每次详情页成功展示后最多上报一次。
2. 上报失败静默处理，不弹错误。
3. 不因点击量上报失败影响详情加载。

### 4.3.7 上报阅读时长

| 项目 | 说明 |
| --- | --- |
| 客户端方法 | `PopularScienceRemoteAPI.reportReadingDuration(articleID:durationSeconds:sessionID:)` |
| HTTP | `POST /api/v1/content/articles/{id}/reading-duration/` |
| 鉴权 | 默认 `requiresAuth=false`；如要绑定用户可改 `true` |
| ETag | `allowETag=false` |
| 串行键 | `popular_science.article.reading_duration.{id}` |
| 队列优先级 | `.low` |
| 重试 | 一期可关闭；二期用本地队列保证最终上报 |

请求体：

```json
{
  "duration_seconds": 45,
  "session_id": "UUID-string",
  "client_platform": "ios"
}
```

客户端处理：

1. 停留不足 3 秒不上报。
2. 单次超过 1800 秒按 1800 秒截断。
3. 页面退出、App 进入后台、切换 Tab 时触发结算。
4. 同一详情页面生命周期只允许结算一次；如果页面重新进入，生成新的 `sessionID`。

建议位置：


DTO 命名建议：

| DTO | 说明 |
| --- | --- |
| `PopularScienceArticleSummaryDTO` | 列表项 |
| `PopularScienceArticleDetailDTO` | 详情 |
| `PopularScienceCategoryDTO` | 分类 |
| `PopularScienceTagDTO` | 标签 |
| `PopularScienceReferenceDTO` | 参考来源 |
| `PopularSciencePageDTO<T>` | 分页响应 |

字段解码要求：

1. 不为 DTO 编写手动 `init(from:)` 和 `encode(to:)`，除非服务端字段确实存在结构不一致且无法通过通用策略表达。
2. snake_case 与 camelCase 转换统一依赖 `Codable+Extensions.swift` 中的 `JSONDecoder.default` / `JSONEncoder.default`。
3. 日期解析统一依赖 `JSONDecoder.default`，不要在 DTO 内手写日期解析。
4. JSON 字符串编解码统一使用 `JSONDecoder.default.decode(_:fromJSONString:)` 和 `JSONEncoder.default.encodeToJSONString(_:)`。
5. URL 字段建议在 DTO 中保留为 `String?`，DTO 到 Domain 映射时转为 `URL?`；非法 URL 丢弃，不让整个列表解码失败。
6. DTO 字段通过 `CodingKeys` 兜底只允许用于极少数服务端字段名不规则场景，不能为了 snake_case 手写 CodingKeys。

### Codable 编解码规范

科普模块必须复用项目内通用 Codable 编解码方式，位置：

```text
SparkClient/Projects/Foundation/Extensions/Codable+Extensions.swift
```

允许使用：

```swift
let decoder = JSONDecoder.default
let value = try decoder.decode(PopularScienceArticleDetailDTO.self, from: data)

let encoder = JSONEncoder.default
let data = try encoder.encode(payload)

let valueFromString = try JSONDecoder.default.decode(PopularScienceArticleDetailDTO.self, fromJSONString: raw)
let jsonString = try JSONEncoder.default.encodeToJSONString(payload)
```

禁止在科普模块新增以下模式：

```swift

// 禁止：仅为了 snake_case / 日期格式手写解码
init(from decoder: Decoder) throws { ... }

// 禁止：仅为了 snake_case / 日期格式手写编码
func encode(to encoder: Encoder) throws { ... }
```

### 7.1.2 Repository 实现规则

`RemotePopularScienceRepository` 负责把远端 API 与本地缓存组合起来：

1. `listArticles`：优先请求远端；第一页成功后保存缓存；远端失败时读取缓存。
2. `loadArticle(id:)`：优先请求远端；成功后缓存；失败时尝试详情缓存。
3. `loadArticle(slug:)`：优先请求远端；成功后按 `id` 和 `slug` 双写缓存。
4. `listCategories`：远端失败时使用分类缓存；无缓存返回空数组而不是让首页失败。
5. `reportView` / `reportReadingDuration`：直接调用 API，失败静默抛给 ViewModel 吞掉。
6. `shareLink`：优先 API，失败后用详情里的 `shareURL` 或本地拼接策略兜底。

# 八、缓存与离线策略

## 8.1 缓存范围

一期建议缓存：

1. 最近一次成功加载的文章列表。
2. 最近打开过的文章详情。
3. 分类列表。

## 8.2 缓存实现

可选方案：

| 方案 | 优点 | 缺点 | 建议 |
| --- | --- | --- | --- |
| JSON 文件缓存 | 实现快，不需要改 CoreData | 查询能力弱 | 一期推荐 |
| CoreData 缓存 | 可查询、可扩展 | 需要模型迁移 | 二期 |
| URLCache/ETag | 自动化程度高 | 对业务状态控制弱 | 可与 JSON 缓存并用 |

一期建议新增：

```text
PopularScienceCacheStore.swift
```

缓存读写要求：

1. JSON 文件缓存也必须使用 `JSONEncoder.default` / `JSONDecoder.default`。
2. 如果缓存以字符串形式落盘，必须使用 `encodeToJSONString(_:)` / `decode(_:fromJSONString:)`。
3. 不允许在 `PopularScienceCacheStore` 中使用裸 `JSONEncoder()` / `JSONDecoder()`。
4. 不允许为了缓存结构手写 DTO 的 `init(from:)` / `encode(to:)`。

缓存 Key：

1. `articles:{locale}:{categoryID}:{page}`。
2. `article:{locale}:{id}`。
3. `article:{locale}:{slug}`。
4. `categories:{locale}`。

## 8.3 离线展示规则

1. 列表加载失败但有缓存：展示缓存列表，并显示非阻断提示。
2. 详情加载失败但有缓存：展示缓存详情，并显示“离线内容可能不是最新”。
3. 没有缓存：展示错误态和重试按钮。
4. 阅读时长上报失败：不影响阅读，不弹错误。

| `loadIfNeeded()` | Tab 首次进入 | 未加载过才调用 `refresh()` |
| `refresh()` | 首次进入/下拉刷新/分类切换 | 重置 `page=1`、`hasNext=true`，加载分类和第一页 |
| `loadNextPageIfNeeded(currentItem:)` | 列表行 appear | 当前 item 接近末尾且 `hasNext=true` 时加载下一页 |
| `selectCategory(_:)` | 用户点击分类 | 更新筛选并刷新 |
| `articleTapped(_:)` | 点击列表项 | 调用路由进入详情 |

`refresh()` 流程：

1. `phase = .loading`。
2. 并发或顺序加载分类与第一页文章。
3. 文章为空：`phase = .empty`。
4. 文章非空：写入 `articles`，`phase = .loaded`。
5. 远端失败但 Repository 返回缓存：展示缓存，设置 `offlineNotice`。
6. 远端失败且无缓存：`phase = .failed(localizedMessage)`。

## 9.2 `PopularScienceArticleDetailViewModel`

建议定义：

```swift
@MainActor
final class PopularScienceArticleDetailViewModel: ObservableObject {
    @Published private(set) var phase: PopularScienceDetailPhase = .loading
    @Published private(set) var article: PopularScienceArticleDetail?
    @Published private(set) var offlineNotice: String?
    @Published var shareItem: PopularScienceShareItem?

    private var didReportView = false
    private var didEndReading = false
    private var readingStartedAt: Date?
    private var readingSessionID = UUID().uuidString
}
```

详情状态：

```swift
enum PopularScienceDetailPhase: Equatable {
    case loading
    case loaded
    case failed(String)
}
```

必需方法：

| 方法 | 触发 | 处理 |
| --- | --- | --- |
| `load()` | 页面 `.task` | 加载详情；成功后调用 `reportViewIfNeeded()` 和 `beginReading()` |
| `retry()` | 错误态重试 | 重新调用 `load()` |
| `reportViewIfNeeded()` | 详情成功展示 | 确保同一页面生命周期只上报一次点击量 |
| `beginReading()` | 详情可见 | 记录 `readingStartedAt` |
| `endReading(reason:)` | 页面消失/后台/切 Tab | 计算阅读时长并上报 |
| `share()` | 点击分享按钮 | 取 `article.shareURL`，无则调用分享 UseCase |

阅读结束规则：

```swift
func endReading(reason: PopularScienceReadingEndReason) {
    guard didEndReading == false else { return }
    didEndReading = true
    guard let startedAt = readingStartedAt else { return }
    let rawSeconds = Int(Date().timeIntervalSince(startedAt))
    guard rawSeconds >= 3 else { return }
    let seconds = min(rawSeconds, 1800)
    Task {
        try? await reportReadingUseCase.reportDuration(
            articleID: articleID,
            durationSeconds: seconds,
            sessionID: readingSessionID
        )
    }
}
```

# 十一、异常与边界场景

| 场景 | 处理 |
| --- | --- |

| 网络失败且无缓存 | 展示错误态和重试 |

| 用户快速切 Tab | 结束本次阅读计时并按规则上报 |
| App 进入后台 | 结束本次阅读计时并按规则上报 |

# 十四、验收标准

## 14.1 功能验收

1. RootTab 中出现“科普”Tab，位置在 Chat 之后、Settings 之前。
2. `settings` 原 raw value 保持不变。
3. 首次进入科普 Tab 可以加载服务端已发布文档列表。
4. 下拉刷新可以重新拉取列表。
5. 列表项点击后进入详情页。
6. 详情页使用现有 `Markdown` 组件渲染服务端 Markdown 正文。
7. 详情页可以展示参考来源和医疗免责声明。
8. 详情页可以调用系统分享面板分享链接。
9. 打开详情后只上报一次点击量。
10. 有效阅读结束后上报阅读时长。
11. 网络失败时有错误态；有缓存时能展示缓存内容。
12. 未发布、已下架或不存在的内容不能正常展示为可阅读详情。

## 14.2 工程验收

1. 新增代码集中在 `Projects/Features/PopularScience`，不污染 `Knowledge` 模块。
2. 网络调用通过项目现有 `SparkNetworkEngine`。
3. DTO 与 Domain 分离。
4. ViewModel 使用 `@MainActor` 管理 UI 状态。
5. Markdown 渲染复用 `Projects/Core/Markdown`。
6. 本地化覆盖简体中文、英文、繁体中文。
7. 关键错误有日志，但不记录完整 Markdown 正文。
8. API 解码、请求编码和缓存编解码统一使用 `Codable+Extensions.swift` 中的通用 `JSONDecoder.default` / `JSONEncoder.default`，不得新增手动 JSON 解码编码逻辑。

## 14.3 兼容性验收

1. iOS 15 导航兼容容器仍可正常 push 详情页。
2. App 升级后原 Home、Chat、Settings Tab 可正常进入。
3. 当前关闭的 `Knowledge` Tab 不受影响。
4. 用户未登录时是否可访问科普内容按服务端鉴权策略执行；若服务端要求登录，客户端展示登录态引导。
