# 饮食营养客户端详细设计文档

> 文档性质：客户端详细设计稿。本文基于《饮食营养需求讨论文档》和《饮食营养数据详设文档》，重点描述客户端页面、操作流程、展示内容、数据来源、按钮动作、计算规则和待补充点。本文不涉及代码改动。

## 一、客户端范围

### Q：第一期客户端要做哪些页面？

A：第一期围绕“首页入口 -> 今日看板 -> 添加记录 -> 保存 -> Apple 健康同步 -> 详情查看”形成闭环。

信息架构：

```text
用户
🏥 医疗档案
├─ 病例
├─ 检查
├─ 体检
├─ 用药

🍎 饮食营养
├─ 总结
├─ 营养
```

第一期页面：

| 页面 | 作用 |
| --- | --- |
| 饮食营养首页 | 展示 `总结` 和 `营养` 两个模块 |
| 总结详情页 | 展示今日摄入、消耗、剩余、来源明细、Apple 健康来源 |
| 餐次详情页 | 展示早餐/午餐/晚餐/小吃某一餐的记录 |
| 食物添加页 | 搜索、拍照、手动输入、选择食物/菜谱 |
| 食物/菜谱确认页 | 调整份量、比例、营养估算，确认保存 |
| 饮食记录历史页 | 按日期查看历史记录 |
| 能量消耗记录页 | 查看和手动添加消耗 |

待补充：

1. 具体路由挂载位置。
2. 是否复用医疗档案成员选择组件。
3. 是否需要饮食营养独立导航栈。

## 三、入口与导航

### Q：首页怎么进入饮食营养？

A：首页健康资料区域新增 `🍎 饮食营养` 分组，下面只展示两个入口：

```text
🍎 饮食营养               首页
├─ 总结                  详细信息
├─ 营养                  更多
```

入口行为：

| 入口 | 点击行为 | 打开方式 |
| --- | --- | --- |
| `首页` | 进入饮食营养首页 | Navigation push |
| `总结` 内 `详细信息` | 打开总结详细页面 | Navigation push |
| `营养` 内 `更多` | 打开营养详细页面 | Navigation push |

页面顶部需要支持成员切换：

1. 默认成员：当前登录用户本人或系统当前选中的健康成员。
2. 切换成员后：重新加载该成员当天饮食数据。
3. 本人成员：允许读取/写入 Apple 健康。
4. 非本人成员：不读取、不写入 Apple 健康，只走服务端。

### Q：`总结` 模块具体展示什么？

A：总结模块展示今日总览，是用户第一眼看到的核心数据。

页面结构：

```text
总结                                      详细信息
┌────────────────────────────────────────┐
│                                        │
│  已食用             剩余             已消耗│
│   369             1,626              411│
│              半圆/圆环进度              │
│                                        │
│ 碳水化合物        蛋白质              脂肪│
│ 69 / 243克       10 / 97克          9 / 64克│
└────────────────────────────────────────┘
```

展示字段：

| 字段 | 说明 | 数据来源 |
| --- | --- | --- |
| 已食用 | 今日总摄入 kcal | 服务端 `NutritionIntake` + Apple 健康外部营养摄入 |
| 剩余 | 今日剩余 kcal | 客户端计算 |
| 已消耗 | 今日能量消耗 kcal | 本人 Apple 健康 + 服务端消耗记录；非本人服务端消耗记录 |
| 碳水化合物 | 今日碳水摄入 / 目标 | 服务端看板 |
| 蛋白质 | 今日蛋白质摄入 / 目标 | 服务端看板 |
| 脂肪 | 今日脂肪摄入 / 目标 | 服务端看板 |
| 圆环进度 | 已食用 / 目标摄入 | 客户端计算 |

计算规则：

```text
已食用 = 服务端饮食摄入 + Apple 健康外部营养摄入
已消耗 = Apple 健康能量消耗 + 服务端手动消耗
剩余 = 目标摄入 - 已食用 + 已消耗
摄入进度 = 已食用 / 目标摄入
营养素进度 = 当前营养素摄入 / 当前营养素目标
```

展示规则：

1. `剩余` 是视觉中心，字号最大。
2. `已食用` 和 `已消耗` 在左右两侧。
3. 圆环用绿色表示已食用，浅灰表示剩余。
4. 三大营养素使用横向进度条。
5. 数值为 0 时也展示，不隐藏。
6. 负剩余时展示 `超出 xxx` 或红色提示，具体文案待补充。

按钮与点击：

| 区域 | 点击行为 | 打开方式 |
| --- | --- | --- |
| `详细信息` | 打开总结详细页面 | Navigation push |
| 已食用 | 打开今日摄入来源页或详情页筛选到摄入 | Navigation push |
| 已消耗 | 打开能量消耗详情页 | Navigation push |
| 碳水/蛋白质/脂肪 | 打开营养素明细 | Navigation push |

总结详情页待补充内容：

1. 今日所有摄入来源。
2. 服务端饮食记录来源。
3. Apple 健康外部营养摄入来源。
4. 本 App 写入 Apple 健康的样本。
5. 能量消耗来源。
6. 三大营养素明细。
7. 周/月趋势是否第一期支持，待补充。

### Q：`营养` 模块具体展示什么？

A：营养模块按餐次展示早餐、午餐、晚餐、小吃。

页面结构：

```text
营养                                                              更多
┌─────────────────────────────────────────────────┐
│ ◯ 早餐 →                                   +    │
├─────────────────────────────────────────────────┤
│ ◯ 午餐 →                                   +    │
│   4 / 1,043千卡                                 │
│   Strawberries                                  │
├─────────────────────────────────────────────────┤
│ ◯ 晚餐 →                                   +    │
│   137 / 1,043千卡                               │
│   Strawberries, Banana                          │
├─────────────────────────────────────────────────┤
│ ◯ 小吃 →                                   +    │
│   615 / 0千卡                                   │
│   Coffee, Apple, Scrambled Eggs,...             │
└─────────────────────────────────────────────────┘
```

每个餐次行：

| 元素 | 说明 |
| --- | --- |
| 圆形图标 | 餐次图标 + 热量进度 |
| 餐次名称 | 早餐/午餐/晚餐/小吃 |
| 箭头 | 表示可进入详情 |
| 热量 | 当前餐次摄入 / 餐次目标 |
| 食物摘要 | 最多 1 行，展示食物和菜谱名称 |
| `+` 按钮 | 添加该餐次食物 |

餐次目标计算：

```text
早餐目标 = 今日目标摄入 * 0.30
午餐目标 = 今日目标摄入 * 0.40
晚餐目标 = 今日目标摄入 * 0.25
小吃目标 = 今日目标摄入 * 0.05
```

服务端可以返回默认目标和餐次分配；客户端负责展示。

按钮与点击：

| 区域 | 行为 | 打开方式 |
| --- | --- | --- |
| 餐次整行 | 跳转对应餐次详情页：早餐/午餐/晚餐/小吃 | Navigation push |
| 餐次名称/箭头 | 跳转对应餐次详情页：早餐/午餐/晚餐/小吃 | Navigation push |
| 黑色圆形 `+` | 打开食物添加页，默认当前餐次 | Navigation push 或 fullScreenCover，待定 |
| `更多` | 打开营养详细页面 | Navigation push |

样式：

1. 餐次卡片为白底、浅灰边框。
2. 四个餐次之间用浅灰分割线。
3. `+` 为黑色圆形按钮，白色加号。
4. 食物摘要使用次级灰色，超出省略。
5. 每行高度固定，避免无记录时跳动。

## 四、饮食营养首页

### Q：首页整体结构是什么？

A：首页是第一期核心页面，默认展示当天数据。

页面结构：

```text
顶部导航
├─ 返回
├─ 标题：饮食营养
├─ 成员选择
└─ 日期切换

内容
├─ 总结模块
└─ 营养模块
```·

顶部操作：

| 操作 | 展示 | 行为 |
| --- | --- | --- |
| 返回 | 左上返回 | 回到首页 |
| 成员选择 | 成员头像/姓名 | 打开成员选择 Sheet |
| 日期切换 | 今日 / 左右箭头 / 日期 | 切换查看日期 |
| 更多 | 可选 | 预留设置、目标、历史入口 |

数据来源：

| 数据 | 来源 |
| --- | --- |
| 服务端饮食记录 | `GET /nutrition/dashboard` 占位 |
| 服务端营养摄入 | `RemoteNutritionDashboard.serverIntake` |
| Apple 健康外部营养摄入 | 本人从 HealthKit 读取后上报服务端，再由看板返回 |
| Apple 健康能量消耗 | 本人客户端读取 HealthKit |
| 手动能量消耗 | 服务端 `NutritionEnergyBurnRecord` |
| 目标值 | 服务端默认目标 |

加载策略：

1. 页面进入时加载当天服务端看板数据。
2. 如果成员是本人，异步读取 Apple 健康消耗和外部营养摄入。
3. Apple 健康外部营养摄入读取后上报服务端。
4. 上报成功后刷新看板。
5. 非本人不触发 Apple 健康读取。

状态：

| 状态 | 展示 |
| --- | --- |
| 首次加载 | 骨架屏或轻量 loading |
| 有数据 | 展示总结和营养 |
| 当天无记录 | 总结显示 0，营养餐次为空 |
| 服务端失败 | 展示错误提示和重试 |
| Apple 健康未授权 | 不阻塞服务端数据显示，在消耗区域展示未授权提示 |
```

## 七、食物/菜谱确认页

### Q：为什么需要确认页？

A：份量和比例会直接影响营养计算，必须允许用户确认。

页面展示：

1. 当前餐次。
2. 已选食物和菜谱。
3. 每项的份量、单位、食用比例。
4. 营养估算：热量、碳水、蛋白质、脂肪。
5. AI 置信度和不确定提示。
6. 图片预览。

比例选择：

```text
1/5、2/5、3/5、4/5、全部
```

也可以支持手动输入：

1. 数量。
2. 单位。
3. 克重。
4. 自定义份量文案。

保存行为：

```text
用户确认
-> App 提交服务端
-> 服务端保存 NutritionMealRecord / NutritionMealFood / NutritionIntake
-> 如果本人且授权 Apple 健康，App 写入 HealthKit
-> App 回写 HealthKit sample UUID 到服务端
-> 返回饮食营养首页或餐次详情
```

接口占位：

| 动作 | 接口占位 |
| --- | --- |
| 创建饮食记录 | `POST /api/v1/nutrition/meal-records/` |
| 回写营养摄入 Apple 健康 ID | `POST /api/v1/nutrition/intakes/{id}/apple-health-id/` |
| 创建自定义食物 | `POST /api/v1/nutrition/food-items/` |
| 创建自定义菜谱 | `POST /api/v1/nutrition/recipes/` |

说明：具体接口字段以后在服务端详设文档中单独细化。

## 八、自定义食物与菜谱

### Q：用户如何添加自己的食物？

A：从食物添加页 `更多 -> 自定义食物` 进入。

自定义食物字段：

1. 食物名称。
2. 分类。
3. 标准份量。
4. 单位。
5. 克重。
6. 热量。
7. 碳水、蛋白质、脂肪。

保存后：

1. 服务端创建 `NutritionFoodItem`。
2. 服务端创建该食物的标准 `NutritionIntake`。
3. 添加页可搜索和复用。

### Q：用户如何添加菜谱？

A：从食物添加页 `更多 -> 自定义菜谱` 进入。

菜谱字段：

1. 菜谱名称，例如 `玉米片配牛奶`。
2. 菜谱分类，例如早餐。
3. 菜谱标准份量。
4. 组成食物列表。
5. 每个食物的默认份量和比例。

保存后：

1. 服务端创建 `NutritionRecipe`。
2. 服务端创建多条 `NutritionRecipeFood`。
3. 服务端按组成食物汇总菜谱标准 `NutritionIntake`。
4. 添加页可作为菜谱项搜索和选择。

```text
