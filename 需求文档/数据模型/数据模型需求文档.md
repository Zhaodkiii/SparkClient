# SparkClient 数据模型需求文档

本文档按功能模块描述 **业务场景**、**数据加载规则**（初始化 / 手动触发 / 进入页面）、**数据来源**（本地持久化 vs 服务端接口）、**领域与存储模型形态**，以及各 **加载业务场景** 与触发方式的对应关系。内容对齐当前 `SparkClient` 工程实现，便于产品与研发统一口径。

---

## 1. 文档范围与约定

- **范围**：客户端侧「谁、何时、从哪、以什么结构」加载或写入数据；不展开后端字段级 OpenAPI 定义。
- **本地数据库**：特指 **Core Data**（`SparkClient.xcdatamodeld`）及与之配套的 Repository / Store。
- **其他本地来源**：`UserDefaults`、钥匙串、应用沙盒文件（JSON 等）、`DeviceCache`（缓存目录 + `UserDefaults` 元数据）、**HealthKit**（系统健康库，非应用自建库）。
- **服务端**：经 `SparkNetworkEngine` 调用的 REST 接口（统一包裹 `{ code, msg, data }` 解码模式为主）。

### 1.1 加载规则分类（全文通用）

| 规则类型 | 含义 | 典型实现形态 |
| --- | --- | --- |
| **初始化数据** | App 冷启动或新用户会话首次建立时，不依赖用户进入某页即执行的预加载 / 引导 | §2 `AppBootstrapper`、登录后 `bootstrapIfNeeded(for:)`；编排目标含 §3 `AIConfigCenter`、`MedicalSyncService`、`SparkOSSConfigurationStore` 等 |
| **手动触发（按钮等）** | 用户显式操作后发起：刷新、保存、同步、重试发送等 | `refresh()`、`save()`、`triggerSyncNow()`、下拉刷新绑定的 `Task` |
| **进入页面自动加载** | 视图 `onAppear` / 首次展示时调用 `loadIfNeeded()` 等，且常带「只加载一次」标记 | `hasLoaded`、`loadForListIfNeeded` |

### 1.2 Core Data 实体一览（与领域模型映射）

| 实体 | 用途摘要 |
| --- | --- |
| `ChatThreadEntity` | 会话线程：标题、患者、场景、时间戳、是否活跃 |
| `ChatMessageEntity` | 消息：角色、类型、正文、推理字段、投递状态、服务端 ID、墓碑标记 |
| `ChatSyncCursorEntity` | 会话同步游标键值 |
| `KnowledgeDocumentEntity` / `KnowledgeChunkEntity` | 知识文档与分块向量（`vectorData` 为 `Binary`） |
| `ExaminationReportEntity` | 检查报告类医疗数据本地落库（含 OCR 原始等 Transformable 字段） |

## 2. 应用引导（App Bootstrap）

### 2.1 模块定位

- `AppBootstrapper`（`@MainActor`）是 **冷启动** 与 **新用户档案首次进入已登录态** 时的编排器：按固定顺序调用 AI 配置、医疗同步、OSS 预取、设备登记等，**不**承载持久化协议细节；具体读写由「基础设施」与各 Feature 仓库完成。
- 与 **基础设施** 的边界：引导只负责「何时调用」；网络解码、设备缓存、OSS 快照对象形态等见 **§3**。

### 2.2 业务场景

- **冷启动（会话仍为 `.loading`）**：在 `sessionStore.restoreIfNeeded()` 之前，尽力完成 AI 远程 Patch 拉取与合并、`prewarm`、全 `AIScenario` 预解析；失败整体 **降级**（仅日志），**仍会**执行设备登记闭包。
- **新会话（`.signedIn`，按 `UserSession.profileID` 去重）**：`routeStore.resetForNewSession()` 回到首页 Tab；再次执行 AI 刷新与预热；若用户开启同步则走 `MedicalSyncService.bootstrapIfNeeded()`；`SparkOSSConfigurationStore.prefetchFromBackend` 预拉 STS；再次设备登记。
- **回到未登录（`.signedOut`）**：`reset()` 清除引导闩锁与已引导 profile 集合、清空 OSS 内存快照、停止聊天实时同步、清除 AI **运行时覆盖**（不删除本地 `AISettingsSnapshot` 持久化文件）。

### 2.3 调用链与 UI 触发（与 `AppCoordinatorView` 对齐）

| 应用状态 | 触发 | 调用 |
| --- | --- | --- |
| `.loading` | `ProgressView` 上 `.task` | `await appBootstrapper.bootstrapAppLaunchIfNeeded()` → `await sessionStore.restoreIfNeeded()` |
| `.signedOut` | 根视图 `.task` | `await appBootstrapper.reset()`；`patientContextStore.update(members: [], selectedMemberID: nil)` |
| `.signedIn(session)` | `.task(id: session.profileID)` | `await appBootstrapper.bootstrapIfNeeded(for: session)`；随后 `pushAdapter.requestAuthorizationIfNeeded()`（通知权限，非引导核心数据） |

### 2.4 加载规则

| 触发类型 | 入口 | 闩锁 / 去重 | 失败策略 |
| --- | --- | --- | --- |
| 冷启动一次 | `bootstrapAppLaunchIfNeeded()` | `didBootstrapLaunch` | `do/catch` 打警告日志；末尾仍 `registerDevice()` |
| 每档案一次 | `bootstrapIfNeeded(for: UserSession)` | `bootstrappedProfiles` 含 `profileID` 则跳过 | 同上；内含路由重置 |
| 登出 / 回登录页 | `reset()` | 清空上述状态与 OSS 快照 | `syncChatUseCase?.stopRealtime()`；`aiConfigCenter.clearRuntimeOverrides()` |

### 2.5 编排依赖（逻辑组件）

| 依赖 | 在引导中的职责 |
| --- | --- |
| `AIConfigCenter` | `refreshRemoteConfig()`（经 `AIRemoteConfigProvider` 拉 `AIRemoteSettingsPatch`，合并入 `AISettingsRepository`）、`prewarm()`、`resolve(for:)` 遍历 `AIScenario.allCases` |
| `MedicalSyncService` | 仅登录引导：`bootstrapIfNeeded()`——读 `MedicalSyncPreference`，若 `isSyncEnabled` 则 `medicalRepository.pullSnapshotFromServer(priority:)` 并更新 `lastSyncAt` 等 |
| `SparkOSSConfigurationStore` + `SparkOSSAPI` | 仅登录引导：`prefetchFromBackend(using:)`（失败只打日志，上传前会再拉） |
| `AppRouteStore` | `resetForNewSession()`：主导航 `selectedTab` 置回 `.home` |
| `registerDevice` 闭包 | 冷启动引导末尾、登录引导末尾各执行一次（实现见「设备登记」模块） |
| `SyncChatUseCase?` | 仅在 `reset()` 时 `stopRealtime()` |

### 2.6 数据与模型要点

- **无独立「Bootstrap JSON」**：引导的「结果」体现在各子系统副作用中，例如：合并后的 `AISettingsSnapshot`（经 `AISettingsRepository.save`）、`MedicalSyncPreference` 的 `lastSyncAt` / `hasCompletedInitialUpload`、`AliyunOSSRuntimeConfig?` 内存缓存、`AppRouteStore.selectedTab`。
- **AI 运行时覆盖**：聊天内临时选模型等走 `AIRuntimeStore`，登出时 `clearRuntimeOverrides()`；与本地持久化的设置快照区分。

### 2.7 加载业务场景对照

| 业务场景 | 初始化 | 手动 | 进页 |
| --- | --- | --- | --- |
| AI 远程 bundle / 试用等合并进本地快照 | ✅ 冷启动 & 登录引导内 `refreshRemoteConfig` | AI 设置页等可再拉 | 视子页面 |
| 医疗全量/拉取快照（引导路径） | ✅ 登录引导内 `MedicalSyncService.bootstrapIfNeeded` | 设置「立即同步」等（见「设置」模块） | — |
| OSS STS 预缓存 | ✅ 登录引导内 `prefetchFromBackend` | — | 上传发生时 `configurationForUpload` 可再拉 |
| 设备登记 | ✅ 两阶段引导末尾 | — | — |

## 3. 基础设施（Infrastructure）

### 3.1 模块定位

- 跨 Feature 复用的 **运行时能力**：HTTP 管线、设备/ETag 缓存、OSS STS、AI 配置中枢与运行时覆盖、主导航路由、医疗同步门面等。
- **不包含**具体业务 UI 状态机；与 **§2 应用引导** 的关系：引导按顺序 **调用** 本节组件，本节描述各组件 **数据从哪来、长什么样**。

### 3.2 网络与统一响应解码

| 组件 | 作用 |
| --- | --- |
| `SparkNetworkEngine` | 串行门控、鉴权头、`ETagHTTPInterceptor`、重试、`send`/`sendRaw` |
| `SparkBackendConfiguration` | 将 `execute(operation)` 接到具体引擎与 `DeviceCache` |
| `APIResponseDecoder.decodeWrappedData` | 解析 `{ "code", "msg", "data" }`，`code == 0` 时对 `data` 解码为 `Decodable`（与 `SparkResponseDecodingMode.backendWrapped` 一致） |

医疗统一资源列表另见 `SparkMedicalResourceAPI` 使用的 `JSONDecoder`（`MedicalDateCoding` 日期容错）。

### 3.3 `DeviceCache`（设备与用户元数据 + ETag 文件缓存）

| 存储位置 | 内容 |
| --- | --- |
| `UserDefaults` | `currentUserID`、`trustedDeviceID`、`logLevel` 等键（见工程 `Keys` 枚举） |
| `Library/Caches/.../SparkClient.DeviceCache/` | ETag 与条件请求相关响应体缓存目录 |

| 对外能力（摘要） | 作用 |
| --- | --- |
| `cache(currentUserID:)` / `cache(trustedDeviceID:)` | 会话与设备登记回写 |
| `clearDeviceMetadata()` / `clearAllCaches()` | 登出或全清 |
| `clearETagResponseCache()` | 仅清 HTTP 条件缓存（设置页可暴露） |

### 3.4 OSS 直传配置：`SparkOSSAPI` · `SparkOSSConfigurationStore` · `AliyunOSSRuntimeConfig`

| 项目 | 说明 |
| --- | --- |
| 接口 | `GET /api/v1/oss/sts/credentials/`，需登录；`decodeWrappedData(OCRSTSCredentialsResponse.self)` |
| 与 OCR STS | 响应形状与 `OCRSTSCredentialsResponse` 一致（阿里云 STS + 可选 bucket/region/endpoint） |

**`OCRSTSCredentialsResponse`（`data` 解码目标，键名兼容 camelCase / snake_case）**

| 字段 | 作用 |
| --- | --- |
| `accessKeyID` / `access_key_id` | 临时访问密钥 ID |
| `accessKeySecret` / `access_key_secret` | 临时 Secret |
| `securityToken` / `security_token` | STS Session Token，可选 |
| `expiration` | ISO8601 或 Unix 秒数字符串，用于本地过期判断 |
| `bucket_name` | 目标桶 |
| `region` | 区域 |
| `endpoint` | OSS Endpoint 字符串 |

**`AliyunOSSRuntimeConfig`（内存侧上传用）**

| 字段 | 作用 |
| --- | --- |
| `accessKeyId` / `accessKeySecret` / `securityToken` | 直传签名用 |
| `bucketName` / `region` / `endpointURL` | 构造上传 URL；三者缺一则 `init?(response:)` 失败 |
| `credentialExpiresAt` | 由 `expiration` 解析；`isFresh(thresholdSeconds: 300)` 用于预缓存是否在过期前 5 分钟仍可用 |

`SparkOSSConfigurationStore`：`snapshot: AliyunOSSRuntimeConfig?`；`prefetchFromBackend` 尽力拉取；`configurationForUpload` 在无快照或快过期时再次请求并写回 `snapshot`；`clear()` 置 `nil`（登出时由引导 `reset` 调用）。

### 3.5 AI 配置中枢：`AIConfigCenter` · 远程 Patch · `AIRuntimeStore`

| 能力 | 数据流 |
| --- | --- |
| `refreshRemoteConfig()` | `AIRemoteConfigProvider.fetchRemotePatch()` → 典型实现 `SparkAIConfigAPI.fetchBootstrapPatch`：`GET /api/v1/ai/config/bootstrap/?platform=ios[&client_version=]`，允许 ETag（`etagTTL: 60`）→ `RemoteAIBootstrapPayload` → `AIRemoteSettingsPatch` → 与本地 `AISettingsSnapshot` `merging(remotePatch:)` 后 `repository.save` |
| `prewarm()` / `currentSnapshot()` | `repository.loadSnapshot()` |
| `resolve(for: AIScenario)` | `ScenarioPolicyResolver` 结合快照与 `AIRuntimeStore` 产出 `AIResolvedConfig` |
| `setRuntimeOverride` / `clearRuntimeOverride(s)` | 会话内临时覆盖（如聊天选模型），存 `AIRuntimeStore`；登出由引导 `clearRuntimeOverrides` |

**`AIRemoteSettingsPatch`（远程合并补丁，字段选摘）**

| 字段 | 作用 |
| --- | --- |
| `revision` | 服务端配置版本号（日志与差异判断） |
| `scenarioRemoteBundles` | 按场景的远程模型 bundle（如聊天模型列表） |
| `chat` / `optimizationText` / … | 各 `AIScenario` 扁平配置（与 bundle 并存、合并策略见 `AISettingsSnapshot+RemoteMerge`） |
| `apiKeys` / `searchKeys` / `toolKeys` / `allModels` | 密钥与模型目录补丁 |
| `userInfo` | `AIRemoteUserInfoPatch`：用户可选模型与工具开关等 |
| `trial` / `trialModelPolicy` | 试用状态与策略 |

### 3.6 `AppRouteStore`（主导航）

| 字段 / 方法 | 作用 |
| --- | --- |
| `RootTab` | `home` / `health` / `knowledge` / `chat` / `settings` |
| `selectedTab` | 当前 Tab，`@Published` |
| `resetForNewSession()` | 新会话回到 `.home`（登录引导内调用） |

### 3.7 医疗同步门面：`MedicalSyncService`

| 方法 | 数据行为 |
| --- | --- |
| `currentPreference()` | `MedicalSyncPreferenceRepository.loadPreference()` |
| `bootstrapIfNeeded()` | 若 `isSyncEnabled`：`pullSnapshotFromServer`（优先级取偏好），更新 `lastSyncAt`、将 `hasCompletedInitialUpload` 置 `true`；鉴权失败静默跳过或通知 |
| `setSyncEnabled` / `syncNow` / `setSyncPriority` | 读写偏好并触发拉取（详见「设置」模块） |

**`MedicalSyncPreference`（持久化结构，全文见「设置」模块）**

| 字段 | 作用 |
| --- | --- |
| `isSyncEnabled` | 是否启用云端同步 |
| `hasCompletedInitialUpload` | 首次上传/引导标记 |
| `lastSyncAt` | 上次成功同步时间 |
| `syncPriority` | `CloudSyncPriority`：`realtime` / `balanced` / `background`，传入 `pullSnapshotFromServer` |

### 3.8 联网可达性门闸：`NetworkPathMonitor`

- `AppCoordinatorView` 在路径未评估时展示加载；`isSatisfied == false` 时展示 `NetworkGateView`，**不**进入会话分支，因而也不会触发已登录引导。
- 属系统网络框架封装，无业务 DTO。

### 3.9 加载业务场景对照

| 业务场景 | 初始化 | 手动 | 进页 |
| --- | --- | --- | --- |
| 网络引擎 / DeviceCache | 随 `Backend` / `AppContainer` 构造 | 设置「清 ETag」等 | — |
| OSS STS | ✅ 登录引导预取 | 上传前 `configurationForUpload` | — |
| AI 远程 Patch | ✅ 引导内刷新 | AI 设置等 | — |
| 医疗同步门面 | ✅ 引导内 `bootstrapIfNeeded` | 设置内开关/立即同步 | — |
| 路由 Tab | ✅ 新会话重置 | 用户点 Tab | — |

## 5. 设备登记（Device）

### 5.1 业务场景

- 匿名或带 JWT 向服务端登记 **安装级 deviceId**、**推送 token**、系统信息；写回 **可信设备 ID**。

### 5.2 加载规则

| 触发 | 说明 |
| --- | --- |
| 初始化 | `AppBootstrapper` 在启动引导末尾、`bootstrapIfNeeded` 末尾调用 `registerDevice()` |
| 手动 / 系统 | 推送 token 更新时再次 `RegisterDeviceUseCase.execute(pushToken:...)`（见推送适配层） |

### 5.3 数据来源

- **服务器**：`DeviceAPI.registerDevice`（经 `Backend`）。
- **本地**：`SparkSystemInfo.installationDeviceID`；`DeviceCache.cache(trustedDeviceID:)`。

### 5.4 数据模型格式

- 请求：bundleId、deviceId、可选 userId、pushToken、系统信息。
- 响应：`device_id` 等登记结果（工程内 DTO）。

### 5.5 加载业务场景对照

| 设备登记 | ✅ 启动/登录引导 | 推送 token 变更 | — |

## 6. 首页（Home）

### 6.1 业务场景

- 展示 **用户档案**、**家庭成员**、按选中成员聚合的 **医疗摘要卡片**（病例/体检/检查/用药等计数与最新日期）。
- 展示 **运动健康**（HealthKit，仅适用于首页规则下的「本人」成员）。

### 6.2 加载规则

| 触发 | 说明 |
| --- | --- |
| 进入页面自动加载 | `HomeViewModel.load()`：默认 `syncRemote: true` |
| 手动 | `refresh()` → 强制 `syncRemote: true` |
| 初始化式分支 | `selectMember` → `load(syncRemote: false)`：仅本地快照重算 + 若适用则读 HealthKit |

### 6.3 数据来源

- **服务器（医疗域）**
  - `refreshRemoteSnapshot()`：`GET /api/v1/medical/resources/?kind=members`（`SparkMedicalQueryAPI.listMembers()`），用于刷新成员列表缓存/ETag，**不直接返回首页卡片数据**。
  - `loadMembers()`：同上接口，解码为 `[RemoteMember]` → 映射为 `[Member]`。
  - 首页通过 `LoadHomeMedicalOverviewUseCase` 直接调用 `SparkMedicalQueryAPI`（`complete-data`、成员列表、服药记录等）组装 `HomeMedicalOverview`，不再使用本地聚合快照结构。
- **账号会话**：`UserSession` 来自 `SessionSnapshotStore`；冷启动经 `GET /api/v1/auth/session/` 刷新最新 `is_pro` 等字段后写回本地（见启动需求 `APP-STARTUP-000001`）。首页问候区直接读 `UserSession.displayName`，不再经独立 Profile 仓储派生。
- **本机系统库**：**HealthKit**（`LoadHomeMotionHealthUseCase` → `HomeHealthDataRepository`），仅当选中 `Member` 为「本人」关系（`self` / `本人`）时读取。

### 6.4 数据模型：字段与作用

以下类型定义于 `HomeDashboard.swift`、`UserSession.swift`、`Member.swift`、`MedicalDataRepository.swift` 及 `Core/Domain/Entities` 下各医疗实体。

#### 6.4.1 `UserSession`（当前登录账号会话，首页账号摘要事实源）

| 字段 | 类型 | 作用 |
| --- | --- | --- |
| `accountID` | `Int64` | 服务端账号主键 |
| `email` | `String` | 登录邮箱或手机号标识 |
| `displayName` | `String` | 展示名 / 昵称（首页问候） |
| `signedInAt` | `Date` | 本会话登录时间（本地快照） |
| `signInMethod` | `SignInMethod` | `apple` / `phone` |
| `isPro` | `Bool` | 是否 Pro（冷启动需刷新） |
| `isNewUser` | `Bool` | 是否新用户（登录响应） |

#### 6.4.2 `Member`（家庭成员 / 就诊人）

| 字段 | 类型 | 作用 |
| --- | --- | --- |
| `id` | `Int` | 服务端成员主键；医疗资源外键 `member_id` 与之对应 |
| `name` | `String` | 展示姓名 |
| `gender` | `String` | 性别编码（如 `male` / `female` / `unknown`） |
| `relationship` | `String` | 与账号关系；**含 `self` / `本人` 时首页可读 HealthKit** |
| `birthDate` | `Date?` | 出生日期 |
| `bloodType` | `String` | 血型 |
| `allergies` | `[String]` | 过敏史 |
| `chronicConditions` | `[String]` | 慢病列表 |
| `notes` | `String` | 备注 |
| `avatarUrl` | `String` | 头像 URL |
| `isPrimary` | `Bool` | 是否主档案；排序与默认选中优先 |
| `updatedAt` | `Date` | 服务端最近更新时间 |

#### 6.4.3 `HomeDashboard`（首页一屏聚合模型）

| 字段 | 类型 | 作用 |
| --- | --- | --- |
| `session` | `UserSession` | 当前账号会话（顶部问候等） |

### 6.5 服务器返回数据格式

#### 6.5.1 HTTP 响应外层（通用）

医疗查询与摘要接口经 `SparkNetworkEngine` 解码，成功体为后端统一包裹（与 `SparkResponseDecodingMode.backendWrapped` 一致）：

  "code": 0,
  "msg": "ok",
  "data": …

1. **新增模块**时，请在本文件追加一节，并至少填齐五列：**业务场景**、**加载规则（三类）**、**数据来源**、**模型格式**、**加载业务场景对照表**。
2. **跨模块共享状态**（如 `PatientContextStore`）在「上游模块」标注写入时机，避免重复拉网。
3. **以服务端为准** 与 **以本地为准** 的模块要在「数据来源」中显式写出冲突策略（例如聊天：先同步再读 Core Data）。
