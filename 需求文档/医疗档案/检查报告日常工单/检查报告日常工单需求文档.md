## 工单 `EXAMINATION-REPORT-000001`：检查/体检报告拍摄自定义相机

### 工单状态

需求设计中。

## 1. 背景

检查报告列表页当前已经提供“拍摄添加报告”入口：

```text
SparkClient/SparkClient/Projects/Features/Home/Presentation/MedicalLists/ExaminationReports/ExaminationReportsListPage.swift:143-147
```

该入口打开通用医疗附件上传列表：

```swift
MedicalAttachmentUploadListSheet(documentType: .examinationReport) { files in
    startExaminationReportRecognition(files: files)
}
```

通用上传列表中，检查报告当前仍使用系统相机：

```text
SparkClient/SparkClient/Projects/Features/Home/Presentation/MedicalLists/Shared/MedicalAttachmentUploadListSheet.swift:117-122
```

现有策略：

```swift
case .medicineBox:
    return .medicineBoxCustomCamera
case .medicationPlan, .examinationReport, .healthExamReport, .caseDocument:
    return .systemCamera
```

因此用户在检查报告、体检报告上传 Sheet 中点击“拍照”时，仍打开 `SystemImagePicker(source: .camera)`。系统相机无法提供报告拍摄所需的取景框、纸张边界提示、连续拍摄、拍后横向预览管理和 OCR 友好提示。

本工单要求在 `CustomCamera/Presentation/Scene` 内新增“医疗报告拍摄自定义相机”，并把检查报告、体检报告上传入口的拍照路径切换到该自定义相机。

## 2. 目标

### 2.1 核心目标

1. 在 `CustomCamera/Presentation/Scene` 下新增医疗报告拍摄自定义相机场景。
2. 检查报告、体检报告上传 Sheet 点击“拍照”时，不再打开系统相机，改为打开医疗报告自定义相机。
3. 自定义相机复用现有 `CustomCameraView`、`CustomCameraManager`、`DefaultCustomCapturedMediaScreen` 等底层能力。
4. 参考 `MedicineBoxCameraSceneView` 的优秀设计，包括首次引导、连续拍摄、拍后缩略图、删除、QuickLook 预览、完成返回多图。
5. 不直接照搬药盒取景比例，应按医疗报告/检查报告/体检报告常见纸张形态重新设计取景框比例。
6. 拍摄结果继续转成 `[MedicalUploadLocalFile]`，保持后续 `startExaminationReportRecognition(files:)` 识别流程不变。
7. 保留相册选择、文件导入、文件预览、最大数量限制等现有上传列表能力。
8. 检查报告入口最多拍摄 3 张图片；体检报告入口最多拍摄 6 张图片。

### 2.2 非目标

1. 本工单不修改服务端识别接口。
2. 本工单不改变 `MedicalUploadLocalFile` 数据结构。
3. 本工单不实现自动纸张边缘检测、自动裁切、透视矫正、OCR 预处理算法。
4. 本工单不改变病例、服药计划等其他上传入口的相机策略。
5. 本工单不改检查报告、体检报告识别结果页和保存入库逻辑。

## 3. 参考实现分析

### 3.1 MedicineBox 值得复用的设计

参考文件：

```text
SparkClient/SparkClient/Projects/Features/CustomCamera/Presentation/Scene/MedicineBox/MedicineBoxCameraSceneView.swift
SparkClient/SparkClient/Projects/Features/CustomCamera/Presentation/Scene/MedicineBox/MedicineBoxCameraGuideView.swift
SparkClient/SparkClient/Projects/Features/CustomCamera/Presentation/Scene/MedicineBox/MedicineBoxCaptureSlot.swift
SparkClient/SparkClient/Projects/Features/CustomCamera/Presentation/Scene/MedicineBox/MedicineBoxCameraViewfinderShape.swift
```

可直接复用或仿照的优秀点：

1. `fullScreenCover` 打开自定义相机，退出后回到上传列表。
2. 使用 `CustomCameraView(manager:)` 组装底层相机，不再依赖系统 `UIImagePickerController`。
3. 首次进入展示拍摄引导，并通过 `GuideStore` 记录是否已读。
4. 拍摄后先进入默认确认页，用户确认后才追加到底部横向预览列表。
5. 支持连续拍摄，确认后将图片追加到底部横向滚动预览列表。
6. 底部预览列表展示缩略图，用户能明确知道已经拍了哪些内容。
7. 已拍图片支持删除。
8. 点击已拍图片时打开 QuickLook 预览，预览删除规则沿用用药相机的一致交互。
9. 点击完成时按拍摄顺序返回图片，不设置必拍项。
10. 返回给上层的是业务结构数组，上层再负责保存临时文件和发起识别。

### 3.2 MedicineBox 不适合直接照搬的问题

药盒相机是为药品包装、保质期、说明书设计的，不适合原样用于检查报告：

1. 取景框比例偏向药盒/说明书混合场景，当前实现高度最大约 `viewfinderWidth * 1.18`，不完全匹配 A4 竖版报告的 `1:1.414` 比例，也不匹配横版影像报告或长条检验单。
2. 底部面板高度按屏幕高度 `26%` 且最低 `220pt`，再用 `panelHeight / 268` 线性缩放内部控件。小屏上底部面板会挤压取景区，大屏上控件可能随面板变大而显得过重。
3. 取景框尺寸主要受屏幕宽度驱动，报告拍摄更应该同时考虑纸张比例、OCR 文字可读性、上下安全区和底部预览列表占用。
4. 药盒四角取景框只提示“把目标放进框内”，缺少报告拍摄所需的纸张边缘、留白、平整、避免反光等提示。
5. 药盒槽位是固定业务内容：药盒正面、保质期、说明书；检查报告和体检报告页数不固定，更适合按拍摄顺序追加到底部横向滚动预览列表。
6. 药盒需求文档与当前代码存在必拍项描述不一致风险：文档曾描述“药盒正面 + 说明书”必拍，但当前代码 `canFinish` 校验的是 `.front` 和 `.expiry`。医疗报告相机本工单取消必拍项，避免相机侧与业务识别侧产生额外校验分歧。
7. 药盒底部左侧显示固定业务标题和图标，医疗报告拍摄应更关注页数、清晰度和 OCR 提示，避免占用过多底部空间。

## 5. 拍摄预览设计

### 5.1 横向滚动预览方案

取消固定槽位，不再预设 `报告首页`、`明细页`、`补充页`。用户每完成一次拍摄确认，图片按拍摄顺序追加到底部横向滚动预览列表。

```text
[第 1 张] [第 2 张] [第 3 张] ...
```

不同入口的最大拍摄数量：

| 入口 | 最大拍摄数量 | 说明 |
| --- | --- | --- |
| 检查报告 | 3 张 | 适合单页或少量附页的检查、检验、影像报告 |
| 体检报告 | 6 张 | 体检报告通常页数更多，允许拍摄更多页面 |

说明：

1. 不设置必拍项，用户可以在未拍摄图片时返回取消，也可以在至少拍摄 1 张后点击完成。
2. 图片顺序即拍摄顺序，返回给上传列表时不再按预设业务位置重排。
3. 缩略图显示页码序号，例如 `1`、`2`、`3`。
4. 到达最大拍摄数量后，拍摄按钮置灰或点击提示“已达到本次拍摄上限”。
5. 如果用户需要上传更多图片，可回到上传列表继续通过相册或文件导入补充。

### 5.2 完成规则

1. 不校验必拍项。
2. 已拍摄至少 1 张图片时，点击完成关闭相机并返回已拍图片。
3. 未拍摄任何图片时，完成按钮置灰；如仍允许点击，应提示“请先拍摄报告图片”。
4. 返回顺序固定为用户拍摄确认的顺序。
5. 删除中间图片后，剩余图片重新按当前顺序展示序号。

## 6. 取景框比例与布局

### 6.1 设计原则

检查报告相机的取景框应服务 OCR 和人工拍摄稳定性：

1. 以竖版报告为默认，优先适配 A4/医院报告单。
2. 取景框宽高比建议接近 `1:1.414`，但需要在小屏上根据可用高度压缩到不遮挡底部控件。
3. 允许横向报告、影像胶片拍摄时使用同一大框容纳，不做第一版横竖切换按钮。
4. 取景框内增加弱提示线或边缘留白提示，提醒用户让报告四边完整入框。
5. 不使用纯固定高度或单一 `width * 1.18` 规则。

### 6.2 推荐布局计算

建议将布局计算从药盒的“底部面板比例驱动”改为“可用拍摄区域 + 报告目标比例”驱动：

```swift
let availableWidth = proxy.size.width
let availableHeight = proxy.size.height
let safeTop = proxy.safeAreaInsets.top
let safeBottom = proxy.safeAreaInsets.bottom

let bottomPanelHeight = min(max(196, availableHeight * 0.24), 252)
let topToolbarHeight = safeTop + 58
let promptHeight: CGFloat = 48
let verticalGap: CGFloat = 12

let cameraAreaTop = topToolbarHeight + verticalGap
let cameraAreaBottom = availableHeight - safeBottom - bottomPanelHeight - promptHeight - verticalGap
let cameraAreaHeight = max(260, cameraAreaBottom - cameraAreaTop)

let targetAspect: CGFloat = 1.414 // height / width, A4 portrait
let maxWidth = min(availableWidth * 0.90, 430)
let maxHeight = cameraAreaHeight * 0.94
let widthByHeight = maxHeight / targetAspect

let viewfinderWidth = min(maxWidth, widthByHeight)
let viewfinderHeight = min(maxHeight, viewfinderWidth * targetAspect)
let viewfinderCenterY = cameraAreaTop + cameraAreaHeight * 0.50
```

约束要求：

| 设备 | 要求 |
| --- | --- |
| 小屏 | 优先保证底部横向预览列表和完成按钮完整展示，取景框可适当压缩 |
| 标准屏 | 取景框接近 A4 竖版比例，报告四边完整入框 |
| 大屏 | 限制最大宽度，避免取景框过宽导致用户离纸过远 |
| 横屏或异常比例 | 保持可用，不做崩溃；可降级为最大可用矩形 |

### 6.3 底部面板改进

MedicineBox 的底部面板内部控件随 `panelHeight` 线性缩放，检查报告相机建议改为固定合理区间：

1. 底部面板高度限定在 `196pt...252pt`。
2. 缩略图高度限定在 `72pt...92pt`。
3. 拍摄按钮大小限定在 `72pt...84pt`。
4. 完成按钮保持最小点击区域 `44pt`。
5. 文案使用 `lineLimit(2)` 和 `minimumScaleFactor(0.8)`，避免小屏溢出。

## 7. 相机页面交互

### 7.1 首次引导

首次进入展示 `ExaminationReportCameraGuideView`。

引导内容建议：

1. 将报告放在平整桌面上。
2. 保持纸张四边完整入框。
3. 避免反光、阴影和手指遮挡。
4. 拍清楚姓名、检查项目、时间、医院、所见和结论。
5. 多页报告可按顺序连续拍摄，检查报告最多 3 张，体检报告最多 6 张。

存储 key：

```text
spark.examination_report.camera.guide.has_seen
```

### 7.2 顶部栏

1. 左侧返回按钮：关闭相机，不保存未返回的内容。
2. 中间标题：`检查报告`。
3. 右侧帮助按钮：再次打开引导页。
4. 第一版可不展示前后摄像头切换；默认后置摄像头。

### 7.3 取景区

1. 展示报告纸张比例取景框。
2. 取景框外使用半透明遮罩。
3. 取景框下方展示拍摄提示，例如“保持报告四边完整入框，文字清晰无遮挡”。
4. 提示文案不依赖固定槽位，可根据已拍数量提示“第 N 张”。

### 7.4 底部面板

底部包含：

1. 横向滚动缩略图预览列表。
2. 中央拍摄按钮。
3. 完成按钮。

交互规则：

1. 用户拍摄并在确认页确认后，将图片追加到底部横向预览列表末尾。
2. 点击已有图片打开 QuickLook 预览。
3. 已有图片右上角展示删除按钮。
4. 删除图片后从底部预览列表移除，并重新计算序号。
5. 预览删除规则与用药相机保持一致：删除只影响当前已拍列表，不关闭相机，不影响其他图片。
6. 未达到最大数量时，拍摄按钮保持可用；达到上限后禁用或提示已达到上限。

### 8.2 fullScreenCover 接入

在 `MedicalAttachmentUploadListSheet` 的 `fullScreenCover` 中新增分支：

```swift
case .examinationReportCustomCamera:
    ExaminationReportCameraSceneView(
        onCancel: { presentedCameraCover = nil },
        onImagesCaptured: { images in
            presentedCameraCover = nil
            for captured in images {
                if let file = saveUIImageToTemp(
                    image: captured.image,
                    namePrefix: "\(fileNamePrefix)_camera_page_\(captured.index)"
                ) {
                    localFiles.append(file)
                }
            }
        },
        maxCaptureCount: documentType.reportCameraMaxCaptureCount
    )
```

### 8.3 文件数量限制

1. 检查报告自定义相机最多返回 3 张图片。
2. 体检报告自定义相机最多返回 6 张图片。
3. 打开相机前仍使用 `ensureCanAddMoreFiles()` 校验。
4. 返回多图时仍需调用 `appendFiles` 或等价逻辑，避免超过剩余文件数。
5. 如果上传列表剩余可追加数量少于相机返回图片数，应按拍摄顺序追加到上限，并提示已达到最大文件数。
6. `MedicalAttachmentUploadDocumentType.maxFileCount` 需要同步支持体检报告拍摄 6 张；如业务仍要求体检报告最终只上传 1 个 PDF 文件，应在本工单中明确放宽图片上传上限。

## 10. 验收标准

### 10.1 入口验收

1. 在检查报告列表页点击底部“拍摄添加报告”打开上传列表。
2. 检查报告上传列表点击“拍照”时，打开 `ExaminationReportCameraSceneView`，本次最多拍摄 3 张。
3. 体检报告上传列表点击“拍照”时，打开 `ExaminationReportCameraSceneView`，本次最多拍摄 6 张。
4. 检查报告、体检报告拍照不再打开系统相机。
5. 药箱入口仍打开 `MedicineBoxCameraSceneView`。
6. 病例、服药计划入口仍按原策略打开系统相机。

### 10.2 相机交互验收

1. 首次进入检查报告相机展示拍摄引导页。
2. 再次进入默认不展示引导，但可点击帮助按钮重新查看。
3. 取景框为竖版 A4 友好比例，同时能容纳横版报告；小屏、大屏不遮挡底部面板。
4. 底部展示横向滚动预览列表，不展示固定槽位。
5. 拍摄确认后图片追加到预览列表末尾。
6. 已拍图片可以删除。
7. 点击已拍图片时打开 QuickLook 预览。
8. 不设置必拍项。
9. 未拍任何图片时完成按钮置灰或提示“请先拍摄报告图片”。
10. 已拍至少 1 张后允许完成并关闭相机。
11. 达到当前入口最大拍摄数量后，拍摄按钮禁用或提示已达到上限。

### 10.3 识别流程验收

1. 相机返回的图片被保存为临时 jpg。
2. 文件名前缀包含 `examination_report_camera_` 或 `health_exam_report_camera_`，并带拍摄顺序后缀。
3. 图片追加到上传列表后可预览、删除。
4. 点击上传列表确认后，继续调用 `startExaminationReportRecognition(files:)`。
5. 原有检查报告、体检报告识别、结果展示、保存入库流程不受影响。

### 10.4 回归验收

1. `MedicalAttachmentUploadListSheet` 的相册选择能力正常。
2. `MedicalAttachmentUploadListSheet` 的文件导入能力正常。
3. 最大文件数量限制仍生效。
4. 药箱多图拍摄不受检查报告相机新增分支影响。
5. 病例、服药计划等非报告上传入口不出现医疗报告相机页面。

## 11. 风险与注意事项

1. 医疗报告种类差异较大，单一 A4 竖版比例不能覆盖所有报告。第一版以常见纸质报告为主，横版影像报告先保证可拍，不做专门横版模式。
2. 多页报告第一版不做固定槽位，检查报告最多 3 张，体检报告最多 6 张；超过上限仍可通过相册或文件上传补充。
3. 自定义相机返回多图时需要遵守上传列表最大数量限制，避免绕过 `maxFileCount`。
4. 取景框只是拍摄指导，不等于真实裁切结果；第一版不承诺自动裁切和透视矫正。
5. 需求和代码必须统一“无必拍项”规则，避免出现 MedicineBox 当前文档与实现不一致的情况。
