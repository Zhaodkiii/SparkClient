# CHAT-000036 对话引导卡片科普问题点击统计未上报修复工单

创建日期：2026-08-23

关联模块：

- 客户端卡片 UI：`SparkClient/Projects/Features/Chat/Presentation/ChatView/MessageCards/Guide/ChatGuideMessageCardView.swift`
- 点击入口：`SparkClient/Projects/Features/Chat/Presentation/ChatDetailViewModel.swift`
- 生成与登记协调器：`SparkClient/Projects/Features/Chat/Application/ChatGuideQuestionGenerationCoordinator.swift`
- 登记与点击上报协议：`SparkClient/Projects/Features/Chat/Application/ChatGuideQuestionReporting.swift`
- 引导卡片 payload：`SparkClient/Projects/Features/Chat/Domain/ChatMessage/BlockPayloads/ChatGuideCardPayload.swift`
- 客户端 API：`SparkClient/Projects/Core/Networking/API/Medical/ChatGuideQuestionAPI.swift`

## 1. 背景

对话引导卡片的 AI 科普问题已经可以成功登记到服务端，后台管理系统也能看到生成记录。但是用户点击已生成的科普问题后，后台管理系统中的点击次数没有增加。

本工单只分析问题并给出修复方案，不实现代码。

## 2. 现象

点击卡片问题后：

- 当前对话可以正常发送该科普问题 prompt。
- 后台管理系统生成记录的点击次数没有增加。
- 客户端日志显示点击统计被跳过。

关键日志：

```text
[CHATGUIDE-DEBUG][api] register success registered=3 failed=0 mapping=["sedentary_programmer_eye_care": 11, "low_diastolic_blood_pressure_care": 12, "thyroid_cyst_daily_care": 10]
[CHATGUIDE-DEBUG][coordinator] register mapping=["sedentary_programmer_eye_care": 11, "low_diastolic_blood_pressure_care": 12, "thyroid_cyst_daily_care": 10] thread=EF063BCB
[CHATGUIDE-DEBUG][coordinator] persist skip: state/member mismatch thread=EF063BCB state=generated payloadMember=nil tokenMember=10
[CHATGUIDE-DEBUG][vm] sendGuideQuestion enter questionId=low_diastolic_blood_pressure_care title=舒张压偏低日常调理 serverQuestionId=nil
[CHATGUIDE-DEBUG][vm] sendGuideQuestion skip click report: serverQuestionId is nil questionId=low_diastolic_blood_pressure_care
```

服务端日志也证明登记成功：

```text
POST /api/v1/medical/chat-guide/questions/register/ status=201
registered=3
client_question_id=thyroid_cyst_daily_care server_question_id=10
client_question_id=sedentary_programmer_eye_care server_question_id=11
client_question_id=low_diastolic_blood_pressure_care server_question_id=12
```

但后续点击时，没有看到点击统计接口被调用：

```text
POST /api/v1/medical/chat-guide/questions/click/
```

因此当前问题不是“后台管理系统没有刷新”，而是客户端点击上报没有发生。

## 3. 问题链路

当前链路应为：

```text
AI 生成 3 个问题
  ↓
客户端登记到服务端
  ↓
服务端返回 client_question_id → server_question_id
  ↓
客户端把 server_question_id 回填到 guide card payload.questions
  ↓
用户点击问题
  ↓
ChatDetailViewModel 读取 question.serverQuestionId
  ↓
调用点击统计接口
  ↓
服务端 click_count +1
```

实际链路为：

```text
AI 生成 3 个问题
  ↓
客户端登记到服务端成功
  ↓
服务端返回映射
  ↓
客户端回填 server_question_id 时被拦截
  ↓
guide card payload.questions[*].serverQuestionId 仍为 nil
  ↓
用户点击问题
  ↓
ChatDetailViewModel 判断 serverQuestionId=nil
  ↓
跳过点击统计上报
  ↓
后台 click_count 不增加
```

## 4. 根因分析

### 4.1 直接原因

`ChatGuideQuestionGenerationCoordinator.persistServerQuestionIDs` 在回填服务端问题 ID 前做了状态与成员校验：

```swift
target.payload.effectiveQuestionGenerationState == .generated
target.payload.questionGeneration?.memberID == token.memberID
```

日志显示：

```text
state=generated payloadMember=nil tokenMember=10
```

也就是说：

- 当前卡片确实是 `generated` 状态。
- 当前生成任务 token 的成员是 `10`。
- 但持久化后的 `payload.questionGeneration.memberID` 是 `nil`。
- 因此回填逻辑认为成员不匹配，跳过 `serverQuestionId` 写入。

### 4.2 触发条件

服务端 `block_updates` 日志显示，AI 生成成功后的 payload 包含：

```json
"question_generation": {
  "state": "generated",
  "generated_at": "...",
  "source": "current_chat_ai",
  "member_profile_digest": "933b6c2c3d635b30"
}
```

但缺少：

```json
"member_id": 10
```

因此重新从本地/同步数据读取 guide card 时，`questionGeneration.memberID` 为空。

### 4.3 为什么点击没有上报

`ChatDetailViewModel.sendGuideQuestion` 当前逻辑是：

```text
如果 question.serverQuestionId 有值：调用 reportGuideQuestionClick
如果 question.serverQuestionId 为 nil：跳过点击上报
```

日志显示：

```text
serverQuestionId=nil
skip click report
```

所以点击统计没有进入 `SparkChatGuideQuestionAPI.reportClick`，服务端自然不会 `click_count +1`。

## 5. 修复目标

1. AI 生成问题登记成功后，必须把服务端返回的 `server_question_id` 回填到对应 `ChatGuideQuestion.serverQuestionId`。
2. 回填成功后，本地持久化和 UI 状态中的 guide card 都应携带 `serverQuestionId`。
3. 用户点击已登记问题时，`ChatDetailViewModel` 能读取到 `serverQuestionId`，并异步调用点击统计接口。
4. 固定兜底问题仍不登记、不上报点击。
5. 不影响当前点击发送 AI prompt 的主流程。

## 6. 修复方案

### 6.1 修复生成成功 payload 的 memberID 写入

在 AI 生成成功并构造 `ChatGuideQuestionGenerationMeta` 时，必须写入当前生成任务的成员 ID：

```text
questionGeneration.memberID = token.memberID
```

要求：

- `state=generated` 时必须带 `memberID`。
- `source=current_chat_ai` 时必须带 `memberID`。
- block payload 本地持久化和 `block_updates` 同步时都能保留该字段。

这样 `persistServerQuestionIDs` 的成员校验可以正常通过。

### 6.2 回填 serverQuestionId 后同步本地 UI 与持久化

`persistServerQuestionIDs` 写入 `payload.questions[index].serverQuestionId` 后，需要确认：

- 调用 `persistPayloadUpdate` 成功。
- `stateStore` 中当前消息 block 被刷新。
- UI 中 `ChatGuideMessageCardView` 重新收到带 `serverQuestionId` 的 payload。

验收日志应能看到：

```text
[CHATGUIDE-DEBUG][coordinator] persist backfill questionId=low_diastolic_blood_pressure_care serverId=12
[CHATGUIDE-DEBUG][coordinator] persist done ...
```

### 6.3 点击上报只依赖 serverQuestionId

`ChatDetailViewModel.sendGuideQuestion` 现有逻辑可以保留：

```text
serverQuestionId != nil -> 上报点击
serverQuestionId == nil -> 跳过点击
```

本工单不建议用 `question.id/title/prompt` 临时反查服务端记录，避免把客户端固定兜底问题误报为 AI 生成记录。

### 6.4 保持固定兜底问题不上报

以下场景仍应保持 `serverQuestionId=nil`：

- 无绑定成员使用固定三条问题。
- AI 生成失败后使用固定兜底问题。
- 解析失败后使用固定兜底问题。
- 历史旧卡片中没有服务端登记映射的问题。

这些问题点击后只发送 prompt，不上报点击统计。

## 7. 备选兜底方案

如果某些历史卡片已经登记成功，但本地没有保存 `serverQuestionId`，可以选择不做历史修复。

原因：

- 点击统计是运营数据，不应为了补历史映射引入复杂反查逻辑。
- 当前问题优先修复新生成卡片的正确链路。
- 旧卡片点击没有统计可以接受。

如后续必须兼容历史卡片，可另开工单设计：

- 客户端根据 `memberID + title + prompt` 查询服务端生成记录。
- 服务端返回匹配到的 record id。
- 客户端再上报点击。

该方案本阶段不推荐。

## 8. 影响范围

客户端可能涉及：

- `ChatGuideQuestionGenerationCoordinator.swift`
  - 生成成功 payload 的 `questionGeneration.memberID` 写入。
  - 登记映射回填的状态校验。
  - 回填后的本地持久化与 UI 刷新。
- `ChatGuideCardPayload.swift`
  - 确认 `ChatGuideQuestionGenerationMeta.memberID` 编解码字段正常。
  - 确认 `ChatGuideQuestion.serverQuestionId` 编解码字段正常。
- `ChatDetailViewModel.swift`
  - 保持点击上报入口。
  - 增加必要日志，确认点击时 `serverQuestionId` 不再为 nil。
- `ChatGuideQuestionReporting.swift`
  - 保持登记返回映射和点击上报协议。
- `ChatGuideMessageCardView.swift`
  - 纯渲染组件，不建议在这里做网络上报或状态修复。

服务端可能涉及：

- 若客户端修复后仍未增加点击，再检查 `/api/v1/medical/chat-guide/questions/click/` 是否按 `server_question_id` 原子递增 `ChatGuideGeneratedQuestionRecord.click_count`。
- 当前日志已证明登记接口正常，优先不动登记接口。

## 10. 验收标准

### 10.1 AI 生成与登记

- 新建绑定成员的对话后，AI 成功生成 3 个科普问题。
- 服务端登记接口返回 3 个 `server_question_id`。
- 客户端日志不再出现：

```text
persist skip: state/member mismatch ... payloadMember=nil tokenMember=10
```

- 客户端日志出现 server id 回填成功记录。

### 10.2 点击统计

- 点击 AI 生成问题后，`sendGuideQuestion` 日志中的 `serverQuestionId` 不为 nil。
- 点击后客户端调用：

```text
POST /api/v1/medical/chat-guide/questions/click/
```

- 服务端返回 success。
- 后台管理系统对应生成记录的 `click_count` 增加。

### 10.3 固定兜底问题

- 无绑定成员场景使用固定三条问题。
- 固定问题的 `serverQuestionId` 仍为 nil。
- 点击固定问题不调用点击统计接口。

### 10.4 回归

- 点击问题后仍能正常向当前对话 AI 发送 prompt。
- 点击上报失败不影响发送 prompt。
- 重新进入已有对话不重新触发 AI 生成。
- 切换成员后新生成的问题可以正常登记、回填、点击统计。

## 11. 测试建议

新增或补充测试：

- `ChatGuideQuestionGenerationCoordinatorTests`
  - AI 生成成功时 `questionGeneration.memberID` 写入正确。
  - 登记返回映射后，`serverQuestionId` 能回填到对应问题。
  - `payloadMember=nil` 的异常旧 payload 不应覆盖新成员结果，但新生成 payload 不应出现该状态。
- `ChatGuideQuestionSendTests`
  - `serverQuestionId != nil` 时触发点击上报。
  - `serverQuestionId == nil` 时不触发点击上报，但仍发送 prompt。
- `ChatGuideCardPayloadCodableTests`
  - `questionGeneration.memberID` 编解码保真。
  - `questions[*].serverQuestionId` 编解码保真。
