## 一、模块目标

修复 `ChatView` 通过根级 `fullScreenCover` 打开时，系统引导卡片健康数据滑块无法跳转的问题，并统一所有 Chat 呈现方式的导航语义。

最终规则：

1. 无论 Chat 由 `NavigationDestination` 还是 `fullScreenCover` 打开，均使用 `NavigationLink → ChatGuideHomeDestinationView`。
2. 点击卡片不关闭 `fullScreenCover`，不切换底部 Tab，不修改 `AppRouteStore.selectedTab`。
3. 目标模块在当前 Chat 导航容器内 push；系统返回后回到原对话。
4. 运动进入 `FitnessHomeView`，饮食进入 `NutritionHomeView`，身材管理和医疗进入 `HealthHomeView`。
5. 复用现有 `ChatGuideHomeDestinationBuilder` 和消息渲染透传链，不新增第二套路由协议。

### 1.1 用户可见问题

复现：进入对话 Tab，自动恢复或新建会话后由根级 Cover 打开 Chat，点击系统引导消息顶部滑块没有反应。

根因是全屏入口没有注入 destination builder，滑块按现有安全降级规则变成了纯展示。期望是在 Cover 内 push 对应模块，返回后仍停留在当前 Thread。

### 1.2 范围

| 项目 | 本期结论 |
| --- | --- |
| 全屏 Chat 引导卡片恢复跳转 | 必须 |
| 普通 Chat NavigationLink 行为 | 保持不变 |
| 全屏 Chat 保持 Cover 呈现 | 必须 |
| 切换 `.healthHome` 或其他 Tab | 不做 |
| 新增 route handler/dismiss intent | 不做 |
| 修改指标、Thread 或消息发送 | 不做 |
| 删除 `ChatGuideHomeDestinationView` | 不做；它是统一目标页 |

## 三、问题分析与根因

### 需求说明

问题并非 `NavigationLink` 无法在 Cover 中使用，而是全屏 Chat 组装遗漏注入。

### 基础要求与业务规则

1. `ChatGuideMetricCarouselView.sectionPage` 已实现：builder 非空时 NavigationLink，为空时只读展示。
2. `ChatView` 已声明并完整透传 `guideHomeDestinationBuilder`。
3. 两个普通 Tab 宿主已构造 builder，因此普通 Chat 正常。
4. `SignedInMainTabHostView.chatFullScreenCover` 外层已有 `CompatibleNavigationContainer`，可以承载 push。
5. 全屏入口构造 `ChatView` 时没有传 builder，这是直接缺口。
6. 原“关闭 Cover 后切 Tab”方案改变了返回语义并引入跨宿主时序，按最新决策废弃。

### 验收标准

- [ ] 全屏入口 builder 不再为 nil。
- [ ] 不新增跨 Tab handler 或模块 dismiss intent。
- [ ] 普通与全屏 Chat 经过同一 NavigationLink/destination。

### 技术细节与设计代码位置

- builder 类型：`ChatRenderContext.swift`。
- 卡片分支：`ChatGuideMetricCarouselView.sectionPage(_:)`。
- Chat 透传：`ChatView.swift`。
- 全屏缺口：`SignedInMainTabHostView.chatFullScreenCover(threadID:source:)`。

## 四、统一 Destination Builder 组装与注入

### 需求说明

将 builder 提升为 App 组合根的共有依赖，同时提供给两个 Tab 宿主和全屏 Chat，避免三个入口重复拼装目标页。

### 基础要求与业务规则

1. 保留类型：`ChatGuideHomeDestinationBuilder = (ChatGuideMetricCategory) -> AnyView`。
2. 推荐在 `SignedInMainTabHostView` 建立唯一 `guideHomeDestinationBuilder`。
3. builder 使用 `session`、`MainTabDependencies` 和 `$activeHomeFullScreenCover` 构造 `ChatGuideHomeDestinationView`。
4. `IOS26TabBarView`、`MainTabCoordinatorView` 改为接收 builder，移除各自重复闭包。
5. `chatFullScreenCover` 构造 `ChatView` 时传入同一个 builder。
6. builder 不捕获 Thread 状态，不关闭 Cover，不写 selectedTab。
7. 若本期不做公共提取，也必须给全屏入口注入等价 builder；重复实现登记为后续重构。

### 验收标准

- [ ] 三类 Chat 入口获得语义一致的 builder。
- [ ] category 映射仍只有一处事实源。
- [ ] 不形成第三份长期重复的构造代码。

### 技术细节与设计代码位置

- 统一组装：`SignedInMainTabHostView.swift`。
- 当前重复组装：两个 Tab 宿主的 `guideHomeDestinationBuilder`。
- 目标依赖：`ChatGuideHomeDestinationView.init(...)`。

## 五、全屏导航与返回行为

### 需求说明

全屏 Chat 与目标模块属于同一个临时导航会话；进入模块不结束 Cover，返回模块恢复原 Chat。

### 基础要求与业务规则

1. 结构保持 `fullScreenCover → CompatibleNavigationContainer → ChatView`。
2. 点击滑块执行 `NavigationLink → ChatGuideHomeDestinationView`。
3. push 前后 `activeHomeFullScreenCover` 保持 `.chat(...)`，不得设为 nil。
4. 不调用 `AppRouteStore.route(to:)`，不改变 selectedTab 和各 Tab route stack。
5. 目标页使用系统返回按钮回到 Chat，不增加“返回首页 Tab”动作。
6. Chat 根页面左上角 `.home/.close` 保持原逻辑，仅用户点击时关闭 Cover。
7. 返回后保留 Thread、消息滚动位置、Composer 草稿和生成状态。

### 验收标准

- [ ] 点击时 Cover 不消失。
- [ ] 目标页在 Cover 内正常 push。
- [ ] 返回到同一 Thread 且状态保持。
- [ ] 底部 Tab 内容未被切换。

### 技术细节与设计代码位置

- Cover：`SignedInMainTabHostView.homeFullScreenCoverContent(_:)`。
- Chat Cover：`chatFullScreenCover(threadID:source:)`。
- 导航容器：`CompatibleNavigationContainer.swift`。

## 七、交互、并发与异常

### 需求说明

统一导航不新增业务状态机，但需覆盖手势、连点和生成中离页。

### 基础要求与业务规则

1. 横向滑动 Carousel 只切页，不误触 NavigationLink。
2. 快速连点不得堆叠多个相同 destination。
3. AI 生成中允许查看模块；Chat 未关闭，因此不取消生成。
4. 返回后读取同一 `ChatStateStore` 最新状态。
5. builder 意外缺失时保持只读降级且不崩溃，但测试必须暴露遗漏。
6. 账号退出时沿根视图生命周期移除 Cover，不增加额外清理状态。

### 验收标准

- [ ] 滑动不误导航，连点不重复 push。
- [ ] 生成中进入/返回不留下悬挂任务。
- [ ] builder 缺失安全降级并可被测试发现。

### 技术细节与设计代码位置

- 点击与分页：`ChatGuideMetricCarouselView.swift`。
- 状态：`ChatView.swift` 和现有 `ChatStateStore`。
- 双渲染链：`ChatSwiftUIConversationView.swift`、`ConversationList/`。

## 八、整体业务流程

```text
全屏或普通 Chat 打开
  ↓
ChatView 获得统一 guideHomeDestinationBuilder
  ↓
用户点击引导滑块 category
  ↓
NavigationLink 调用 builder(category)
  ↓
push ChatGuideHomeDestinationView
  ↓
显示 FitnessHomeView / NutritionHomeView / HealthHomeView
  ↓
系统返回
  ↓
回到原 ChatView

全屏场景全过程：fullScreenCover 保持打开，selectedTab 保持不变
```

## 九、状态模型

## 十五、当前实现、缺口与演进

### 15.1 当前实现

- 已有 builder、NavigationLink、目标页及类别映射。
- `ChatView` 已透传 builder。
- 普通 Tab 宿主已分别构造 builder。
- 全屏 Chat 外层已有导航容器。

### 15.2 当前缺口

1. 全屏 Chat 未注入 builder。
2. builder 构造分散在两个 Tab 宿主，根入口无法直接复用。
3. 缺少 Cover 内 push、返回保持和 RootTab 不变测试。

### 15.3 实施顺序

1. 将 builder 构造提升到 `SignedInMainTabHostView`。
2. 同一 builder 注入两个 Tab 宿主和全屏 `ChatView`。
3. 移除 Tab 宿主重复拼装，保留 Chat 现有透传链。
4. 补全屏导航、返回、RootTab 不变和双渲染测试。

### 15.4 架构决策

**统一复用 `NavigationLink → ChatGuideHomeDestinationView`。**

全屏 Chat 已在 `CompatibleNavigationContainer` 中，问题只是 builder 注入遗漏。该方案保持两种呈现方式一致，避免新增跨宿主状态与时序。

明确废弃旧方案：引导卡片点击不关闭 Cover，不通过 `.home` route 切 `.healthHome`，不写 `HomeSectionPreferenceStore`。
