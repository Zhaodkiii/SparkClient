## 一、需求背景

用户查看体检报告或检查报告时，通常会紧接着产生“这个指标是否异常”“影像结论是什么意思”“需要复查什么”“多个异常是否相关”等问题。目前如果用户从详情页退出，再进入对话并重新选择报告，会产生明显的上下文切换和重复选择成本。

本工单要求在下列服务端报告详情页提供统一的快捷对话入口：

1. 体检报告详情页。
2. 检查报告总览详情页。
3. 实验室检查明细页。
4. 影像检查明细页。
5. 病理检查明细页。

用户点击入口后，系统应复用公共健康资源快捷对话链路，将当前报告作为 `HealthResourceRef` 加入目标 Thread 的 Composer 预览区，并全屏打开 `ChatView`。系统不得自动生成问题、不得自动发送消息、不得将完整报告正文复制进普通文本输入框。

## 二、目标与成功标准

### 2.1 产品目标

- 用户在报告详情页一次点击即可进入正确成员的对话。
- 进入对话时，当前报告已经显示在输入框上方的健康资源预览区。
- 实验室、影像、病理虽使用不同详情 UI，但共享同一种检查报告身份和上下文读取链路。
- 入口复用公共按钮、请求模型、会话选择、模型门控和全屏路由，不为每个报告页面单独实现 Chat 逻辑。
- 家庭多成员场景严格隔离，不得把成员 A 的报告加入成员 B 的 Thread。

### 2.2 可量化指标

| 指标 | 目标 |
| --- | --- |
| 有效报告点击快捷对话后成功打开 Chat | ≥ 99%（排除无模型、网络和数据损坏） |
| 打开 Chat 时报告预览首屏可见 | 100% |
| 同一次点击重复创建/重复注入 | 0 |
| 跨成员错误绑定 | 0 |
| 本地未入库草稿错误进入正式报告上下文 | 0 |
| 快速连点产生多个全屏页或 Thread | 0 |

## 四、用户故事

### 4.1 体检报告

作为查看本人或家庭成员体检报告的用户，我希望从报告详情直接进入对话，并自动携带当前体检报告，以便询问异常指标、风险与复查建议。

### 4.2 检查报告总览

作为查看检查报告的用户，我希望在报告总览中直接开启对话，以便 AI 能结合报告基本信息、所见和结论回答问题。

### 4.3 实验室、影像和病理明细

作为正在阅读某个检查明细的用户，我希望不必返回总览就能开启对话，同时让 Chat 带入当前检查报告，以便围绕正在看的内容继续提问。

## 五、页面入口与交互要求

### 5.1 公共视觉形态

所有目标页面使用公共 `HealthResourceConversationButton`：

- SF Symbol：`message.circle.fill`。
- 图标视觉尺寸：56 pt。
- 最小可点击区域：44×44 pt。
- 前景色：App tint/accent color。
- 背景：系统背景圆形底。
- 阴影：与病历详情快捷对话入口一致。
- 默认位置：页面右下角，距 trailing 20 pt、距 bottom 28 pt，并适配 safe area。

不得在每个详情页复制按钮样式、通知名称或打开 Chat 的代码。页面只负责构造资源请求并调用公共 overlay/action。

### 5.2 体检报告详情页

目标页面：

`SparkClient/Projects/Features/Home/Presentation/MedicalLists/HealthExamReports/HealthExamReportDetailPage.swift`

要求：

1. 在 `HealthExamRecognitionResultView` 外层挂载公共快捷对话入口。
2. 使用当前页面最新的 `item` 数据构造请求。
3. 页面中的编辑、分享、归档、删除 Sheet 不得与快捷对话入口同时响应。
4. 当页面正展示全屏阻断加载、删除进行中或数据无效时，入口不可触发。
5. Scroll/List 底部应保留足够空间，按钮不得遮住附件或最后一个报告区块。

### 5.3 检查报告总览详情页

目标页面：

`SparkClient/Projects/Features/Home/Presentation/MedicalLists/ExaminationReports/ExaminationReportDetailPage.swift`

要求：

1. 服务端模式 `.server` 显示快捷对话入口。
2. 本地识别草稿 `.localDraft` 不显示入口；草稿必须先保存并获得有效服务端 ID。
3. `isLoadingDetails == true` 时入口不可点击，且不得浮在阻断加载层上方响应点击。
4. 请求必须使用 `@State report`，不能使用初始化时的旧报告值，保证附件、关联、结论更新后快照同步。
5. 快捷对话不改变当前检查分类，不触发编辑和保存。

### 5.4 实验室、影像与病理明细页

路由入口：

`SparkClient/Projects/Features/Home/Presentation/MedicalLists/ExaminationReports/ExaminationReportSummaryDetailPage.swift`

由 `ExaminationReportCategoryDetailPage` 统一承载：

| 分类 | 当前详情实现 |
| --- | --- |
| 实验室 | 当前路由复用 `ImagingReportDetailPage` 的明细展示分支；后续若恢复 `LaboratoryReportDetailPage`，快捷入口仍由分类路由统一提供 |
| 影像 | `ImagingReportDetailPage` |
| 病理 | `PathologyReportDetailPage` |

要求：

1. 快捷入口挂在 `ExaminationReportCategoryDetailPage` 公共路由层，不分别复制到三个子页面。
2. 每个可见页面只能出现一个快捷对话按钮；从总览 push 到明细后，父页面按钮不得叠到子页面上。
3. 明细页仍引用整个检查报告的 `resourceID`，不把 `RemoteMedExamDetail.id` 当成 `examination_report` ID。
4. `navigationTitleOverride` 仅作为预览标题优先值，不改变 canonical identity。
5. 用户从单项实验室指标进入时，Chat 获取的是完整检查报告上下文；当前浏览项仅用于轻量展示提示，不裁剪 AI 上下文。

## 六、健康资源身份与展示快照映射

### 6.1 Canonical identity

| 页面 | `resourceType` | `resourceID` | `memberID` |
| --- | --- | --- | --- |
| 体检报告详情 | `health_exam_report` | `item.id` | `item.member` |
| 检查报告总览 | `examination_report` | `report.id` | `report.member` |
| 实验室/影像/病理明细 | `examination_report` | `report.id` | `report.member` |

下列条件任一不满足时，不得发起请求：

- `resourceID > 0`
- `memberID > 0`
- `HealthResourceType(rawValue:)` 可识别
- 当前数据为服务端正式记录

### 6.2 体检报告展示快照

| 字段 | 映射优先级 |
| --- | --- |
| `displayTitle` | `institutionName` → `reportNo` → “体检报告” |
| `displaySubtitle` | `summary` → 空字符串 |
| `typeBadge` | 本地化“体检报告”/“体检” |
| `source` | `health_exam_report_detail` |

### 6.3 检查报告展示快照

| 字段 | 总览映射 | 分类明细映射 |
| --- | --- | --- |
| `displayTitle` | `itemName` → `category` → “检查报告” | `navigationTitleOverride` → `itemName` → “检查报告” |
| `displaySubtitle` | `impression` → `findings` → `organizationName` → 空 | `impression` → `findings` → 空 |
| `typeBadge` | 本地化“检查报告”/“检查” | 同左 |
| `source` | `examination_report_detail` | `examination_report_category_detail` |

展示快照仅服务于 Composer 缩略预览与详情加载失败时的兜底，不是 AI 完整上下文。完整上下文继续由 `ChatHealthResourcePreviewLoader`、`HealthResourceContextResolver` 和现有查询 API 按 identity 获取。

## 七、快捷对话业务流程

```text
用户点击报告详情右下角对话按钮
  ↓
页面构造 HealthResourceConversationRequest
  ↓
SignedInMainTabHostView 接收公共请求
  ↓
HealthResourceConversationCoordinator 校验 identity
  ↓
查找同成员 5 分钟内最近活跃 Chat Thread
  ├── 命中
  │     ↓
  │   保留原草稿并追加当前报告引用
  │
  └── 未命中
        ↓
      检查可用 Chat 模型
        ├── 无模型：提示并进入 APIKeysSettingsView
        └── 有模型：创建绑定当前成员的新 Thread
  ↓
检查去重、成员一致性与最多 5 份资源限制
  ↓
fullScreenCover 打开 ChatView
  ↓
输入框上方展示当前报告预览，不自动发送
```

### 7.1 Thread 复用

复用 `CHAT-000039`：

- 仅复用同成员、`.chat` 场景、未删除、最近 5 分钟活跃的 Thread。
- 其他成员 Thread 即使刚刚活跃也不得复用。
- 命中 Thread 已包含同一报告时不重复追加。
- 命中 Thread 已有文本、附件或其他资源时必须保留。
- 已有 5 份资源时提示上限，不打开一个看似成功但未带入报告的 Chat。

### 7.2 新建 Thread

- 只有没有可复用 Thread 时才检查模型并新建。
- 新 Thread 必须显式绑定 `memberID`，不得依赖当前首页选择成员作为隐式兜底。
- 创建或草稿注入失败时，删除本次新建的空 Thread。
- 不得因视图 body 重算、Sheet 关闭或通知重复送达而创建多个 Thread。

## 八、模型/API Key 门控

1. 无可复用 Thread 且无可用 `.chat` 模型时，使用现有文案：
   - `chat.list.no_available_model.title`
   - `chat.list.no_available_model.message`
   - `chat.list.no_available_model.action`
2. 用户选择设置后，通过 `HomeSheet.apiKeysSettings` 在统一 `.sheet(item:)` 中展示 `APIKeysSettingsView`。
3. 用户关闭设置页后，如果原报告请求仍有效，则重新执行准备流程。
4. 用户取消提示时清理 pending request，不创建 Thread。
5. 设置页关闭后的重试不得重复注入报告。

## 九、Chat 内预览与发送规则

### 9.1 进入 Chat 后

- 当前报告显示在 Composer 上方健康资源预览区。
- 用户可点击预览进入现有报告预览 Sheet。
- 用户可移除当前报告。
- 用户可继续添加其他健康资源，但总数仍不得超过 5。
- 文本输入框保持空白或保留复用 Thread 的原草稿。
- 不自动触发发送和 AI 生成。

### 9.2 发送时

- `HealthResourceSendValidator` 再次校验所有资源与 Thread 成员一致。
- 体检报告按 `health_exam_report` 解析上下文。
- 实验室、影像和病理统一按 `examination_report` 解析上下文。
- 消息引用块保存 canonical identity 与显示快照，不保存附件二进制。
- 报告详情在发送前已更新时，应由 loader/query 获取最新服务端数据，而不是只使用入口快照。

## 十、页面状态与异常处理

| 场景 | 预期行为 |
| --- | --- |
| 有效服务端报告 | 显示并允许点击 |
| 本地未保存草稿 | 不显示入口 |
| `resourceID <= 0` | 不可触发，记录非敏感诊断日志 |
| `memberID <= 0` | 不可触发，提示资料暂不可对话 |
| 正在加载完整检查详情 | 入口不可响应 |
| 正在删除/归档/分享 | 禁止重复触发或与当前阻断操作并发 |
| 快速连续点击 | 只接受第一次请求，后续点击忽略或显示 loading |
| 资源已经在复用 Thread 草稿中 | 直接打开，不能重复追加 |
| Thread 已有 5 份资源 | 提示移除部分资料，不创建无意义新 Thread |
| 无可用模型且无复用 Thread | 提示进入 API Key 设置 |
| 设置后仍无可用模型 | 再次提示，不循环创建 Sheet |
| 报告被服务端删除 | 不进入带空上下文的 Chat，提示资料已不存在或加载失败 |
| 网络离线但本地有完整缓存 | 允许展示缓存预览，发送阶段按现有离线策略处理 |

## 十一、成员隔离与隐私

1. 报告的 `member` 字段是成员绑定唯一事实源。
2. 不使用首页当前选择成员覆盖报告所属成员。
3. 不允许把报告加入 `thread.memberID == nil`、其他成员或非 `.chat` Thread。
4. 日志仅记录资源类型、资源 ID、成员 ID、来源和 Thread 短 ID。
5. 日志不得输出体检摘要、检查所见、影像结论、病理描述、医生姓名、机构名称、附件 URL 或 API Key。
6. 通知对象仅在 App 进程内传递轻量请求，不持久化完整报告 DTO。

## 十三、本地化与无障碍

### 13.1 本地化

新增或复用下列语义文案，并覆盖简体中文、繁体中文和英文：

| Key | 简体中文建议 |
| --- | --- |
| `chat.health_resource_conversation.action` | 就此资料对话 |
| `chat.health_resource_conversation.action.hint` | 打开对话并自动带入当前健康资料 |
| `chat.ask_report.resource_type.health_exam_report` | 体检报告 |
| `chat.ask_report.resource_type.examination_report` | 检查报告 |

禁止仅依赖 fallback 中文作为正式交付；所有用户可见文案应进入项目本地化资源。

### 13.2 无障碍

- VoiceOver 标签应说明“咨询当前体检报告”或“咨询当前检查报告”，不能只播报“message circle fill”。
- Hint 应说明会打开对话并带入当前报告。
- Dynamic Type 下按钮不能遮挡报告正文。
- 开启“按钮形状”后仍可识别为可操作控件。
- loading/disabled 状态需要有可感知反馈。
- 对比度符合系统 tint 与背景组合要求。

## 十五、测试方案

### 15.1 单元测试

1. 体检请求映射：ID、成员、标题、摘要、type/source 正确。
2. 检查总览请求映射：优先使用 itemName，再回退 category。
3. 分类明细请求映射：标题优先使用 `navigationTitleOverride`，identity 仍使用报告 ID。
4. 实验室、影像、病理均映射为 `.examinationReport`。
5. 本地草稿和无效 ID 不可发起请求。
6. 同成员 5 分钟 Thread 命中时复用。
7. 其他成员 Thread 不复用。
8. 同一报告引用去重。
9. 已有 5 份资源时返回明确失败。
10. 新建后注入失败会删除新 Thread；复用失败不会删除既有 Thread。

## 十八、风险与决策

| 风险 | 影响 | 默认决策/缓解 |
| --- | --- | --- |
| 分类明细误用明细行 ID | Chat 无法加载报告 | 始终使用父报告 `report.id` |
| 父子详情同时叠加按钮 | UI 重复、点击混乱 | 子分类入口统一放在 `ExaminationReportCategoryDetailPage` |
| 加载遮罩仍可点按钮 | 带入不完整或旧数据 | loading 时隐藏或禁用并阻止命中测试 |
| 本地草稿使用临时负 ID | 无法从服务端解析上下文 | 保存入库前不展示入口 |
| 快照包含过多医疗文本 | 隐私和草稿膨胀 | 快照仅标题、短副标题和 badge |
| 报告详情更新后仍带入旧值 | 预览与实际不一致 | 检查页使用 `@State report`，完整数据发送时重新加载 |
| 家庭成员切换导致错误复用 | 严重隐私问题 | identity/member/thread 三重校验 |

## 十九、完成定义（Definition of Done）

只有同时满足以下条件，工单才可关闭：

1. 五类目标详情入口全部可用且每页只有一个按钮。
2. 体检和检查 canonical identity 映射经过自动化测试。
3. 进入 Chat 时预览已就绪，不出现后置闪现。
4. 不自动发送，原 Thread 草稿在复用时完整保留。
5. 本地草稿、无效 ID、跨成员、资源上限、无模型与加载中状态均有确定行为。
6. 关闭 Chat 能返回原详情页面，且不会丢失报告页导航状态。
7. 本地化、VoiceOver、深色模式和大字体验收通过。
8. Debug Simulator 构建及相关测试通过。
9. QA 完成体检、实验室、影像、病理四类真实数据回归并留存结果。
