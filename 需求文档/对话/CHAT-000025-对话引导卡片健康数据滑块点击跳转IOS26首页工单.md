## 1. 一句话目标

对话引导卡片中的健康数据滑块支持消息内导航：点击运动、身材、饮食、医疗任一滑块页后，通过卡片内 `NavigationLink` 直接 push 一个独立的 `IOS26HomeView(...)`，并根据滑块类别定位到首页对应分段，同时在该 destination 上单独补齐健康首页头部 toolbar。

## 2. 背景与方案变更

`CHAT-000024` 已定义对话引导卡片，卡片包含四个健康数据滑块分页：

```text
运动数据
身材管理
饮食营养
医疗数据
```

上一版方案要求通过 App 级路由切换主 Tab 到 `.healthHome`。本工单改为新方案：

1. 不切换主 Tab。
2. 不调用 `routeStore.route(to: .home)` 作为滑块点击主链路。
3. 不依赖主 Tab 宿主的 `.toolbar { tabToolbar }`。
4. 在消息卡片内部用 `NavigationLink` 包住滑块主体。
5. `NavigationLink` destination 直接构造 `IOS26HomeView(...)`。
6. destination 自己补充与 `.healthHome` 等价的头部 toolbar。

目标 destination 形态：

```swift
IOS26HomeView(
    dependencies: homeDependencies,
    viewModel: homeViewModel,
    taskManager: taskManager,
    medicalDocumentUploadViewModel: medicalDocumentUploadViewModel,
    externalMedicalDocumentImportCoordinator: externalMedicalDocumentImportCoordinator,
    launchIntentCoordinator: launchIntentCoordinator,
    session: session,
    actionHandler: actionHandler,
    chatListViewModel: chatListViewModel,
    deepTutorChatViewModel: deepTutorChatViewModel,
    currentSection: ios26HomeSectionBinding,
    safeAreaRefreshRevision: homeSafeAreaRefreshRevision,
    activeFullScreenCover: $activeHomeFullScreenCover
)
.toolbar {
    ToolbarItem(placement: .topBarLeading) {
        memberSelectorHeader
    }
    healthHomeTrailingToolbar
}
```

## 3. 当前代码事实

### 3.1 IOS26HomeView 分段

`IOS26HomeView` 内部存在：

```swift
enum HomeSection: String, CaseIterable, Identifiable {
    case dashboard
    case nutrition
    case fitness
}
```

`IOS26HomeView` 通过：

```swift
@Binding var currentSection: HomeSection
```

接收当前分段。因此消息内 push 的 destination 可以用本地 `@State` 或宿主注入的 binding 指定初始分段。

### 3.2 Toolbar 复用语义

主 Tab 宿主已有 `.healthHome` toolbar 分支：

```swift
case .healthHome:
    ToolbarItem(placement: .topBarLeading) {
        memberSelectorHeader
    }
    healthHomeTrailingToolbar
```

本工单要求在 Chat push 出来的 `IOS26HomeView` destination 上单独补齐同等头部，不能依赖主 Tab 当前 selected tab。

## 4. 需求范围

### 4.1 滑块 NavigationLink

需求说明：

对话引导卡片的数据滑块区域整体可点击。点击后通过 `NavigationLink` push 到 `IOS26HomeView`。

基础要求与业务规则：

1. 点击范围为滑块数据页主体，不包含下方健康科普问题列表。
2. 点击问题仍执行 `CHAT-000024` 的“发送科普问题给 AI”逻辑。
3. 卡片组件不操作 `AppRouteStore`。
4. 卡片组件不切换主 Tab。
5. 首页 destination 所需依赖由 Chat 页面宿主注入。
6. 进入 destination 时直接落到目标 section，避免先显示默认 dashboard 再跳动。

推荐映射：

| 滑块类别 | 跳转方式 | `IOS26HomeView.HomeSection` | 说明 |
| --- | --- | --- | --- |
| 运动数据 | `NavigationLink` push | `.fitness` | 进入首页内运动健康分页 |
| 身材管理 | `NavigationLink` push | `.dashboard` | 首页 dashboard 暂承载成员健康总览 |
| 饮食营养 | `NavigationLink` push | `.nutrition` | 进入首页内饮食营养分页 |
| 医疗数据 | `NavigationLink` push | `.dashboard` | 进入首页 dashboard 的医疗档案区域 |

验收标准：

1. 点击运动滑块，push 到 `IOS26HomeView` 并停在运动分段。
2. 点击饮食滑块，push 到 `IOS26HomeView` 并停在营养分段。
3. 点击身材/医疗滑块，push 到 `IOS26HomeView` dashboard。
4. 点击问题列表不会触发首页跳转。

### 4.2 Destination 封装

需求说明：

新增 `ChatGuideHomeDestinationView`，封装 `IOS26HomeView(...)` 的依赖注入、初始 section 和 toolbar。这样 `ChatGuideMessageCardView` 不需要直接知道 App 宿主里所有对象。

推荐结构：

```swift
struct ChatGuideHomeDestinationView: View {
    let targetSection: IOS26HomeView.HomeSection
    let dependencies: HomeFeatureDependencies
    @ObservedObject var homeViewModel: HomeViewModel
    @ObservedObject var taskManager: TaskManager
    @ObservedObject var medicalDocumentUploadViewModel: MedicalDocumentUploadViewModel
    @ObservedObject var externalMedicalDocumentImportCoordinator: ExternalMedicalDocumentImportCoordinator
    @ObservedObject var launchIntentCoordinator: LaunchIntentCoordinator
    let session: UserSession
    let actionHandler: IOS26HomeDashboardActionHandler
    @ObservedObject var chatListViewModel: ChatListViewModel
    @ObservedObject var deepTutorChatViewModel: DeepTutorChatViewModel
    @Binding var activeFullScreenCover: HomeFullScreenCover?

    @State private var currentSection: IOS26HomeView.HomeSection
}
```

初始化时直接绑定目标分段：

```swift
init(targetSection: IOS26HomeView.HomeSection, ...) {
    self.targetSection = targetSection
    _currentSection = State(initialValue: targetSection)
}
```

body 内部：

```swift
IOS26HomeView(
    dependencies: dependencies,
    viewModel: homeViewModel,
    taskManager: taskManager,
    medicalDocumentUploadViewModel: medicalDocumentUploadViewModel,
    externalMedicalDocumentImportCoordinator: externalMedicalDocumentImportCoordinator,
    launchIntentCoordinator: launchIntentCoordinator,
    session: session,
    actionHandler: actionHandler,
    chatListViewModel: chatListViewModel,
    deepTutorChatViewModel: deepTutorChatViewModel,
    currentSection: $currentSection,
    safeAreaRefreshRevision: safeAreaRefreshRevision,
    activeFullScreenCover: $activeFullScreenCover
)
.toolbar {
    ToolbarItem(placement: .topBarLeading) {
        memberSelectorHeader
    }
    healthHomeTrailingToolbar
}
```

说明：`safeAreaRefreshRevision` 应由宿主注入，不建议在真实实现里硬编码。

### 4.3 RenderContext 注入

需求说明：

Chat 消息渲染层需要获得一个 destination builder，用于把滑块类别变成 `NavigationLink` destination。

推荐新增：

```swift
struct ChatRenderContext {
    let guideHomeDestinationBuilder: (ChatGuideMetricCategory) -> AnyView
}
```

卡片使用方式：

```swift
NavigationLink {
    guideHomeDestinationBuilder(section.category)
} label: {
    ChatGuideMetricFlatPanel(section: section)
}
.buttonStyle(.plain)
```

实现约束：

1. `ChatMessageBlock+Render.swift` 只传递 builder。
2. `ChatMessageBubbleContentView` 只透传 builder。
3. `ChatConversationMessageRow` / `ChatConversationListPage` 从宿主接收 builder。
4. `ChatDetailViewModel` 不持有首页依赖。
5. payload 模型不依赖 SwiftUI 类型。

### 4.4 跳转后头部 Toolbar 补齐

需求说明：

从 Chat 消息 push 到独立 `IOS26HomeView` 后，destination 顶部必须使用健康首页头部，而不是 Chat 头部。

必须补充：

```swift
ToolbarItem(placement: .topBarLeading) {
    memberSelectorHeader
}
healthHomeTrailingToolbar
```

基础要求：

1. `memberSelectorHeader` 显示当前成员；成员为空时保持现有 fallback。
2. `healthHomeTrailingToolbar` 根据 `currentSection` 展示对应右侧操作。
3. `.nutrition` 分段展示营养目标/历史入口。
4. `.fitness` 分段可沿用现有空态。
5. `.dashboard` 分段展示设置入口。
6. 返回 Chat 后，Chat toolbar 能恢复。

## 7. 状态与异常

| 场景 | 处理 |
| --- | --- |
| 卡片 payload 缺少 category | 不渲染 `NavigationLink`，降级为普通滑块面板 |
| destination builder 缺失 | 降级为普通滑块面板，不影响问题点击 |
| 用户连续点击滑块 | NavigationStack 自身处理 push；必要时禁用重复快速点击 |
| 当前系统使用旧 MainTab 宿主 | `MainTabCoordinatorView` 也必须注入 builder |
| 进入 nutrition 后 toolbar 未刷新 | toolbar 写在 destination wrapper，跟随 `currentSection` 更新 |
| 首页成员为空 | 复用现有 `memberSelectorHeader` fallback，不阻塞跳转 |

## 8. 测试策略

1. 单元测试：`ChatGuideMetricCategory` 到 `IOS26HomeView.HomeSection` 映射。
2. View 测试：`ChatGuideMessageCardView` 的滑块主体包含 `NavigationLink`。
3. UI 手测：从 Chat 点击四个滑块分页，确认 push destination、分段和 toolbar。
4. 回归测试：点击三个科普问题仍发送 AI 消息，不跳首页。
5. 兼容测试：`IOS26TabBarView` 与 `MainTabCoordinatorView` 两套宿主都能提供 destination builder。

## 9. 整体验收标准

1. 对话引导卡片滑块主体可点击。
2. 运动数据通过 `NavigationLink` push 到 `IOS26HomeView` 的运动健康分段。
3. 饮食营养通过 `NavigationLink` push 到 `IOS26HomeView` 的饮食营养分段。
4. 身材管理和医疗数据通过 `NavigationLink` push 到 `IOS26HomeView` 首页 dashboard。
5. 跳转后 destination 显示健康首页的 `memberSelectorHeader`。
6. 跳转后右侧 toolbar 使用 `healthHomeTrailingToolbar`，不残留 Chat toolbar。
7. 不切换主 Tab，不调用 `routeStore.route(to: .home)` 作为滑块点击主方案。
8. 不影响 `CHAT-000024` 中科普问题点击发送功能。
