## 1. 一句话目标

对话引导卡片中的健康数据滑块支持点击导航：点击运动、身材、饮食、医疗任一滑块页后，从当前 Chat 会话跳转到 iOS 26 健康首页 `IOS26HomeView`，并根据滑块类别定位到首页对应分段，同时补齐 `.healthHome` 场景下的顶部成员选择头和右侧 toolbar。

## 2. 背景与问题

`CHAT-000024` 已定义对话引导卡片，卡片包含四个健康数据滑块分页：

```text
运动数据
身材管理
饮食营养
医疗数据
```

当前新增需求是：用户不只查看数据，还可以点击滑块区域进入首页继续查看和管理。目标首页实例由主 Tab 宿主创建：

```swift
IOS26HomeView(
    dependencies: homeDependencies,
    viewModel: homeViewModel,
    taskManager: taskManager,
    medicalDocumentUploadViewModel: medicalDocumentUploadViewModel,
    externalMedicalDocumentImportCoordinator: externalMedicalDocumentImportCoordinator,
    launchIntentCoordinator: launchIntentCoordinator,
    session: session,
    actionHandler: actionHandler,
    chatListViewModel: chatListViewModel,
    deepTutorChatViewModel: deepTutorChatViewModel,
    currentSection: ios26HomeSectionBinding,
    safeAreaRefreshRevision: homeSafeAreaRefreshRevision,
    activeFullScreenCover: $activeHomeFullScreenCover
)
.toolbar { tabToolbar }
```

因此 Chat 卡片不能直接 new 一个 `IOS26HomeView` 作为 push destination。正确方向是由 App 级主 Tab 宿主处理导航：切换 `routeStore.selectedTab` 到 `.healthHome`，并设置 `IOS26HomeView.HomeSection`。

## 3. 当前代码事实

### 3.1 IOS26HomeView 分段

`IOS26HomeView` 内部存在 `HomeSection`：

```swift
enum HomeSection: String, CaseIterable, Identifiable {
    case dashboard
    case nutrition
    case fitness
}
```

`IOS26HomeView` 通过 `@Binding var currentSection: HomeSection` 接收当前分段。主 Tab 宿主通过：

```swift
currentSection: $homeSectionPreferenceStore.section
```

把 `HomeSectionPreferenceStore.shared.section` 传入首页。

### 3.2 App 级路由

`AppRouteStore.RootTab` 已包含：

```swift
case healthHome
case chat
case nutrition
case fitness
```

`AppRoute.home.rootTab` 会解析为 `.healthHome`。因此从 Chat 跳首页可走：

```swift
routeStore.route(to: .home)
```

或显式：

```swift
routeStore.selectedTab = .healthHome
```

推荐使用统一路由入口，并在跳转前设置首页分段。

### 3.3 healthHome toolbar 现状

`IOS26TabBarView` 和 `MainTabCoordinatorView` 均已有 `.healthHome` 分支：

```swift
case .healthHome:
    ToolbarItem(placement: .topBarLeading) {
        memberSelectorHeader
    }
    healthHomeTrailingToolbar
```

本工单要求跳转后该头部必须正常出现，尤其是从 Chat Tab 切回 `.healthHome` 时不能残留 Chat toolbar。

## 4. 需求范围

### 4.1 滑块点击导航

需求说明：

对话引导卡片的数据滑块区域整体可点击。点击后根据当前滑块类别跳转到 iOS 26 首页对应分段。

基础要求与业务规则：

1. 点击范围为滑块数据页主体，不包含下方健康科普问题列表。
2. 点击问题仍然执行 `CHAT-000024` 的“发送科普问题给 AI”逻辑。
3. 卡片组件只发出业务事件，不直接操作 `AppRouteStore`。
4. 导航由 Chat 页面上层或主 Tab 宿主注入。
5. 跳转前需要设置首页分段，避免用户先看到默认 dashboard 再跳动。

推荐映射：

| 滑块类别 | 跳转 RootTab | `IOS26HomeView.HomeSection` | 说明 |
| --- | --- | --- | --- |
| 运动数据 | `.healthHome` | `.fitness` | 进入首页内运动健康分页 |
| 身材管理 | `.healthHome` | `.dashboard` | 首页 dashboard 暂承载成员健康总览；后续可细化到体征页 |
| 饮食营养 | `.healthHome` | `.nutrition` | 进入首页内饮食营养分页 |
| 医疗数据 | `.healthHome` | `.dashboard` | 进入首页 dashboard 的医疗档案区域；后续可细化到医疗列表页 |

验收标准：

1. 在 Chat 会话内点击运动滑块，切到健康首页并停在运动分段。
2. 点击饮食滑块，切到健康首页并停在营养分段。
3. 点击身材/医疗滑块，切到健康首页 dashboard。
4. 点击问题列表不会触发首页跳转。
5. 正在发送 AI 消息时仍允许跳首页查看数据，但不得触发问题发送。

### 4.2 导航事件模型

需求说明：

为 `ChatGuideCardPayload` 或 View 事件新增导航 action 语义，保证数据与 UI 行为可扩展。

推荐模型：

```swift
enum ChatGuideMetricCategory: String, Codable, Sendable {
    case movement
    case bodyManagement
    case nutrition
    case medical
}

struct ChatGuideMetricNavigationTarget: Codable, Equatable, Sendable {
    var rootTab: String       // "healthHome"
    var homeSection: String   // "dashboard" / "nutrition" / "fitness"
}
```

推荐 View 回调：

```swift
struct ChatGuideMessageCardView: View {
    let payload: ChatGuideCardPayload
    let onMetricTap: (ChatGuideMetricCategory) -> Void
    let onQuestionTap: (ChatGuideQuestion) -> Void
}
```

`ChatRenderContext` 增加：

```swift
let onGuideMetricTap: (ChatGuideMetricCategory) -> Void
```

验收标准：

1. 点击事件能从 `ChatGuideMessageCardView` 逐层上抛到 Chat 页面宿主。
2. `ChatMessageBlock+Render.swift` 只负责传递回调，不直接引用首页路由。
3. payload 编解码不依赖 SwiftUI 类型。

### 4.3 App 级跳转实现

需求说明：

在 Chat 页面宿主接收到滑块点击事件后，通过 App 级状态完成跳转。

推荐流程：

```text
ChatGuideMessageCardView 点击当前滑块页
  ↓
ChatRenderContext.onGuideMetricTap(category)
  ↓
ChatConversationMessageRow / ChatConversationListPage 上抛
  ↓
主 Tab 宿主处理 handleChatGuideMetricNavigation(category)
  ↓
HomeSectionPreferenceStore.shared.section = mappedSection
  ↓
routeStore.route(to: .home, replaceStack: false)
  ↓
TabView selection 切到 .healthHome
  ↓
IOS26HomeView(currentSection:) 显示对应分段
```

核心代码示例：

```swift
@MainActor
func handleChatGuideMetricNavigation(_ category: ChatGuideMetricCategory) {
    switch category {
    case .movement:
        homeSectionPreferenceStore.section = .fitness
    case .nutrition:
        homeSectionPreferenceStore.section = .nutrition
    case .bodyManagement, .medical:
        homeSectionPreferenceStore.section = .dashboard
    }
    routeStore.route(to: .home)
}
```

如果 Chat 页面当前只持有 `ChatDetailViewModel`，不要把 `AppRouteStore` 塞进 ViewModel；优先让 `ChatConversationListPage` 或主 Tab 宿主注入 `onGuideMetricNavigation`。

验收标准：

1. 跳转由主 Tab 宿主统一处理。
2. Chat ViewModel 不依赖 App 级路由类型。
3. 跳转不会创建新的 `IOS26HomeView` 实例作为 Chat 内 push 页面。
4. 返回 Chat 后原会话滚动状态按现有策略保持。

### 4.4 跳转后头部 Toolbar 补齐

需求说明：

从 Chat 点击滑块切到 `.healthHome` 后，顶部必须使用健康首页头部，而不是 Chat 头部。

要求实现的 toolbar 分支：

```swift
case .healthHome:
    ToolbarItem(placement: .topBarLeading) {
        memberSelectorHeader
    }
    healthHomeTrailingToolbar
```

基础要求与业务规则：

1. `memberSelectorHeader` 必须显示当前成员；成员为空时保持现有 fallback。
2. `healthHomeTrailingToolbar` 根据 `homeSectionPreferenceStore.section` 展示对应右侧操作。
3. `.nutrition` 分段应展示营养目标/历史入口。
4. `.fitness` 分段不强制新增右侧按钮，沿用现有空态。
5. `.dashboard` 分段展示设置入口。
6. iOS 26 新 Tab 宿主和兼容宿主都要覆盖，避免不同系统版本行为不一致。

验收标准：

1. 从 Chat 跳转到健康首页后，左上显示成员选择头。
2. 跳到饮食营养分段时，右上显示营养相关 toolbar。
3. 跳到运动分段时，不显示 Chat 的知识库入口。
4. 切回 Chat 后，Chat toolbar 能恢复。

## 7. 状态与异常

| 场景 | 处理 |
| --- | --- |
| Chat 卡片 payload 缺少 category | 不触发跳转，记录 debug 日志 |
| 首页 section 设置成功但 route 切换失败 | 保持 Chat，不改变消息状态 |
| 用户连续点击滑块 | 只执行最后一次；可用 300ms 节流 |
| 当前系统使用旧 MainTab 宿主 | `MainTabCoordinatorView` 也必须接入 |
| 跳转到 nutrition 后 toolbar 未刷新 | 明确监听 `homeSectionPreferenceStore.section`，必要时触发 `homeSafeAreaRefreshRevision` 或 view update |
| 首页成员为空 | 复用现有 `memberSelectorHeader` fallback，不阻塞跳转 |

## 8. 测试策略

1. 单元测试：`ChatGuideMetricCategory` 到 `IOS26HomeView.HomeSection` 映射。
2. ViewModel/宿主测试：调用 `handleChatGuideMetricNavigation(.movement)` 后，`selectedTab == .healthHome` 且 `section == .fitness`。
3. UI 手测：从 Chat 点击四个滑块分页，确认跳转分段和 toolbar。
4. 回归测试：点击三个科普问题仍发送 AI 消息，不跳首页。
5. 兼容测试：`IOS26TabBarView` 与 `MainTabCoordinatorView` 两套宿主都通过。

## 9. 整体验收标准

1. 对话引导卡片滑块主体可点击。
2. 运动数据跳转到 `IOS26HomeView` 的运动健康分段。
3. 饮食营养跳转到 `IOS26HomeView` 的饮食营养分段。
4. 身材管理和医疗数据跳转到 `IOS26HomeView` 首页 dashboard。
5. 跳转后显示 `.healthHome` 的 `memberSelectorHeader`。
6. 跳转后右侧 toolbar 使用 `healthHomeTrailingToolbar`，不残留 Chat toolbar。
7. 不在 Chat 内 push 一个新的 `IOS26HomeView`，必须回到主 Tab 的健康首页实例。
8. 不影响 `CHAT-000024` 中科普问题点击发送功能。
