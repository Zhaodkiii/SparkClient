## 1. 模块目标

对话引导卡片上半部分的健康数据滑块不再写入 `chatGuideCard.payload.metricSections`，也不随消息同步服务端；改为页面渲染时基于当前对话绑定成员实时读取本地缓存/内存数据生成。

核心目标：

1. `metric_sections` 不再持久化到 CoreData message block，也不进入服务端消息 payload。
2. `ChatGuideMetricCarouselView` 从“纯 payload 渲染”升级为“页面级实时数据组件”，由 ViewModel/Provider 提供当前快照。
3. 运动数据、饮食营养必须检查当前对话绑定成员是否可读取本机 Apple 健康数据。
4. 当前对话成员未绑定 Apple 健康能力时，运动/饮食展示 `-` 占位，并提供“去绑定”按钮。
5. 医疗数据仍以当前对话绑定成员的本地缓存 complete-data 为主，不把统计快照持久化到消息。
6. 科普问题生成流程保持不变，本工单不调整问题生成触发、prompt、AI 输入或回写链路。

## 2. 当前实现事实

### 2.1 当前滑块数据被持久化

`ChatGuideCardPayload` 当前包含：

```swift
var metricSections: [ChatGuideMetricSection]
```

因此当前 message payload 会持久化并同步类似以下内容：

```json
"metric_sections": [
  {
    "category": "movement",
    "title": "运动数据",
    "items": [
      { "id": "steps", "title": "步数", "value_text": "1602", "unit_text": "步" },
      { "id": "calories", "title": "热量消耗", "value_text": "10", "unit_text": "千卡" }
    ],
    "chart": { "normalized_values": [0.1487, 1, 0.8234, 0.4438, 0.2594, 0] },
    "state": "ready"
  }
]
```

问题：

1. 健康数据是时间敏感数据，持久化后会过期。
2. HealthKit 数据属于本机/成员绑定上下文，不适合随 chat message 上传服务端。
3. 历史对话重新进入时看到的是旧快照，而不是当前缓存。
4. `metric_sections` 会增加 message payload 体积，并把 UI 展示数据和消息语义耦合。

### 2.2 当前渲染组件是纯 payload 组件

`ChatGuideMetricCarouselView.swift` 当前入口：

```swift
struct ChatGuideMetricCarouselView: View {
    let sections: [ChatGuideMetricSection]
    var homeDestinationBuilder: ChatGuideHomeDestinationBuilder? = nil
}
```

`ChatGuideMessageCardView` 当前直接传入：

```swift
ChatGuideMetricCarouselView(
    sections: payload.metricSections,
    homeDestinationBuilder: homeDestinationBuilder
)
```

`ChatMessageBlock+Render.swift` 当前只把 `payload` 交给卡片：

```swift
case .chatGuideCard(let payload):
    ChatGuideMessageCardView(payload: payload, ...)
```

结论：

当前滑块没有页面级数据加载状态，也没有根据当前 thread.memberID 实时计算的入口。

### 2.3 当前数据构建在 payload builder 内

`ChatGuideCardPayloadBuilder.build(memberID:defaultMemberBindingEnabled:)` 当前会并发读取：

1. 运动数据：`fetchStepVisualization`、`fetchEnergyVisualization`
2. 身材管理：`fetchBodyManagementSummary`
3. 饮食营养：`fetchNutritionReadVisualization`、`fetchEnergyVisualization`
4. 医疗数据：`fetchMemberCompleteData(memberID:)`

并把结果写入 `ChatGuideCardPayload.metricSections`。

### 2.4 当前 Apple 健康成员边界不足

`Member` 已有：

```swift
var isSelfMember: Bool {
    let normalized = relationship.trimmingCharacters(in: .whitespacesAndNewlines).lowercased()
    return normalized == "self" || normalized == "本人"
}
```

注释也说明 `relationship` 会影响“首页运动健康是否读 HealthKit”。这意味着 HealthKit 读数不能只看 `HKHealthStore.isHealthDataAvailable()`，还必须看当前对话绑定成员是否是可绑定本机 Apple 健康数据的成员。

当前 `ChatGuideCardPayloadBuilder` 的 `makeMovementSection`、`makeNutritionSection` 只检查了：

```swift
healthReader.isHealthDataAvailable()
```

未明确检查 thread 绑定成员是否为本人/已绑定 Apple 健康。

## 3. 需求范围

### 3.1 滑块数据不持久化

#### 需求说明

从 chat guide card 的持久化 payload 中移除健康数据滑块明细。消息只持久化“这是一张 guide card”和科普问题状态，不持久化当前步数、热量、营养、医疗计数、图表数组等展示快照。

#### 基础要求与业务规则

1. 新建 guide card 时，`metricSections` 不写入最终持久化 payload。
2. 服务端同步消息时不包含 `metric_sections`。
3. 历史消息解码时，如果旧 payload 仍包含 `metricSections`，可以兼容读取，但 UI 优先使用实时快照。
4. 若实时快照加载失败，不回写 message payload。
5. 实时快照只存在于页面状态、内存缓存或领域缓存中。
6. 不因为滑块数据变化触发 message block update。

#### 推荐 schema 演进

短期兼容方案：

```swift
struct ChatGuideCardPayload: Codable, Equatable, Sendable {
    var schemaVersion: Int
    var generatedAt: Date
    var memberID: Int?
    var questions: [ChatGuideQuestion]
    var questionGeneration: ChatGuideQuestionGenerationMeta?
    var metricSections: [ChatGuideMetricSection]? // 仅兼容旧数据，不再写新数据
}
```

更理想方案：

```swift
struct ChatGuideCardPayload: Codable, Equatable, Sendable {
    var schemaVersion: Int
    var generatedAt: Date
    var memberID: Int?
    var questions: [ChatGuideQuestion]
    var questionGeneration: ChatGuideQuestionGenerationMeta?
}
```

如果直接删除字段风险较高，建议先保留 decode 兼容，新增 `schemaVersion = 3`，新写入 payload 的 `metricSections = []` 或不编码该字段。

#### 验收标准

1. 新建对话的 system guide message payload 不包含 `metric_sections` 明细。
2. CoreData 中新 guide block 不保存步数/热量/营养/医疗统计快照。
3. 服务端 push body 不包含 `metric_sections` 明细。
4. 旧消息中已有 `metric_sections` 时不崩溃。
5. 旧消息重新进入时滑块展示实时缓存，而不是旧 payload 值。

### 3.2 页面卡片实时获取缓存数据

#### 需求说明

`ChatGuideMetricCarouselView` 不再只依赖 `payload.metricSections`。它应由页面上下文提供当前 thread/member 的实时健康数据快照。

推荐新增页面级状态：

```swift
enum ChatGuideMetricSnapshotState: Equatable {
    case loading
    case ready([ChatGuideMetricSection])
    case failed([ChatGuideMetricSection])
}
```

或：

```swift
struct ChatGuideMetricSnapshot: Equatable, Sendable {
    var memberID: Int?
    var sections: [ChatGuideMetricSection]
    var loadedAt: Date
    var source: Source

    enum Source: String, Sendable {
        case memoryCache
        case localCache
        case liveHealthKit
        case fallback
    }
}
```

#### 基础要求与业务规则

1. 卡片出现时按当前 `thread.memberID` 加载快照。
2. 快照优先使用已有首页/成员上下文缓存，避免每次消息渲染都打网络。
3. 如果缓存不存在，可轻量异步加载，但不得阻塞消息渲染。
4. 同一 thread/member 同一生命周期内应去重请求。
5. 当前对话成员切换后，滑块快照必须切换到新 memberID。
6. 滑块快照变化只刷新 UI，不更新 message payload。
7. 快照加载失败时按 section 展示失败态/空态，不影响科普问题列表。

#### 推荐结构

```text
Presentation/
├── ChatGuideMessageCardView.swift
├── ChatGuideMetricCarouselView.swift
├── ChatGuideMetricSnapshotViewModel.swift       # 新增
└── ChatMessageBlock+Render.swift

Application/
├── ChatGuideMetricSnapshotProvider.swift        # 新增
└── ChatGuideCardPayloadBuilder.swift            # 停止写 metric sections
```

推荐调用链：

```text
ChatMessageBlock+Render
  ↓
ChatGuideMessageCardView(payload, metricSnapshotProvider, thread/member context)
  ↓
ChatGuideMetricSnapshotViewModel.load(threadID, memberID)
  ↓
ChatGuideMetricSnapshotProvider
  ↓
Home/Health/Nutrition/Medical 缓存读取
  ↓
sections 更新到 ChatGuideMetricCarouselView
```

#### UI 状态

```text
加载中:
┌──────────────────────────────────────────────┐
│ 运动数据                         今日         │
│ - 步                         - 千卡          │
│                     ▁ ▁ ▁ ▁ ▁ ▁              │
└──────────────────────────────────────────────┘

已加载:
┌──────────────────────────────────────────────┐
│ 运动数据              今日 · 最近更新 00:58   │
│ 步数 1602 步          热量消耗 10 千卡        │
│                     ▁ ▆ ▅ ▃ ▂ ▁              │
└──────────────────────────────────────────────┘
```

#### 验收标准

1. 新建对话进入后，滑块能展示当前缓存健康数据。
2. 退出再进入旧对话，滑块展示当前缓存，而不是创建时旧值。
3. 健康数据缓存更新后，重新进入或刷新页面可看到新值。
4. 滑块加载失败不影响科普问题展示。
5. 滑块刷新不触发 block update。

### 3.3 运动数据 Apple 健康绑定态

#### 需求说明

运动数据属于 Apple 健康本机数据。展示前必须检查当前对话绑定成员是否可以读取当前设备 Apple 健康数据。如果当前对话成员没有绑定/不属于本机 Apple 健康成员，则不展示旧数据或其他成员数据。

#### 基础要求与业务规则

1. 先取当前 thread.memberID。
2. 根据 memberID 找到 `Member`。
3. 判断该成员是否可读取本机 Apple 健康：
   - 优先规则：`Member.isSelfMember == true`。
   - 如项目已有更明确的 Apple 健康绑定关系，以绑定关系为准。
4. 如果不可读取，运动数据展示 `-` 占位。
5. 不可读取时展示“去绑定”按钮。
6. 不可读取时不调用 HealthKit 查询，避免拿到当前设备本人的数据误展示给家属成员。
7. 已绑定且 HealthKit 可用但无授权时，展示未授权/去绑定。
8. 已绑定且 HealthKit 授权可读但无数据时，展示 `-` 或暂无数据，保留去绑定/授权入口。

#### 推荐 section 状态

```swift
ChatGuideMetricSection(
    id: "movement",
    category: .movement,
    title: "运动数据",
    subtitle: "未绑定 Apple 健康",
    items: [
        ChatGuideMetricItem(id: "steps", title: "步数", valueText: "-", unitText: "步", tintName: "green"),
        ChatGuideMetricItem(id: "calories", title: "热量消耗", valueText: "-", unitText: "千卡", tintName: "orange")
    ],
    action: ChatGuideMetricAction(kind: .bindHealth, title: "去绑定"),
    state: .unauthorized
)
```

#### 主流程

```text
渲染运动数据 section
  ↓
读取当前 thread.memberID
  ↓
找到 Member
  ↓
是否 Apple 健康可读成员？
  ├─ 否 -> 展示 - / 去绑定，不查 HealthKit
  └─ 是
      ↓
    HealthKit 是否可用/授权？
      ├─ 否 -> 展示 - / 去绑定
      └─ 是 -> 读取缓存/HealthKit 快照
```

#### 验收标准

1. 当前对话成员不是本人/未绑定 Apple 健康时，运动数据不展示真实步数。
2. 未绑定时步数显示 `- 步`，热量显示 `- 千卡`。
3. 未绑定时展示“去绑定”按钮。
4. 未绑定时不会调用 HealthKit 读取运动数据。
5. 切换到本人/已绑定成员后，运动数据可展示真实缓存。

### 3.4 饮食营养 Apple 健康绑定态

#### 需求说明

饮食营养中的“已食用/已消耗/剩余”可能依赖 Apple 健康营养读数、运动消耗和成员营养目标。展示前同样必须检查当前对话成员是否绑定 Apple 健康能力。

#### 基础要求与业务规则

1. 当前对话成员未绑定 Apple 健康时，不读取 HealthKit 营养和能量数据。
2. 未绑定时展示 `-` 占位。
3. 未绑定时展示“去绑定”按钮。
4. 如果成员有服务端营养目标但 HealthKit 未绑定，仍不展示“已食用/已消耗”的真实本机数据。
5. 如果只缺 HealthKit 饮食数据但有目标，可以展示目标副标题，但指标值仍用 `-`。
6. 已绑定后，优先使用本地缓存的 Nutrition/HealthKit 快照。

#### 推荐 section 状态

```swift
ChatGuideMetricSection(
    id: "nutrition",
    category: .nutrition,
    title: "饮食营养",
    subtitle: "未绑定 Apple 健康",
    items: [
        ChatGuideMetricItem(id: "eaten", title: "已食用", valueText: "-", unitText: "千卡", tintName: "green"),
        ChatGuideMetricItem(id: "remaining", title: "剩余", valueText: "-", unitText: "千卡", tintName: "orange"),
        ChatGuideMetricItem(id: "burned", title: "已消耗", valueText: "-", unitText: "千卡", tintName: "red")
    ],
    action: ChatGuideMetricAction(kind: .bindHealth, title: "去绑定"),
    state: .unauthorized
)
```

#### 主流程

```text
渲染饮食营养 section
  ↓
读取当前 thread.memberID
  ↓
是否 Apple 健康可读成员？
  ├─ 否 -> 已食用/剩余/已消耗全部展示 -
  └─ 是
      ↓
    读取营养目标 + 饮食缓存 + 能量缓存
      ↓
    生成实时 section
```

#### 验收标准

1. 当前对话成员未绑定 Apple 健康时，饮食营养不展示真实本机营养数据。
2. 未绑定时已食用、剩余、已消耗均展示 `- 千卡`。
3. 未绑定时展示“去绑定”按钮。
4. 未绑定时不调用 HealthKit 营养查询。
5. 已绑定后能展示当前缓存中的饮食营养数据。

## 4. 整体业务流程

```text
新建/进入对话
  ↓
读取 guide card payload
  ↓
payload 只提供问题区状态，不提供健康滑块数据
  ↓
ChatGuideMetricSnapshotViewModel 根据 thread.memberID 加载实时快照
  ↓
运动/饮食先检查 Apple 健康绑定态
  ├─ 未绑定 -> - 占位 + 去绑定
  └─ 已绑定 -> 读取缓存/轻量查询
  ↓
医疗数据读取当前成员 complete-data 缓存
  ↓
ChatGuideMetricCarouselView 展示实时 sections
```

## 5. 状态模型

| 状态 | 来源 | UI |
| --- | --- | --- |
| `loading` | 页面刚出现，快照加载中 | 四个 section skeleton 或 `-` 占位 |
| `ready` | 缓存读取成功 | 展示实时数据 |
| `unauthorized` | 当前成员未绑定 Apple 健康或未授权 | `-` + 去绑定 |
| `empty` | 已绑定但无数据 | `-` 或暂无数据 |
| `failed` | 缓存/读取失败 | 轻量失败态，不影响问题区 |

成员绑定状态：

| 成员状态 | 运动数据 | 饮食营养 |
| --- | --- | --- |
| thread.memberID == nil | `-` + 去绑定 | `-` + 去绑定 |
| 非本人/未绑定 Apple 健康 | `-` + 去绑定 | `-` + 去绑定 |
| 本人/已绑定但 HealthKit 不可用 | 不可用态 | 不可用态 |
| 本人/已绑定但无授权 | `-` + 去绑定 | `-` + 去绑定 |
| 本人/已绑定且有缓存 | 展示缓存 | 展示缓存 |

## 6. 数据与持久化

不再持久化：

1. `metric_sections`
2. 步数、热量、饮食、体重等格式化展示值
3. sparkline `normalized_values`
4. 医疗计数展示快照
5. Apple 健康授权/绑定状态快照

仍可持久化：

1. guide card block kind
2. `schemaVersion`
3. `memberID`
4. `questions`
5. `questionGeneration`

本地缓存来源建议：

| 数据 | 建议来源 |
| --- | --- |
| 运动数据 | HealthKit 读缓存 / SparkHealthTool 轻量查询 |
| 身材管理 | HealthKit 体重/BMI/体脂缓存 |
| 饮食营养 | Nutrition cache + HealthKit nutrition/energy cache |
| 医疗数据 | 当前成员 complete-data 缓存 |
| 成员绑定态 | `MemberContextStore` / 成员 relationship / 后续 Apple 健康绑定记录 |

## 7. 错误模型

| 错误 | 处理 |
| --- | --- |
| 当前 thread 不存在 | 滑块展示空态 |
| thread.memberID 为空 | 运动/饮食 `-` + 去绑定，医疗空态 |
| 找不到成员 | 运动/饮食 `-` + 去绑定 |
| 成员不是本人/未绑定 Apple 健康 | 运动/饮食 `-` + 去绑定 |
| HealthKit 不可用 | 不可用态 |
| HealthKit 未授权 | `-` + 去绑定 |
| HealthKit 查询失败 | failed，不回写消息 |
| 营养缓存失败 | 饮食 failed 或 `-` |
| complete-data 缓存缺失 | 医疗 failed/empty |
| 页面快速滚动复用 | task 去重并按 memberID 校验结果 |

## 8. 与其他模块的接口边界

本模块负责：

1. Chat guide card 健康滑块实时渲染。
2. 根据当前对话成员判断 Apple 健康可读性。
3. 未绑定时展示 `-` 和去绑定入口。
4. 不把滑块展示数据写入消息 payload。

本模块不负责：

1. Apple 健康授权页完整流程。
2. Nutrition 业务数据录入。
3. 医疗 complete-data 服务端刷新策略。
4. 科普问题点击后的 AI 回复。

ChatView / ChatDetailViewModel 当前 thread/member 上下文

## 11. 当前实现、缺口与演进

当前实现：

1. 滑块数据模型和 UI 已存在。
2. `ChatGuideCardPayloadBuilder` 已能构建四类 section。
3. `ChatGuideMetricCarouselView` 已支持分页、空态、失败态和 action。
4. `Member.isSelfMember` 已提供本人判断基础。
5. 科普问题生成流程已有独立工单与实现，本工单保持不变。

当前缺口：

1. `metricSections` 仍在 payload 中持久化。
2. `ChatGuideMetricCarouselView` 仍是 payload 驱动，不是页面实时数据驱动。
3. 运动/饮食没有明确按当前对话成员判断 Apple 健康绑定态。
4. 缺少“不持久化健康滑块数据”的同步与 schema 测试。

建议演进：

1. 本期先用 `isSelfMember` 作为 Apple 健康可读性判断。
2. 后续如服务端支持 Apple 健康成员绑定关系，再替换为明确绑定记录。
3. 后续可增加“刷新滑块”轻交互，但仍只刷新页面状态，不写消息。

## 12. 整体验收标准

1. 新建 guide card payload 不再包含真实 `metric_sections` 数据。
2. 服务端同步不再上传步数、热量、饮食、医疗统计快照。
3. 页面卡片能实时展示当前缓存健康数据。
4. 历史对话重新进入时滑块展示最新缓存，不展示旧 payload 快照。
5. 当前对话成员未绑定 Apple 健康时，运动数据展示 `-` 和“去绑定”。
6. 当前对话成员未绑定 Apple 健康时，饮食营养展示 `-` 和“去绑定”。
7. 未绑定 Apple 健康时不调用 HealthKit 读取运动/饮食数据。
8. 已绑定 Apple 健康时可展示真实缓存数据。
9. 滑块数据刷新不触发 message block 本地更新或服务端 block update。
10. 科普问题生成流程、触发时机、prompt、AI 回写与点击发送保持不变。
