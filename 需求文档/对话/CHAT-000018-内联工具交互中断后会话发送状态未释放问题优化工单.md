## 1. 一句话结论

该问题大概率不是输入框本身的问题，而是 Chat 生成任务在“等待工具交互卡片提交”时被取消，但 `ToolInteractionCoordinator` 内部的 `CheckedContinuation` 没有被统一 resume/cancel，导致 `currentGenerationTask` 仍挂起。由于 `startSendingCurrentDraft` 入口有 `guard currentGenerationTask == nil`，用户后续输入新内容会被静默挡住。

## 2. 用户复现流程

```text
1. 用户发起一轮对话。
2. AI 调用 ask_user_question 或 request_member_selection。
3. 当前设置为“会话卡片”展示方式。
4. 对话内出现问答卡片或选择成员卡片。
5. AI 当前轮次没有真正结束，而是在等待用户选择。
6. 用户不选择卡片，直接点击输入框上的终止按钮。
7. UI 上看起来已经终止。
8. 用户输入新的问题并点击发送。
9. 新消息无法发送，或发送按钮行为无响应。
```

当前内联成员选择：

    let completionID = UUID()
    return await withCheckedContinuation { continuation in
        inlineMemberContinuations[completionID] = continuation

问题点：

除非用户提交卡片或卡片自己调用 `cancelInlineQuestion / cancelInlineMemberSelection`，否则 continuation 可能一直留在字典里。

### 3.4 工具执行会因等待用户输入而停在当前轮

关键代码：

```text
/Users/hua/Documents/project/Reference/LookHealthClient/SparkClient/SparkClient/Projects/Core/AIRuntime/ChatOrchestrator.swift
```

工具调用后，如果工具返回 `isAwaitingUserInput`，当前轮会返回 `finishReason = awaiting_user_input`。但内联卡片模式下，更多情况是工具执行器直接 await `ToolInteractionCoordinator.requestQuestionAnswer/requestMemberSelection`，等待卡片提交后再返回工具结果。

因此用户点击“终止”时，必须同时打断：

```text
AI runtime 请求
ToolHub 工具执行
ToolInteractionCoordinator continuation
消息内 pending 卡片
ChatDetailViewModel 当前 generation task
```

只打断其中一部分，会出现 UI 看似停止但运行态仍未退出。

## 4. 根因判断

### 4.1 高概率根因

外层取消没有桥接到 `ToolInteractionCoordinator` 的内联 continuation。

```text
用户点终止
  -> currentGenerationTask.cancel()
  -> stateStore.isSending = false
  -> UI 进入可输入状态
  -> 但 currentGenerationTask 仍挂在 withCheckedContinuation
  -> defer 不执行
  -> currentGenerationTask 不置 nil
  -> 下一次 startSendingCurrentDraft 被 guard currentGenerationTask == nil 拦住
```

这正好解释“貌似没有完全终止”和“输入新的东西无法发送”。

### 4.2 次要风险

1. Sheet 模式的 `userWaitGate` 也可能在终止时没有统一关闭。
2. 消息内 pending 卡片仍可点击，用户可能在已中断的旧轮次上提交答案。
3. 旧轮次 continuation 如果稍后被提交，可能错误恢复已被用户放弃的工具调用。
4. `stateStore.isSending` 与 `currentGenerationTask` 可能出现状态分裂：UI 显示不在发送，但 ViewModel 仍认为有 task。
5. `currentGenerationCancellationToken` 可能已经 cancel，但 `ToolInteractionCoordinator` 不读这个 token。

## 5. 目标行为

用户点击终止按钮后，必须满足：

```text
1. 当前 AI task 停止。
2. 当前 cancellationToken 被 cancel。
3. ToolInteractionCoordinator 所有属于本轮 generation 的 pending continuation 被 resume(.cancelled)。
4. 当前 active Sheet 被关闭或按取消完成。
5. 当前消息内 pending 工具交互卡片更新为 cancelled/interrupted。
6. currentGenerationTask 最终置 nil。
7. currentGenerationCancellationToken 最终置 nil。
8. stateStore.isSending 为 false。
9. 新输入可以立即发送。
10. 旧卡片不能再恢复旧轮次工具调用。
```

## 6. 优化方案

### 6.1 新增统一取消入口

建议在 `ToolInteractionCoordinator` 新增一个强制取消方法：

```swift
@MainActor
func cancelAllPendingInteractions(reason: ToolInteractionCancelReason)
```

职责：

```text
1. activePresentation 如果存在，按类型设置 pendingOutcome 为 cancelled/dismissed。
2. resumeUserGate()，释放 Sheet 队列等待。
3. 遍历 inlineQuestionContinuations，全部 resume(.cancelled)。
4. 遍历 inlineMemberContinuations，全部 resume(.cancelled)。
5. 遍历 inlineHealthResourceCandidateContinuations，全部 resume(.cancelled)。
6. 遍历 inlineConsentContinuations，全部 resume(.cancelled)。
7. 清空所有 continuation 字典。
8. 清空 queue 中还未展示但带 completion 的 work，并 resume 为 cancelled。
9. 将 isDraining 恢复为 false 或保证 drain loop 能自然结束。
```

建议取消原因：

```swift
enum ToolInteractionCancelReason: String, Sendable {
    case userStoppedGeneration
    case threadChanged
    case viewModelDeinitialized
    case runtimeCancelled
}
```

### 6.2 cancelCurrentGeneration 必须调用交互取消

`ChatDetailViewModel.cancelCurrentGeneration()` 应在取消 task 前后调用：

```text
toolInteractionCoordinator.cancelAllPendingInteractions(reason: .userStoppedGeneration)
```

建议顺序：

```text
1. 记录 assistantClientMessageID。
2. 标记本轮正在取消，避免后续卡片提交恢复旧轮次。
3. cancelAllPendingInteractions。
4. currentGenerationCancellationToken?.cancel()
5. currentGenerationTask?.cancel()
6. stateStore.setSending(false)
7. finalizeInterruptedAssistantMessageIfNeeded
```

关键点：先 resume continuation，再 cancel task，能让挂起的工具 await 有机会返回 `.cancelled` 并走正常收尾。

### 6.3 currentGenerationTask 需要兜底释放

当前依赖 `sendCurrentDraft` 的 `defer` 释放：

```text
stateStore.setSending(false)
currentGenerationCancellationToken = nil
currentGenerationAssistantClientMessageID = nil
currentGenerationTask = nil
```

如果 task 被挂住，defer 不会执行。建议增加兜底：

```text
1. cancelCurrentGeneration 中标记 cancellingGenerationID。
2. cancel 后启动短延迟 watchdog。
3. 若 1-2 秒后 currentGenerationTask 仍非 nil 且 token 已 cancel，则强制清理 ViewModel 引用。
4. 日志记录 cancelled_task_did_not_exit。
```

这不是代替正确取消，只是防止 UI 永久卡死。

### 6.4 pending 卡片需要转为 cancelled/interrupted

关键模型：

```text
/Users/hua/Documents/project/Reference/LookHealthClient/SparkClient/SparkClient/Projects/Features/Chat/Domain/ChatMessage/BlockPayloads/ChatToolInteractionCards.swift
```

当前卡片状态已有：

```text
pending / submitted / cancelled / expired
```

建议终止时把本轮 assistant 消息内所有 pending 工具交互卡片更新为：

```text
status = .cancelled
resultText = "本轮回答已终止，未提交选择。"
```

适用卡片：

```text
ChatToolQuestionCard
ChatToolMemberSelectionCard
ChatHealthResourceCandidateSelectionCard
ChatToolConsentCard
```

这样做有两个好处：

```text
1. 用户视觉上知道旧卡片已经失效。
2. 防止用户稍后点击旧卡片导致恢复旧 continuation。
```

### 6.5 卡片提交前校验 generation 有效性

当前提交入口：

```text
submitInlineToolQuestionCard
submitInlineToolMemberSelectionCard
skipInlineHealthResourceCandidateCard
chooseInlineHealthResourceCandidateCard
resolveInlineToolConsentCard
```

建议增加校验：

```text
1. card.status 必须为 pending。
2. completionID 必须仍存在于 ToolInteractionCoordinator。
3. 所属 assistant message 必须仍是当前 generation 或未被 interrupted。
4. 如果 continuation 已不存在，则只把卡片标为 expired/cancelled，不再触发 AI 续跑。
```

可在 `ToolInteractionCoordinator` 增加只读能力：

```swift
func hasPendingInlineInteraction(completionID: UUID) -> Bool
```

或者按类型拆分：

```swift
func hasPendingInlineQuestion(id: UUID) -> Bool
func hasPendingInlineMemberSelection(id: UUID) -> Bool
```

### 6.6 Sheet 模式也要纳入统一取消

虽然用户这次描述的是“对话内弹出消息弹窗”，但同类问题也可能发生在 Sheet 队列：

```text
activePresentation
userWaitGate
queue
pendingOutcome
```

因此 `cancelAllPendingInteractions` 不能只清理 inline continuation，还要处理 Sheet 队列。

## 11. 风险与注意事项

1. `CheckedContinuation` 只能 resume 一次，批量取消时必须先 remove 再 resume。
2. `Task.cancel()` 不会自动让 `withCheckedContinuation` 返回，必须显式 resume。
3. 不要只把 `currentGenerationTask = nil` 当作修复；那会掩盖旧 task 仍可能恢复 UI 的问题。
4. 终止旧轮次后，旧卡片不能再触发成员切换或 AI 续跑。
5. Sheet 队列和 inline continuation 要统一处理，否则不同展示模式会出现不一致。
6. 如果新增 watchdog，只能作为兜底日志和 UI 解锁，不应替代正确的 continuation 清理。

## 12. 最终判断

这个问题可以修，而且应该优先修。它属于 Chat 运行态收口缺陷：UI 已经让用户“终止”，但工具交互等待态没有一起结束。

推荐的核心修复不是在发送按钮上绕过 `currentGenerationTask == nil`，而是在终止动作里建立一个强制取消边界：取消 AI、取消工具交互、取消卡片、恢复 continuation、释放 ViewModel task。这样下一轮发送自然恢复，也能避免旧卡片在未来误恢复旧工具调用。
