> 创建日期：2026-08-11

## 1. 一句话目标

基于当前任务中心列表页与任务详情页截图反馈，优化移动端信息层级、筛选密度、卡片表达、详情分组和执行操作路径，让任务模块从“字段展示完整”升级为“移动端可读、可操作、有质感”的健康任务界面。

本工单重点解决三个高感知问题：

1. 不再把 `health_monitoring`、`medium`、`manual` 等底层 rawValue 直接暴露给用户。
2. 列表页筛选区从“占半屏”收敛为“常用状态常驻 + 高级筛选收纳”。
3. 详情页从纯文本平铺改为 Grouped Card 信息分组，并把主操作固定在底部。

本工单参考两个本地 skill 的原则：

1. `apple-design` / `苹果设计`：强调即时反馈、空间一致性、材质层级、直接操作、底部 Sheet 与吸底操作的 iOS 体验。

## 3. 当前问题复盘

### 3.1 列表页问题

当前任务中心已经能展示比较完整的数据，但移动端屏幕里的主次关系不够明确。

主要问题：

1. 筛选栏同时展开状态、类型、优先级、时间 4 组条件，占用过多垂直空间。
2. 用户进入页面后首先看到的是筛选条件，而不是任务本身。
3. 卡片文案里出现类似“目标：xxx”“动作：xxx”的前缀时，信息重复且显得工程化。
4. 优先级标签颜色区分不足，高/中/低优先级缺少稳定视觉语义。
5. 类型标签颜色语义不够统一，医疗、运动、饮食需要形成稳定识别。
6. 底部“新建任务”吸底按钮与“上次同步”文案存在重叠风险。
7. 列表页缺少直接完成入口，用户必须进入详情页才能完成任务，路径偏长。

### 3.2 详情页问题

当前任务详情能把字段展示出来，但看起来更像一份调试表单，而不是面向用户的移动端详情页。

主要问题：

1. 子模型字段直接展示 rawValue，例如 `health_monitoring`。
2. 标题、状态、优先级、时间、来源、提醒时间全部纵向平铺，缺乏卡片分组。
3. 医疗/运动/饮食业务面板与通用基础信息的视觉差异不够明显。
4. “完成 / 跳过 / 失败”三个按钮平铺在页面中部，主次不清晰，容易误触。
5. 核心执行操作没有吸底，用户滚动详情后需要找按钮。
6. 编辑、取消、次要执行动作没有形成稳定的 `...` 菜单层级。

## 4. 目标与非目标

### 4.1 用户目标

1. 用户一眼知道当前最重要的任务是什么。
2. 用户可以在列表页直接完成简单任务。
3. 用户进入详情页后能清晰理解任务目的、时间、类型和提醒。
4. 用户不会看到底层代码枚举值。
5. 用户执行任务时能明确区分主操作与次操作。

### 4.2 产品目标

1. 提升任务中心首屏内容密度与可读性。
2. 降低用户在筛选区迷失的概率。
3. 提升健康任务模块的专业感与信任感。
4. 为后续 iOS26 Liquid Glass / Floating TabBar 下的任务页体验留出视觉兼容空间。

### 4.3 非目标

1. 本工单不新增任务业务类型。
2. 本工单不重做 `TaskExecution` 服务端协议。
3. 本工单不修改首页任务摘要逻辑。
4. 本工单不重构整个任务模块架构，只针对列表页和详情页做 UI/交互优化。
5. 本工单不引入第三方 UI 框架。

## 7. 列表页设计方案

### 7.1 筛选区域改造

当前 4 组筛选全部展开，移动端密度过高。建议改成：

1. 顶部常驻状态分段：`全部 / 待完成 / 已完成`
2. 右上角高级筛选按钮：图标使用 `line.3.horizontal.decrease.circle`
3. 高级筛选内容通过 Bottom Sheet 展示：类型、优先级、时间
4. 如果有高级筛选生效，筛选按钮显示小圆点或数量 Badge

#### 优化后 plain text

```text
┌────────────────────────────────────┐
│  任务中心                 [筛选图标] │
│  待完成 12   逾期 3   今日 5        │
│                                    │
│  ┌──────────────────────────────┐  │
│  │  全部     待完成     已完成   │  │
│  └──────────────────────────────┘  │
│                                    │
│  今天优先处理                      │
│  ┌──────────────────────────────┐  │
│  │ ○ 服药提醒              高    │  │
│  │   晚餐后 30 分钟服药          │  │
│  │   医疗  今天 20:00  已过期     │  │
│  └──────────────────────────────┘  │
│                                    │
│  ┌──────────────────────────────┐  │
│  │ ○ 慢跑 30 分钟           中    │  │
│  │   保持中等强度，完成后记录时长 │  │
│  │   运动  明天 07:00            │  │
│  └──────────────────────────────┘  │
│                                    │
│                 上次同步 20:12      │
│                         (+)        │
└────────────────────────────────────┘
```

### 7.2 高级筛选 Sheet

高级筛选不在首屏展开，点击筛选图标后出现底部 Sheet。

```text
┌────────────────────────────────────┐
│  筛选                              │
│                                    │
│  类型                              │
│  [医疗] [运动] [饮食]              │
│                                    │
│  优先级                            │
│  [高] [中] [低]                    │
│                                    │
│  时间                              │
│  [今日] [明日] [未来]              │
│                                    │
│  [重置]                    [完成]  │
└────────────────────────────────────┘
```

交互要求：

1. Sheet 从筛选按钮触发，空间关系明确。
2. `完成` 后列表平滑更新。
3. `重置` 清空类型、优先级、时间筛选，不影响状态分段。
4. 筛选按钮在高级筛选生效时显示角标，例如 `2`。

### 7.3 卡片信息收拢

任务卡片只保留用户真正需要扫读的信息：

1. 左侧完成控件：`○ / ✓`
2. 主标题：直接展示 `task.title`
3. 副标题：展示 `task.description`，最多 2 行
4. 底部元信息：类型、时间、过期状态
5. 右上角优先级 Tag

必须删除：

1. `目标：`
2. `动作：`
3. 任何服务端字段名
4. 任何 rawValue

### 7.4 Tag 颜色规范

#### 类型 Tag

| 类型 | 背景 | 文字 | 语义 |
| --- | --- | --- | --- |
| 医疗 | `systemBlue.opacity(0.12)` | `systemBlue` | 专业、监测、医疗 |
| 运动 | `systemGreen.opacity(0.12)` | `systemGreen` | 活力、运动 |
| 饮食 | `systemOrange.opacity(0.12)` | `systemOrange` | 营养、餐食 |

#### 优先级 Tag

| 优先级 | 背景 | 文字 | 语义 |
| --- | --- | --- | --- |
| 高 | `systemRed.opacity(0.12)` | `systemRed` | 需要尽快处理 |
| 中 | `systemYellow.opacity(0.18)` | `systemOrange` | 正常关注 |
| 低 | `tertiarySystemFill` | `secondaryLabel` | 低干扰 |

### 7.5 一键完成交互

列表页左侧完成控件用于快速完成任务。

要求：

1. 只在 `pending` 任务显示可点击圆形控件。
2. 已完成任务显示 `checkmark.circle.fill`，不可重复提交。
3. 点击后立即进入 loading / disabled 状态。
4. 成功后卡片状态切换为完成，伴随轻量 haptic。
5. 失败后控件回滚，并显示轻量错误提示。
6. 控件热区不小于 `44 x 44 pt`。

### 7.6 底部按钮与同步时间

当前底部“新建任务”蓝按钮遮挡最后同步时间。建议采用二选一：

方案 A：继续吸底主按钮，但给列表和同步文案预留安全区。

```swift
.safeAreaInset(edge: .bottom) {
    TaskCreateBottomBar(onCreate: onCreate)
}
.contentMargins(.bottom, 96, for: .scrollContent)
```

方案 B：改为右下角 FAB，底部只显示同步时间。

```text
┌────────────────────────────────────┐
│  列表内容                          │
│                                    │
│  上次同步 20:12                    │
│                              ┌──┐  │
│                              │＋│  │
│                              └──┘  │
└────────────────────────────────────┘
```

推荐本期采用方案 B：更符合任务列表管理工具的移动端常见交互，也能减少按钮遮挡。

## 8. 详情页设计方案

### 8.1 信息分组

详情页改为三段式：

1. 头部 Hero：任务标题、描述、状态/优先级 Badge、类型图标
2. 基础信息卡片：时间、重复、来源、提醒时间
3. 业务信息卡片：医疗/运动/饮食差异化面板

### 8.2 优化后 plain text

```text
└────────────────────────────────────┘
```

### 8.3 头部区

头部区不使用卡片包裹，保持页面呼吸感。

内容：

1. `task.title`：`title2` 或 `title3`，中高字重
2. `task.description`：`body`，最多 3 行
3. 状态 Badge：待完成 / 已完成 / 已取消 / 已过期
4. 优先级 Badge：高 / 中 / 低
5. 类型 Badge：医疗 / 运动 / 饮食

### 8.4 基础信息卡片

基础信息卡片展示通用字段：

1. 时间：`dueTime` 优先，其次 `startTime`
2. 重复：不重复 / 每日 / 每周
3. 来源：手动创建 / AI 生成 / 报告
4. 提醒：医疗任务优先展示 `TaskMedical.reminderTime`

布局建议：

1. 使用浅灰底圆角卡片。
2. Key 使用 `caption` + secondary。
3. Value 使用 `subheadline` + primary。
4. 每行高度不小于 36 pt。

### 8.5 业务面板卡片

业务面板独立于基础信息卡片。

医疗：

1. 医疗任务类型：映射后文案，例如 `health_monitoring -> 健康监测`
2. 提醒时间
3. 描述

运动：

1. 运动类型：例如 `walking -> 步行`
2. 时长
3. 强度：例如 `medium -> 中等强度`
4. 描述

饮食：

1. 餐次：例如 `breakfast -> 早餐`
2. 目标热量
3. 食物推荐
4. 描述

### 8.6 底部执行操作

详情页只把主操作固定吸底：

1. 主按钮：`标记完成`
2. 次要操作：`跳过`、`失败` 放入 `...` 菜单
3. 已完成任务不显示主按钮，只展示完成状态与执行时间
4. 取消任务属于编辑菜单，不放在主执行区

底部操作条要求：

1. 使用 `.safeAreaInset(edge: .bottom)`。
2. 背景使用 `.bar` 或系统材质。
3. 按钮高度不少于 44 pt。
4. 提交中禁用按钮并展示 Progress。

## 9. rawValue 映射设计

### 9.1 映射原则

1. 服务端 rawValue 只用于协议，不直接展示。
2. 映射逻辑集中在 `TaskDisplayMapping.swift`。
3. 默认兜底不能原样裸露下划线，需要做基础格式化。
4. 所有固定文案必须走 `NSLocalizedString` 或 `L10n.text`。

| `general_medical` | 医疗任务 |

## 10. 关键代码示例

### 10.1 新增展示映射文件

建议新增：

`SparkClient/Projects/Features/Task/Domain/TaskDisplayMapping.swift`

```swift
import SwiftUI

enum TaskDisplayMapping {
    static func medicalTaskType(_ rawValue: String) -> String {
        switch rawValue {
        case "health_monitoring":
            return NSLocalizedString("task.medical_type.health_monitoring", comment: "健康监测")
        case "medication":
            return NSLocalizedString("task.medical_type.medication", comment: "用药提醒")
        case "follow_up":
            return NSLocalizedString("task.medical_type.follow_up", comment: "复诊随访")
        case "checkup":
            return NSLocalizedString("task.medical_type.checkup", comment: "体检计划")
        case "report_review":
            return NSLocalizedString("task.medical_type.report_review", comment: "报告解读")
        case "general_medical":
            return NSLocalizedString("task.medical_type.general", comment: "医疗任务")
        default:
            return fallbackDisplayName(rawValue)
        }
    }

    static func intensity(_ rawValue: String) -> String {
        switch rawValue {
        case "low":
            return NSLocalizedString("task.exercise.intensity.low", comment: "低强度")
        case "medium":
            return NSLocalizedString("task.exercise.intensity.medium", comment: "中等强度")
        case "high":
            return NSLocalizedString("task.exercise.intensity.high", comment: "高强度")
        default:
            return fallbackDisplayName(rawValue)
        }
    }

    static func mealType(_ rawValue: String) -> String {
        switch rawValue {
        case "breakfast":
            return NSLocalizedString("task.diet.meal.breakfast", comment: "早餐")
        case "lunch":
            return NSLocalizedString("task.diet.meal.lunch", comment: "午餐")
        case "dinner":
            return NSLocalizedString("task.diet.meal.dinner", comment: "晚餐")
        case "snack":
            return NSLocalizedString("task.diet.meal.snack", comment: "加餐")
        default:
            return fallbackDisplayName(rawValue)
        }
    }

    private static func fallbackDisplayName(_ rawValue: String) -> String {
        rawValue
            .split(separator: "_")
            .map { $0.prefix(1).uppercased() + $0.dropFirst() }
            .joined(separator: " ")
    }
}
```

```swift
struct TaskCompletionToggle: View {
    let task: HealthTask
    let isSubmitting: Bool
    let onComplete: () -> Void

    var body: some View {
        Button {
            guard task.status == .pending, isSubmitting == false else { return }
            onComplete()
        } label: {
            Image(systemName: iconName)
                .font(.title3.weight(.semibold))
                .foregroundStyle(iconColor)
                .frame(width: 44, height: 44)
        }
        .buttonStyle(.plain)
        .disabled(task.status != .pending || isSubmitting)
        .accessibilityLabel(accessibilityTitle)
    }

    private var iconName: String {
        switch task.status {
        case .pending:
            return "circle"
        case .completed:
            return "checkmark.circle.fill"
        case .canceled:
            return "minus.circle"
        }
    }

    private var iconColor: Color {
        switch task.status {
        case .pending:
            return Color(uiColor: .tertiaryLabel)
        case .completed:
            return Color(uiColor: .systemGreen)
        case .canceled:
            return Color(uiColor: .secondaryLabel)
        }
    }

    private var accessibilityTitle: String {
        task.status == .pending
            ? NSLocalizedString("task.action.complete", comment: "标记完成")
            : task.status.displayName
    }
}
```
