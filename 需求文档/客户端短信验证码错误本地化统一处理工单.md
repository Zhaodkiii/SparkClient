# 客户端短信验证码错误本地化统一处理工单

## 1. 工单摘要

| 项目 | 内容 |
|---|---|
| 工单名称 | 客户端短信验证码错误本地化统一处理 |
| 需求来源 | 后端 OTP 接口错误响应已改为稳定 `msg` key，客户端需要统一映射成本地化用户文案 |
| 影响范围 | 手机号验证码发送、重发、登录验证、账号注销手机号验证 |
| 当前状态 | 已实现 |

## 2. 问题背景

手机号验证码发送失败时，客户端日志出现：

```text
登录流程：验证码发送失败 error=OTP requested too frequently
```

服务端响应示例：

```json
{
  "code": 42901,
  "msg": "OTP requested too frequently",
  "data": {
    "request_id": "AB49292E-55CD-45F1-B9A4-FFA5BD5911E0"
  }
}
```

该形态存在两个问题：

1. `msg` 是英文自然语言，客户端无法稳定做本地化映射。
2. 短信供应商错误、OTP 频控、验证码验证失败的展示口径不统一。

后端已调整为稳定错误 key：

```json
{
  "code": 42902,
  "msg": "sms_send_rate_limited",
  "data": {
    "error_type": "sms_send_rate_limited",
    "reason": "isv.BUSINESS_LIMIT_CONTROL:触发天级流控Permits:10",
    "request_id": "..."
  }
}
```

## 3. 目标

客户端统一使用 `msg` 作为本地化 key 来源：

```text
后端 msg=sms_send_rate_limited
-> 客户端 key=api_error.msg.sms_send_rate_limited
-> 展示本地化文案
```

`data.reason` 仅用于日志、诊断和客服排查，不直接作为普通用户展示文案。

## 5. 技术实现

客户端已有统一错误本地化入口：

```text
BackendErrorLocalizer.message(for:statusCode:)
```

当前解析顺序：

1. 如果 `data.message` / `data.msg` 存在，优先展示该字段。
2. 如果存在 `api_error.code.<code>`，使用业务码本地化。
3. 否则将后端 `msg` 规范化为 `api_error.msg.<msg>` 并查询 `Localizable.strings`。
4. 如果仍未命中，回退展示后端 `msg` 或 HTTP 通用错误。

本工单不改网络栈代码，仅补齐 `Localizable.strings` 中短信/OTP 相关 key。原因是后端新契约已经把普通展示字段收敛到 `msg`，客户端现有 `BackendErrorLocalizer` 可直接承接。

## 7. 验收口径

1. 服务端返回 `msg=otp_requested_too_frequently` 时，客户端展示“验证码请求过于频繁，请稍后再试。”。
2. 服务端返回 `msg=invalid_phone_number` 时，客户端展示“手机号格式不正确，请重新输入。”。
3. 服务端返回 `msg=phone_number_required` 时，客户端展示“请输入手机号。”。
4. 服务端返回 `msg=invalid_credentials` 时，客户端展示“账号或密码不正确。”。
5. 服务端返回 `msg=user_inactive` 时，客户端展示“当前账号已停用，请联系管理员。”。
6. 服务端返回 `msg=bundle_id_not_allowed` 时，客户端展示“当前应用版本暂不支持该登录方式。”。
7. 服务端返回 `msg=sms_send_rate_limited` 且 `data.reason=isv.BUSINESS_LIMIT_CONTROL:触发天级流控Permits:10` 时，客户端展示“短信发送过于频繁，请稍后再试。”。
8. 普通用户界面不直接展示阿里云原始错误串。
9. 日志仍可记录后端 `reason/request_id`，便于排查。
10. 英文环境下展示英文文案，不展示后端 key。
