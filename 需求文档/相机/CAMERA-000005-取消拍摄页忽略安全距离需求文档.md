# CAMERA-000005 取消拍摄页忽略安全距离需求文档

> 文档性质：需求工单。本文只描述需求与技术改造点，不实现代码。

## 1. 工单背景

当前自定义相机多个业务拍摄页面在启动相机会话后直接使用：

```swift
.startSession()
.ignoresSafeArea()
```

这会让拍摄页面根视图、相机预览、遮罩和底部控制区域都延伸到系统安全区之外。此前 `CAMERA-000004` 曾将“拍摄页允许忽略安全区、预览页不忽略安全区”作为策略，但当前需求已调整：拍摄页面也需要取消根级忽略安全距离设置。

新的目标是：

```text
拍摄页面：取消根级 .ignoresSafeArea()
预览页面：继续不忽略底部安全区
遮罩/阴影/取景框/底部面板：按 safeAreaInsets 重新计算
```

取消忽略安全距离后，原本依赖全屏坐标系计算的拍摄阴影、遮罩裁剪区域、底部面板高度、提示文案位置等都需要重新按安全区布局校准，避免出现遮罩错位、底部阴影缺口、取景框上移/下移异常、底部按钮被压缩等问题。

## 4. 需求目标

### 4.1 核心目标

1. 取消五个拍摄场景中 `.startSession()` 后的根级 `.ignoresSafeArea()`。
2. 拍摄页面整体遵守系统安全区，不再强行铺到底部 Home Indicator 区域。
3. 相机输出、暗色遮罩、取景框、提示文案、底部面板需要基于 `GeometryProxy.safeAreaInsets` 重新计算。
4. 检查报告拍摄页 `ExaminationReportCameraSceneView.swift:338-440` 的遮罩/阴影必须重点适配。
5. 取消忽略安全区后，不应出现相机预览露白、遮罩缺口、底部面板悬空、取景框位置异常。
6. 各业务拍摄页视觉应保持稳定：可用区域内沉浸，但不越过系统安全边界。

### 4.2 非目标

1. 本工单不改变相机底层拍摄逻辑。
2. 本工单不改变拍摄结果数据模型。
3. 本工单不重做拍摄页 UI 风格。
4. 本工单不改拍摄后预览页的业务流程。
5. 本工单不处理图片编辑器、裁剪器的独立全屏安全区问题。

## 5. 技术细节

### 5.1 安全区坐标系变化

取消根级 `.ignoresSafeArea()` 后，`GeometryReader` 的可用区域和 `safeAreaInsets` 语义会发生实际影响：

```text
取消前：
根视图可延伸到安全区外
遮罩/相机预览按全屏尺寸绘制
底部面板可通过 ignoresSafeArea(edges: .bottom) 填满底部

取消后：
根视图默认遵守安全区
相机预览绘制区域变小
遮罩 cutoutRect 需要按新的可用区域计算
底部面板不应再额外吃掉 safeBottom
```

实施时必须重新验证：

1. `proxy.size.height` 是否已经是安全区内高度。
2. `proxy.safeAreaInsets.bottom` 是否仍需要加入 `bottomPanelHeight`。
3. `bottomPanel` 的 `height: panelHeight + safeBottom` 是否需要改为只使用 `panelHeight`。
4. `.padding(.bottom, max(safeBottom, 16))` 是否会导致底部间距重复。
5. `cameraAreaBottom = availableHeight - safeBottom - bottomPanelHeight ...` 是否会重复扣除底部安全区。

### 5.2 相机输出视图

当前检查报告拍摄页：

```swift
createCameraOutputView()
    .ignoresSafeArea()
```

取消策略：

```swift
createCameraOutputView()
```

需要验证：

1. 相机预览是否填满安全区内区域。
2. 顶部 navigation toolbar 下方是否出现黑边。
3. 底部面板上方是否出现空白缝隙。
4. 如果预览需要填满 ZStack，但不越过安全区，应使用 `.frame(maxWidth: .infinity, maxHeight: .infinity)`，而不是 `.ignoresSafeArea()`。

### 5.3 暗色遮罩/拍摄阴影

当前检查报告拍摄页：

```swift
ExaminationReportCameraOutsideMask(
    cutoutRect: layout.viewfinderRect,
    cornerRadius: ...
)
.fill(Color.black.opacity(0.38), style: FillStyle(eoFill: true))
.ignoresSafeArea()
```

取消 `.ignoresSafeArea()` 后，遮罩绘制区域会变为安全区内区域。需要重新计算：

1. `cutoutRect` 是否仍以 ZStack 坐标系为基准。
2. `ExaminationReportCameraOutsideMask.path(in rect:)` 是否使用传入 `rect` 绘制全区域。
3. `cutoutRect` 是否需要根据 `safeTop` / toolbar 高度偏移。
4. 遮罩是否覆盖到底部面板上方，而不是覆盖底部面板。
5. 取消忽略安全区后，底部是否出现未被遮罩覆盖的亮条。

建议：

```text
遮罩 Shape 的外部 rect 使用当前安全区内容区域
cutoutRect 使用同一坐标系中的 viewfinderRect
不要通过 ignoresSafeArea 扩大遮罩覆盖范围
如果需要覆盖 navigation bar 背景，应单独处理 toolbar 背景，而不是全局忽略安全区
```

### 5.4 取景框布局

`ExaminationReportViewfinderLayout` 当前已读取：

```swift
let safeTop = proxy.safeAreaInsets.top
let safeBottom = proxy.safeAreaInsets.bottom
```

并计算：

```swift
let cameraAreaTop = safeTop + topChromeHeight
let cameraAreaBottom = availableHeight - safeBottom - bottomPanelHeight - promptHeight - bottomVerticalGap
```

取消根级忽略安全区后，需要确认 `availableHeight` 是否已经排除了部分安全区。如果是，则继续减 `safeBottom` 可能导致取景框过度上移、底部空间过大。

要求：

1. 统一定义 `contentTop`、`contentBottom`、`cameraAreaTop`、`cameraAreaBottom`。
2. 避免在同一轴向重复扣除安全区。
3. 取景框应位于 toolbar 与底部面板之间。
4. 提示文案应位于取景框下方，并且不与底部面板重叠。

建议在布局结构中明确：

```swift
let safeArea = proxy.safeAreaInsets
let containerHeight = proxy.size.height
let bottomReservedHeight = bottomPanelHeight
let cameraAreaBottom = containerHeight - bottomReservedHeight - promptHeight - bottomVerticalGap
```

如果 `GeometryReader` 所在视图已遵守安全区，则不要再额外减 `safeArea.bottom`。

### 5.5 底部面板

当前检查报告底部面板：

```swift
.padding(.bottom, max(safeBottom, 16))
.frame(width: width, height: panelHeight + safeBottom, alignment: .top)
.background(
    RoundedRectangle(cornerRadius: 28, style: .continuous)
        .fill(Color(uiColor: .systemBackground))
        .ignoresSafeArea(edges: .bottom)
)
.frame(maxHeight: .infinity, alignment: .bottom)
```

取消忽略安全区后，底部面板需要重新判断：

1. `panelHeight + safeBottom` 是否还合理。
2. 背景是否还需要 `.ignoresSafeArea(edges: .bottom)`。
3. `.padding(.bottom, max(safeBottom, 16))` 是否会导致内容被抬得过高。
4. 面板底部圆角是否应贴合安全区内底边。

目标建议：

```text
底部面板本身遵守安全区
背景不再忽略底部安全区
内容底部 padding 使用固定业务间距或 safeAreaInset，而不是重复叠加 safeBottom
```

可选方案：

```swift
.safeAreaInset(edge: .bottom, spacing: 0) {
    bottomPanel(...)
}
```

或：

```swift
bottomPanel(...)
    .padding(.bottom, 0)
```

具体采用哪种由实现时结合现有 ZStack 层级决定，但必须避免 `panelHeight + safeBottom` 与 `safeBottom padding` 双重计算。

## 7. 更详细的技术设计

### 7.1 坐标系判定方法

取消 `.ignoresSafeArea()` 后，最容易出错的是坐标系判断。实施时需要先明确每个 `GeometryReader` 的 `proxy.size` 和 `proxy.safeAreaInsets` 是否仍表示“全屏坐标”。

建议临时增加调试日志或 SwiftUI overlay，分别打印：

```swift
let size = proxy.size
let safe = proxy.safeAreaInsets
```

需要记录：

```text
scene = ExaminationReport
size.width
size.height
safe.top
safe.bottom
viewfinderRect
promptY
bottomPanelHeight
```

判断原则：

| 情况 | 说明 | 布局处理 |
| --- | --- | --- |
| `proxy.size.height` 仍接近屏幕全高 | GeometryReader 仍在全屏容器中 | 需要显式扣除 `safeTop/safeBottom` |
| `proxy.size.height` 已是安全区内容高 | 外层已遵守 safe area | 不要再重复扣除 `safeTop/safeBottom` |
| `safeBottom > 0` 且底部面板又使用 `panelHeight + safeBottom` | 高风险重复计算 | 应改为单一安全区策略 |
| 遮罩 Shape 的 `rect` 与 `viewfinderRect` 不在同一坐标系 | cutout 会错位 | 必须统一到同一个 GeometryReader 坐标系 |

本工单要求每个场景至少确认一次上述信息，尤其是检查报告场景。

### 7.2 推荐布局抽象

建议为文档/药箱/处方这类“取景框 + 提示 + 底部面板”的拍摄页收敛一套布局输入，避免五个文件各自重复处理安全区。

建议抽象：

```swift
struct CustomCameraSceneSafeAreaLayout {
    let containerSize: CGSize
    let safeInsets: EdgeInsets
    let navigationReservedHeight: CGFloat
    let bottomPanelHeight: CGFloat
    let promptHeight: CGFloat
    let topGap: CGFloat
    let bottomGap: CGFloat
}
```

输出：

```swift
struct CustomCameraSceneLayoutResult {
    let contentBounds: CGRect
    let cameraBounds: CGRect
    let viewfinderRect: CGRect
    let promptY: CGFloat
    let bottomPanelFrame: CGRect
}
```

这样可以明确：

```text
contentBounds：当前 SwiftUI 内容可用区域
cameraBounds：允许相机预览与遮罩出现的区域
viewfinderRect：取景框 cutout
bottomPanelFrame：底部面板位置
```

如果第一期不抽公共结构，也应在各 `ViewfinderLayout` 内用清晰变量名表达同样含义。

### 7.3 推荐布局公式

取消根级忽略安全区后，建议先按“内容区域已遵守安全区”设计：

```swift
let container = CGRect(origin: .zero, size: proxy.size)
let safe = proxy.safeAreaInsets

let contentTop: CGFloat = 0
let contentBottom: CGFloat = container.height

let bottomPanelHeight = ...
let bottomPanelTop = contentBottom - bottomPanelHeight

let cameraAreaTop = contentTop + topToolbarHeight + topVerticalGap
let cameraAreaBottom = bottomPanelTop - promptHeight - bottomVerticalGap
let cameraAreaHeight = max(minCameraAreaHeight, cameraAreaBottom - cameraAreaTop)
```

如果验证后发现 `proxy.size.height` 仍包含安全区，再使用显式安全区版本：

```swift
let contentTop = safe.top
let contentBottom = container.height - safe.bottom
let bottomPanelTop = contentBottom - bottomPanelHeight
```

禁止混用：

```swift
let contentBottom = container.height - safe.bottom
let bottomPanelHeight = basePanelHeight + safe.bottom
let bottomPadding = max(safe.bottom, 16)
```

这种写法会在同一方向上三次处理底部安全区。

### 7.4 检查报告布局改造建议

当前 `ExaminationReportViewfinderLayout` 里有：

```swift
let availableHeight = proxy.size.height
let safeTop = proxy.safeAreaInsets.top
let safeBottom = proxy.safeAreaInsets.bottom
let bottomPanelHeight = min(max(196, availableHeight * 0.24), 252)
let topToolbarHeight = safeTop + 58
let cameraAreaBottom = availableHeight - safeBottom - bottomPanelHeight - promptHeight - bottomVerticalGap
```

取消根级忽略安全区后，建议重构为两步：

第一步，明确内容边界：

```swift
let bounds = CGRect(origin: .zero, size: proxy.size)
let safeInsets = proxy.safeAreaInsets
let contentTop = usesFullScreenGeometry ? safeInsets.top : 0
let contentBottom = usesFullScreenGeometry ? bounds.height - safeInsets.bottom : bounds.height
```

第二步，只在内容边界内排版：

```swift
let topToolbarHeight: CGFloat = 58
let cameraAreaTop = contentTop + topToolbarHeight + topVerticalGap
let bottomPanelTop = contentBottom - bottomPanelHeight
let promptBottomLimit = bottomPanelTop - bottomVerticalGap
let cameraAreaBottom = promptBottomLimit - promptHeight
```

再计算取景框：

```swift
let cameraAreaHeight = max(260, cameraAreaBottom - cameraAreaTop)
let viewfinderCenterY = cameraAreaTop + cameraAreaHeight * 0.54
```

提示文案：

```swift
let idealPromptY = viewfinderRect.maxY + viewfinderPromptGap + promptHeight / 2
let maxPromptY = promptBottomLimit - promptHeight / 2
promptY = min(idealPromptY, maxPromptY)
```

这样 `safeBottom` 只参与 `contentBottom` 一次。

### 7.5 遮罩 Shape 技术要求

当前 `ExaminationReportCameraOutsideMask`：

```swift
func path(in rect: CGRect) -> Path {
    var path = Path()
    path.addRect(rect)
    path.addRoundedRect(in: cutoutRect, cornerSize: ...)
    return path
}
```

该 Shape 本身是正确的，但前提是：

```text
rect 和 cutoutRect 必须处于同一个坐标系
```

取消 `.ignoresSafeArea()` 后要检查：

1. `rect` 是不是安全区内 ZStack 的大小。
2. `cutoutRect` 是不是也基于同一个 ZStack 计算。
3. 如果 toolbar 是 SwiftUI navigation toolbar，实际可见顶部区域是否属于 ZStack。
4. 如果 navigation bar 背景不在 ZStack 内，遮罩不应试图覆盖 navigation bar。

建议为遮罩增加显式 frame：

```swift
ExaminationReportCameraOutsideMask(...)
    .fill(...)
    .frame(width: proxy.size.width, height: proxy.size.height)
```

不建议通过：

```swift
.ignoresSafeArea()
```

去扩大遮罩范围。

### 7.6 相机输出视图替代写法

原写法：

```swift
createCameraOutputView()
    .ignoresSafeArea()
```

目标写法之一：

```swift
createCameraOutputView()
    .frame(maxWidth: .infinity, maxHeight: .infinity)
    .clipped()
```

如果预览比例导致安全区内有空白，需要从 CameraBridge/Preview 层检查填充模式，而不是在场景层强行忽略安全区。

要求：

1. 相机输出在安全区内铺满。
2. 输出内容可裁切，但不越过安全区。
3. 不出现 `.scaledToFit` 风格的黑边。
4. 不通过全局 `.ignoresSafeArea()` 解决预览填充问题。

### 7.7 底部面板去重规则

底部面板只能选择一种安全区处理方式：

| 方式 | 说明 | 推荐程度 |
| --- | --- | --- |
| `safeAreaInset(edge: .bottom)` | 系统负责把面板放到安全区上方 | 推荐 |
| 内容区域内 bottom aligned | GeometryReader 已是安全区内高度，面板贴内容底部 | 推荐 |
| `panelHeight + safeBottom` | 适合全屏忽略安全区旧方案 | 新方案不推荐 |
| 背景 `.ignoresSafeArea(edges: .bottom)` | 填充 Home Indicator 区域 | 新方案不推荐 |

如果保留 `safeBottom` 参数，也应只用于最小内边距：

```swift
let bottomPadding = max(12, min(safeBottom, 20))
```

而不是：

```swift
height = panelHeight + safeBottom
paddingBottom = max(safeBottom, 16)
background.ignoresSafeArea(edges: .bottom)
```

### 7.8 NutritionFood 特殊注意

`NutritionFoodCameraSceneView` 不是底部面板式页面，而是参考食物拍摄页：

```text
顶部品牌/返回/帮助
中部取景框
底部照片/拍摄/闪光灯
```

取消根级忽略安全区后：

1. 底部绿色拍摄按钮需要整体上移到 Home Indicator 上方。
2. `bottomControls` 不应再通过 `.ignoresSafeArea(edges: .bottom)` 向下扩展。
3. 暗色遮罩需要覆盖安全区内全部背景。
4. 如果顶部 navigation toolbar 仍由 SwiftUI toolbar 承载，背景预览可能从 toolbar 下方开始，需要确认是否符合视觉预期。
5. 若产品仍要求“视觉上全屏相机”，可只让背景层扩展，但可交互控制遵守安全区；但本工单主目标是取消根级忽略安全距离。

1. 安全区边界。
2. `viewfinderRect`。
3. `cameraAreaTop/cameraAreaBottom`。
4. `bottomPanelFrame`。
5. `promptY`。

验收完成后，调试 overlay 默认关闭或删除。

### 7.10 复用风险

五个场景代码结构高度相似，但目前各自有独立布局常量。改造时有两种路径：

| 路径 | 优点 | 风险 |
| --- | --- | --- |
| 分别修五个场景 | 改动局部，风险小 | 容易公式不一致 |
| 抽公共安全区布局 helper | 统一、安全 | 需要更多回归 |

本工单建议第一期至少统一公式和变量命名；是否抽公共 helper 可根据实际代码量决定。

## 11. 与 CAMERA-000004 的关系

`CAMERA-000004` 原先定义：

```text
拍摄实时取景页允许忽略底部安全区
拍摄后预览页必须保留底部安全区
```

本工单对该策略做修正：

```text
拍摄实时取景页也取消根级忽略安全区
预览页继续保留底部安全区
所有遮罩/阴影/底部面板都按安全区重新计算
```

后续实现以 `CAMERA-000005` 为准。
