## 2. 一句话需求

自定义相机已经支持连续拍摄多张图片，但当前聊天和医疗文档上传入口在 `onMediaBatchCaptured` 中只取第一张；需要将批量拍摄结果完整转换为业务附件或上传文件，按拍摄顺序批量回传给调用方。

## 3. 背景与问题

当前 `CustomCameraFullScreenView` 的批量回调签名已经具备多媒体数组能力：

```swift

    onMediaBatchCaptured: { mediaItems in

    },
    onImageCaptured: { image in
        ...
    },
    onVideoCaptured: { url, thumbnail in
        ...
    },
    onDismiss: {
        ...
    }
)
```

## 4. 需求目标

1. `CustomCameraFullScreenView` 的 `onMediaBatchCaptured` 保持批量结果语义。
2. 聊天输入区批量拍摄多张图片后，按拍摄顺序一次性追加多张 `ChatComposerAttachmentPreview`。
3. 医疗文档上传菜单批量拍摄多张图片后，按拍摄顺序一次性生成多份 `MedicalUploadLocalFile` 并回传。
4. 单张拍摄路径 `onImageCaptured` 继续保持现有单张行为。
5. 视频拍摄结果本期不接入聊天附件和医疗文档上传，继续记录日志并关闭相机。
6. 不改变附件上传、OCR、发送、医疗文档识别和文件导入的后续链路。
7. 不引入系统相机回退，不重新使用 `UIImagePickerController` 或 `SystemImagePicker(source: .camera)`。

## 6. 详细需求

### 6.1 聊天输入区批量接入

入口文件：

```text
SparkClient/Projects/Features/Chat/Presentation/Composer/HanlinChatInputView.swift
```

目标行为：

1. 从 `mediaItems` 中提取所有图片：

```swift
let images = mediaItems.compactMap { $0.getImage() }
```

2. 将每张图片转换为 `ChatComposerAttachmentPreview`：

```swift
let attachments = images.compactMap { makeCameraAttachment(from: $0) }
```

3. 如果 `attachments` 非空，一次性调用：

```swift
onAttachmentsPicked(attachments)
```

4. 图片顺序必须与 `mediaItems` 顺序一致。
5. 如果部分图片 JPEG/PNG 编码失败，只跳过失败项，成功项仍需追加。
6. 如果全部转换失败，关闭相机并记录错误日志。
7. 如果当前聊天附件存在数量上限，应按现有上限裁剪，不允许突破既有限制。

建议实现形态：

```swift
private func makeCameraAttachments(from mediaItems: [CustomCameraMedia]) -> [ChatComposerAttachmentPreview] {
    mediaItems
        .compactMap { $0.getImage() }
        .compactMap { makeCameraAttachment(from: $0) }
}
```

### 6.2 医疗文档上传批量接入

入口文件：

```text
SparkClient/Projects/Features/MedicalDocumentUpload/Presentation/MedicalDocumentFilePickerMenu.swift
```

目标行为：

1. 从 `mediaItems` 中提取所有图片。
2. 每张图片调用现有临时文件保存逻辑：

```swift
saveUIImageToTemp(image: image, namePrefix: "camera")
```

3. 成功生成的文件一次性回传：

```swift
onFilesSelected(files)
```

4. 批量数量应遵守 `maxPhotoSelectionCount`。
5. 文件顺序必须与拍摄顺序一致。
6. 部分图片保存失败时，成功项仍需回传，失败项记录日志。
7. 全部保存失败时不调用 `onFilesSelected([])`，只记录错误日志并关闭相机。

建议实现形态：

```swift
private func handleCameraMediaBatch(_ mediaItems: [CustomCameraMedia]) {
    let files = mediaItems
        .compactMap { $0.getImage() }
        .prefix(maxPhotoSelectionCount)
        .compactMap { saveUIImageToTemp(image: $0, namePrefix: "camera") }

    if files.isEmpty == false {
        onFilesSelected(Array(files))
    } else {
        logger.error("自定义相机批量拍摄后未生成可用临时文件。", module: .medical)
    }
}
```

## 7. 兼容策略

1. 保持 `CustomCameraFullScreenView` 现有 API 不变。
2. `onImageCaptured` 和 `onVideoCaptured` 的单项回调继续保留，避免影响其他调用点。
3. `onMediaBatchCaptured` 是多拍确认后的主路径，业务入口不得再只取 `.first`。
4. 聊天和医疗文档上传都只处理图片媒体；视频媒体本期忽略并记录日志。
5. 不回退系统相机。

## 8. 验收标准

### 8.1 聊天输入区

1. 在聊天输入区打开自定义相机。
2. 连续拍摄 3 张图片。
3. 在相机预览页确认。
4. 返回聊天输入区后，应出现 3 个图片附件缩略图。
5. 3 个附件顺序与拍摄顺序一致。
6. 每个附件都进入现有上传/OCR准备流程。
7. 删除其中任意一个附件不影响其他附件。
8. 发送消息时，多张相机图片均随消息提交。

### 8.2 医疗文档上传

1. 在医疗文档上传入口打开自定义相机。
2. 连续拍摄 3 张图片。
3. 在相机预览页确认。
4. 返回上传页面后，应新增 3 个待上传文件。
5. 文件名以 `camera_` 前缀生成，且每张图片有独立临时文件。
6. 上传列表顺序与拍摄顺序一致。
7. 如果 `maxPhotoSelectionCount` 小于拍摄数量，只导入允许数量内的图片。

### 8.3 回归

1. 单张拍照仍只新增 1 个附件或 1 个上传文件。
2. 取消相机不新增任何数据。
3. 拍摄视频后不新增聊天附件或医疗文档文件，并有日志说明本期暂不支持视频导入。
4. 相册多选和文件导入不受影响。
5. 项目 Debug 构建通过。

## 11. 风险与注意事项

1. 批量图片可能导致瞬时内存升高，应避免在闭包内额外复制大图数据。
2. 聊天附件上限必须继续生效，避免批量拍摄绕过 UI 限制。
3. 医疗文档入口 `maxPhotoSelectionCount` 是单次选择上限，不应因为相机多拍被突破。
4. 批量保存临时文件时，部分失败不应导致全部丢失。
5. 如果 `onMediaBatchCaptured` 与 `onImageCaptured` 在某些路径中同时触发，需要避免重复追加同一张图片。

## 12. 完成定义

本工单完成后，用户通过自定义相机连续拍摄多张图片，在聊天输入区和医疗文档上传入口均能看到多张结果，而不是只返回第一张；单张拍摄、取消、视频暂不支持、相册和文件导入行为保持稳定。
