## 2. 背景

SparkClient 当前针对以下六类医疗文档提供定制拍摄能力：

1. 病历。
2. 医疗检查报告。
3. 体检报告。
4. 服药计划。
5. 处方计划/处方单。
6. 药盒。

前五类业务属于“竖版医疗文档连续拍摄”场景。药盒属于“三个固定槽位拍摄”场景，按药盒正面、保质期、说明书组织图片，其中药盒正面和保质期为必拍项。

六类业务虽然底部数据组织不同，但相机页面骨架基本一致，包括相机会话、相机参数、导航栏、引导弹层、预览临时文件、取景框、阴影遮罩、安全区、提示文字、拍摄按钮、完成按钮和防连拍逻辑。当前代码分别维护了四套完整实现：

- `CaseDocumentCameraSceneView`：病历。
- `ExaminationReportCameraSceneView`：医疗检查报告、体检报告。
- `PrescriptionMedicationCameraSceneView`：处方单、服药计划。
- `MedicineBoxCameraSceneView`：药盒固定槽位拍摄。

四套实现中存在大量结构相同、名称不同的代码。例如：

- `CaseDocumentBottomPanelMetrics`
- `ExaminationReportBottomPanelMetrics`
- `PrescriptionMedicationBottomPanelMetrics`
- `MedicineBoxBottomPanelMetrics`

前三个报告类尺寸模型中的 `topPadding`、`rowSpacing`、缩略图尺寸、拍摄按钮尺寸及其他参数完全相同。药盒底部组件使用三个固定槽位，尺寸模型和完成条件与报告列表不同，但其外围页面、拍摄动作和基础组件仍与报告类重复。

继续分别维护会产生以下问题：

- 检查报告页面修复取景框比例后，病历和处方页面不会自动获得修复。
- 安全区、顶部按钮颜色、底部面板圆角等问题需要在多处重复修改。
- 同一交互在不同页面逐渐产生尺寸、颜色和行为差异。
- 新增另一种文档拍摄业务时容易复制整份相机页面，进一步扩大维护成本。
- 三种报告类结果模型字段完全一致，却需要多套保存和转换逻辑。
- 药盒为了保留槽位语义需要独立结果模型，但不应因此复制整套相机页面。

## 3. 需求目标

将病历、医疗检查报告、体检报告、服药计划、处方计划和药盒统一接入一套“医疗文档公共相机场景骨架”。

改造完成后必须满足：

1. 六类业务共用同一个相机会话宿主、基础页面骨架和拍摄生命周期。
2. 六类业务共用同一个参数化取景框布局器和阴影遮罩实现。
3. 报告类共用连续缩略图底部组件，药盒注入固定槽位底部组件。
4. 报告类共用一个连续拍摄结果模型；药盒保留带 `slot` 的结果模型。
5. 报告连续拍摄和药盒槽位拍摄作为两种工作流接入公共场景，不复制外围页面。
6. 顶部导航、相机预览、安全区、遮罩、预览、拍摄按钮和背景形状以检查报告方案为公共基线。
7. 药盒保留正面、保质期、说明书槽位、必拍校验和自动切换槽位能力。
8. 后续调整公共相机页面时只修改公共实现；底部业务差异只修改对应底部组件或工作流。
9. 不影响营养食物等非医疗文档相机场景。

### 8.1 统一视觉参数

六种上下文的公共页面均按检查报告拍摄页面的视觉方案执行：

- 报告类主题色统一为 `Color(uiColor: .systemBlue)`；药盒槽位底部组件可保留 `systemPurple` 业务强调色。
- 取景框线条统一使用白色和圆角端点；线宽由 layout profile 提供，报告类为 `4pt`，药盒为 `5pt`。
- 外围遮罩统一为黑色 `0.38` 透明度。
- 导航栏背景统一使用 `systemBackground`。
- 导航栏按钮和标题统一使用 `label`，避免白底白字。
- 底部面板只保留顶部左右圆角，底部两个角为直角。
- 缩略图序号徽标使用统一主题色。
- 完成按钮启用态使用统一主题色。

业务层不得散落覆盖取景框比例、面板高度或按钮尺寸。报告和药盒的差异必须集中在两个静态 `layoutProfile` 中，由同一个布局器消费。

## 9. 统一场景入口

对业务层保留两个强类型入口，但二者必须组合同一个内部公共宿主：

```swift
ReportDocumentCameraSceneView(
    context: MedicalDocumentCameraContext,
    maxCaptureCount: Int,
    onCancel: @escaping () -> Void,
    onImagesCaptured: @escaping ([ReportDocumentCapturedImage]) -> Void
)

MedicineBoxCameraSceneView(
    onCancel: @escaping () -> Void,
    onImagesCaptured: @escaping ([MedicineBoxCapturedImage]) -> Void
)
```

`ReportDocumentCameraSceneView` 只接受除 `.medicineBox` 之外的报告上下文。`MedicineBoxCameraSceneView` 是药盒业务的强类型适配入口。两者内部必须创建或组合 `MedicalDocumentCameraSceneHost`，不得各自保留完整相机页面。

内部公共 Screen 建议使用泛型或 `@ViewBuilder` 注入底部组件：

```swift
MedicalDocumentCameraScreenShell(
    configuration: configuration,
    prompt: prompt,
    canFinish: canFinish,
    onCapture: onCapture,
    onFinish: onFinish
) {
    bottomPanel
}
```

不得为了注入底部组件在 Common 层使用多个业务 switch 复制整段 ZStack。若使用泛型，应保持具体 View 类型，非必要不使用 `AnyView`。

### 9.1 参数约束

- `maxCaptureCount` 小于 `1` 时，内部按 `1` 处理。
- `onCancel` 只负责通知业务层关闭 `fullScreenCover`，不得返回半成品。
- `onImagesCaptured` 只在用户点击完成且至少存在一张图片时触发。
- 返回数组必须保持拍摄页当前显示顺序。
- 场景内部不得保存上传业务的文件名前缀。
- 药盒入口没有 `maxCaptureCount`，其数量由三个固定槽位定义。

### 9.2 统一结果模型

合并以下三个完全一致的模型：

- `CaseDocumentCapturedImage`
- `ExaminationReportCapturedImage`
- `PrescriptionMedicationCapturedImage`

目标模型：

```swift
struct ReportDocumentCapturedImage: Identifiable, Equatable {
    let id: UUID
    let index: Int
    let image: UIImage
}
```

规则：

- `index` 从 `1` 开始。
- 删除任意图片后，剩余图片按当前数组顺序重新生成连续编号。
- `Equatable` 延续当前行为，以 `id` 和 `index` 判断，不比较 `UIImage` 像素内容。
- 文件保存和命名仍在 `MedicalAttachmentUploadListSheet` 完成。

### 9.3 药盒结果模型

`MedicineBoxCapturedImage` 必须保留，不合并到 `ReportDocumentCapturedImage`：

```swift
struct MedicineBoxCapturedImage: Identifiable, Equatable {
    let id: UUID
    let slot: MedicineBoxCaptureSlot
    let image: UIImage
}
```

原因是药盒结果必须携带 `.front`、`.expiry`、`.instruction` 业务语义，上传文件名也依赖 `slot.fileNameSuffix`。公共宿主通过泛型 Output 或工作流完成回调返回具体类型，不使用丢失类型信息的 `[UIImage]`。

## 10. 统一医疗文档拍摄布局

### 10.1 坐标系统

- `GeometryReader` 使用安全区内可用区域。
- 相机页面根视图不得调用 `.ignoresSafeArea()`。
- 不重复扣除 `proxy.safeAreaInsets.top` 或 `proxy.safeAreaInsets.bottom`。
- 不再额外预留 `topToolbarHeight = 58`，因为导航栏已经位于 GeometryReader 内容区之外。
- 相机预览、遮罩、取景框、提示文字和底部面板必须共用同一个 GeometryReader 坐标系。

### 10.2 参数化布局 Profile

公共布局器只保留一份计算公式，差异通过不可变 profile 输入：

| 参数 | 报告类 Profile | 药盒 Profile |
| --- | --- | --- |
| 底部面板高度 | `clamp(height * 0.24, 196, 252)` | `clamp(height * 0.26, 220, 268)` |
| `promptHeight` | `48` | `52` |
| `topVerticalGap` | `12` | `12` |
| `bottomVerticalGap` | `10` | `8` |
| `viewfinderPromptGap` | `10` | `12` |
| 最小取景比例 | `1.28` | `1.12` |
| 最大取景比例 | `1.414` | `1.24` |
| 遮罩圆角系数 | `0.06` | `0.09` |
| 取景框线宽 | `4` | `5` |

药盒包装通常比 A4 报告更短、更偏横向，因此保留药盒取景比例；差异只存在于 profile 数据，不允许保留第二份 `MedicineBoxViewfinderLayout` 算法。

### 10.3 底部面板高度

```text
bottomPanelHeight = clamp(contentHeight * 0.24, 196, 252)
```

上述示例是报告类 profile。药盒使用 `clamp(contentHeight * 0.26, 220, 268)`。两者都占用安全区内高度，不再额外叠加 `safeBottom`。

### 10.4 取景框可用区域

公共公式从当前 profile 读取参数：

```text
topVerticalGap = profile.topVerticalGap
promptHeight = profile.promptHeight
viewfinderPromptGap = profile.viewfinderPromptGap
bottomVerticalGap = profile.bottomVerticalGap
```

计算关系：

```text
cameraAreaTop = topVerticalGap
bottomPanelTop = contentHeight - bottomPanelHeight
promptBottomLimit = bottomPanelTop - bottomVerticalGap
cameraAreaBottom = promptBottomLimit - promptHeight
cameraAreaHeight = max(0, cameraAreaBottom - cameraAreaTop)
```

### 10.5 舒适拍摄比例

以检查报告已调整后的舒适拍摄区域为统一标准：

```text
preferredWidth = min(max(0, availableWidth - 32), 440)
availableAspect = cameraAreaHeight / preferredWidth
viewfinderAspect = clamp(
    availableAspect,
    profile.minimumAspect,
    profile.maximumAspect
)
viewfinderHeight = min(cameraAreaHeight, preferredWidth * viewfinderAspect)
viewfinderWidth = min(preferredWidth, viewfinderHeight / viewfinderAspect)
```

含义：

- iPhone 上左右优先各保留 `16pt`。
- 宽屏设备最大取景框宽度为 `440pt`，避免 iPad 上无限拉伸。
- 报告类高度充足时使用接近 A4 的 `1:1.414` 竖版比例，高度紧张时最低为 `1:1.28`。
- 药盒根据包装和槽位底部组件空间，在 `1:1.12...1:1.24` 之间适配。
- 不再使用旧方案中的 `availableWidth * 0.88` 和 `cameraAreaHeight * 0.86` 二次缩小。

### 10.6 取景框纵向位置

```text
remainingVerticalSpace = max(0, cameraAreaHeight - viewfinderHeight)
viewfinderTop = cameraAreaTop + remainingVerticalSpace * 0.35
```

取景框在剩余区域中略向上偏，减少顶部空白并为下方提示文字留出稳定空间。

### 10.7 提示文字位置

```text
idealPromptY = viewfinderRect.maxY + viewfinderPromptGap + promptHeight / 2
maxPromptY = promptBottomLimit - promptHeight / 2
promptY = min(idealPromptY, maxPromptY)
```

提示文字不得与取景框或底部面板重叠。

## 11. 遮罩与实际裁剪区域

### 11.1 单一数据源

`viewfinderRect` 必须同时用于：

- 外围阴影镂空区域。
- 四角取景框的位置和尺寸。
- `.cameraCaptureViewfinder()` 标记的实际捕获区域。
- 需要显示的调试边界。

不得为阴影、边框和实际裁剪分别计算 CGRect。

### 11.2 遮罩规则

- Shape 的 `path(in:)` 先添加整个内容区域。
- 再添加 `viewfinderRect` 对应的圆角矩形。
- 使用 `FillStyle(eoFill: true)` 形成镂空。
- 圆角半径统一由 `min(width, height) * profile.maskCornerRadiusFactor` 计算；报告类为 `0.06`，药盒为 `0.09`。
- 遮罩 frame 必须等于 GeometryReader 的 `proxy.size`。

### 11.3 相机预览层

相机预览只填充安全区内内容：

```swift
createCameraOutputView()
    .frame(maxWidth: .infinity, maxHeight: .infinity)
    .clipped()
```

公共场景中不得重新添加 `.ignoresSafeArea()`。

## 12. 可插拔底部拍摄组件

### 12.1 组件结构

公共 Screen 只约定底部组件占据 `layout.bottomPanelHeight`，不感知缩略图的数据结构。两种底部组件均由两行组成：

1. 报告类为横向连续缩略图；药盒为三个固定槽位。
2. 文档类型标题、拍摄按钮、完成按钮。

必须通过泛型 View、`@ViewBuilder` closure 或等价的组合方式注入，禁止在公共 Screen 内复制两套完整 ZStack。

### 12.2 背景形状

- 面板顶部左角和顶部右角半径为 `28pt`。
- 面板底部左角和底部右角必须为 `0`。
- 背景使用 `systemBackground`。
- 不使用四角 `RoundedRectangle`。
- 不通过 `.ignoresSafeArea(edges: .bottom)` 延伸背景。

复用一个公共 Shape，例如 `MedicalDocumentTopRoundedRectangle`。

### 12.3 报告类连续缩略图组件

- 尚未拍摄时展示虚线缩略图占位框。
- 占位图标由 `context.bottomPanelIcon` 提供。
- 边框使用 `separator`，透明度 `0.6`，线宽 `1.5`，dash 为 `[6]`。
- 图片使用 `scaledToFill`。
- 显示页码徽标。
- 右上角显示删除按钮。
- 点击图片打开 Quick Look 预览。
- 删除后列表立即重新编号。
- 缩略图列表超过宽度后允许横向滚动。

### 12.4 药盒固定槽位组件

药盒底部组件保留以下专属行为：

- 固定展示 `.front`、`.expiry`、`.instruction` 三个槽位，不使用横向无限列表。
- 必拍槽位标题保留 `*` 标识。
- 当前 `selectedSlot` 使用紫色边框、紫色标题和浅紫背景表示选中。
- 空槽位显示各自的 `placeholderSystemImage`。
- 已拍槽位显示裁剪缩略图和删除按钮。
- 点击未选中槽位只切换 `selectedSlot`。
- 点击已选中且已有图片的槽位打开预览。
- 拍摄确认后写入当前槽位，并自动前进到下一个未拍槽位。
- 重拍同一槽位时覆盖该槽位图片，不新增第四张图片。

药盒底部组件可以保留独立尺寸模型和紫色业务强调色，但拍摄按钮、完成按钮、删除按钮及面板背景必须调用 Common 层组件，不得复制绘制代码。

### 12.5 公共拍摄按钮

- 外圈使用主题色 `0.35` 透明度。
- 内圈使用主题色实心填充。
- 图标使用 `camera.fill` 和白色前景。
- `isCapturing == true` 时禁用；报告类达到上限时同时禁用，药盒允许选择已有槽位重拍。
- 禁用态透明度为 `0.55`。
- 点击后触发 `.medium` 触感反馈。
- 防连拍时间延续当前 `1.2s`，后续如需调整必须修改公共常量。

### 12.6 公共完成按钮

- 报告类没有图片时为禁用视觉状态，点击后显示对应业务的空结果提示。
- 药盒只有在正面和保质期都已拍摄时才进入启用视觉状态。
- 药盒缺少必拍项时点击完成，按缺失组合提示“药盒正面”“保质期”或两者。
- 存在图片时使用主题色背景。
- 报告类完成后返回当前有序图片数组。
- 药盒完成后按槽位顺序返回 `MedicineBoxCapturedImage` 数组。

## 13. 顶部导航栏

六种场景统一执行：

- 返回按钮：`chevron.left`，`44x44pt` 点击区域。
- 中间标题：使用对应业务 `navigationTitle`。
- 帮助按钮：`questionmark.circle`，`44x44pt` 点击区域。
- 导航栏背景：`systemBackground` 且明确可见。
- 按钮和标题前景色：`Color(uiColor: .label)`。
- 不使用白色按钮或白色标题，避免浅色导航栏不可见。
- 状态栏保持显示。

## 14. 统一引导页与持久化

### 14.1 公共引导页

四套 GuideView 的容器、按钮和展示生命周期应提取为一个 `MedicalDocumentCameraGuideHost`，具体说明内容由报告类或药盒 GuideContent 注入：

- 标题。
- 副标题。
- 业务图标或插图。
- 清晰拍摄提示。
- 报告类显示最大拍摄数量说明；药盒显示三个槽位及必拍项说明。
- 开始拍摄按钮。

### 14.2 引导记录

### 14.3 展示规则

- 首次进入对应场景自动展示引导。

## 15. `MedicalAttachmentUploadListSheet` 接入改造

### 15.1 统一上下文映射

删除以下分散映射：

- `attachmentUploadExaminationReportCameraContext`
- `attachmentUploadPrescriptionMedicationCameraContext`

改为一个统一属性：

```swift
var attachmentUploadMedicalDocumentCameraContext: MedicalDocumentCameraContext?
```

映射规则：

| --- | --- |
| `.caseDocument` | `.caseDocument` |

| `.medicationPlan` | `.medicationPlan` |
| `.prescription` | `.prescription` |
| `.medicineBox` | `.medicineBox` |
| `.auto` | `nil` |

### 15.2 统一 fullScreenCover 路由

`MedicalAttachmentUploadCameraCover` 中以下三个 case：

- `.examinationReportCustomCamera`
- `.prescriptionMedicationCustomCamera(...)`
- `.caseDocumentCustomCamera`

合并为：

```swift
case reportDocumentCustomCamera(MedicalDocumentCameraContext)
```

药盒由于返回强类型槽位结果，保留独立路由 case：

- `.medicineBoxCustomCamera`
- `.systemCamera`

报告类分支只创建一次 `ReportDocumentCameraSceneView`：

```swift
ReportDocumentCameraSceneView(
    context: context,
    maxCaptureCount: min(
        documentKind.attachmentUploadReportCameraMaxCaptureCount,
        remainingFileSlots

```

药盒分支继续创建强类型 `MedicineBoxCameraSceneView`，但该 View 只能是公共 Host 的薄适配入口。需求重点是报告类只保留一段接入逻辑，同时报告与药盒不得各自维护完整相机 Screen。

### 15.4 统一文件保存

所有报告类图片使用同一保存规则：

```text
{fileNamePrefix}_camera_page_{index}_{UUID}.jpg
```

- JPEG 压缩质量继续使用 `0.95`。
- 保存失败的单张图片可跳过，但必须记录 warning 日志。
- 保存成功后统一调用 `appendFiles(files)`。
- 不改变各 `MedicalDocumentKind` 现有 `fileNamePrefix`。

药盒仍按槽位保存：

```text
{fileNamePrefix}_camera_{slot.fileNameSuffix}_{UUID}.jpg
```

药盒文件保存分支可以保留，因为文件名依赖槽位语义；JPEG 编码、错误日志和 `appendFiles` 应调用公共保存辅助方法。

## 16. 兼容与迁移策略

### 16.1 推荐策略

分两阶段迁移：

第一阶段：

- `MedicineBoxCameraSceneView` 改为公共 Host 的强类型适配器，保留药盒工作流和底部槽位组件。

第二阶段：

### 16.2 轻量适配器要求

- 底部面板。

- 预览临时文件处理。

### 16.3 删除目标

- 四套 `ViewfinderLayout` 合并为一个参数化布局器。

- 四套拍摄 Screen 合并为一个公共 ScreenShell。
- 三套报告缩略图列表合并为一套，药盒保留一个槽位组件。

- 四套预览临时文件逻辑。
- 四套相机会话和防连拍外围逻辑。

## 17. 状态与事件流程

```text
业务上传页
  -> 根据 MedicalDocumentKind 生成 MedicalDocumentCameraContext
  -> 报告类打开 ReportDocumentCameraSceneView 薄入口
  -> 药盒打开 MedicineBoxCameraSceneView 薄入口
  -> 两个入口组合同一个 MedicalDocumentCameraSceneHost
  -> 检查引导是否已读
  -> 启动 CustomCamera 会话
  -> 用户拍摄
  -> 默认媒体确认页确认图片
  -> 公共 Host 把图片交给当前 CaptureWorkflow
  -> 报告工作流追加页码图片；药盒工作流写入 selectedSlot
  -> 用户可预览或删除
  -> 用户点击完成
  -> 报告工作流校验至少一张且未超上限
  -> 药盒工作流校验正面与保质期
  -> 返回对应强类型结果数组
  -> 上传页保存为临时 JPEG
  -> appendFiles
  -> 关闭 fullScreenCover
```

### 17.1 取消流程

- 用户点击返回按钮后调用 `onCancel`。
- 不返回当前已拍摄图片。
- 业务层关闭 fullScreenCover。
- 相机会话随页面销毁停止。
- 已创建的 Quick Look 临时文件必须清理。

### 17.2 拍摄上限流程

- `canCaptureMore = capturedImages.count < maxCaptureCount`。
- 达到上限后拍摄按钮禁用。
- 任何绕过禁用态的调用仍需在 `capturePhoto()` 中进行 guard。
- 触发上限提示时使用当前上下文对应文案。

上述上限流程仅适用于报告类。药盒固定为三个槽位，拍摄已有槽位表示覆盖重拍，不使用 `maxCaptureCount`。

## 22. 风险与处理

### 22.1 旧结果类型被其他页面引用

风险：直接删除三个结果模型可能导致未检索到的调用点编译失败。

处理：先全局检索并迁移；必要时提供短期 `typealias` 或轻量转换，但不得复制实现。

### 22.2 引导状态重置

风险：使用新的统一 key 会导致老用户再次看到首次引导。

处理：继续读取现有 key，或首次读取时把旧 key 迁移到新 key。

### 22.3 不同业务文案丢失

风险：合并页面时只保留检查报告文案，处方和服药计划提示不准确。

处理：所有公共展示差异集中进入 `MedicalDocumentCameraContext`，报告和药盒工作流差异分别封装，并为六种上下文建立配置测试。

### 22.4 公共组件过度开放

风险：为兼容每个旧页面暴露大量尺寸参数，最终仍形成多个变体。

处理：公共布局参数默认封闭；业务只提供语义配置。只有真实的新型文档布局才能新增明确的 layout strategy。

### 22.5 相机裁剪与视觉框不一致

风险：抽取组件时遮罩与 `.cameraCaptureViewfinder()` 使用不同坐标空间。

处理：所有相关视图强制使用同一个 `viewfinderRect`，真机拍摄后对比取景框内四边内容。

### 22.6 药盒被错误抽象为普通报告

风险：为了追求单一结果模型，丢失正面、保质期、说明书语义，导致必拍校验和文件命名退化。

处理：公共化的是相机宿主和页面骨架，不是强制统一业务状态。药盒保留独立 CaptureWorkflow、BottomPanel、CaptureSlot 和 CapturedImage。

## 23. 推荐实施顺序

1. 新建 `MedicalDocumentCameraContext`、公共配置和两个 layout profile。
2. 从检查报告页面提取公共 Host、ScreenShell、Layout、Shapes 和 Chrome。
3. 提取报告类 CaptureWorkflow、统一结果模型和连续缩略图 BottomPanel。
4. 将药盒状态提取为 MedicineBoxCaptureWorkflow，并保留槽位 BottomPanel。
5. 让两个工作流接入同一个公共 Host 和 ScreenShell。
6. 合并引导容器、GuideStore 和预览临时文件服务，并兼容旧 key。
7. 在 `MedicalAttachmentUploadListSheet` 增加统一上下文映射，合并报告 cover 分支。
8. 依次迁移检查报告、体检报告、病历、处方单、服药计划和药盒。
9. 删除或降级旧 SceneView 为轻量适配器。
10. 全局检索重复 Layout、Mask、CameraScreen、导航栏和拍摄按钮。
11. 执行编译、两种 profile 布局测试和真机拍摄验收。

## 24. 完成定义

本工单只有在“公共能力真正只有一份”时才算完成。

仅将检查报告的新参数同步复制到病历、处方和药盒文件，不属于完成；仅把常量抽到公共文件但仍保留四套页面、相机会话和导航逻辑，也不属于完成。

最终代码应表现为：六个业务上下文、一个公共相机 Host、一个公共 ScreenShell、一个参数化布局算法、一个公共遮罩与导航实现、两个拍摄工作流、两个底部组件，以及报告结果模型和药盒槽位结果模型。业务差异存在于配置和工作流中，完整相机页面只能存在一份。
