## 工单 `CAMERA-000001`：自定义相机底层模块内嵌与首页入口

### 工单状态

需求设计中。

## 1. 背景

SparkClient 需要新增一个“自定义相机”能力，用于在应用内直接完成拍照、录像、预览和结果确认等操作。当前参考实现位于：

```text
/Users/hua/Downloads/Reference/Camera-main
```

该项目本身是一个独立 Swift Package / Pod 形态的相机库，包名为 `MijickCamera`，其源码主要位于：

```text
Camera-main/Sources
├─ Public
│  ├─ Camera Settings
│  ├─ Models
│  └─ UI
└─ Internal
   ├─ Assets
   ├─ Extensions
   ├─ Manager
   ├─ Models
   ├─ Miscellaneous
   └─ UI
```

本需求明确：不以引入外部包、Swift Package、Pod 或二进制依赖的形式接入 `Camera-main`。需要把 `Camera-main` 的相机所有代码功能完整迁入 SparkClient 项目的一个内部模块内，使其成为 SparkClient 自有模块代码。

该模块的定位不是一次性的首页相机页面，而是 SparkClient 内部的底层相机能力层。首页相机入口只是第一期验证入口；后续医疗档案、饮食营养、报告扫描、头像拍摄等不同业务场景，应基于同一套底层相机能力自定义不同的拍摄界面、控制按钮、结果确认页和业务回调。

## 2. 核心目标

### 第一期目标

1. 在 SparkClient 内新增一个独立的自定义相机底层模块。
2. 将 `Camera-main` 的相机源码、资源和能力尽量完整迁入该模块内维护。
3. 不通过 `Package.swift`、CocoaPods、SPM dependency 或其他包管理方式引用 `Camera-main`。
4. 相机底层能力需与具体业务 UI 解耦，支持后续按 SparkClient 不同拍摄场景自定义相机界面。
5. 首页新增一个“相机”模块入口，作为第一期默认入口和能力验证入口。
6. 点击首页相机模块后，使用 SwiftUI `fullScreenCover` 打开相机首页。
7. 首页相机可先使用默认相机界面，但底层必须支持业务方替换相机页、预览页、错误页和控制区。
8. 相机首页应保留 `Camera-main` 当前默认相机能力：权限处理、拍照、录像、前后摄像头切换、闪光灯、手电筒、网格、手动缩放、手动对焦、拍摄结果预览和确认/取消。
9. 相机模块需能被 SparkClient 后续业务复用，例如饮食拍照、医疗档案拍照、报告拍照、头像/资料拍摄等。

### 第一期边界

1. 本期不做服务端接口改造。
2. 本期不做拍摄结果上传、AI 识别、归档入库等业务闭环。
3. 本期不改造医疗档案、饮食营养、对话等既有拍照入口。
4. 本期不引入新的第三方相机包。
5. 本期不要求重写相机核心能力，优先完整迁移并适配 `Camera-main` 现有能力。
6. 本期不要求一次性完成所有业务场景 UI，只需提供可扩展的底层能力和默认首页入口。
7. 本期不做复杂影像编辑能力，例如裁剪、标注、OCR 框选、美颜、滤镜编辑器。

## 3. 集成方式要求

### 3.1 模块形态

在 SparkClient 内新增内部 Feature 模块，建议目录：

```text
SparkClient/SparkClient/Projects/Features/CustomCamera
├─ Domain
│  ├─ CustomCameraMedia.swift
│  └─ CustomCameraError.swift
├─ Application
│  ├─ CustomCameraConfiguration.swift
│  └─ CustomCameraResultHandler.swift
├─ Infrastructure
│  └─ CustomCameraFileStore.swift
├─ Presentation
│  ├─ Default
│  │  ├─ CustomCameraHomeView.swift
│  │  ├─ CustomCameraPreviewView.swift
│  │  └─ CustomCameraErrorView.swift
│  ├─ Scene
│  │  ├─ CustomCameraScene.swift
│  │  ├─ CustomCameraSceneConfiguration.swift
│  │  └─ CustomCameraSceneResult.swift
│  └─ Components
└─ Internal
   ├─ Core
   ├─ Assets
   ├─ Extensions
   ├─ Manager
   ├─ Models
   └─ UI
```

说明：

1. `Internal/Core` 和 `Internal/Manager` 承载从 `Camera-main` 迁入的底层相机能力，是 SparkClient 内部相机内核。
2. `Presentation/Default` 承载默认相机首页、默认预览页和默认错误页，用于首页入口和通用场景。
3. `Presentation/Scene` 承载场景化相机入口协议/配置，后续不同业务可基于底层能力定制自己的相机界面。
4. `Domain` 定义 SparkClient 内部可复用的媒体结果模型和错误模型。
5. `Application` 定义相机配置、能力开关、拍摄结果回调、业务接入和后续统一处理能力。
6. `Infrastructure` 预留临时文件、图片/视频缓存和后续上传前处理能力。

实际落地时可根据 SparkClient 现有模块风格微调，但必须保持“相机能力属于 SparkClient 内部模块”的原则。

### 3.1.1 分层定位

自定义相机模块需要按“底层能力”和“场景 UI”分层：

```text
SparkClient 业务场景
├─ 首页通用相机
├─ 饮食营养拍食物相机
├─ 医疗档案拍报告相机
├─ 头像/资料拍摄相机
└─ 后续其他拍摄场景

CustomCamera 场景层
├─ 默认相机界面
├─ 食物拍摄界面
├─ 报告扫描界面
└─ 头像拍摄界面

CustomCamera 底层能力层
├─ 权限
├─ AVCaptureSession 管理
├─ 设备切换
├─ 图片输出
├─ 视频输出
├─ 对焦/曝光/缩放
├─ 闪光灯/手电筒
├─ 方向/镜像
├─ 滤镜/预览
└─ 媒体结果生成
```

要求：

1. 业务场景不直接操作 `AVCaptureSession`，统一通过 `CustomCamera` 底层能力访问。
2. 业务场景可以选择默认相机界面，也可以提供自己的 SwiftUI 相机界面。
3. 不同场景可以配置拍摄模式，例如只拍照、只录像、拍照+录像、是否允许切换摄像头、是否展示网格、是否展示闪光灯。
4. 不同场景可以配置结果处理方式，例如确认后关闭、确认后进入上传、确认后进入 AI 识别、确认后进入裁剪。
5. 底层能力迁入后应尽量保持完整，不因第一期只做首页入口而删除 `Camera-main` 中未来可能复用的能力。

## 5. 相机首页需求

### 5.1 页面定位

相机首页是自定义相机模块的默认主入口页，负责承载相机实时预览、拍摄控制、模式切换和拍摄结果进入预览。

第一期首页入口可复用 `Camera-main` 默认相机页能力作为基础，后续再根据 SparkClient 视觉体系做品牌化改造。

需要特别说明：默认相机首页不是底层相机能力的唯一表现形式。`CustomCamera` 应允许不同业务场景基于同一套相机内核创建不同的 SwiftUI 页面，例如：

| 场景 | 自定义方向 |
| --- | --- |
| 首页通用相机 | 保留默认拍照/录像完整控制 |
| 饮食营养拍食物 | 默认只拍照，可突出“确认识别”“重拍” |
| 医疗档案拍报告 | 默认只拍照，可突出边缘对齐、连续拍摄、下一步上传 |
| 头像拍摄 | 默认前置相机，可显示头像取景框 |
| 对话附件拍摄 | 可弱化复杂控制，强调快速拍摄和发送 |

### 5.2 必备能力

| 能力 | 要求 |

| 拍照 | 支持拍摄图片 |
| 录像 | 支持录制视频，可保留原库有声/无声能力 |

| 闪光灯 | 支持拍照闪光灯开关/自动能力 |
| 手电筒 | 支持常亮补光 |
| 网格 | 支持辅助网格开关 |

### 5.3 拍摄结果

拍摄结果需要抽象为 SparkClient 内部统一模型，至少包含：

| 字段 | 说明 |
| --- | --- |
| 媒体类型 | 图片或视频 |
| 本地 URL / 临时路径 | 视频文件或图片临时文件路径 |
| 图片对象 | 图片拍摄结果可提供 `UIImage` 或等价表示 |

| 元信息 | 可选：尺寸、时长、方向、文件大小 |

### 5.4 场景化自定义要求

为方便后续不同拍摄场景自定义不同相机界面，底层相机模块需要支持以下可配置能力：

| 配置项 | 说明 |
| --- | --- |

| 交互能力 | 是否允许缩放、点击对焦、曝光调节、滤镜 |
| 结果页面 | 使用默认预览页或业务自定义预览页 |

## 9. 非功能需求

### 9.1 性能

1. 相机预览启动应尽量快速，避免首页点击后长时间黑屏。
2. 拍照完成后预览页应稳定展示，不应出现明显卡顿。
3. 录像时应避免主线程阻塞。
4. 退出相机后应释放相机会话，避免后台继续占用摄像头。

### 9.2 稳定性

1. 多次打开/关闭相机不应崩溃。
2. 进入相机后切后台再回前台，相机会话应可恢复或给出明确错误。
3. 无摄像头设备、模拟器、权限拒绝等场景不应崩溃。
4. 拍摄过程中横竖屏、设备方向变化应保持结果方向正确。

### 9.3 隐私与安全

1. 未经用户确认的拍摄结果不应进入业务数据。
2. 临时文件应有清理策略，避免长期占用存储。
3. 权限文案需说明相机/麦克风用途。
4. 不应自动上传拍摄内容。
