## 2. 一句话需求

将 `DefaultCustomCapturedMediaScreen` 中已经具备的高质量图片查看能力抽取为相机外也能使用的公共全屏预览页，同时保留一层相机专用适配，确保现有“拍摄—预览—继续拍摄/编辑—确认”全流程不受影响；第一阶段在聊天输入区用该公共页面替代图片场景下的 `unifiedFilePreview`，仅开放不可编辑模式。

## 3. 背景与问题

### 3.1 当前相机预览能力较完整，但被相机上下文锁定

当前参考实现位于：

```text
/Users/hua/Downloads/Reference/SupportClient/SupportClient/Projects/Features/SecondCamera/CustomCamera/Presentation/Default/CapturedMedia/DefaultCustomCapturedMediaScreen.swift
```

SparkClient 内对应实现位于：

```text
/Users/hua/Downloads/Reference/SparkClient/SparkClient/Projects/Features/CustomCamera/CustomCamera/Presentation/Default/CapturedMedia/DefaultCustomCapturedMediaScreen.swift
```

该页面已经提供：

1. 单图缩放和平移。
2. 多图缩略图轨道与选中项切换。
3. 图片编辑、裁剪、输出质量切换和保存。
4. 继续拍摄和从相册追加。
5. 删除已拍媒体。
6. 接受媒体并回传相机结果。
7. 视频播放。

但其初始化方式只有：

```swift

```

并且直接依赖：

- `SecondCameraMultiCaptureStore`。
- `Namespace.ID`。
- `discardAction`。
- `continueCaptureAction`。
- `acceptMediaAction`。
- `CustomCapturedMediaScreen` 协议。
- 相机 manager 持有的多图队列生命周期。

因此聊天、医疗档案、Markdown 等普通业务页面不能安全地直接创建该页面。强行构造空的相机动作会让公共预览与相机状态机耦合，并可能误触发清空队列、继续拍摄或结果确认。

### 3.2 当前统一文件预览不符合目标图片预览体验

聊天输入区当前使用：

```swift

    isPresented: $showUnifiedFilePreview,
    inputs: composerDraft.attachments.map(\.previewInput),
    startIndex: unifiedFilePreviewStartIndex

```

对应代码位置：

```text
/Users/hua/Downloads/Reference/SparkClient/SparkClient/Projects/Features/Chat/Presentation/Composer/HanlinChatInputView.swift
```

`unifiedFilePreview` 当前通过 `.sheet` 展示 `UnifiedFilePreview`，内部主要使用 `QLPreviewController`。它适合 PDF 和普通文件，但图片查看体验、页面视觉和自定义相机的拍摄后预览不一致，也无法平滑承接后续图片编辑能力。

### 3.3 不能直接删除 Quick Look 能力

`ChatComposerAttachmentPreview` 支持：

- 图片。
- PDF。
- 普通文件。

因此“替代 `unifiedFilePreview`”不能解释为删除所有 Quick Look 预览。公共图片预览页只负责可解码图片；PDF、普通文件、无法解码的图片和不支持的媒体仍需保留 Quick Look 或错误兜底，否则会形成已有能力回退。

## 4. 需求目标

### 4.1 核心目标

1. 将拍摄后图片预览的通用展示能力与相机业务动作解耦。
2. 保留 `DefaultCustomCapturedMediaScreen` 作为相机拍摄后预览入口，现有相机调用方式不变或保持源码兼容。
3. 提供可从任意 SwiftUI 页面全屏弹出的公共图片预览入口。
4. 公共入口支持明确的“允许编辑”和“不允许编辑”两种能力模式。
5. 第一阶段只实现并接入“不允许编辑”模式。
6. 第一阶段在 `HanlinChatInputView` 中替代图片附件的 `unifiedFilePreview` 展示效果。
7. 图片以 `fullScreenCover` 全屏展示，不再以普通 `.sheet` 展示。
8. 非图片附件继续使用 Quick Look，不降低 PDF 和文件预览能力。
9. 相机原有拍摄、继续拍摄、相册追加、删除、编辑、裁剪、质量选择、保存和确认回传流程保持不变。

### 4.2 产品结果

完成第一阶段后：

- 用户在聊天输入区点击图片附件，会进入与自定义相机风格一致的全屏图片预览页。
- 用户可以查看当前图片、缩放、平移，并在多张图片之间切换。
- 用户只能关闭预览，不能编辑、裁剪、调整质量、保存副本、删除附件、追加图片或进入相机。
- 用户点击 PDF 或其他文件时，仍能继续通过 Quick Look 预览。
- 用户完成相机拍摄后，原有预览确认流程无行为变化。

## 6. 用户故事

### 6.1 聊天图片只读预览

作为聊天用户，我希望点击尚未发送的图片附件后全屏查看图片，以便在发送前确认图片内容和顺序，但不会误修改附件。

验收条件：

- 点击第 N 张图片后，从第 N 张开始展示。
- 页面支持缩放和平移。
- 多图时可切换到其他图片。
- 页面有明确关闭入口。
- 页面不显示任何编辑或数据变更操作。
- 关闭后聊天草稿、附件顺序和上传状态不变。

### 6.2 非图片附件继续预览

作为聊天用户，我希望 PDF 或其他文件仍然可以打开，以便公共图片预览改造不会破坏文件附件能力。

验收条件：

- 点击 PDF 时仍进入 Quick Look。
- 点击普通文件时仍按当前支持能力进入 Quick Look 或错误态。
- 非图片不进入图片编辑体系。

### 6.3 相机拍摄后预览保持不变

作为拍摄用户，我希望公共化改造后仍可以继续拍摄、追加相册图片、编辑、裁剪、删除和确认，以便既有拍摄任务不受影响。

验收条件：

- 相机上下文仍持有原有 `SecondCameraMultiCaptureStore`。
- 继续拍摄不会丢失已有队列。
- 接受媒体时仍输出编辑后的最终结果。
- 删除最后一项时仍按现有流程退出或回到相机。

## 7. 交互设计

### 7.1 公共只读图片预览

页面结构：

```text
全屏背景
├── 顶部关闭按钮
├── 中部图片预览区
│   ├── 等比适配
│   ├── 双指缩放
│   └── 拖动查看
└── 底部缩略图轨道（多图时展示；单图可隐藏）
```

行为要求：

1. 使用 `fullScreenCover` 展示。
2. 关闭按钮只关闭当前预览，不修改输入集合。
3. 单图默认按完整图片等比适配。
4. 切换图片后缩放状态按现有 UIKit 图片预览规则重置。
5. 多图轨道只提供选择，不显示删除按钮和“添加更多”。
6. 不显示相机预览页当前底部的编辑、裁剪、质量、保存和确认按钮。
7. 不显示继续拍摄或相册追加入口。
8. 背景、安全区和图片圆角尽量复用相机预览的视觉基线。

### 7.2 相机预览模式

相机模式 UI 和行为保持当前实现：

- 左上角放弃/返回动作。
- 底部多图轨道。
- 继续拍摄。
- 相册追加。
- 删除。
- 编辑。
- 裁剪。
- 质量选择。
- 保存副本。
- 确认并回传。

公共化不能把相机模式降级成只读模式。

### 7.3 编辑能力模式定义

建议使用枚举，不使用多个容易冲突的 Bool。第一阶段的内部模式为：

```swift
enum SecondCameraMediaPreviewMode: Equatable, Sendable {
    case readOnly
    case cameraEditable
}
```

其中 `.cameraEditable` 只服务现有相机流程；普通业务调用方第一阶段只能通过只读构造方法进入 `.readOnly`。第二阶段完成编辑结果协议后，再新增公共 `.editable`，不得以空实现方式提前开放。

## 8. 推荐技术方案

### 8.1 总体原则

不要让聊天页伪造 `SecondCameraCapturedMediaContext`，也不要把相机专用动作改成全局可选闭包后在页面内部到处判空。

推荐拆分为三层：

```text
业务展示入口
├── DefaultCustomCapturedMediaScreen（相机适配层）
└── SecondCameraPublicMediaPreview（公共全屏入口）
                    │
                    ▼
SecondCameraMediaPreviewContent（公共展示内核）
                    │
                    ▼
预览会话状态 / 图片加载器 / UIKit 缩放预览
```

职责说明：

1. `SecondCameraMediaPreviewContent`：只负责渲染当前媒体、缩放、选中切换、工具区组合和错误态。
2. `DefaultCustomCapturedMediaScreen`：继续接收 `SecondCameraCapturedMediaContext`，注入相机动作和可变队列。
3. `SecondCameraPublicMediaPreview`：接收公共输入、选中项 ID 和关闭动作，第一阶段固定为只读，不接触相机 manager。
4. 文件类型路由层：图片进入公共预览，非图片进入 Quick Look。

### 8.2 为什么不直接复用整个 `DefaultCustomCapturedMediaScreen`

当前页面同时承担“内容展示”和“相机工作流编排”。直接暴露会产生以下风险：

- 公共页面可以误调用 `discardAction` 清空相机队列。
- 公共页面必须创建没有业务含义的 `continueCaptureAction`。
- 公共预览关闭动作与相机接受媒体动作语义混淆。
- 相机 store 的最大数量、来源类型和编辑状态泄漏到 Core UI。
- 后续公共编辑结果无法定义清晰的数据所有权。

因此工单所称“让 `DefaultCustomCapturedMediaScreen` 支持扩展为公共预览”是指复用其预览内核和编辑基础设施，并保留它作为相机适配入口，不要求把现有相机页面原样暴露给所有模块。

## 9. 公共 API 设计建议

### 9.1 公共预览输入

第一阶段继续接受现有 `FilePreviewInput`，减少聊天业务转换成本。公共构造方法固定为只读，不暴露尚未完成的编辑参数：

```swift
struct SecondCameraPublicMediaPreview: View {
    let inputs: [FilePreviewInput]
    let selectedID: UUID?
    let onClose: () -> Void
}
```

约束：

1. 公共图片页面只消费 `FilePreviewInput.isImage == true` 的项目。
2. `id` 必须沿用 `FilePreviewInput.id`，不得重新生成 UUID，否则选中态会漂移。
3. 调用方必须在类型路由前保存原始点击项身份，并传入 `selectedID`，不能仅依赖过滤后的整数索引。
4. URL 不可用或解码失败时展示错误态，不崩溃、不越界。

### 9.2 建议使用选中 ID，而不是只使用索引

现有调用使用 `startIndex`。当附件数组包含图片和 PDF 时，过滤图片会改变索引：

```text
原数组：[图片 A, PDF B, 图片 C]
点击图片 C 的原索引：2
过滤后图片数组：[图片 A, 图片 C]
图片 C 的新索引：1
```

建议路由内部先得到：

```swift
let selectedID = inputs[safe: startIndex]?.id
```

再在目标数组中通过 ID 计算目标索引。不能把原始 `startIndex` 直接传给过滤后的图片列表。

### 9.3 View 便捷入口

建议新增语义清晰的全屏 modifier：

```swift
extension View {
    func secondCameraMediaPreview(
        isPresented: Binding<Bool>,
        inputs: [FilePreviewInput],
        selectedID: UUID? = nil,
        onDismiss: (() -> Void)? = nil
    ) -> some View
}
```

内部使用：

```swift
fullScreenCover(isPresented: isPresented, onDismiss: onDismiss) {
    SecondCameraPublicMediaPreview(...)
}
```

第一阶段不得修改现有 `unifiedFilePreview` 的全局语义，避免其他调用点在无评审的情况下全部从 sheet 变为全屏。

### 9.4 类型路由

推荐聊天接入维护一个路由状态，而不是同时竞争两个 `isPresented`：

```swift
enum ChatAttachmentPreviewRoute: Identifiable {
    case images(inputs: [FilePreviewInput], selectedID: UUID)
    case quickLook(inputs: [FilePreviewInput], startIndex: Int)
}
```

如果为了减少改动继续使用两个 Bool，也必须保证一次点击只激活一个 presentation，并在关闭后清理另一条路由状态。

建议行为：

| 点击项 | 目标预览 |
| --- | --- |
| 本地可用图片 | 公共只读图片预览，全屏 |
| PDF | 现有 Quick Look |
| 普通文件 | 现有 Quick Look |
| URL 失效 | 对应预览的错误态 |
| MIME/UTType 不明确但扩展名为图片 | 由 `inferredUTType` 判断；解码失败进入错误态 |

## 10. 状态模型改造

### 10.1 相机 store 不应直接成为所有公共预览的唯一输入模型

`SecondCameraMultiCaptureStore` 当前包含相机专用语义：

- 最大数量固定为 10。
- `appendCamera`。
- `appendLibrary`。
- `remainingCapacity`。
- `CustomCameraMedia`。
- 每项编辑会话和输出质量状态。

公共只读预览不需要以上大部分能力。最终推荐采用“无状态公共渲染组件 + 两个明确 Store 适配器”，不把 `ObservableObject` 协议 existential 直接注入 SwiftUI：

```text
DefaultCustomCapturedMediaScreen
└── @ObservedObject SecondCameraMultiCaptureStore
    └── SecondCameraMediaPreviewViewport（无状态渲染）

SecondCameraPublicMediaPreview
└── @StateObject SecondCameraReadOnlyPreviewStore
    └── SecondCameraMediaPreviewViewport（无状态渲染）
```

这样处理的原因：

1. `@ObservedObject` 最稳定的使用方式是持有明确的具体类型或泛型类型；直接使用带 `ObservableObject` 的协议 existential 会引入 associated type、发布机制和类型擦除问题。
2. 相机 Store 继续作为相机队列唯一事实源，不需要复制或双向同步。
3. 公共只读 Store 只公开选择和加载能力，类型层面没有追加、删除、清空和确认 API。
4. 真正复用的是图片视口、加载态、错误态、缩略图 Cell 和布局规则，而不是强行让两个业务共享同一个可变 Store。

不推荐给 `SecondCameraMultiCaptureStore` 增加公共只读初始化。该做法虽然改动较少，但公共调用方仍能获得相机写操作，能力边界只能依赖 UI 隐藏，无法从类型系统保证只读。

### 10.2 输入快照

公共预览打开时应创建一份稳定输入快照，避免 `body` 每次刷新都重新执行：

```swift
composerDraft.attachments.map(\.previewInput)
```

原因：

1. `previewInput` 当前会把 `Data` 写入临时目录。
2. 在 SwiftUI 重算中重复调用可能产生重复磁盘写入。
3. 预览期间附件数组变化会导致索引漂移。

要求：

- 点击缩略图时一次性构造 `[FilePreviewInput]` 快照。
- 将快照存入预览路由状态。
- 关闭后释放路由状态。
- 临时文件生命周期继续由附件草稿或专门文件管理器负责，预览页不应擅自删除仍可能被发送流程使用的文件。

## 11. 图片加载与内存要求

### 11.1 不要在主线程批量解码所有原图

`SecondCameraPreviewItem` 当前持有多个 `UIImage` 和缩略图。若聊天一次预览多张高像素图片，打开时同步创建所有原图会造成：

- 主线程卡顿。
- 瞬时内存上升。
- 大图解码导致页面打开延迟。

第一阶段要求：

1. 当前选中图片优先加载。
2. 相邻图片可预取缩略图，但不要一次性完整解码全部原图。
3. 缩略图使用降采样，不使用原图直接缩小显示。
4. 图片解码在后台执行，UI 状态回写在 `MainActor`。
5. 离开页面后取消未完成的加载任务。
6. 收到内存警告时释放非当前项的大图缓存。

### 11.2 图片方向与色彩

公共页必须保持：

- EXIF 方向正确。
- 不因生成缩略图而旋转。
- 广色域图片不出现明显色偏。
- 透明 PNG 背景可辨识。
- 超长图仍可完整缩放查看。

### 11.3 安全访问 URL

若未来接入 security-scoped URL，应在业务导入阶段完成文件复制或访问授权管理。公共预览页不长期持有 `startAccessingSecurityScopedResource()`；它只消费已经可访问的本地 URL。

## 12. 相机流程兼容要求

### 12.1 初始化兼容

以下调用必须保持可用：


## 16. 错误与边界处理

### 16.1 空输入

- 不展示空白全屏页。
- 如果 presentation 已触发但输入为空，显示“没有可预览的图片”并提供关闭按钮。
- 不发生数组越界。

### 16.2 起始索引越界

- 小于 0 时回退到第一项。
- 大于等于数量时回退到最后一项或第一项，策略必须统一。
- 推荐优先使用选中 ID；找不到 ID 时回退第一项。

### 16.3 文件不存在

- 展示与当前 `UnifiedFilePreview` 等价的不可用错误态。
- 错误态保留关闭按钮。
- 不自动删除输入 URL。

### 16.4 图片解码失败

- 展示“图片无法加载”。
- 多图时允许继续切换其他可用图片。
- 日志记录文件扩展名、UTType 和错误类型，不记录图片二进制内容或敏感路径全文。

### 16.5 预览期间附件变化

- 当前展示使用打开时快照，不随外部草稿实时增删。
- 关闭后重新打开时读取最新附件。
- 不在预览页内修改聊天草稿。

### 16.6 重复点击

- presentation 期间忽略新的缩略图打开请求，或先关闭后切换路由。
- 不允许同时弹出公共图片预览和 Quick Look。

## 17. 安全区、方向和系统兼容

1. 公共页背景可铺满屏幕，但关闭按钮和底部轨道必须遵守安全区。
2. Home Indicator 不得遮挡关闭或轨道操作。
3. iPhone 刘海、Dynamic Island 和普通屏幕均需验证。
4. 公共页不应擅自锁定设备方向；按 SparkClient 当前方向策略展示。
5. 以 SparkClient 实际 deployment target 为准。当前工程配置主要为 iOS 16.0；若产品仍要求独立支持 iOS 15，必须先确认对应 target/configuration，再补充兼容实现和真机验收，不能仅凭历史文档宣称支持。
6. `fullScreenCover` 关闭后焦点和聊天输入栏状态应正常恢复。

### 18.1 无障碍

- 关闭按钮提供明确的 accessibility label。

## 28. 建议数据类型完整定义

### 28.1 模式定义

```swift
enum SecondCameraMediaPreviewMode: Equatable, Sendable {
    case readOnly
    case cameraEditable
}
```

说明：

1. `.readOnly` 供公共预览使用。
2. `.cameraEditable` 只由 `DefaultCustomCapturedMediaScreen` 使用。
3. 第一阶段不提供公共 `.editable` 构造方法，避免调用方误以为已经支持编辑结果回传。
4. 第二阶段设计完成后，再将 `.cameraEditable` 收敛为带 capability/result handler 的通用 `.editable`。

### 28.2 公共显示项

公共 Viewport 不应直接依赖 `SecondCameraPreviewItem`，建议增加轻量显示模型：

```swift
struct SecondCameraMediaPreviewDisplayItem: Identifiable {
    let id: UUID
    let title: String?
    let revision: Int
    let thumbnail: UIImage?
    let content: Content

    enum Content {
        case idle
        case loading
        case image(UIImage)
        case video(URL)
        case failure(SecondCameraMediaPreviewLoadError)
    }

    var imageIdentity: String {
        "\(id.uuidString)-\(revision)"
    }
}
```

实现注意：

- 不要求该类型自动合成 `Equatable`，因为 `UIImage` 不适合参与值比较。
- SwiftUI 刷新依据 `id + revision`，不要比较图片二进制内容。
- 相机编辑、裁剪或质量变化后继续 bump `revision`。
- 公共只读图片首次加载完成时至少 bump 一次 revision，确保 UIKit bridge 收到新 identity。

### 28.3 只读输入项

```swift
struct SecondCameraReadOnlyPreviewItem: Identifiable {
    let id: UUID
    let fileURL: URL
    let displayName: String
    let inferredUTType: UTType?

    var thumbnail: UIImage?
    var image: UIImage?
    var revision: Int = 0
    var loadState: LoadState = .idle
}

enum LoadState: Equatable {
    case idle
    case loading
    case loaded
    case failed(SecondCameraMediaPreviewLoadError)
}
```

`FilePreviewInput` 到该类型的映射必须保留：

- `id`。
- `fileURL`。
- `resolvedDisplayName`。
- `inferredUTType`。

不得把源 `FilePreviewInput.id` 替换成新 UUID。

### 28.4 加载错误

```swift

    case fileMissing
    case unsupportedType
    case cannotCreateImageSource
    case cannotDecodeImage
    case cancelled

```

## 29. SecondCameraReadOnlyPreviewStore 详细设计

### 29.1 类型职责

```swift
@MainActor
final class SecondCameraReadOnlyPreviewStore: ObservableObject {
    @Published private(set) var items: [SecondCameraReadOnlyPreviewItem]
    @Published private(set) var selectedID: UUID?

    private let loader: any SecondCameraPreviewImageLoading
    private var loadTasks: [UUID: Task<Void, Never>] = [:]

    init(
        inputs: [FilePreviewInput],
        selectedID: UUID?,
        loader: any SecondCameraPreviewImageLoading
    )

    var selectedItem: SecondCameraReadOnlyPreviewItem? { get }
    func select(id: UUID)
    func loadSelectedIfNeeded()
    func prefetchNeighbors()
    func cancelOutstandingLoads()
}
```

Store 只允许：

- 读取项目。
- 改变当前选择。
- 加载当前图片。
- 预取相邻缩略图。
- 取消加载。

Store 不得提供：

- `append`。
- `remove`。
- `clear`。
- `replaceImage`。
- `accept`。
- `save`。

### 29.2 初始化规则

初始化顺序：

1. 过滤 `isImage == true` 的输入。
2. 按原输入顺序生成只读项目。
3. 如果传入的 `selectedID` 存在于过滤结果中，选择该项目。
4. 如果找不到 `selectedID`，选择第一项。
5. 如果过滤后为空，`selectedID = nil`。
6. 初始化阶段不在主线程同步解码原图。

### 29.3 选择行为

```swift
func select(id: UUID) {
    guard items.contains(where: { $0.id == id }) else { return }
    selectedID = id
    loadSelectedIfNeeded()
    prefetchNeighbors()
}
```

约束：

- 重复选择同一 ID 不重复启动完整解码。
- 选择新项目时可以取消距离当前选择超过 1 的完整图加载。
- 相邻项只预取缩略图，不能默认完整解码。

### 29.4 销毁行为

`SecondCameraPublicMediaPreview.onDisappear` 必须调用：

```swift
store.cancelOutstandingLoads()
```

任务闭包必须弱引用 Store 或在取消后及时结束，避免 `Task -> Store -> Task` 循环。

## 30. 图片加载器详细设计

### 30.1 协议

```swift
protocol SecondCameraPreviewImageLoading {
    func loadPreviewImage(from url: URL, maxPixelSize: CGFloat) async throws -> UIImage
    func loadThumbnail(from url: URL, maxPixelSize: CGFloat) async throws -> UIImage
}
```

测试中注入 fake loader，避免单元测试依赖真实大图解码。

当前工程使用 Swift 5 编译设置。若后续启用 Swift 6 strict concurrency，`UIImage` 不是天然 `Sendable`，不能简单给协议补 `Sendable` 了事；届时应让后台解码层返回受控的 `CGImage`/不可变结果包装，并在 MainActor 构造或接管 UIKit 对象，或对经过审计的不可变包装显式承担 `@unchecked Sendable` 责任。

### 30.2 ImageIO 实现

推荐复用工程已有的 ImageIO 降采样思路。核心参数：

```swift
let sourceOptions: CFDictionary = [
    kCGImageSourceShouldCache: false
] as CFDictionary

let thumbnailOptions: CFDictionary = [
    kCGImageSourceCreateThumbnailFromImageAlways: true,
    kCGImageSourceCreateThumbnailWithTransform: true,
    kCGImageSourceShouldCacheImmediately: true,
    kCGImageSourceThumbnailMaxPixelSize: maxPixelSize
] as CFDictionary
```

实现步骤：

1. 先检查 `url.isFileURL` 和 `FileManager.fileExists`。
2. 使用 `CGImageSourceCreateWithURL` 创建 source。
3. 从 source properties 读取像素宽高，不先创建完整 `UIImage`。
4. 按目标用途计算 `maxPixelSize`。
5. 使用 `CGImageSourceCreateThumbnailAtIndex` 解码并自动应用 EXIF 方向。
6. 在后台任务中创建 `CGImage`。
7. 在返回前检查 `Task.isCancelled`。
8. 最终构造 `UIImage(cgImage:scale:orientation:)`。

### 30.3 尺寸策略

建议初始参数：

| 用途 | 最大像素边建议 |
| --- | --- |
| 缩略图轨道 | `160 * UIScreen.main.scale` |
| 当前大图预览 | `min(max(viewportPixelWidth, viewportPixelHeight) * 3, 8192)` |
| 相邻项预取 | 只加载缩略图 |

说明：

- `8192` 是第一阶段保护上限，不是输出图片限制。
- 公共只读预览不会修改源文件，降采样只影响屏幕显示缓存。
- 如果 3 倍视口不足以满足 5 倍缩放清晰度，应通过性能测试调整，而不是无条件加载原始 48MP 图片。

### 30.4 缓存键

缓存键至少包含：

```text
标准化 URL + 文件修改时间 + 目标 maxPixelSize
```

仅使用 URL 作为 key 会在同路径文件被覆盖后读到旧图片。

### 30.5 缓存边界

1. 缩略图和大图使用不同缓存。
2. 大图缓存设置 `totalCostLimit`，cost 使用近似字节数：`width * height * 4`。
3. 内存警告时清空非当前大图缓存。
4. 预览关闭后可以保留有限缩略图缓存，但不得由单次会话永久持有所有大图。
5. 不把 `UIImage` 写入磁盘二次缓存；源文件本身已经是磁盘缓存。

## 31. 公共 Viewport 详细设计

### 31.1 输入必须是渲染状态，不持有业务 Store

### 31.2 状态渲染

| --- | --- |

- 选择了另一项。
- 同一项从缩略图升级为大图。
- 相机同一项编辑后刷新。
- 相机同一项裁剪或质量变化后刷新。

## 33. HanlinChatInputView 参考接入骨架

### 33.1 路由数据

```swift
private enum ChatAttachmentPreviewRoute: Identifiable {
    struct ImageRequest: Identifiable {
        let id = UUID()
        let inputs: [FilePreviewInput]
        let selectedID: UUID
    }

    struct QuickLookRequest: Identifiable {
        let id = UUID()
        let inputs: [FilePreviewInput]
        let startIndex: Int
    }

    case images(ImageRequest)
    case quickLook(QuickLookRequest)

    var id: UUID {
        switch self {
        case .images(let request): request.id
        case .quickLook(let request): request.id
        }
    }
}
```

`request.id` 表示一次 presentation 会话；附件 ID 继续由 `FilePreviewInput.id` 表示，两者不能混用。

### 33.2 状态

```swift
@State private var attachmentPreviewRoute: ChatAttachmentPreviewRoute?
```

删除：

```swift
@State private var showUnifiedFilePreview = false
@State private var unifiedFilePreviewStartIndex = 0
```

### 33.3 点击处理

```swift
private func openAttachmentPreview(
    attachmentID: UUID,
    attachments: [ChatComposerAttachmentPreview]
) {
    let inputs = attachments.map(\.previewInput)
    guard let tappedIndex = inputs.firstIndex(where: { $0.id == attachmentID }) else {
        return
    }

    let tapped = inputs[tappedIndex]
    if tapped.isImage {
        let imageInputs = inputs.filter(\.isImage)
        guard imageInputs.contains(where: { $0.id == tapped.id }) else { return }
        attachmentPreviewRoute = .images(
            .init(inputs: imageInputs, selectedID: tapped.id)
        )
    } else {
        attachmentPreviewRoute = .quickLook(
            .init(inputs: inputs, startIndex: tappedIndex)
        )
    }
}
```

这里故意将 `selectedID` 传给图片预览，而不是把 `tappedIndex` 传给过滤后的数组。

### 33.4 两种 presentation 样式绑定

由于图片要求全屏、Quick Look 需要保持现有 sheet，可以从单一 route 派生两个 Binding：

```swift
private var imagePreviewRequestBinding: Binding<ChatAttachmentPreviewRoute.ImageRequest?> {

            return request

}

private var quickLookRequestBinding: Binding<ChatAttachmentPreviewRoute.QuickLookRequest?> {
    Binding(
        get: {
            guard case .quickLook(let request) = attachmentPreviewRoute else { return nil }
            return request
        },
        set: { request in
            if request == nil { attachmentPreviewRoute = nil }
        }
    )
}
```


注意：SwiftUI presentation 的 `item` 必须具有稳定身份。不要在 `body` 内每次创建新的 request UUID。

## 34. 临时文件生成与所有权

### 34.1 当前问题

`ChatComposerAttachmentPreview.previewInput` 是计算属性，访问时会把 `data` 原子写入 temporary directory。以下代码会为所有附件触发文件物化：

```swift
composerDraft.attachments.map(\.previewInput)
```

如果它直接出现在 SwiftUI `body` 或 modifier 参数中，任何 body 重算都可能重复执行磁盘写入。

### 34.2 第一阶段最低要求

1. 只在用户点击附件时创建输入快照。
2. 同一次预览会话只创建一次。
3. 预览页面不重复生成临时文件。
4. 关闭页面后不立即删除这些文件，因为附件上传/发送仍可能读取它们。

### 34.3 推荐后续收敛

建议把文件物化从计算属性迁到显式服务：

```swift
protocol ChatAttachmentPreviewInputBuilding {
    func makeInputs(
        from attachments: [ChatComposerAttachmentPreview]
    ) throws -> [FilePreviewInput]
}
```

服务可实现：

- 文件已存在且大小匹配时跳过写入。
- 文件名使用附件 ID，保证稳定。
- 草稿删除附件时清理对应临时文件。
- 草稿整体销毁时批量清理。
- 应用启动时清理超过保留期限的孤儿文件。

### 34.4 所有权表

| 资源 | 创建者 | 使用者 | 删除者 |
| --- | --- | --- | --- |
| 聊天附件临时文件 | Chat 预览输入工厂/附件导入层 | 预览、上传、发送 | Chat 草稿文件生命周期管理器 |
| 公共预览 UIImage 缓存 | 图片加载器 | 公共预览 | 缓存淘汰/内存警告 |

## 37. 并发与 MainActor 约束

1. `SecondCameraReadOnlyPreviewStore` 标注 `@MainActor`。
2. `@Published` 状态只能在 MainActor 修改。
3. 文件检查和 ImageIO 解码不得阻塞 MainActor。
4. 每个 item 同时最多有一个完整图加载任务和一个缩略图任务。
5. 新请求到来时复用进行中的同 key 任务，避免重复解码。
6. `Task` 完成回写前再次检查项目仍存在且请求 revision 匹配。
7. 页面销毁后任务即使完成，也不得重新拉起已销毁的页面状态。

建议回写保护：

```swift
let requestID = UUID()
itemLoadRequestIDs[itemID] = requestID

let image = try await loader.loadPreviewImage(...)

guard itemLoadRequestIDs[itemID] == requestID else { return }
guard !Task.isCancelled else { return }
updateItem(id: itemID) { item in
    item.image = image
    item.loadState = .loaded
    item.revision += 1
}
```

这可以防止旧任务晚到后覆盖新状态。

## 41. Definition of Done

只有同时满足以下条件，工单第一阶段才可以关闭：

1. 公共图片预览没有聊天业务依赖。
2. 公共只读 Store 从接口层面不可修改输入集合。
3. 图片使用全屏展示，PDF/文件保持 Quick Look。
4. 混合附件起始项通过 ID 正确映射。
5. 输入快照不在 SwiftUI body 重算中反复写文件。
6. 大图按需解码，关闭页面能取消任务。
7. 相机 builder 签名和现有调用方式保持兼容。
8. 相机完整流程通过人工回归。
9. Debug simulator build 通过。
10. 新增错误文案完成本地化和无障碍标注。
11. 工单中的第一阶段验收项全部有测试记录或明确人工证据。
