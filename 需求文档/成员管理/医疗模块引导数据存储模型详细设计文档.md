# 医疗模块引导数据存储模型详细设计文档

创建日期：2026-06-20  
关联需求：`医疗模块引导流程重构需求讨论文档.md`  
客户端参考：`SparkClient/Projects/Features/Home/Presentation/Members/MemberSetup/Medical/MemberMedicalSetupSheet.swift`  
服务端参考：`SparkService/medical/models.py`

---

## 一、设计背景

医疗模块引导流程要从“慢病、用药、体检指标、症状随访”四步表单，升级为：

```text
AI医生助手开场
-> 问答式建档
-> 风险评估
-> 体检规划
-> 健康管理计划
-> 随访任务
```

当前服务端已有两个关键模型：

1. `MemberMedicalProfile`
   - 位置：`SparkService/medical/models.py:76-99`
   - 适合保存成员医疗画像摘要。
   - 包括慢病、长期用药、体检关注项、症状随访关注项、补充说明。

2. `MedExamDetail`
   - 位置：`SparkService/medical/models.py:477-517`
   - 适合保存体检报告、检查检验报告中的行级指标。
   - 当前业务类型只有 `health_exam_report` 和 `examination_report`。

但新的问答式医疗引导会出现一种新数据：

```text
用户在问答流程内直接填写的关键健康指标
```

例如：

```text
血压：135/85 mmHg
空腹血糖：6.1 mmol/L
糖化血红蛋白：6.2 %
尿酸：520 umol/L
LDL-C：3.8 mmol/L
ALT：68 U/L
体重：72 kg
腰围：92 cm
```

这些数据不是完整体检报告，也不是检查检验报告，但它们又需要进入指标趋势、风险评估、AI体检计划和随访任务。

因此需要单独设计“关键指标”业务类型。

---

## 二、核心结论

### Q：关键指标应该放在 `MemberMedicalProfile.extra` 里吗？

A：不建议。

原因：

1. `extra` 适合保存问答扩展信息，不适合保存可趋势化的指标。
2. 指标需要按时间查询、排序、趋势分析。
3. 指标需要单位、参考范围、异常标记、来源、置信度。
4. 指标后续会被 AI 风险评估、体检计划、任务系统复用。

更合适的方式是：

```text
新增关键指标业务主表
复用 MedExamDetail 保存指标明细
MedExamDetail.business_type 增加 key_indicator
```

---

### Q：为什么要给关键指标单独创建业务类型？

A：因为关键指标和报告指标的来源、生命周期、展示方式不同。

| 维度 | 报告指标 | 关键指标 |
|---|---|---|
| 来源 | 体检报告、检验报告、影像报告 | 问答流程、手动录入、设备同步、AI随访 |
| 是否有报告主表 | 有 | 不一定有 |
| 是否需要趋势 | 需要 | 更需要 |
| 是否影响 AI 体检计划 | 是 | 是 |
| 是否可直接由用户填写 | 通常不是 | 是 |
| 是否需要单独业务归属 | 已有报告主表 | 需要 |

建议增加：

```text
MedExamDetail.BusinessType.KEY_INDICATOR = "key_indicator"
```

同时新增关键指标主表：

```text
MemberMedicalKeyIndicatorRecord
```

这样：

```text
MemberMedicalKeyIndicatorRecord
  └─ MedExamDetail(business_type=key_indicator, business_id=record.id)
```

既保留了指标趋势统一能力，也避免把问答数据硬塞进体检报告。

## 三、服务端数据模型设计

### 3.1 MemberMedicalProfile：成员医疗画像摘要

现有模型继续保留，定位为“医疗画像摘要”，不承担所有指标明细。

建议字段职责：

| 字段 | 职责 |
|---|---|
| `member` | 所属成员 |
| `chronic_conditions` | 慢病标签，例如高血压、糖尿病、高血脂 |
| `long_term_medications` | 长期用药摘要 |
| `medication_notes` | 用药补充说明 |
| `exam_focus` | 体检关注项，例如血糖、血脂、尿酸 |
| `symptom_follow_up_focus` | 症状与随访关注项 |
| `notes` | 用户补充说明 |
| `extra` | 问答扩展信息和非趋势类画像字段 |

`extra` 推荐保存：

```json
{
  "occupation": "programmer",
  "sedentary_hours_level": "over_8h",
  "smoking_status": "current",
  "cigarettes_per_day": "10",
  "smoking_years": "12",
  "alcohol_status": "weekly",
  "exercise_frequency": "1_2_per_week",
  "sleep_duration_level": "6_7h",
  "family_history": ["hypertension", "colorectal_cancer"],
  "last_exam_year": "2025",
  "last_exam_institution": "某体检中心",
  "has_exam_report": "true"
}
```

不建议保存：

```text
血压具体值
血糖具体值
尿酸具体值
血脂具体值
肝肾功能具体值
```

这些应进入关键指标业务。

---

### 3.2 新增 MemberMedicalKeyIndicatorRecord：关键指标记录主表

### Q：为什么需要主表？

A：因为一次问答、一次随访、一次手动录入可能会包含多个指标，需要一个业务归属。

例如用户在问答里填写：

```text
血压 135/85
空腹血糖 6.1
尿酸 520
LDL 3.8
```

这是一组“同一次采集”的关键指标，应该有共同的：

```text
来源
采集时间
录入场景
问答会话 ID
备注
```

建议模型：

```python
class MemberMedicalKeyIndicatorRecord(MedicalBaseModel):
    class Source(models.TextChoices):
        GUIDE_QA = "guide_qa", "guide_qa"
        MANUAL = "manual", "manual"
        AI_FOLLOW_UP = "ai_follow_up", "ai_follow_up"
        REPORT_EXTRACTION = "report_extraction", "report_extraction"
        DEVICE = "device", "device"

    class Scenario(models.TextChoices):
        MEDICAL_GUIDE = "medical_guide", "medical_guide"
        FOLLOW_UP = "follow_up", "follow_up"
        RISK_ASSESSMENT = "risk_assessment", "risk_assessment"
        EXAM_PLAN = "exam_plan", "exam_plan"

    member = models.ForeignKey(Member, related_name="key_indicator_records", on_delete=models.CASCADE, db_index=True, db_comment="所属成员")
    source = models.CharField(max_length=32, choices=Source.choices, default=Source.MANUAL, db_index=True, db_comment="记录来源：问答引导、手动录入、AI随访、报告抽取、设备")
    scenario = models.CharField(max_length=32, choices=Scenario.choices, default=Scenario.MEDICAL_GUIDE, db_index=True, db_comment="业务场景：医疗引导、随访、风险评估、体检计划")
    recorded_at = models.DateTimeField(null=True, blank=True, db_index=True, db_comment="用户填写或测量时间")
    qa_session_id = models.CharField(max_length=64, blank=True, default="", db_index=True, db_comment="问答流程会话 ID，用于回溯本次引导")
    title = models.CharField(max_length=128, blank=True, default="", db_comment="记录标题，例如医疗引导关键指标")
    summary = models.TextField(blank=True, default="", db_comment="记录摘要，例如血压偏高、尿酸偏高")
    extra = models.JSONField(default=dict, blank=True, db_comment="扩展信息，例如原始问答、AI解释、设备来源")
    is_deleted = models.BooleanField(default=False, db_index=True, db_comment="是否删除")

    class Meta:
        db_table = "medical_member_key_indicator_record"
        db_table_comment = "成员关键健康指标记录主表，一次问答/随访/手动录入可关联多条指标明细。"
        ordering = ["-recorded_at", "-updated_at", "-id"]
        indexes = [
            models.Index(fields=["member", "recorded_at", "is_deleted"]),
            models.Index(fields=["member", "source", "is_deleted"]),
            models.Index(fields=["member", "scenario", "is_deleted"]),
            models.Index(fields=["qa_session_id", "is_deleted"]),
        ]
```

设计要点：

1. 主表不直接放大量指标字段。
2. 主表用于表达“这是一组同一次采集的数据”。
3. 指标明细仍放到 `MedExamDetail`。
4. `qa_session_id` 方便从 AI 问答流程回放。
5. `recorded_at` 用于趋势图和风险评估。

### 3.3 MedExamDetail 增加关键指标业务类型

### Q：为什么关键指标明细复用 `MedExamDetail`？

A：`MedExamDetail` 已经具备指标行需要的通用字段：

```text
category
sub_category
item_name
item_code
result_value
unit
reference_range
flag
result_at
diagnosis
extra
```

新增业务类型：

```python
class BusinessType(models.TextChoices):
    HEALTH_EXAM_REPORT = "health_exam_report"
    EXAMINATION_REPORT = "examination_report"
    KEY_INDICATOR = "key_indicator"
```

关键指标写入示例：

```text
business_type = key_indicator
business_id = MemberMedicalKeyIndicatorRecord.id
member = 成员 ID
category = "vital_sign"
sub_category = "blood_pressure"
item_name = "收缩压"
item_code = "systolic_bp"
result_value = "135"
unit = "mmHg"
reference_range = "<120"
flag = "H"
result_at = recorded_at
```

舒张压：

```text
item_name = "舒张压"
item_code = "diastolic_bp"
result_value = "85"
unit = "mmHg"
```

空腹血糖：

```text
category = "glucose_metabolism"
item_name = "空腹血糖"
item_code = "fasting_glucose"
result_value = "6.1"
unit = "mmol/L"
flag = "H"
```

设计收益：

1. 报告指标和问答关键指标可统一趋势查询。
2. AI 风险评估只需要读取 `MedExamDetail`，不必适配多套指标模型。
3. 后续可以把设备数据、随访数据也归一到同一指标明细体系。

## 四、关键指标编码建议

### 4.1 第一期开通指标

建议第一期只支持高价值指标，不要一开始覆盖所有检验项目。

| 指标 | item_code | category | 单位 | 来源场景 |
|---|---|---|---|---|
| 收缩压 | `systolic_bp` | `vital_sign` | mmHg | 问答、随访、手动 |
| 舒张压 | `diastolic_bp` | `vital_sign` | mmHg | 问答、随访、手动 |
| 心率 | `heart_rate` | `vital_sign` | bpm | 问答、随访、手动 |
| 身高 | `height_cm` | `body_metric` | cm | 建档、问答 |
| 体重 | `weight_kg` | `body_metric` | kg | 建档、随访 |
| 腰围 | `waist_cm` | `body_metric` | cm | 问答、随访 |
| BMI | `bmi` | `body_metric` | kg/m2 | 系统计算 |
| 空腹血糖 | `fasting_glucose` | `glucose_metabolism` | mmol/L | 问答、报告 |
| 糖化血红蛋白 | `hba1c` | `glucose_metabolism` | % | 问答、报告 |
| 总胆固醇 | `total_cholesterol` | `blood_lipid` | mmol/L | 问答、报告 |
| LDL-C | `ldl_c` | `blood_lipid` | mmol/L | 问答、报告 |
| HDL-C | `hdl_c` | `blood_lipid` | mmol/L | 问答、报告 |
| 甘油三酯 | `triglyceride` | `blood_lipid` | mmol/L | 问答、报告 |
| 尿酸 | `uric_acid` | `metabolism` | umol/L | 问答、报告 |
| ALT | `alt` | `liver_function` | U/L | 问答、报告 |
| AST | `ast` | `liver_function` | U/L | 问答、报告 |
| 肌酐 | `creatinine` | `kidney_function` | umol/L | 问答、报告 |
| eGFR | `egfr` | `kidney_function` | ml/min/1.73m2 | 报告、计算 |

## 五、问答流程如何写入关键指标

### Q：问答流程中如何填写关键指标？

A：建议在医疗引导中增加“关键指标”步骤。

流程：

```text
基础档案
-> 病史档案
-> 生活习惯
-> 关键指标
-> 体检档案
-> 风险评估
-> AI体检计划
```

关键指标页面不是完整体检报告录入，而是让用户填最重要的几个数。

页面示例：

```text
最近是否知道这些指标？

血压       未填写 >
空腹血糖   未填写 >
血脂       未填写 >
尿酸       未填写 >
肝功能     未填写 >
肾功能     未填写 >

不知道也没关系，可以跳过。
```

点击“血压”：

```text
收缩压  ___ mmHg
舒张压  ___ mmHg
测量时间 今天/最近一次/自定义
```

点击“血糖”：

```text
空腹血糖 ___ mmol/L
糖化血红蛋白 ___ %
测量时间
```

保存后：

```text
创建 MemberMedicalKeyIndicatorRecord
插入多条 MedExamDetail(business_type=key_indicator)
```


## 九、与任务系统的关系

关键指标异常后可以生成任务。

示例：

```text
尿酸 520 umol/L
-> AI 风险评估提示尿酸偏高
-> 建议 1-3 个月复查尿酸和肾功能
-> 用户确认
-> 创建 Task(type=medical, source=ai)
-> 创建 TaskMedical(medical_task_type=recheck)
```

任务系统落点：

| 模型 | 用途 |
|---|---|
| `TaskPlan` | 长期健康管理计划 |
| `Task` | 具体任务 |
| `TaskMedical` | 医疗任务详情 |
| `TaskNotification` | 复查/体检提醒 |
| `TaskExecution` | 用户是否完成 |

## 十、第一期实现范围

## 十一、验收标准

1. 问答流程内可以填写血压、血糖、血脂、尿酸、肝肾功能等关键指标。
2. 关键指标不会写入 `MemberMedicalProfile.extra` 作为长期事实源。
3. 服务端能保存一组关键指标记录，并关联多条 `MedExamDetail`。
4. `MedExamDetail.business_type` 支持 `key_indicator`。
5. 客户端能展示关键指标摘要。
6. AI 体检计划能读取关键指标，并解释推荐原因。
