## 一、背景

当前成员建档流程中，用户完成成员基础信息后进入“选择维护模块”页面。

现状：

```text
选择维护模块
  -> 点击医疗模块
  -> 直接打开 MemberMedicalSetupSheetView
  -> 按完整医疗流程连续推进
```

当前 `MemberModuleSetupView.swift:41-51` 中模块卡片点击直接调用：

```text
viewModel.openSheet(for: module)
```

这会导致两个问题：

1. 用户只是想补某一块资料，却被带入完整流程。
2. 医疗模块内部已经拆成多个大组，但入口没有“汇总/进度”页面，用户不知道每一块是否完成。

目标是新增模块汇总页：

```text
选择维护模块
  -> 点击医疗模块
  -> Navigation push 到医疗模块汇总页
  -> 点击某个分组卡片
  -> Sheet 打开该分组的独立维护流程
  -> 完成后关闭 Sheet，回到汇总页
```

饮食模块也需要进入汇总页。第一期饮食模块只有一个卡片：

```text
基础信息
```

后期再增加更多饮食分组。

## 二、核心目标

### 2.1 模块入口改为 Navigation

点击“医疗模块”不再直接打开完整 sheet。

目标：

```text
MemberModuleSetupView
  -> 点击医疗模块
  -> Navigation push: MemberMedicalModuleSummaryView
```

点击“饮食健康”同理：

```text
MemberModuleSetupView
  -> 点击饮食健康
  -> Navigation push: MemberNutritionModuleSummaryView
```

### 2.2 分组维护使用 Sheet

模块汇总页内，每一个分组卡片独立打开一个 sheet。

医疗模块分组：

```text
基础档案
健康病史与症状记录
生活习惯
过往体检档案
风险评估
```

饮食模块第一期分组：

```text
基础信息
```

### 2.3 单个分组完成后只关闭 Sheet

用户在某个分组内点击完成：

```text
保存该分组
关闭 Sheet
回到模块汇总页
更新卡片完成状态
```

不能继续自动跳到下一个分组。

例如：

```text
基础档案 Sheet
  -> 性别
  -> 出生日期
  -> 身高
  -> 体重
  -> 职业
  -> 久坐时间
  -> 基础档案概况预览
  -> 点击完成
  -> 关闭 Sheet
  -> 回医疗模块汇总页
```

不要继续跳到：

```text
健康病史与症状记录
```

### 2.4 保留“开始全部流程”

汇总页需要保留一个“开始全部流程”入口。

点击后仍使用现有完整流转：

```text
基础档案
-> 健康病史与症状记录
-> 生活习惯
-> 过往体检档案
-> 风险评估
```

该入口可继续使用现有 `MemberMedicalSetupSheetView` 的完整流程，保持 `MemberSetupFlowView.swift:69-76` 现有 sheet 流转能力。

### 2.5 暂不填写行为

在模块汇总页或分组 sheet 内点击“暂不填写”：

```text
返回选择维护模块页面
该模块被选中
但状态显示未完成
首页仍按用户选择开启对应模块
```

也就是说：

```text
选中模块 != 完成模块
```

选中模块用于首页展示。

完成模块用于建档完成度。

## 三、整体流程

### 3.1 医疗模块入口流程

```text
选择维护模块
  |
  | 点击医疗模块卡片
  v
医疗模块汇总页
  |
  | 点击基础档案
  v
基础档案 Sheet
  |
  | 点击完成
  v
关闭 Sheet，回医疗模块汇总页
```

### 3.2 医疗模块完整流程

```text
医疗模块汇总页
  |
  | 点击开始全部流程
  v
MemberMedicalSetupSheetView 完整流程
  |
  v
基础档案
  |
  v
健康病史与症状记录
  |
  v
生活习惯
  |
  v
过往体检档案
  |
  v
风险评估
  |
  v
总结保存
  |
  v
关闭 Sheet，回医疗模块汇总页或选择维护模块页
```

### 3.3 饮食模块入口流程

```text
选择维护模块
  |
  | 点击饮食健康
  v
饮食健康汇总页
  |
  | 点击基础信息
  v
饮食基础信息 Sheet
  |
  | 点击完成
  v
关闭 Sheet，回饮食健康汇总页
```

### 4.3 医疗分组卡片设计

每个卡片需要展示：

```text

```

状态：

```text

```

建议视觉：

```text

未完成：橙色标签
已完成：绿色标签
```

卡片字段：

| 分组 | 副标题 | 完成判断 |

| 基础档案 | 性别、出生日期、身高体重、职业、久坐时间 | 已保存基础档案摘要 |
| 健康病史与症状记录 | 症状、慢病、用药、手术、过敏、家族史 | 任一病史分项完成或用户确认无 |

| 过往体检档案 | 体检记录、关键指标、下一次体检计划 | 已完成体检档案汇总 |
| 风险评估 | 风险提示、AI体检建议 | 已生成或确认风险评估 |

| 点击区域 | 行为 |
|---|---|
| 医疗模块卡片 | Navigation push 到 `MemberMedicalModuleSummaryView` |

| 暂不完善 | 返回首页/上级；不强制完成模块 |
| 完成 | 保存当前 selected/completed 状态并关闭建档流程 |

### 6.1 完整流程

### 6.2 分组流程


### 6.3 代码设计建议

`MemberMedicalSetupSheetView` 可以增加启动模式：

```swift
enum MedicalSetupEntryMode {
    case full
    case basicProfile
    case healthHistory
    case lifestyle
    case examArchive
    case riskAssessment
}
```

不同模式决定：

```text
初始页面
可访问页面范围
完成后行为
```

示例：

```text
full:
    基础档案 -> 病史 -> 生活习惯 -> 体检档案 -> 风险评估 -> 总结

basicProfile:
```

饮食模块同理：

## 七、状态设计

### 7.1 模块选中状态

模块选中表示首页展示该模块。

```text
selectedModules contains medical
    -> 首页展示 medicalInfoSection
```

### 7.2 模块完成状态

模块完成表示该模块至少有一组核心信息完成。

```text
completedModules contains medical
    -> 选择维护模块页显示已完成
```

### 7.3 分组完成状态

新增分组级状态。

建议结构：

```swift
struct MemberModuleSectionProgress: Identifiable, Equatable {
    let module: MemberSetupModule
    let sectionCode: String
    let title: String
    let summary: String
    let status: MemberModuleSectionStatus
}

enum MemberModuleSectionStatus {
    case notStarted
    case incomplete
    case completed
}
```

服务端可通过 `MemberModuleSetting.extra` 或 `MemberMedicalProfile.extra` 保存分组进度。

建议优先：

```text
MemberModuleSetting.extra.section_progress
```

原因：

```text
分组进度是模块配置状态，不是医疗事实数据。
```

### 7.4 暂不填写状态

用户点击“暂不填写”：

```text
selectedModules += module
completedModules 不增加 module
section_progress 保持 incomplete / notStarted
返回选择维护模块页
```

首页模块展示：

```text
按 selectedModules 判断
```

模块完成度展示：

```text
按 completedModules + section_progress 判断
```

## 九、验收标准

### 9.1 医疗模块

1. 在选择维护模块页点击医疗模块，使用 Navigation push 进入医疗模块汇总页。
2. 医疗模块汇总页展示 5 个分组卡片。
3. 点击“基础档案”只打开基础档案 sheet。
4. 基础档案完成后关闭 sheet，回到医疗模块汇总页，不继续跳到健康病史与症状记录。
5. 点击“健康病史与症状记录”只维护该分组，完成后回到汇总页。
6. 点击“生活习惯”只维护该分组，完成后回到汇总页。
7. 点击“过往体检档案”只维护该分组，完成后回到汇总页。
8. 点击“风险评估”只维护该分组，完成后回到汇总页。
9. 点击“开始全部流程”保持现有完整流转。
10. 暂不填写返回选择维护模块页，医疗模块保持选中但显示未完成。

### 9.2 饮食模块

1. 在选择维护模块页点击饮食健康，使用 Navigation push 进入饮食健康汇总页。
2. 饮食健康汇总页第一期只展示“基础信息”卡片。
3. 点击“基础信息”打开饮食基础信息 sheet。
4. 完成后关闭 sheet，回到饮食健康汇总页。
5. 暂不填写返回选择维护模块页，饮食模块保持选中但显示未完成。

### 9.3 首页展示

1. 模块只要被用户选中，就参与首页展示。
2. 模块未完成时，首页仍展示模块入口或空态摘要。
3. 完成状态只影响建档进度，不影响首页模块是否展示。

## 十、阶段拆分

### 阶段一：路由与汇总页

1. 新增医疗模块汇总页。
2. 新增饮食健康汇总页。
3. `MemberModuleSetupView` 点击模块改为 Navigation push。
4. 保留原有完整 sheet 能力。

### 阶段二：医疗分组 Sheet

1. `MemberMedicalSetupSheetView` 增加 `MedicalSetupEntryMode`。
2. 支持 `full` 与 5 个分组模式。
3. 分组模式完成后关闭 sheet，不进入下一组。
4. 汇总页卡片状态刷新。

### 阶段三：饮食分组 Sheet

1. `MemberNutritionSetupSheetView` 增加 `NutritionSetupEntryMode`。
2. 第一阶段支持 `basicInfo`。
3. 完成后关闭 sheet，回饮食汇总页。

### 阶段四：模块状态与首页展示

1. 区分 selected 与 completed。
2. 暂不填写时保持 selected，completed=false。
3. 首页按 selected 展示医疗/饮食模块。
4. 模块选择页按 completed 和 section_progress 展示进度。

## 十一、最终结论

成员模块维护需要从“点击模块直接进入完整 sheet”调整为：

```text
点击模块
-> Navigation push 模块汇总页
-> 点击分组卡片
-> Sheet 维护该分组
-> 完成后关闭 Sheet 回汇总页
```

同时保留：

```text
开始全部流程
```

用于继续现有完整引导链路。

这样用户既可以按完整流程建档，也可以只补某一块资料；模块是否开启和资料是否完成也能清晰分离，首页展示规则会更稳定。
