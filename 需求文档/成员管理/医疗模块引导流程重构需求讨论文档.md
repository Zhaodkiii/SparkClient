# 医疗模块引导流程重构需求讨论文档

创建日期：2026-06-20  
适用范围：成员建档后的「医疗模块去完善」流程  
客户端参考：`SparkClient/Projects/Features/Home/Presentation/Members/MemberSetup/Medical/MemberMedicalSetupSheet.swift`  
服务端参考：`SparkService/task_system/models.py`

---

## 一、背景

当前医疗模块引导页已经从一个大表单拆成了：

```text
慢病档案 -> 用药 -> 体检指标 -> 症状/随访 -> 总结
```

这个结构比单页表单更好，但仍然偏向“用户自己知道要填什么”。真实健康管理场景里，很多用户并不知道哪些信息会影响体检计划，也不知道哪些信息对 AI 判断风险有价值。

本次重构目标不是让用户填更多表，而是把医疗模块改造成：

```text
AI医生助手开场
-> 问答式建档
-> 风险评估
-> 体检规划
-> 长期健康管理计划
-> 随访任务
```

最终目标：

1. App 先知道成员基础医疗信息。
2. AI 根据成员填写的信息、历史报告、家庭病史和生活方式，制定适合用户的体检计划。
3. 体检计划、复查提醒、随访问题可以落入 `task_system` 任务系统。
4. 医疗建议只作为健康管理和就医提醒，不替代医生诊断和治疗方案。

---

## 二、为什么要重构

### Q：为什么医疗模块不能一开始就让用户填大表单？

A：医疗信息和普通资料不同，大表单会带来三个问题：

1. 用户不知道哪些信息重要，容易跳过。
2. 医学词汇多，用户理解成本高。
3. 表单没有解释“为什么问”，用户会觉得被过度收集隐私。

更合适的方式是问答式引导。每个问题都要说明：

```text
为什么问
影响哪个流程
医学依据或健康管理价值
用户怎么回答最省事
```

例如“是否吸烟”不是为了简单记录习惯，而是会影响肺癌筛查、心血管风险、慢阻肺风险和体检项目推荐。

---

### Q：为什么最终目标是 AI 体检计划？

A：医疗模块如果只保存慢病、用药、体检指标，用户感知价值不强。用户真正想得到的是：

1. 我今年该做哪些体检？
2. 哪些项目必须做？
3. 哪些项目可以延后？
4. 我的报告异常要不要复查？
5. 下个月该关注什么？

因此医疗引导的终点应该不是“资料保存成功”，而是：

```text
基础健康档案
-> 风险分层
-> 个性化体检计划
-> 复查/随访/健康任务
```

任务系统可承接 AI 生成的长期计划：

```text
Task(type=medical, source=ai)
TaskMedical(medical_task_type=exam_plan / follow_up / recheck / report_upload)
TaskNotification(channel=local / apns)
TaskExecution(记录用户是否完成)
TaskPlan(长期健康管理计划)
```

## 三、产品定位

### Q：医疗模块应该像“问诊”还是“体检顾问”？

A：第一期建议定位为“AI体检顾问 + 健康档案助手”，不要定位成诊断医生。

原因：

1. App 可以根据年龄、性别、病史、家族史和生活方式推荐体检项目。
2. App 可以提醒复查、随访和上传报告。
3. App 不应该给出疾病诊断、治疗方案或停药建议。

推荐产品话术：

```text
我可以帮你整理健康档案，并根据你的基本情况生成体检和随访建议。
如果出现明显不适、报告异常或需要治疗，请以医生面诊意见为准。
```

## 四、目标流程

### 4.1 总流程

```text
AI开场
-> 基础档案
-> 既往病史
-> 家族病史
-> 生活习惯
-> 体检档案
-> 体检项目记录
-> 异常结果录入
-> 风险评估
-> 个性化体检计划
-> 长期健康管理计划
-> AI随访任务
-> 总结页保存
```

### 4.2 推荐分层

第一期不要把 20 多个问题全部摊在一个页面。建议分为 5 层：

```text
基础档案
病史档案
体检档案
风险评估
AI健康计划
```

每层内部采用问答卡片或一步一页。

## 五、问答式建档设计

下面每个问题都包含：

```text
问题目的：为什么问这个问题
影响流程：会影响哪些后续推荐
医学/管理依据：为什么这个问题有健康管理价值
第一期处理：第一期是否必须做
```

### 5.1 AI 开场

#### Q：进入医疗模块时，AI 应该怎么开场？

A：建议开场文案：

```text
为了给你制定更适合的体检和健康管理方案，我需要了解一些基本情况。
大约需要 3 分钟，你可以随时跳过，后续也可以补充。
```

问题目的：

1. 降低用户心理压力。
2. 告诉用户为什么要填写。
3. 明确不是诊断，只是健康管理计划。

影响流程：

1. 决定是否进入完整问答。
2. 决定用户跳过后是否只保存模块开启状态。
3. 决定后续 AI 是否可生成完整体检计划。

第一期处理：

1. 必须做。
2. 以普通页面实现即可，不强依赖真正 AI 对话 UI。

### 5.2 基础信息

#### Q1：为什么要问性别？

A：性别会影响体检项目和癌症筛查。

问题目的：

1. 区分乳腺癌、宫颈癌、前列腺癌等性别相关筛查。
2. 影响 BMI、代谢风险、心血管风险解释。
3. 影响 AI 体检计划模板。

影响流程：

```text
性别
-> 风险评估
-> 癌症筛查项目
-> 体检套餐推荐
-> 任务提醒
```

医学/管理依据：

1. 女性需要考虑乳腺、宫颈相关筛查。
2. 男性中吸烟率更高，肺癌和心血管风险管理更常见。
3. 前列腺筛查仅适用于男性。

第一期处理：

1. 已在 Member 基础信息里存在，可复用。
2. 医疗引导页展示确认，不重复强制录入。

---

#### Q2：为什么要问出生年份或年龄？

A：年龄是体检计划最核心的变量之一。

问题目的：

1. 判断是否进入特定年龄段筛查。
2. 决定体检频率。
3. 决定慢病风险分层。

影响流程：

```text
年龄
-> 体检项目推荐
-> 癌症筛查推荐
-> 慢病风险
-> 随访频率
```

医学/管理依据：

1. 高血压、糖尿病、血脂异常随年龄上升更常见。
2. 结直肠癌、肺癌、胃癌等筛查通常与年龄和风险因素强相关。
3. 老年成员更需要用药、复查、跌倒风险和照护提醒。

第一期处理：

1. 通过 `birth_date` 推导。
2. 不单独存储年龄字段。

---

#### Q3：为什么要问身高和体重？

A：身高体重用于计算 BMI，是基础风险评估和健康计划的核心指标。

问题目的：

1. 计算 BMI。
2. 判断超重、肥胖、消瘦。
3. 影响脂肪肝、糖尿病、高血压、血脂异常风险。
4. 可联动饮食健康模块。

影响流程：

```text
身高体重
-> BMI
-> 代谢风险
-> 体检项目增强
-> 饮食/运动建议
```

医学/管理依据：

1. 超重和肥胖与脂肪肝、高血压、糖尿病、高血脂风险相关。
2. BMI 不是诊断，但适合作为健康管理分层指标。

第一期处理：

1. 医疗模块可读取饮食健康目标里的身高体重。
2. 如果没有饮食健康数据，医疗引导页允许补充。
3. 不建议重复建多个身高体重事实源。

---

#### Q4：为什么要问职业？

A：职业影响久坐、熬夜、体力劳动、粉尘暴露、驾驶风险等。

建议选项：

```text
程序员
办公室文职
教师
销售
医护人员
司机
工人
自由职业
退休
其他
```

问题目的：

1. 判断久坐、熬夜、体力劳动、职业暴露。
2. 决定生活方式建议。
3. 提高 AI 建议的个性化程度。

影响流程：

```text
职业
-> 久坐/运动建议
-> 颈肩腰背风险提示
-> 心血管代谢风险
-> 特殊体检项目提示
```

医学/管理依据：

1. 长期久坐与代谢风险、腰背不适相关。
2. 司机、工人等职业可能存在作息、粉尘、噪声、体力负荷等风险。

第一期处理：

1. 建议做。
2. 可保存到 `MemberMedicalProfile.extra.occupation`。
3. 后续可结构化为枚举字段。

---

#### Q5：为什么要问每天久坐时间？

A：久坐时间比“是否运动”更能反映现代中国用户的常见风险。

建议选项：

```text
小于4小时
4~6小时
6~8小时
超过8小时
```

问题目的：

1. 判断代谢风险和生活方式干预强度。
2. 给出办公室人群可执行建议。
3. 影响随访任务，比如站立提醒、步数目标。

影响流程：

```text
久坐时间
-> 运动建议
-> 体重管理建议
-> 心血管代谢风险
-> 每月随访问答
```

第一期处理：

1. 建议做。
2. 可保存到 `MemberMedicalProfile.extra.sedentary_hours_level`。

### 5.3 既往病史

#### Q6：为什么要问既往疾病？

A：既往疾病直接决定体检项目和随访重点。

建议多选：

```text
高血压
糖尿病
高血脂
冠心病
脂肪肝
甲状腺疾病
肝炎
肾病
痛风
胃病/胃炎
肠息肉
无
其他
```

问题目的：

1. 建立慢病档案。
2. 生成体检计划时增加对应检查。
3. 后续创建复查任务。

影响流程：

```text
既往病史
-> 风险评估
-> 体检项目推荐
-> 复查提醒
-> AI随访问答
```

医学/管理依据：

1. 高血压、糖尿病、高血脂影响心脑血管风险。
2. 肝炎、脂肪肝影响肝功能、肝脏彩超、AFP 等管理建议。
3. 痛风影响尿酸、肾功能、饮食建议。

第一期处理：

1. 必须做。
2. 写入 `MemberMedicalProfile.chronicConditions`。

---

#### Q7：为什么要问长期用药？

A：长期用药影响用药提醒、复查项目和就医安全。

问题目的：

1. 判断是否需要用药计划。
2. 判断是否需要复查肝肾功能、电解质、血压血糖等。
3. 避免 AI 建议与现有用药冲突。

影响流程：

```text
长期用药
-> 用药计划
-> 复查任务
-> 报告解读上下文
```

医学/管理依据：

1. 长期用药人群通常需要规律复查。
2. 用药信息能帮助报告解读更谨慎。

第一期处理：

1. 必须做。
2. 如果用户选择“有长期用药”，引导打开 `MedicationPlanStepperView`。
3. 药品明细不必一次填完，允许跳过。

---

#### Q8：为什么要问手术史？

A：手术史会影响长期随访和体检重点。

问题目的：

1. 保存重大医疗事件。
2. 对肿瘤术后、心血管术后、胆囊/甲状腺等术后人群做专项随访。
3. 影响 AI 生成复查计划。

影响流程：

```text
手术史
-> 病例时间线
-> 复查计划
-> 体检项目推荐
```

第一期处理：

1. 可选做。
2. 简化为是否做过手术 + 手术名称 + 时间。
3. 后续可写入 `surgeries` 资源。

---

#### Q9：为什么要问药物过敏？

A：过敏史属于基础医疗安全信息。

建议选项：

```text
青霉素
头孢
磺胺类
海鲜
花粉
酒精
无
其他
```

问题目的：

1. 在就医和用药提醒里提示风险。
2. AI 解读报告和建议就医时需要知道。
3. 家庭成员共享时，照护人可以快速查看。

影响流程：

```text
过敏史
-> 成员医疗档案
-> 用药提醒
-> 就医资料卡
```

第一期处理：

1. 必须做。
2. 可写入成员基础信息 `allergies` 或 `MemberMedicalProfile.extra.allergies`。
3. 建议长期归一到 Member 基础字段。

### 5.4 家族病史

建议多选：

```text
高血压
糖尿病
脑卒中
心脏病
肺癌
肝癌
胃癌
肠癌
乳腺癌
宫颈癌
前列腺癌
无
不清楚
```

问题目的：

1. 判断遗传和家庭聚集风险。
2. 调整体检项目和筛查年龄。
3. 让 AI 体检计划更贴合中国家庭管理场景。

```text
家族病史
```

2. 结直肠癌、乳腺癌、胃癌、肝癌等需要关注家族史。

第一期处理：

1. 建议做。
2. 新增 `MemberMedicalProfile.extra.family_history`。
3. 后续可独立表结构化。

### 5.5 生活习惯

#### Q11：为什么要问吸烟？

A：吸烟是中国用户体检管理里非常关键的风险因素。

建议选项：

```text
从不
已戒烟
偶尔
经常
```

如果经常：

```text

```

问题目的：

1. 判断肺癌筛查是否需要更积极。
2. 判断心血管、慢阻肺风险。
3. 生成戒烟随访任务。

影响流程：

```text
吸烟
-> 肺癌风险
-> 低剂量胸部CT建议
-> 心血管风险
-> 每月随访任务
```

医学/管理依据：

1. 肺癌在中国发病和死亡负担都很高。
2. 吸烟是肺癌和心血管疾病的重要风险因素。

第一期处理：

1. 必须做。
2. 保存 `smoking_status`、`cigarettes_per_day`、`smoking_years`。

### 5.6 体检档案

#### Q15：为什么要问是否做过体检？

A：有体检历史和没有体检历史，推荐策略完全不同。

问题目的：

1. 判断是“从零建立体检计划”，还是“基于历史报告调整计划”。
2. 判断是否需要上传报告。
3. 判断是否需要补录最近一次体检异常。

影响流程：

```text
是否体检
-> 上传报告
-> 解析报告
-> 风险评估
-> 下一次体检计划
```

第一期处理：

1. 必须做。
2. 如果用户没有体检历史，直接进入 AI 推荐体检计划。
3. 如果有体检历史，引导填写最近一次体检时间、机构和报告。

---

#### Q16：为什么要问最近一次体检时间？

A：体检时间决定复查周期和报告有效性。

建议选项：

```text
2026年
2025年
2024年
更早
不记得
```

影响流程：

```text
体检时间
-> 是否需要今年体检
-> 是否需要复查
-> 任务计划开始时间
```

第一期处理：

1. 必须做。
2. 保存到体检记录或 `MemberMedicalProfile.extra.last_exam_year`。

#### Q17：为什么要问体检机构？

A：机构信息可以帮助用户回忆报告来源，也能作为医疗资源详情展示字段。

第一期处理：

1. 可选。
2. 文本输入。
3. 保存到体检记录摘要。

---

#### Q18：为什么要支持上传电子体检报告？

A：AI 体检计划最有价值的数据来自真实报告。

支持类型：

```text
PDF
图片
没有
```

影响流程：

```text
上传报告
-> OCR/结构化抽取
-> 异常指标识别
-> 风险评估
-> 下一次体检计划
```

第一期处理：

1. 必须支持“有报告则上传”。
2. 上传入口可复用医疗档案已有报告上传能力。
3. 上传不是强制项。

### 5.7 体检项目记录

#### Q19：为什么要问最近一次体检做过哪些项目？

A：同样是“做过体检”，不同体检项目覆盖范围差异很大。

建议分组：

```text
基础检查：
- 血常规
- 尿常规
- 肝功能
- 肾功能
- 血脂
- 空腹血糖
- 尿酸

影像检查：
- 腹部彩超
- 胸部CT
- 低剂量肺CT
- 心脏彩超
- 甲状腺彩超
- 乳腺彩超

癌症筛查：
- 胃镜
- 肠镜
- 粪便潜血
- AFP
- PSA
- HPV
- TCT
```

问题目的：

1. 判断哪些项目今年不必重复。
2. 判断哪些关键项目缺失。
3. 生成补充体检建议。

影响流程：

```text
已做项目
-> 缺失项目识别
-> 个性化体检计划
-> 任务系统提醒
```

第一期处理：

1. 建议做。
2. 如果用户上传报告，可由 AI 自动抽取项目。
3. 如果没有报告，允许用户手动多选。

### 5.8 体检结果异常

#### Q20：为什么要问体检是否有异常？

A：异常结果决定复查、随访和就医提醒。

建议选项：

```text
有
无
不清楚
```

如果有，可支持：

```text
手动选择：
- ALT升高
- 尿酸升高
- 血糖偏高
- LDL偏高
- 脂肪肝
- 甲状腺结节
- 肺结节
- 肾功能异常

AI自动提取：
从上传报告里提取异常指标。
```

问题目的：

1. 明确需要复查的异常。
2. 避免 AI 体检计划只基于年龄模板。
3. 形成指标趋势管理。

影响流程：

```text
异常结果
-> 风险评估
-> 复查任务
-> 专科就医提醒
-> AI随访
```

第一期处理：

1. 必须做。
2. “不清楚”是重要选项，避免用户被迫判断医学结果。
3. 上传报告后优先 AI 自动提取。

## 六、中国用户体检和癌症筛查重点

### Q：中国用户的医疗引导为什么要特别关注癌症筛查？

A：中国用户对癌症风险非常敏感，且体检规划中最容易产生价值感的就是“哪些癌症筛查该做、多久做一次、是否需要增加项目”。

产品设计不能简单把所有癌症都推荐给所有人，否则会造成焦虑和过度检查。更合理的方式是：

```text
年龄 + 性别 + 家族史 + 生活习惯 + 既往病史 + 最近体检项目
-> 风险分层
-> 只推荐适合用户的筛查项目
```

参考来源：

1. IARC / WHO Global Cancer Observatory 的 Cancer Today 数据页可用于查看 2022 年各国家癌症发病和死亡结构。
2. 国家癌症中心近年发布的中国癌症负担数据中，肺癌、结直肠癌、甲状腺癌、肝癌、胃癌、乳腺癌等是高发癌种；肺癌、肝癌、胃癌、食管癌、结直肠癌等是主要死亡负担来源。

文档使用原则：

1. 不在客户端写死“所有人都做全部筛查”。
2. 只把癌症筛查作为 AI 体检计划推荐依据。
3. 具体筛查方案需结合年龄、性别、家族史和医生建议。

---

### Q：第一期最值得纳入长期体检管理的癌症有哪些？

A：建议第一期重点围绕 7 类：

```text
肺癌
结直肠癌
肝癌
胃癌
乳腺癌
宫颈癌
前列腺癌
```

原因：

1. 覆盖中国常见癌症和高死亡负担癌症。
2. 有相对明确、可落地的体检项目。
3. 适合做长期提醒和报告跟踪。

---

### Q：这些癌症对应哪些体检项目？

A：建议映射如下：

| 癌症 | 推荐筛查项目 | 适用提示 |
|---|---|---|
| 肺癌 | 低剂量胸部 CT | 年龄、吸烟、职业暴露、家族史相关 |
| 结直肠癌 | 肠镜、粪便潜血 | 年龄、肠息肉史、家族史相关 |
| 肝癌 | 肝脏彩超、AFP | 乙肝/肝炎、肝硬化、长期饮酒相关 |
| 胃癌 | 胃镜 | 胃病史、家族史、地区饮食习惯相关 |
| 乳腺癌 | 乳腺彩超、钼靶 | 女性、年龄、家族史相关 |
| 宫颈癌 | HPV、TCT | 女性、年龄和既往筛查情况相关 |
| 前列腺癌 | PSA | 男性、年龄、家族史相关 |

第一期处理：

1. 只做“是否建议关注/是否建议咨询医生”的推荐。
2. 不做诊断结论。
3. 推荐文案必须包含“如有异常请到医院就诊”。

---

## 七、风险评估

### Q：风险评估应该输出什么？

A：第一期建议输出“健康管理风险”，不是医学诊断。

输出示例：

```text
健康评分：85

风险等级：
- 心血管代谢风险：中等
- 糖尿病风险：低
- 肝胆代谢风险：中等
- 肺部筛查关注：低
- 胃肠筛查关注：中等
```

问题目的：

1. 让用户理解为什么推荐这些体检项目。
2. 让 AI 体检计划有解释。
3. 让后续随访任务有优先级。

影响流程：

```text
问答数据
-> 风险评估
-> 体检计划
-> 任务优先级
-> 随访频率
```

第一期处理：

1. 可以先用规则 + AI 文案总结。
2. 后续再做独立风险评分模型。

## 八、AI 个性化体检计划

### Q：AI 体检计划应该如何生成？

A：输入应来自以下数据：

```text
Member 基础信息
MemberMedicalProfile 医疗画像
体检历史
上传报告结构化结果
异常指标
家族病史
生活习惯
```

输出建议分为三层：

```text
必须做
建议增加
可选关注
```

示例：

```text
必须做：
- 血常规
- 尿常规
- 肝功能
- 肾功能
- 血脂
- 空腹血糖

建议增加：
- 腹部彩超
- 甲状腺彩超

根据风险关注：
- 如长期吸烟或家族史明显，可咨询医生是否需要低剂量胸部 CT
```

第一期处理：

1. 生成文本计划 + 结构化项目列表。
2. 支持用户确认后创建任务。
3. 不自动创建大量任务，避免通知骚扰。

## 九、长期健康管理计划

### Q：AI 健康计划应该如何落到任务系统？

A：建议将 AI 计划拆成 `TaskPlan` 和 `Task`。

长期计划：

```text
TaskPlan
- title: 年度体检与健康管理计划
- member
- creator
- start_date
- end_date
- extra.ai_plan_snapshot
```

具体任务：

```text
Task(type=medical, source=ai)
TaskMedical(medical_task_type=annual_exam / recheck / follow_up / report_upload)
TaskNotification(reminder_time)
```

示例：

```text
未来1个月：
- 每周运动3次
- 记录血压或体重

未来3个月：
- 复查血脂/尿酸/肝功能

未来6个月：
- 完成专项复查

未来1年：
- 完成年度体检
```

第一期处理：

1. AI 生成计划后先展示确认页。
2. 用户点击“生成提醒”后创建任务。
3. 任务类型使用 `TaskType.MEDICAL`。
4. 任务来源使用 `TaskSource.AI`。
5. 医疗任务子类型写入 `TaskMedical.medical_task_type`。

## 十、AI 随访系统

### Q：为什么需要每月 AI 随访？

A：一次体检计划不能覆盖长期健康管理。每月轻量问答能让 App 持续更新用户状态。

建议每月问题：

```text
本月体重变化？
最近血压？
最近血糖？
是否有新的检查报告？
是否完成运动目标？
是否存在不适症状？
是否有新的用药？
```

影响流程：

```text
随访问答
-> 更新医疗画像
-> 调整任务计划
-> 提醒上传报告
-> 生成复查建议
```

第一期处理：

1. 先支持手动进入随访问答。
2. 后续再接任务系统自动提醒。

## 十一、客户端页面重构建议

### Q：`MemberMedicalSetupSheet` 应该如何重构？

A：建议从当前固定 4 步重构为 5 层问答流程。

当前：

```text
慢病档案
用药
体检指标
症状/随访
总结
```

目标：

```text
MedicalGuideIntroPage
MedicalBasicProfileStep
MedicalHistoryStep
MedicalFamilyHistoryStep
MedicalLifestyleStep
MedicalExamArchiveStep
MedicalExamProjectStep
MedicalAbnormalResultStep
MedicalRiskSummaryStep
MedicalExamPlanStep
MedicalTaskPlanConfirmStep
MedicalGuideSummaryPage
```

第一期可以先压缩为：

```text
开场页
基础档案
病史档案
体检档案
风险评估
AI体检计划
总结页
```

---

### Q：页面交互应该是问答还是表单？

A：核心问题采用问答卡片，少量字段使用表单。

推荐交互：

```text
单选：性别、是否体检、是否吸烟
多选：既往病史、家族病史、体检项目
文本：药物名称、手术名称、体检机构
上传：体检报告 PDF/图片
AI抽取：异常指标和体检项目
确认页：风险评估和体检计划
```

原因：

1. 用户回答成本低。
2. 更像 AI 医生助手。
3. 结构化数据质量更好。

---

### Q：跳过如何处理？

A：每一步都可以跳过，但需要区分“未知”和“没有”。

示例：

```text
无：用户明确没有
不清楚：用户不知道
跳过：用户暂时不想回答
```

这三个状态不能混用。

原因：

1. “无家族史”和“不清楚家族史”风险解释不同。
2. “没有体检报告”和“暂时不上传”后续引导不同。
3. AI 生成计划时需要知道哪些数据缺失。

## 十二、数据模型建议

### Q：医疗引导数据应该存在哪里？

A：建议分三层。

第一层：成员基础信息  
已有 `Member` 保存：

```text
name
relationship
gender
birth_date
allergies
chronic_conditions
```

第二层：医疗画像  
使用或扩展 `MemberMedicalProfile`：

```text
chronic_conditions
long_term_medications
medication_notes
exam_focus
symptom_follow_up_focus
notes
extra
```

第三层：AI 体检计划和任务  
使用 `task_system`：

```text
TaskPlan
Task
TaskMedical
TaskNotification
TaskExecution
```

---

### Q：是否需要新增医疗引导专用表？

A：建议需要，但可以分阶段。

第一期：

1. 先用 `MemberMedicalProfile.extra` 存储结构化扩展字段。
2. 不阻塞客户端流程。

第二期：

新增：

```text
MemberMedicalGuidanceProfile
MemberMedicalRiskAssessment
MemberMedicalExamPlan
MemberMedicalFollowUpAnswer
```

原因：

1. `extra` 适合第一期快速试错。
2. 风险评估和体检计划需要版本化，不适合长期只放 JSON。
3. AI 生成结果需要可追踪、可回放、可解释。

### Q：AI 体检计划的数据结构应该包含什么？

A：建议结构：

```text
member_id
plan_version
generated_by
generated_at
input_snapshot
risk_summary
must_do_items
recommended_items
optional_items
follow_up_tasks
disclaimer
```

其中：

```text
input_snapshot
```

必须保存，因为后续用户资料变化后，需要知道旧计划是基于什么生成的。

## 十三、AI 提示词和安全边界

### Q：AI 生成体检计划时需要哪些安全限制？

A：必须限制为健康管理建议。

提示词原则：

```text
不要诊断疾病
不要建议停药或换药
不要替代医生
异常结果建议到医院复查或咨询医生
筛查项目按风险分层推荐，避免制造焦虑
输出必须结构化
```

输出必须包含：

```text
推荐原因
项目名称
优先级
建议频率
是否需要医生确认
风险提示
```

## 十五、验收标准

1. 医疗模块进入后不再只是慢病/用药/体检/随访四个简单表单。
2. 每个问题都解释为什么问、影响什么流程。
3. 用户可以跳过，但跳过不会被当成“无”。
4. 保存成功后才开通医疗模块。
5. AI 体检计划能说明推荐原因。
6. 计划可落入任务系统，至少支持年度体检、复查、报告上传、随访提醒四类任务。
