# MEMBER-000004 成员建档默认开通医疗模块并跳过模块选择需求工单

> 文档性质：临时流程调整需求工单。
> 创建日期：2026-07-15
> 影响端：SparkClient iOS

## 一、背景

当前成员建档流程在完成「姓名生日 -> 亲属性别 -> 创建成员」后，会进入模块选择页，由用户选择医疗模块或饮食健康模块。

本阶段产品策略暂时调整为：新成员创建成功后默认开通医疗模块，并直接结束建档流程，不再进入模块选择页面。

## 二、目标

1. 成员创建成功后，客户端立即为该成员保存医疗模块开通状态。
2. 医疗模块只标记为已开通，不标记为已完成。
3. 医疗模块开通成功后触发创建完成回调，并关闭整个建档流程。
4. 用户不再看到模块选择页面。

## 三、范围

### 3.1 客户端入口

- `SparkClient/Projects/Features/Home/Presentation/Members/MemberSetup/MemberSetupFlowView.swift`
- `SparkClient/Projects/Features/Home/Presentation/Members/MemberSetup/MemberSetupFlowViewModel.swift`

### 3.2 流程调整

原流程：

```text
姓名生日 -> 生日选择 -> 亲属性别 -> 创建成员 -> 模块选择页 -> 完成
```

调整后：

```text
姓名生日 -> 生日选择 -> 亲属性别 -> 创建成员 -> 默认开通医疗模块 -> 完成并退出
```

## 四、业务规则

1. 默认开通模块固定为 `medical`。
2. 保存模块状态时：
   - `moduleCode = medical`
   - `isEnabled = true`
   - `isCompleted = false`
   - `displayOrder = 0`
   - `summaryText = ""`
   - `completedAt = nil`
3. 医疗模块开通失败时，不关闭流程，并展示现有错误提示。
4. 本工单不删除模块选择页和饮食健康模块能力，只绕过新建成员后的入口。
5. 维护已有成员模块的流程不受影响，仍可进入模块选择与模块汇总页面。

## 五、验收标准

1. 新建成员在亲属性别页点击下一步后，创建成员成功且医疗模块开通成功时，建档流程直接关闭。
2. 新建成员流程不会跳转到模块选择页。
3. 新成员首页/成员详情中应能按既有逻辑识别医疗模块已开通。
4. 饮食健康模块不会在新建成员完成时被默认开通。
5. 如果成员创建失败，仍停留当前流程并提示创建失败。
6. 如果医疗模块开通失败，仍停留当前流程并提示保存失败，不误触发创建完成回调。

## 六、回滚说明

如后续恢复模块选择页，只需将创建成功后的处理改回进入 `.modules` 路由，并移除默认医疗模块保存分支。
